# WP-355: i386 integers of 65 to 128 bits: shifts, intrinsics, `switch`

Spec: `spec/codegen-x86.md` §22 ("Shifts, intrinsics, `switch`"), the
refusal rows of §7 and §8. Module: `crates/hod_x86/src/wideint.rs`
(`shift`, `intrinsic`, `switch`); dispatch in `int.rs`; the constants of
`x87::int_branch`. Tests: `crates/hod/tests/i386_wide_int.rs`
(`shifts_as_llc`, `intrinsics_as_llc`, `switch_as_llc`,
`what_stays_refused`); `i386_fpclass.rs`'s `an_i80_shift_compiles`
replaces the test that named the `i80` shift refused.

## Where it comes from

WP-346 left `shl` / `lshr` / `ashr`, the integer intrinsics and `switch`
at 65 to 128 bits refused (`x86:i64:wide:{shift,intrinsic,switch}`).
`_BitInt(N)` reaches all three from C; clang 19 and 22
(`--target=i686-linux-gnu -O0`) write, at `_BitInt(128)`, `ctpop`,
`ctlz`, `cttz`, `bitreverse`, `abs`, `smax`, `umin` (and the others of
the four), `sadd.sat`, `ssub.sat`, `uadd.sat`, and (clang 22 only)
`fshl` / `fshr`, from `__builtin_{popcountg,clzg,ctzg}` and
`__builtin_elementwise_*`; at `_BitInt(72)` / `_BitInt(100)` they write
`ctpop.i72`, `ctlz.i72`, `abs.i100`.

## What `llc` does (measured, 19 and 22, `-O0 -global-isel=0
-fast-isel=0`, CPU `generic` and `i686`)

- Shifts at 65, 96, 100 and 128 bits, by a constant and a variable
  amount: in line, no call, no branch, no `cmov`. A variable amount goes
  through a stack buffer (the value beside zeros or its sign, indexed by
  `(amount >> 3) & 12` at 100 and 128 bits, then `shld` / `shrd` by
  `cl`); an `i100` is promoted to `i128` and only the amount's low byte is
  read.
- Intrinsics at 72 and 128 bits: no call but `fshl` / `fshr` at 72
  bits, which call compiler-rt's `__umodti3` (libgcc for i386 has none);
  without `cmov` branches in `ctlz`, `cttz` (both flags), the four min /
  max, the saturating operations and the funnel shifts; none with `cmov`;
  none ever in `ctpop`, `bswap`, `bitreverse`, `abs`.
- Constant operands at `i128`, CPU `generic`: `umax` / `umin` with 0,
  `umax` with all ones and `smax` with the width's minimum do not branch;
  `smax` with `2^63` and `smin` with `2^63 - 1` do. `x87::int_branch`
  compared its constants as 64-bit values (the wrong answer for each of
  the last five); it now compares them as 128-bit values.

## What landed

- Shifts by any amount at 65 to 128 bits (§22): a frame buffer of `L + 4`
  limbs, limb distance `q = amount / 32` and bit distance `amount % 32`;
  a variable amount indexes the buffer with `edx = &buffer -/+ 4
  ((ecx >> 5) & 3)`, which keeps every access inside it for any amount.
  No branch, no call, no pool register.
- `switch` on such an integer: limb-wise `cmp` / `jne` per case, the top
  limb zero-extended in `edx`.
- `ctpop`, `ctlz`, `cttz`, `bswap`, `bitreverse`, `abs`, `smax`, `smin`,
  `umax`, `umin` in `hod_x86` at every width from 65 to 128; through the
  facade only `i128`, because the shared classifier refuses the integer
  intrinsics at the other widths (`intrinsic:llvm.<name>/int-wide`).

## Evidence

- `i386_wide_int`, 9 tests: `shifts_as_llc` 36 runs, `switch_as_llc` 36
  runs, `intrinsics_as_llc` 36 runs equal `llc`'s (LLVM 19 and 22, CPU
  `generic` / `i686` / `pentium4`, static and PIE, plain and
  `Stress::ALL`). Shifts: widths 65, 72, 96, 100, 120, 128, every value
  of the boundary table by the amounts 0, 1, 31, 32, 33, 63, 64, 65, 95,
  96, 97, 127, N-1 below the width, as variable amounts and as constants,
  garbage above the width in the value and the amount, `x op x`, results
  stored, sign-extended, compared, added to and shifted again; amounts
  128, 200, 2^32-1, 2^64+3 and all ones (poison, not printed) run without
  a fault. Switch: the six widths, the even values of the boundary table
  as cases (high limbs set), the odd ones and four near misses reaching
  the default, garbage above the width. Intrinsics (through `hod_x86`'s
  own entry, so the odd widths are run too): the six widths over every
  pair of boundary values, the `true` count flags with zero masked by a
  `select`, the constants of the barrier list above, `bswap` at 96, 128,
  80 and 112 bits, a `double` quotient kept across each call (x87
  rounding at `llc`'s block boundaries).
- `HOD_REQUIRE_TOOLS=1 cargo test -p hod_x86`: 46 tests pass. Every
  `i386*` binary of `-p hod`: 34 binaries, 139 tests pass (two tests
  outside `i386_wide_int` named the shift, `ctpop.i128` and `switch`
  refused; they now expect them to compile or name the remaining
  refusals). `cargo fmt --all --check` and `cargo clippy --workspace
  --all-targets -- -D warnings` clean.
- irdiff `--target i686`: 171 PASS, 0 FAIL, 0 ERROR at LLVM 22 and at
  LLVM 19 (unchanged: no seed reaches these forms).
- compare-binaries, base `422cfcb3` (own target directory) against the
  head, over `tests/ir` and both kiln corpora, `-j 4`: 14168
  comparisons, 0 different, 0 changed outcome, 47 identical failures
  (the corpora reach no wide integer on i686).
- Not measured: whether `intrinsics_as_llc` fails without the
  `int_branch` change (the barrier constants were checked against
  `llc`'s assembly, above, and the run test passes with the change).

## Not done

Refused by name: `x86:i64:wide:intrinsic` for `{s,u}{add,sub}.sat`,
`{s,u}shl.sat`, `fshl` / `fshr` and `scmp` / `ucmp` of wide operands
(not compared at run time); `x86:i64:wide:div`, `x86:i64:wide:abi`,
`x86:abi:wide-arg`, `x86:i64:wide:width` as before. The intrinsics at
widths other than 128 stay the shared classifier's refusal; enabling
them there is a change for every target.
