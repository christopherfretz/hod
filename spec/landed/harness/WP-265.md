# WP-265 — the gate runs the report's self-test and checks the workflow files

Landed: two steps of `cargo xtask ci`, in the quick gate too, after
`fmt` (`spec/harness.md` "ci", "`scripts` and `workflows`"), and both
in the hosted lane's `lints` job (`xtask::ci::HOSTED_STEPS`; "CI" 5). No
code under `crates/` changed.

## The steps

- **`scripts`** (`xtask::scripts::scripts_gate`): `python3 -I
  scripts/oss/oss-report-selftest.py` (WP-263; until now run by hand),
  failing on a non-zero exit; then every shell script under `scripts/`
  parsed without running, with the shell its first line names: `sh -n`
  for `#!/bin/sh` (dash on Debian), `bash -n` for a `bash` shebang and for
  a `.sh` file without one (`env.sh`, to be sourced). 37 scripts at
  landing; 3.8 s on the development machine, nearly all of it the
  self-test.
- **`workflows`** (`xtask::scripts::workflows_gate`,
  `scripts/check-workflows.py`): every `.github/workflows/*.yml` and
  `.github/actions/*/action.yml` (8 files) parsed by PyYAML; a parse
  error, a key given twice, a workflow without `on` or `jobs`, a job with
  neither `runs-on` nor `uses`, a `runs-on` job without steps, a `needs`
  naming no job of the file, a step with neither `run` nor `uses`, or an
  action without `runs.using` fails it, one line per finding. The loader
  reads booleans as YAML 1.2 (only `true`/`false`), as GitHub does, so the
  key `on` stays a string (PyYAML's default would make it `True`).

The checker is Python because no Rust YAML crate is added (the shipped
crates have no third-party dependency and `xtask` has one approved one)
and the standard library of Python has no YAML parser: PyYAML is Debian's
`python3-yaml`, added to the hod-ci action's package list. Without it the
checker exits 3 and the step is skipped with that reason, a failure under
`HOD_REQUIRE_TOOLS=1` (the hosted lane sets it).

## Each step can fail

The self-test's expectation for "leftovers: no verdict" changed from exit
0 to exit 9 in the worktree (restored afterwards):

```
oss-report-selftest: FAILED: leftovers: no verdict (exit 0)
ci: scripts: FAILED in 3.8 s
```

A `scripts/zz-broken.sh` with an unclosed `if` (removed afterwards):

```
scripts: bash -n scripts/zz-broken.sh: exit status: 2
ci: scripts: FAILED in 4.2 s
```

The `workflows` step's failures are the fixtures of
`xtask/tests/workflows_check.rs` (`xtask/tests/data/workflows/`: a valid
workflow, a parse error, a `needs` naming a missing job, a job without
`runs-on`, a step without `run`/`uses`, a composite action's step without
either, and several files at once). The development machine has no
PyYAML: there the step and these tests are skipped (each fails under
`HOD_REQUIRE_TOOLS=1`, as designed); the checks' logic was exercised there
with the parser replaced by Python objects, and the tests first run where
`python3-yaml` is installed (the hosted lane).

## Found on the way

`scripts/libcxx-hod-kiln.sh` (`#!/bin/sh`) does not parse under `bash
-n`: the apostrophe in `${HOD_LIBCXX_KILN:?... the shim's kiln++-hod}`
inside double quotes opens a quote for bash, not for dash. It runs under
its shebang's `sh`, which accepts it, so the step parses it with `sh`;
run with `bash` it would fail.
