# WP-143 — x86-64 data and module-level constructs (X-data, design 0006)

Landed: `crates/hod_cg/src/emit/mod.rs` (x86-64 rules, no-ops for
AArch64), the `x86_64` column of the module-level rows of
`crates/hod_ir/src/classify/matrix.rs`, `docs/status/support.md`,
`spec/codegen.md` §5.6.3 (and the two §9.7 sentences that named x86-64
as missing), x86-64 cases in `crates/hod_cg/tests/{emit_llc,emit_asm,
emit_link}.rs` and `borrow/mod.rs`.

## Differences from `llc` found, and how each was settled

| difference | settled |
|---|---|
| `.text` of an object without functions: hod 1-aligned, `llc` 4 | fixed: `ArchInfo::text_align` is 4 on both targets |
| padding between functions: hod `0x90` bytes, `llc` long `nop`s | fixed: `X86AsmBackend::writeNopData`'s table, at most 10 bytes, longest first |
| an address of a `dso_local` definition in data of a shared object: hod names the section (through the local alias), `llc` names the symbol | fixed: `ArchInfo::data_prefers_local` (AArch64's `lowerConstant` override prefers the local alias; x86-64 uses `AsmPrinter`'s, which does not); the constructor tables follow the same rule |
| an address in a 1-byte field: hod refused it (`init:address-width`), `llc` writes `R_X86_64_8` (`_PC8` in a difference) | fixed: `abs(1)`/`prel(1)` on x86-64 |
| `cf-protection-return`: `llc` writes `.note.gnu.property` | implemented: the note with the shadow-stack bit; the code does not change |
| `cf-protection-branch`: `llc` writes `endbr64` (code) | left `todo(T-X64)` with the reason in the row's note |
| a number minus an address in data | `llc` fails on x86-64 too: `init:neg-addr` is rejected on both targets |

`tests/borrow` read x86-64 PC-relative relocations against a section
symbol at the wrong symbol (the addend counts from the end of the
field): it now adds the 4 back before looking the symbol up.

## Rows

Switched on for x86-64: `module:asm-symbols`, `module:linker-options`,
`module:dependent-libraries`, `module:global-ctors`,
`module:global-dtors`, `module:cf-protection-return`,
`structor:priority`, `structor:associated`, `global:variable-definition`,
`global:alias`, `global:alias-offset`, `global:ifunc`, `global:section`,
`global:align`, `global:unnamed-addr`, `global:used`,
`linkage:available_externally`, `linkage:linkonce`,
`linkage:linkonce_odr`, `linkage:weak`, `linkage:weak_odr`,
`linkage:private`, `linkage:extern_weak`, `linkage:common`,
`visibility:hidden`, `visibility:protected`, `tls:general-dynamic`,
`tls:local-dynamic`, `tls:initial-exec`, `tls:local-exec` (the symbol and
its definition; an access is WP-134's), `comdat:any`,
`comdat:nodeduplicate`, `init:data`, `init:symbol`, `init:sym-diff`,
`init:int-of-addr`. Rejected on x86-64 as on AArch64: `init:neg-addr`.

Left `todo(T-X64)`: `module:cf-protection-branch` (code: `endbr64`);
`init:blockaddress` and `init:block-diff` (they need the block offsets
of x86-64 code, which X-control records; the emission itself is
target-neutral); the `debug:*` rows (X-debug).

## Evidence

- `tests/emit_llc.rs`: the 17 target-neutral snippets on x86-64 and 5
  x86-64 snippets agree with `llc` 19 and 22 section by section
  (contents, flags, entry sizes, groups, symbols, relocations); AArch64
  unchanged.
- `tests/emit_asm.rs`: the directive cases on x86-64 (`#` comments; the
  `//` case is AArch64's only: `hod_ir` refuses it on x86-64).
- `tests/emit_link.rs`: the data module with `llc`'s `main` (30 probes),
  a data module whose code is a C driver (constructors with priorities
  and an associated COMDAT, a destructor, an IFUNC, TLS read and written
  from C, tables of C functions), and an `available_externally` copy:
  bfd, lld and mold, `qemu-x86_64`, LLVM 19 and 22; hod's output equals
  `llc`'s.
- The full pipeline (`hod` release binary, `hod_x64`'s code for `ret`
  functions and an IFUNC resolver), a module of data, COMDAT, weak, TLS,
  alias, IFUNC and a priority constructor, linked with a C driver: hod's
  object, `llc`'s, and the two mixed links (hod's data with `llc`'s
  code, `llc`'s data with hod's code) print the same under bfd, lld and
  mold.
- AArch64: 416 corpus modules (every 15th of the manifest, LLVM 19 and
  22) with the base and the final binary: 393 objects byte-identical,
  the 23 refusals identical.
- `cargo xtask irdiff --target x86_64`: no seed is refused at a module
  row any more; the first refusals are instruction groups (`inst:load`
  7, `inst:add` 5, `type:double` 4, `inst:call` 4, `inst:icmp` 3, ...),
  and `init:blockaddress` 1, `intrinsic:llvm.threadlocal.address` 1.
