# WP-123 — x86-64 memory, X-mem (design 0006 §2.9, §2.10)

Landed: `spec/codegen.md` §5.6.4; `hod_x64::mem` (`crates/hod_x64/src/mem.rs`);
the support-matrix rows below; seed `tests/ir/odd_width_store.ll`.

## What it does

- `load`/`store` (non-atomic; `volatile` is an ordinary access, a dead
  volatile load is still emitted) of every `Gpr` value: integers of 1..=64
  bits (exactly the store size read and written, bits above the width
  zeroed in memory, 3/5/6/7-byte pieces), pointers; and every `Fpr` value:
  `half`, `bfloat` (`pinsrw`/`pextrw`), `float` (`movss`), `double` and
  64-bit vectors (`movsd`), `fp128` and 128-bit vectors (`movups`).
  Constants are stored as immediates.
- `ptradd`: constant offsets, any number of indices of any width
  (sign-extended), scaled by the addressing mode, `shl` or `imul`; fused
  into its only load/store (§4.6), else `lea`. Symbol bases through
  `common::sym_address` with the offset as addend; slot bases as frame
  accesses.
- `alloca` (dynamic): constant or variable count (zero-extended), any
  element size, alignment above 16 by masking `rsp`.
- `llvm.stacksave`/`llvm.stackrestore`.

## Refused

| name | what |
|---|---|
| `x64:ptradd-vector` | a `ptradd` producing a vector of pointers |
| `limit:frame-size` | an `alloca` alignment not a power of two or above 2^32; a constant size ≥ 2^63 |
| `x64:todo:atomic` | an atomic load or store (X-atomic, WP-133) |

`mem::MEM` (`x64:todo:mem`) stays as a `pub const`, unused.

## Where hod differs from `llc` on purpose

- An `alloca` aligned above 16: `llc` realigns the whole frame (`and
  rsp` in the prologue and a base pointer); hod aligns the allocation
  alone and never realigns the frame (over-aligned fixed slots are the
  core's dynamic slots). Design 0006 §2.9 planned `x64:stackrealign`;
  supported instead, as on AArch64.
- A constant `Fpr` store is always integer immediate stores, never a
  register round trip.
- `half` moves with `pinsrw`/`pextrw` (SSE2), never `f16c`.
- No load folding: every load is its own instruction.

## Evidence

- `crates/hod_x64/tests/mem.rs`, generator `tests/common/mem_gen.rs`
  (AArch64's, WP-036, extended with `Fpr` types and three-index
  addresses): 1500 generated functions in one object and one process,
  compared with `hod_interp` in five modes: hod static, hod stressed,
  hod PIC, `llc` 22, `llc` 19 (`-O0 -fast-isel=0 -relocation-model=pic`),
  under `qemu-x86_64`. `HOD_MEM_SEEDS=n` runs more (ignored test).
- `half`/`bfloat`/`fp128` (not run by `hod_interp`): a guarded-buffer
  byte check from C, hod plain and stressed, `llc` 22 and 19.
- Dynamic, over-aligned (64, 4096), zero-sized and >2^24-byte `alloca`s,
  stack save/restore, over-aligned and far slots: C driver checks of
  alignment, ordering and `rsp` alignment at calls; hod by ld, lld and
  mold, `llc` 22 and 19.
- Mixed objects: hod's caller with `llc`'s callee and the reverse.
- Instruction shape: fusion into `[base + index*scale + disp]`, `movsxd`
  of an i32 index, `imul` for a scale of 36, odd-width store pieces.
- Seed `odd_width_store.ll` passes `irdiff` on both targets.
- Text bytes of the 1500 functions: hod PIC 771183, `llc` 22 607208
  (1.27).

## Mutations (each caught, then reverted)

1. A variable index zero-extended instead of sign-extended
   (`compute`): the generator test and `ptradd_fuses_into_the_addressing_mode`.
2. The constant offset dropped when an index is present: the same two.
3. An odd-width store not masked: the generator test,
   `an_odd_width_store_writes_its_store_size`, `mixed_objects_agree`.

## Matrix rows (x86-64)

`function:slots`, `function:over-aligned-slot`, `inst:alloca`,
`inst:ptradd`, `mem:volatile`, `operand:slot`,
`intrinsic:llvm.stacksave`, `intrinsic:llvm.stackrestore`; `inst:load`
and `inst:store` for `Int`, `Ptr`, `Half`, `BFloat`, `Float`, `Double`,
`Fp128` (`I128`, `IntWide`, `Aggregate` and `Vector`, whose wide members
are `Mem`, stay with X-aggr, WP-126).
