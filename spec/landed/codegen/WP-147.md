## What was checked outside hod

- **`__truncxfbf2`.** The GCC 14 cross toolchain's libgcc has it
  (`libgcc_s.so.1` exports `__truncxfbf2@@GCC_13.0.0`; `libgcc.a` has
  `truncxfbf2.o`). `llc` 22 calls it; `llc` 19 fails to select `fptrunc
  x86_fp80 to bfloat`.
- **`fxam` and `llc` on a pseudo-denormal.** The host is AArch64; under
  `qemu-x86_64`, `fxam` reports a pseudo-denormal as a denormal (C3 C2
  C0 = 1 1 0), which is what Intel's manual documents. Over all 1024
  masks, `llc` 19 and 22 answer false for every single class (no class
  holds it) and true for 301 (19) and 299 (22) masks by their
  expansions; they differ on `0x7`, `0xf3`, `0x203` (19 true) and
  `0x30c` (22 true). 22's `0x30c` (normal or infinity) is true while
  its `0x108` (normal) and `0x204` (infinity) are false: no class gives
  that, so the newer `llc` is not followed; hod uses `fxam`'s class.
- **sjlj on AArch64.** `llc` 19 and 22 compile `llvm.eh.sjlj.setjmp` to
  0 and `longjmp` to nothing for AArch64, and clang refuses
  `__builtin_setjmp` there; the matrix row is `never` on AArch64.

## Differences from `llc`, deliberate

- `is.fpclass` of a pseudo-denormal: hod's class is the subnormal one
  for every mask (above).
- `setjmp` refuses a register value live across it
  (`x64:sjlj-live-value`), which `llc` compiles; hod's policy may reuse
  the spill slot such a value is read from after the second return.
