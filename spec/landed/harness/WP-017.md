# WP-017 — `xtask corpus`: the IR hod has to compile

Landed: `spec/harness.md` "corpus" (`capture`, `verify`, `census`,
`fetch`), and the first census of a captured corpus,
`docs/status/corpus.md`. The corpus itself is build output
(`<build root>/corpus`) and is not in the repository.

## What it did

- `xtask/src/corpus.rs`: the command line, the defaults ("Where things
  are"), `fetch`.
- `xtask/src/corpus/capture.rs`: groups, the capture directory and its
  `llc` script, the per-test capture of both sources, staging, admission
  through `irdiff`'s `Session`, the commit, `CAPTURE.tsv`, the summary.
- `xtask/src/corpus/kiln.rs`: kiln's test headers (the rules of
  `kiln/xtask/src/test.rs` that decide how a run test is built, run and
  checked), discovery, the static skips, the plan of one test.
- `xtask/src/corpus/torture.rs`: discovery of `gcc.c-torture/execute`, the
  `dg-options` and `.x` rules, the translation of GCC's flags for clang.
- `xtask/src/corpus/entry.rs`: what an entry file is; what cannot be one.
- `xtask/src/corpus/manifest.rs`, `sha256.rs`: the tables and their
  escaping; SHA-256 (FIPS 180-4, checked against the standard's vectors)
  because no dependency may be added.
- `xtask/src/corpus/verify.rs`: the manifest check and the `irdiff` runs.
- `xtask/src/corpus/census.rs`, `census/scan.rs`, `census/report.rs`: the
  tables, the lexical scanner, the report.
- `xtask/tests/corpus_fakes.rs` (five tests with shell-script tools,
  7 to 10 s), `xtask/tests/corpus_real.rs` (one test with the real clang,
  `llc` and linkers, 4 to 6 s).
- `xtask/src/main.rs`, `xtask/src/lib.rs`: the wiring.

No new dependency, no `unsafe`. One change outside the package's files,
additive: `Search::on_path` and `Search::versioned` in
`xtask/src/irdiff/tools.rs` are now `pub` (the capture finds `clang-<N>`
with them). `irdiff` behaves as before.

## Decisions, and why

- **The capture is a shim.** kiln is given an LLVM directory in which
  only `llc` is replaced, by a script that saves what it is given and
  runs the real `llc`. The module is therefore exactly what hod will be
  given in that place, the rest of kiln's pipeline (its `opt` runs, its
  link) is untouched, and the program that sets the expectations is the
  one the real tools build.
- **kiln++ under its own name.** `kiln++` is a symbolic link to `kiln`;
  the name selects the C++ driver. A path made canonical turns every C++
  link into a C link (249 link failures in the first capture). The spec
  says so because the next harness will make the same mistake.
- **kiln runs in a mirror of its repository's root** (two symbolic
  links), with `-fdebug-prefix-map=<cwd>=.`: tests are named as kiln's
  own harness names them, modules hold no path of the machine, and
  nothing can be written into kiln's repository.
- **Expectations are what the program did**, after it has been checked
  against what the test's header says it must do. A test's header often
  checks nothing but the exit status; the corpus then still pins the
  whole standard output.
- **Admission is `irdiff` itself**, in strict mode, with a stand-in that
  declines. Whatever `irdiff` would call an ERROR on the oracle's side
  can therefore not be an entry, with any linker: the corpus is sound by
  construction, and `verify` is a check of that, not the first time it is
  tried. It costs one `llc` run and three links per candidate.
- **One reason per skipped test, and a row for it.** The numbers that
  say how much of a suite hod is measured on are those of `SKIPPED.tsv`;
  the report prints every skipped test.
- **Both LLVM majors, every test, by default.** The whole corpus is
  164 MiB against a budget of about 2 GiB, so no selection was needed;
  `--limit` exists for a quick look and for tests.
- **Entries are not rewritten.** A module is kept byte for byte below
  its header; the header holds what `irdiff` needs and what the producer
  was given. Entries are host-specific (the triple is in the module);
  `;@ target:` says so.
- **`llc`'s arguments are recorded, not replayed.** The directive format
  has no place for them and this package does not extend it. All but 12
  entries were built with exactly what `irdiff` passes; the 12 add
  `-debugger-tune=gdb`.
- **The key is over the inputs that are cheap to hash** (the test file,
  the versions, the suite's revision), not over everything a test
  includes. `--force` is the answer to a changed header.
- **The census is a token scanner with a statement joiner**, not a
  parser: it needs no part of `hod_ir`, so it can be pointed at IR the
  parser cannot read yet, which is the IR one most wants counted. It
  counts what it cannot place instead of guessing.
- **`fetch` is a command**, so that the pin (tag and commit) is in the
  code and the suite is obtained the same way everywhere: a blobless,
  shallow, sparse clone of the one directory.

## Evidence

On the development container (aarch64 Linux, 24 cores, shared and loaded;
LLVM 22.1.8 and 19.1.7, gcc 14.2, GNU ld 2.44, lld 22, mold 2.37.1; no
wild; kiln 1.0.1 at `bd60e182`; GCC tests at `releases/gcc-16.1.0`,
`6afcc4f6`):

- `cargo xtask corpus capture -j 3 --force` (everything, both majors):

  | group | tests | captured | skipped | seconds |
  |---|---:|---:|---:|---:|
  | `kiln/llvm22` | 1540 | 1224 | 316 | 192 |
  | `kiln/llvm19` | 1540 | 1190 | 350 | 200 |
  | `gcc-torture/llvm22` | 1812 | 1672 | 140 | 212 |
  | `gcc-torture/llvm19` | 1812 | 1674 | 138 | 250 |

  5760 entries, 163.8 MiB of entry files (177 MB on disk with the
  tables); 14 min 26 s in all with the machine's load above 20, 11 min 3 s
  an hour earlier. The work directory is 24 kB afterwards; the GCC
  checkout is 32 MB. Skips by reason are in `docs/status/corpus.md`.
- Reproducible: two forced captures and the `--retry-skipped` captures
  between them left `MANIFEST.tsv` and all 5760 entry files byte for byte
  the same (SHA-256 of every file compared). `SKIPPED.tsv` differed twice
  on the way, and both causes are fixed and tested: a program that prints
  an address (`return-addr.c`) had its output quoted in the detail, and
  `irdiff` cuts a long detail at a length, which fell inside a path whose
  length depends on the process id. With the final code two
  `--retry-skipped` captures in a row (all 944 skipped tests built again)
  gave the same `SKIPPED.tsv`.
- `cargo xtask corpus capture -j 3` again: nothing captured, every file
  of the corpus unchanged including `CAPTURE.tsv`, 32 s (of which the
  capture 18 s: it hashes every test and every entry).
- `cargo xtask corpus verify -j 3`: manifest 5760 entries, 0 problems;
  `irdiff --hybrid` with LLVM 22: 2896 tests, 8688 results, 8688 PASS in
  688 s; with LLVM 19: 2864 tests, 8592 results, 8592 PASS in 557 s; exit
  status 0, 21 min in all. hod built 0 of 5760 objects (every module is a
  fallback, `codegen-not-implemented`): the run proves the corpus, and is
  the baseline the code generator starts from.
  `verify --manifest-only`: 16 s.
- `cargo xtask corpus census`: 5760 modules counted in 13 s (a development
  build), a report of 2063 lines; "Not recognised by the scanner": none.
  On 123 kiln modules the scanner's definitions, basic blocks and
  instructions (511, 1144, 8871) are exactly those of an independent
  regular-expression count.
- `HOD_REQUIRE_TOOLS=1 cargo xtask ci --quick`: green, 116 s on the loaded
  machine. The package's share: `corpus_fakes` 9.4 s, `corpus_real` 2.9 s,
  33 unit tests under 0.1 s. The gate needs neither kiln, nor the GCC
  suite, nor a captured corpus.

## What the first census says

The numbers are in `docs/status/corpus.md`; what they mean for the order
of work:

- **The dialect is small and both majors must be read.** No calling
  convention but the default in 5760 modules; `comdat any` only; general
  dynamic TLS only (7 modules); 51 intrinsics by folded name, `memset`
  and `memcpy` far ahead; seven kinds of constant expression, almost all
  `getelementptr`. Against that, LLVM 22 and 19 differ in what is
  written: `getelementptr nuw`, `captures(none)` for `nocapture`,
  `dead_on_return`, `nocreateundeforpoison`, `splat` constants, another
  data layout string and `"frame-pointer"` value.
- **C++ needs COMDATs and unwinding early, in few shapes.** Two thirds of
  kiln's modules have `linkonce_odr` definitions in a COMDAT; `invoke` and
  `landingpad` are in 12 % of them, with `__gxx_personality_v0` the only
  personality, and `cleanup`, catch-all and typed `catch` the only
  clauses.
- **One module is three quarters of kiln's instructions.**
  `stress/cleanup-scopes-30k.cpp` is 21 MB: one function of 360,008
  instructions in 60,002 blocks. Totals for kiln are that module; the
  module counts (in parentheses in every table) are the guide to how
  common a construct is. The same holds for the torture suite's five
  `memcpy-*`/`memclr` modules of 2049 functions each, which set its
  per-function medians. For hod the stress module is a requirement of its
  own: nothing per function may be worse than linear.
- **Inline assembly is almost always empty.** All 10,819 `asm` calls of
  the torture suite have an empty template (optimization barriers); real
  templates are in a handful of kiln modules, with `callbr` in three and
  `module asm` in four.
- **Wide and odd types are rare but present**: `i128` in 25 modules per
  major, `fp128` (AArch64 `long double`) in 56, bit-field and `_BitInt`
  widths such as `i65`, `i72` and `i129` in a few, vectors in at most 14
  modules per shape, `half` and `bfloat` in three. By value, `[2 x i64]`
  is the aggregate that matters; `{ iN, i1 }` comes from the overflow
  intrinsics.
- **The corpus hardly has debug info**: six modules per major (kiln's
  `-g` tests), all with `#dbg_declare` records and none with
  `llvm.dbg.*` calls. A corpus for the debug-information work has to be
  captured with `-g`; this one says nothing about it.

## The kiln tests that fail without hod

The question was which tests of an earlier 402-test slice of kiln's
suite fail (17 did) when hod is not involved at all. What that slice was
is not recorded, and no prefix, stride or directory selection of the
measurements below gives 402 and 17, so the answer is given for the whole
suite, where it is exact.

kiln has 1540 tests with `expect: run`. Built and run **as their headers
say** (the capture), with plain kiln++ and the real `llc`:

- one fails to compile:
  `conformance/expr.const/builtins-srcloc-path-style.cpp`. It asserts
  that `__builtin_FILE()` of an included header is an absolute path; the
  capture names the test's directory relative to kiln's root. An artifact
  of the capture, not a kiln failure.
- none fails to link with the system's linker, none fails when run, none
  disagrees with its header;
- two (LLVM 22; one of them with LLVM 19) are built and run correctly
  and then fail admission, at the mold link only: `mold: error: symbol
  type mismatch: gets` (`dcl.struct.bind/p0963-binding-condition.cpp`)
  and `... glob` (`over.match.copy/direct-init-explicit-conversion-to-copy-ctor.cpp`).
  Each test defines a global variable with the name of a libc function;
  mold reports it, and `irdiff` links with `--fatal-warnings`. (Why the
  first passes with LLVM 19 was not looked into.)

Built **without reading the header beyond `args:`** (one file, kiln++
under its own name, no placeholders, no `requires:`, no standard input,
no `xfail:`), 176 of the 1540 fail: 171 do not build, 5 build and do not
do what the header says. By what the header would have said:

| tests | why they fail for a runner that ignores the header |
|---:|---|
| 113 | more than one translation unit (`module:`, `unit:`, `header-unit:`, `pch:`, `two-step:`): the other units are never built, the link has undefined symbols, or the import is not found. All 63 run tests of `conformance/module.interface` are here. |
| 33 | a `%{...}` placeholder for a toolchain (`'meta' file not found` and the like) |
| 10 | `requires:` the host does not meet (x86-only, one LLVM major only) |
| 7 | marked `xfail:` |
| 5 | `%{test_dir}` in link or LTO arguments is not substituted |
| 2 | need an environment (`env:`) |
| 1 | the path-style test above |
| 5 | run and differ: `basic.start.main/stdin.cpp` (no standard input given), `basic.start.main/environment.cpp` (no `env:`), `basic.link/unnamed-enum-internal-name-run.cpp` (`xfail:`), `ext.arm.sve/sve-builtins-run.cpp` and `sve-vector-bits-run.cpp` (need SVE, which the host lacks) |

And run as `kiln` instead of `kiln++`, every C++ test that needs the C++
library fails to link. So failures "without hod" of a kiln slice are
failures of the runner's reading of kiln's headers, or of the name it
runs the compiler under; kiln itself builds every one of its run tests
that a single command can build. A harness that drives kiln's tests
through hod should take its test list from the corpus, where each of
these tests is listed with its reason.

## Proposals and follow-ups

- **A directive for extra `llc` arguments** (`;@ llc-args:`), so that the
  12 `-debugger-tune=gdb` entries are built as kiln builds them. Not done
  here: it changes the directive format, which is `irdiff`'s.
- **The modules kiln gives `opt`.** 97 tests per major (optimized,
  coroutine, always-inline, LTO) hand `llc` bitcode after an `opt` run.
  hod replaces `llc`, so what it must read there is bitcode or the output
  of `opt`; capturing those needs either `llvm-dis` in the capture or a
  decision that hod is not on that path.
- **Multi-file tests** (119 kiln tests, 59 torture tests of `builtins/`):
  an entry is one module. They need a multi-module test form in `irdiff`.
- **`%{test_dir}` as an absolute path** would capture the one
  `compile-fails` test, at the price of a machine's path in its module.
- **A `-g` capture**: the same suites built with debug information, as a
  second set of groups, for the debug-information work.
- **Four torture tests fail admission** for reasons that are the
  harness's, not the module's: `fprintf-2.c`, `printf-2.c` and
  `user-printf.c` use `tmpnam`, about which GNU ld warns, and `irdiff`
  links with `--fatal-warnings`; `return-addr.c` prints an address.
- **Other targets and `wild`**: the corpus is captured for the host; a
  cross capture needs a cross `clang`/kiln sysroot and gives entries
  `irdiff` cannot run. `wild` joins admission when it is installed.
