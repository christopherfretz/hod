# WP-051 — x86-64 scalar SSE, bit tests, absolute fields and the TLS sequences

Landed: `spec/mc-x64.md` sections "Scalar floating point", "Bit tests",
"Thread-local storage", and the additions to "Shape of the API" (the
`_xr`/`_rx` suffixes), "Registers and operand kinds" (`Xmm`, `FpSize`,
`FpCmp`), "Memory operands" (`with_abs32`), "Instruction layout",
"Atomics" (`cmpxchg8b_m`, the lockable bit tests), "Fixups and
relocations" (`Fixup::Abs32`, the TLS and `32S` rows), "Not provided" and
"Test method".

## What it did

- `src/reg.rs`: `Xmm`, `FpSize`, `FpCmp`; `Mem::with_abs32` and
  `Mem::is_abs32`.
- `src/fixup.rs`, `src/inst.rs`: `Fixup::Abs32` and `is_pc_relative`; an
  absolute field forces `disp32` and is the instruction's site, with
  addend 0.
- `src/sse.rs` (new): 47 constructors (6 with a checked twin): scalar
  moves, the 128-bit moves a spill needs, `movd`/`movq`, arithmetic,
  the packed logical forms, `ucomis`/`comis`/`cmps`, and the conversions.
- `src/bt.rs` (new): `bt`, `bts`, `btr`, `btc` in four forms each (16,
  all checked); the memory forms of the last three are lockable.
- `src/atomic.rs`: `cmpxchg8b_m`. `src/tls.rs` (new): `tls_gd_lea`,
  `tls_gd_call`.
- The crate has 230 instruction constructors, 74 with a checked twin
  (164 and 52 before).
- `tests/l1`: five new groups (`absolute-fields`, `bit-tests`,
  `scalar-floating-point`, `xmm-memory-operands`,
  `thread-local-storage`), 18 more relocation sites, the `link` module.

## Evidence

- 266,516 encodings in fourteen groups equal `llvm-mc`'s bytes and
  disassemble as the table says, at LLVM 22 and 19 (106,260 of them new).
  Of the 55 new rejections, the 36 that have text are all errors to
  `llvm-mc` (226 of all 472), at both majors.
- 86 relocation sites (18 new: SSE and bit tests through RIP, `TLSGD`,
  the `PLT32` of the call, `TLSLD`, `GOTPC32_TLSDESC`, `DTPOFF32`,
  `TPOFF32`, `32S`) agree with LLVM's relocations in offset, type and
  addend.
- The four TLS models assembled from hod's bytes and sites are equal in
  code and relocations to the compiler's text at both majors, and link
  with GNU ld 2.44 (`x86_64-linux-gnu-ld.bfd`), lld 22 and mold 2.37 into
  33 static executables, PIEs and shared objects identical to the ones
  linked from LLVM's objects; the executables have the dynamic models
  relaxed. Without its prefixes the general-dynamic pair is refused by
  GNU ld and miscompiled by lld and mold (a load without `fs`), which the
  control test shows. No program runs: the host is AArch64 and the brief
  forbids emulating.
- Mutations, each caught and then reverted: the scalar store's opcode
  `0F 11` changed to `0F 10` (168 disagreements in
  `scalar_floating_point_matches_llvm`); an absolute field not forced to
  `disp32` (`absolute_fields_match_llvm`: the site is missing); one `66`
  dropped from `tls_gd_call` (both `link` tests).

## Decisions, and why

- **The precision is an operand (`FpSize`), as the size is.** ADDSS and
  ADDSD differ only in their prefix, as `add` at 32 and 64 bits differs in
  REX.W; a code generator lowering `fadd` passes the type through, as it
  does on AArch64 (`hod_mc_a64::FpSize`). The constructor's name is the
  SDM name without the precision letter (`adds`, `xorp`, `cvtts2si`).
- **`xmm` registers are their own type.** A general register where an
  `xmm` is meant does not type-check; the layout routine sees only the
  number.
- **An absolute field is a property of the memory operand**, not new
  constructors: every instruction with a memory operand can carry a
  `TPOFF32`/`DTPOFF32`/`32S` field, and `Mem::rip` refuses it, so an
  instruction never has two sites. `with_abs32` returns `Option` for that
  one refusal rather than silently ignoring it.
- **Only the general-dynamic pair has constructors.** It is the only
  sequence that needs bytes no other constructor writes; the other models
  are ordinary instructions whose exact forms the spec names.
- **Linking through `.reloc`, not `hod_obj`.** The crate has no
  dependency on the object writer (and the brief adds none); `llvm-mc`
  with `.byte` and `.reloc` places hod's bytes and hod's sites exactly,
  and the comparison is with the same sequence assembled from text.

## Gaps

- In "Not provided": `min`/`max`/`round` and the rounding conversions,
  packed SSE, AVX; immediate absolute fields (`R_X86_64_32`); the
  `-fno-plt` general-dynamic call and the descriptor call
  (`TLSDESC_CALL` marks an instruction, not a field).
- `hod_x64` does not use the crate yet.
