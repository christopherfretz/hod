## Threads

The default is one thread. `HOD_THREADS=<n>` grants `n`; under a make
jobserver (fifo form) hod takes idle tokens for a large module, never
waiting, up to 16 threads. A module gets one thread per
`PARALLEL_MIN_INSTS` = 4096 instructions.

Break-even (`crates/hod/tests/back.rs` `break_even`, release build, the
code generation phase alone, best of 15, µs, host load about 15 on 24
cores):

| instructions | 1 thread | 2 | 4 | 8 |
|---:|---:|---:|---:|---:|
| 480 | 43 | 61 | 129 | 249 |
| 3,840 | 340 | 262 | 295 | 476 |
| 7,680 | 687 | 447 | 372 | 573 |
| 15,360 | 1,336 | 772 | 560 | 715 |
| 30,720 | 2,750 | 1,504 | 906 | 877 |
| 61,440 | 5,303 | 2,851 | 1,573 | 1,223 |
| 245,760 | 22,625 | 11,879 | 6,367 | 3,834 |

About 90 ns per instruction on one thread; a thread costs 20-60 µs to
start and join. Two beat one from 2-4k instructions, four beat two near
7.7k, eight beat four near 30k: 4096 per thread follows the curve.

## Evidence

- **Census** (`cargo xtask corpus reasons --llc -j 4`, corpus of 6,251
  entries, 6,655 modules; `docs/status/reasons.md`): before, no module
  compiled (`generate` declined everything); now 176 of 3,347 (LLVM 22)
  and 169 of 3,308 (LLVM 19) compile in strict mode. First refusals left:
  `inst:call` 1,954 / 1,938, `intrinsic:llvm.memset` 381 / 373,
  `intrinsic:llvm.memcpy` 232 / 233, `function:personality` 97 / 93,
  `inst:store/double` 86 / 86, `function:variadic` 64 / 64. No module
  gave `internal-error`. The routes (text, native bitcode, `llvm-dis`)
  agree on every module.
- **Time and memory against `llc -O0`** (`-O0 -relocation-model=pic
  -filetype=obj`, LLVM 22, best of 5, peak RSS from `/usr/bin/time`):
  - the 71 single-module LLVM 22 corpus entries hod compiles (small, 2-6
    KiB): hod 6.9 ms median against `llc` 14.2 ms (0.46x; 0.25x to
    0.90x), 2.9 MiB against 61 MiB (0.05x), objects 0.92x `llc`'s size;
    sum 495 ms against 1,033 ms. Process start dominates both.
  - a 7.1 MB module of 4,096 functions, 245k instructions (the
    `back.rs` generator): hod 0.16 s, 26 MiB on one thread; 0.13 s,
    29 MiB on four; `llc` 0.99-1.32 s, 126 MiB. Object 2.4 MB against
    1.7 MB. Phases on one thread (ms): read 18.6, parse 8.4, classify
    0.0, bodies 78.0 (reading the bodies as text, classify, verify),
    emission 27.3, object 2.2, compile 1.6, write 23.5. On four threads
    emission is 8.2: the text reader is now the largest phase.
- **kiln end to end** (`crates/hod_cli/tests/kiln_e2e.rs`, LLVM 22 and
  19): integer C++ (`extern "C"` functions with loops, a switch, globals,
  a constant table, pointers, a struct) through `kiln++` and the shim in
  strict mode, at `-O0` (text) and `-O1` (bitcode): outcome `hod`;
  `llvm-readelf`, `llvm-objdump -d -r` and `llvm-dwarfdump --eh-frame`
  read the object cleanly; linked with a C driver under `ld.bfd`, `lld`
  and `mold` it prints what the same source built by kiln with LLVM
  prints. kiln's default flags (`-relocation-model=pic`) are accepted;
  what is refused is code: FP stores and loads at `-O0`
  (`inst:store/double`), `llvm.fmuladd` at `-O1` without
  `-ffp-contract=off`, vectors at `-O2`, and any call.
- **Benchmark** (`cargo xtask bench --runs 5`, `docs/status/perf.md`):
  no input builds yet: 19 decline in their bodies (calls, FP stores,
  `module:asm`), now after reading every body, so a decline costs more
  than before (`small-c` 21 ms, was 7.6 at `module:pic`); `hod+fallback`
  1.10x `llc` over the sum. `huge-function` is an ERROR: the text reader
  rejects valid IR (`malformed input: line 55568:12: use of undefined
  value '%42022'`, a `br label %42022` to a numbered block defined above
  it; LLVM accepts it). The module was refused at the module pass before,
  so its bodies were never read.
- **tests/ir**: the 32 existing programs still decline (24 at
  `inst:call`; the rest at `insertvalue`, atomics, `i128`, `memcpy`,
  overflow intrinsics, `select` of `double`, TLS, varargs); the three new
  `exit_*` programs pass under bfd, lld and mold on LLVM 22 and 19.

## Decisions where the spec was silent

- **Internal errors** fall back in hybrid mode (a build should not break
  on a hod bug) but exit 1, never 2, in strict mode, and log
  `internal-error`: a harness counts them as failures.
- **The first refusal in module order** is the answer whatever thread met
  it: workers skip functions after the earliest known failure, and the
  minimum index wins.
- **`-mattr`** is judged before any body, as a module refusal; a
  function's attribute in that function.
- **Relocation model unset** is `static` (`llc`'s default on Linux
  AArch64); `ropi`/`rwpi` and `-split-dwarf-output` are refused by name.
- **The optimization level** is ignored: the same code at every `-O`.
- **Jobserver**: only the fifo form; the descriptor forms are ignored
  (hod runs on its implicit token). The fifo is opened at first use, so
  a small module never touches it.
