# WP-342 — a `byval` parameter of a coroutine with debug info (`hod_dwarf`, `hod_cg`)

Spec: `spec/dwarf.md` §6.16 (the R3 table's by-address row, the
paragraph "A parameter passed by address", the refusal) and the refusal
table. Base `f20f08b6`. No new abbreviation family.

## Where it comes from

clang passes a large aggregate parameter by address: `byval` on x86-64
and i386, a pointer to the caller's copy on AArch64 (stored to a slot
and declared with `DIExpression(DW_OP_deref)`). In a coroutine it
declares the parameter at that place and again at the coroutine's copy,
a heap slot `memcpy`'d after `coro.begin`; kiln declares the copy as an
artificial variable of the same name and scope. Before this package
x86-64 and i386 refused the module (`debug:variable-twice`), and
AArch64 merged the two records as a `coro.begin` copy under the
argument's `DW_OP_deref`: in a resumed activation that read the heap
copy's first word as an address (gdb could not read the parameter).
Program: `tests/debug/coro_byval.cpp` (`walk(big p)`, 32-byte `big`).

## The oracle's debug information (measured)

clang 22 `-O0 -g`, CoroSplit run by clang, `llc` 22 `-O0`
(`-global-isel=0 -fast-isel=0`): the ramp's `p` is
`DW_OP_fbreg s, DW_OP_deref` (the spilled incoming address: x86-64
`fbreg -8`, AArch64 `fbreg -16`), the resume, destroy and cleanup
clones' `p` is `DW_OP_fbreg word, DW_OP_deref, DW_OP_plus_uconst 0x18`
(the heap copy at frame offset 24). One DIE per clone, no location list.

## What landed

- `crates/hod_dwarf/src/coro.rs`: `CoroAt::Passed { stack, deref, mode,
  heap }`, written `fbreg mode, deref, bra R, fbreg s, deref, skip E, R:
  fbreg word, deref, plus_uconst o, E:`: the caller's copy while the mode
  word is 0 (the ramp), the heap copy in an activation a stub entered.
- `crates/hod_cg/src/coro_debug.rs`: a pass in `coro_vars` pairs a
  parameter passed by address (`Indirect` on a machine-stack home with
  an empty expression, or a machine-stack `Slot` under
  `DW_OP_deref`) with its heap-slot copy: the same variable (clang, one
  DIE, the second record dropped) or an artificial variable of its name
  and scope (kiln, both DIEs get the location), the expression empty.
- hod head on the program's pre-split module: x86-64
  `fbreg -272, deref, bra +7, fbreg -216, deref, skip +6, fbreg -264,
  deref, plus_uconst 0x18`; AArch64 `fbreg +24, deref, bra +6, fbreg +48,
  deref, skip +5, fbreg +32, deref, plus_uconst 0x18` (base:
  `... plus_uconst 0x18, DW_OP_deref`, the wrong location).

## What stays refused

`debug:coro-passed-expression` (new): the ramp record has an expression
other than the address's own `DW_OP_deref`, or the frame copy's record
has any expression (a fragment). The two places would need different
expressions and the DIE has one. No front end writes it.

## The mode word (a reviewer's question)

The mode word is a machine-stack slot the prologue sets to 0 (x86-64,
i386 `mov [rbp - mode], 0`; AArch64 `str xzr`, in `coro_body::enter`
right after the frame is built) and each stub sets to 1; it is written
before the body's first `is_stmt` row, so no stop after the prologue
sees it uninitialised. The debug lane's first stop (`break walk`, `run`,
`print p` in the ramp, before `coro.begin`) prints `p` as the oracle's
session does (the caller's copy, `{1, 2, 3, 4}`), for clang 19, clang 22
and kiln on both 64-bit targets: the expression took the caller's-copy
branch there; a mode word read as nonzero would have gone through the
frame word, still 0, and failed to read.
