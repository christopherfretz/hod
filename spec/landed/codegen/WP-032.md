# WP-032 — `hod_cg::emit_module`, `sym_access`

Landed: `spec/codegen.md` §7.4 (now with the signatures) and §9.7 (the
rules and the known differences from `llc`), `crates/hod_cg/src/access.rs`,
`crates/hod_cg/src/emit/`, the `Options` fields `llc`'s object options
need, and the support-matrix rows of what is implemented and tested
(AArch64; x86-64 stays `todo` until it has a target).

## What it did

- `src/options.rs`: `Options` gains `reloc_model: RelocModel` (`Static`
  by default, as `llc`; `Pic`; `DynamicNoPic`), `code_model:
  Option<CodeModel>` (`Options::code_model(module)` resolves it),
  `function_sections`, `data_sections`. **Interface change**: a struct
  literal of `Options` now needs `..Options::default()`.
- `src/access.rs`: `sym_access`, `call_access`, `prefers_local_alias`
  (§7.4), pure functions of the module, the options and the symbol.
- `src/emit/`: `section.rs` (the `TargetLoweringObjectFileELF` rules and
  `MCContext`'s section key), `data.rs` (BSS suitability, C strings,
  relocation info of an initializer), `mod.rs` (`ModuleEmitter`,
  `emit_module`, `Emitted`, `PlacedFunc`, the construct names it
  rejects in `emit::unsupported`).

## Tests

- `tests/sym_access.rs`: 2880 answers (AArch64 and x86-64 × static, PIC,
  PIC with `PIE Level` × LLVM 19 and 22) against `llc`'s relocations; the
  section-symbol rule and call relocations on the same objects. A
  deliberate mutation of the rule gives 768 differences.
- `tests/emit_llc.rs`: 17 snippets (scalars, strings, pointers, static
  pointers, TLS, explicit sections, COMDATs, `llvm.used`,
  `-data-sections`, aliases and IFUNCs, functions, `-function-sections`,
  structors, linker options, anonymous symbols, relative references,
  code relocations) compared, normalized, with `llc`'s object on LLVM 19
  and 22: all agree. Functions carry `llc`'s own code (`tests/borrow/`),
  so placement and relocation of code are checked before a target exists.
- `tests/emit_link.rs`: a data module of every kind (30 probes: sections,
  pointers with offsets, differences, TLS, COMDAT, common, weak,
  `extern_weak`, aliases, an IFUNC, prioritized constructors) linked with
  an `llc`-compiled `main` by GNU ld, lld and mold, and run: `hod`'s
  object prints what `llc`'s prints, on LLVM 19 and 22.
- `tests/emit_merge.rs`: generated programs compiled by the test target
  into 1, 2, 3 and n chunks and on two threads, static and PIC, with
  synthetic landing-pad rows: byte-identical objects and rows; each
  function's code, symbol, relocations and rows carried exactly.
- `tests/emit_corpus.rs` (`HOD_CG_CORPUS`): every corpus module with its
  bodies stripped, against `llc`; counts below.
- `tests/emit_bench.rs` (`#[ignore]`, `HOD_CG_BENCH`): time and peak
  memory against `llc`.

## Results

Corpus (`.build/corpus`, bodies stripped, `-relocation-model=pic`):

| LLVM | modules | agree | differ | refused | skipped |
|---|---|---|---|---|---|
| 19 | 2864 | 2833 | 1 | 15 | 15 |
| 22 | 2896 | 2866 | 1 | 16 | 13 |

- differ (1 per major, `expr.prim.lambda/run-local-class.cpp`): variable
  order in `.data.rel.ro` (`SymId` order against file order; documented
  in §9.7, follow-up below).
- refused: `module:asm` by `hod_cg` (4 per major); the rest by `hod_ll`
  before emission (`attr:convergent`, `debug-info`,
  `special-global:llvm.global.annotations`, `attr:fmv-features`).
- skipped: the stripped module cannot be printed (`blockaddress` of a
  function whose body was stripped).
- Fixed on the way: unreferenced hidden, protected and `extern_weak`
  declarations are kept as `llc` keeps them; module asm refused.

Time and memory (`tests/emit_bench.rs`, release, fastest of 5; `hod`
emit plus ELF write in process, `llc` whole process; peak RSS):

| module | hod emit+write | hod parse | llc | hod peak | llc peak | object hod / llc |
|---|---|---|---|---|---|---|
| memclr.c (2048 variables, 802 KiB) | 0.33 ms | 2.8 ms | 40 ms | 4.2 MiB | 60 MiB | 282936 / 282912 |
| memcpy-a8.c | 0.33 ms | 2.8 ms | 49 ms | 4.0 MiB | 60 MiB | 283056 / 283032 |
| pr84478.c | 0.04 ms | 0.11 ms | 22 ms | 2.5 MiB | 58 MiB | 56392 / 56416 |
| strlen-5.c | 0.03 ms | 0.16 ms | 33 ms | 2.5 MiB | 58 MiB | 4288 / 4360 |
| virtual-base-run.cpp | 0.05 ms | 0.13 ms | 27 ms | 2.7 MiB | 58 MiB | 17480 / 18160 |

Emission adds at most about 0.6 MiB to the peak over the parse alone.
The test harness process is a few MiB of the `hod` peak.

## Follow-ups

- `hod_ll`: number every defined global in file order before reading
  initializers, so `SymId` order is `llc`'s layout order (the one corpus
  difference).
- x86-64: the matrix rows stay `todo(X64)`; `ArchInfo` has the x86
  relocations and `0x90` padding, but there is no x86 target and no x86
  oracle run of `emit_module` yet.
- TLS rows (`tls:*`) stay with their owner: emission places TLS
  variables, but the code access sequences are the targets'.
