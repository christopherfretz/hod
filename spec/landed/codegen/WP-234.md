# WP-234: `getelementptr` on vectors of pointers

Spec: `spec/codegen.md` §5.5 "Memory (WP-036)" (AArch64) and §5.6.4
"Memory (WP-123)" (x86-64), "Vector `getelementptr`"; `hod_ir`'s
`ConstPool::fold_gep`.

kiln `-O2` modules of libc++ tests (the `flat_multimap` tests) hold a
`getelementptr` whose base is `<2 x ptr> zeroinitializer` and whose
index is a constant `<2 x i64>`; strict hod refused them as
`x64:ptradd-vector` / `a64:ptradd-vector`. `llc` builds them.

## What was built

- `crates/hod_x64/src/mem.rs` `ptr_add_vector` and
  `crates/hod_a64/src/mem.rs` `ptr_add_vector`: a `ptradd` whose result
  is `<N x ptr>` is lowered one lane at a time, with scalar arithmetic.
  Every vector operand's image is found first (a `Mem` vector's slot,
  or an `Fpr` vector's register stored into a fresh 16-byte frame slot
  and given back at once); a scalar operand is splatted (put again for
  each lane); a scalar constant index, and a zero-like vector one, is
  folded into the constant offset. For each lane: the base's lane plus
  the offset, then each index's lane sign-extended from its width (the
  low 64 bits of an `i128` lane or scalar: truncation) and scaled as a
  scalar `ptradd`'s index and added; the sum stored as the result's
  lane. x86-64 computes in `rcx`/`rdx`, which hold no values; AArch64
  takes two pool temporaries per lane and gives them back after it, so
  nothing is pinned across lanes under `Stress::ALL`. The result's image
  is its slot (`Mem`), or a frame slot loaded into its register at the
  end (`Fpr`). `N` is any lane count whose lanes are addressable (1 to
  256); `inbounds`, `nuw` and `nusw` change nothing.
- `crates/hod_ir/src/fold.rs` `fold_gep_lanes`: a constant
  `getelementptr` with a fixed vector operand folds lane by lane into a
  vector of the lanes' addresses (`Addr`, `AddrOfInt`, `null`), in an
  initializer or as an operand; before, it stayed an `Expr` and both
  targets refused it as `const-expr:getelementptr`.
- `crates/hod_a64/src/vector.rs` `spill_at`: an `Fpr` vector stored at
  a given frame place (what `spill` does into a scratch image).
- The names `x64:ptradd-vector` and `a64:ptradd-vector` are gone from
  the code (nothing is refused under them).

## What stays refused

- An index vector whose lanes are not 8, 16, 32, 64 or 128 bits
  (`<N x i33>`): `x64:vector-odd-element`, `a64:vector-odd-element`.
- `<N x i1>` indices: `x64:vector-mask` / `a64:vector-mask` (`mask-wide`
  beyond 64).
- More than 256 lanes: `x64:vector-length`, `a64:vector-length`.
- Scalable vectors stay `hod_ir`'s `getelementptr:scalable`.
- A constant vector `getelementptr` some lane of which does not fold
  (an unknown lane, a base that is not a symbol plus an offset) stays
  `const-expr:getelementptr`.

## Notes

- `hod_interp` still refuses a vector `getelementptr` as
  `inst:ptradd-vector` (the interpreter is not part of this package).
