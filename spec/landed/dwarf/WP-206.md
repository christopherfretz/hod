# WP-206 — member function declarations of every flag

Spec: `spec/dwarf.md` §6.27. Abbreviation family taken: 114
(`fam::METHOD_ANY`, 2048 codes from 12550; `CODE_END` 14598).

## What was built

- `hod_dwarf` `types.rs`: `MethodAttrs` carries the calling convention
  apart from the shapes no family holds; `method_family` tries the
  families of WP-058 and WP-189 first (unchanged, `fixed_method_family`)
  for a declaration without a calling convention, then family 114:
  `linkage_name`, `name`, decl, `calling_convention`, `type`,
  `virtuality` + `vtable_elem_location` + `containing_type`,
  `declaration`, `artificial`, `external`, `noreturn`, accessibility,
  `explicit`, as `llc`'s `applySubprogramAttributes` orders them. The
  writer puts the convention's byte after decl.
- The refusal's detail now says which of the remaining reasons holds
  (`method_refusal`).
- `dwarf4.rs`: family 114 is checked against `llc`'s version 4 output
  (`checked_later`).

## Evidence

- The saved module (the logging library's `logging_unittest.cc`, kiln,
  AArch64) compiles under `--strict`; so do its two older copies under
  `stale-run5`. Nothing else stops it.
- Grid (`.build/target-wp-206/grid/grid.py`, not committed): 170 C++
  translation units × clang 19, clang 22, kiln++ × AArch64, x86-64.
  1030 modules built, every DIE tree equal to `llc` 22's and, for clang
  19's modules, `llc` 19's (offsets, indices, places of locals and the
  object pointer's offset masked, §6.7), every object `--verify` clean.
  165 distinct declaration shapes (55 without the convention's value),
  126 (16) of them refused before; all 165 built, none still refused.
  360 of those modules are clang's `preserve_most` nodes with the
  `cc:` replaced by each other convention (AAPCS, AAPCS_VFP,
  PreserveAll, PreserveNone, Swift, SwiftTail, Win64, X86RegCall,
  X86_64SysV, vectorcall): the conventions whose code hod refuses
  (`cc:*`, 182 modules, code generation) are checked that way.
  96 modules have no member declaration (a class only declared), 18 are
  refused by the front end (all kiln's `swiftcall`; clang ignores, with
  a warning, a convention the target does not take, and writes none).
- `crates/hod/tests/debug_member_decls_wp206.rs`: one class with each
  shape of family 114 (both targets, DWARF 5 and 4, against `llc` 19 and
  22), kiln's noreturn lambda with its code, and the five refusals.
- Debuggers: `tests/debug/lambda_invoker.cpp` (kiln, clang 22, clang 19;
  bfd, lld, mold; gdb and lldb 19): `ptype Gate` / `type lookup Gate`
  list the explicit conversion operator and the static member, a
  breakpoint in the lambda called through the pointer shows `__invoke
  (code=7)` in the backtrace and `code`; gdb's `ptype stop` prints the
  closure class. AArch64: 18 of 18 PASS (36 sessions); x86-64 under
  qemu (`--target x86_64`): 18 of 18 PASS (36 sessions); every
  transcript equal to `llc`'s.
- `cargo xtask debug trees` on the saved module: its first difference
  from `llc` 22 is a parameter's place in a libstdc++ `chrono` operator
  (`DW_OP_breg31` against hod's `DW_OP_fbreg`, the frame-place class of
  §6.25), not a declaration.
- Base against head (`-g`, `--strict`): the 14 corpus modules with
  debug information (12 identical objects, 2 refused the same by both)
  and the 51 saved real-project modules with debug information (48
  identical, the 3 glog modules compile only at head).

## Findings outside this package

- kiln writes no `cc:` on a `DISubroutineType` (a member or lambda under
  `__attribute__((preserve_most))` and the like): `llc` and hod then
  write no `DW_AT_calling_convention`.
- kiln drops `noreturn` from a lambda's static invoker when the
  attribute is written `[] [[noreturn]] ()` (it keeps it for
  `__attribute__((noreturn))`).
- `hod_ir` does not read `DW_CC_LLVM_DeviceKernel` (LLVM 22's name;
  `crates/hod_ir/src/debug/names.rs:519` lists the conventions); no
  CPU target writes it.

## Still refused

`debug:die-unsupported`: a ref-qualifier or `deleted` together with a
calling convention, `artificial` with `noreturn`, or `explicit` with
`noreturn`; a nameless declaration needing family 114; a virtual member
without a vtable index or whose containing type has no DIE; a calling
convention above 255; a C prototype or Fortran's flags. No front end
wrote any of them in the grid.
