# WP-235 — moving kiln's pin from `21b9110a4` to `8f93304ee`

Landed: kiln 1.2.0 at `8f93304ee` (27 commits after the pin) built
beside the pinned one, both corpora's kiln groups captured again with
it, every new or changed entry compared with `llc`, the in-repository
files the switch needs regenerated, and what the move is for measured.
With `8f93304ee` kiln writes one body per function for an explicit
instantiation (WP-1425), so the LLVM 19.1.7 `-g` modules hod declined
as `debug:invalid` are built; its `-g` module of a class-type template
value parameter is valid (WP-1424); it accepts `-mno-outline`,
`-ftls-model=`, `-ggnu-pubnames`, parenthesized declarator-ids, the
null constant for `_Atomic(T*)`, and C's separate tag and typedef name
spaces. Procedure: `docs/VALIDATION.md` "Moving kiln's pin". Measured
with a release hod of this branch (main at `c51896b2`, wave 22).

## What the move is for

Each through kiln's driver with `KILN_BACKEND=hod`, `KILN_HOD=` this
branch's release hod and `KILN_HOD_STRICT=1`; `backend` is read from
`KILN_STATS_LOG`.

- **Sources saved from the third open-source round** (11 files, the
  commands of their notes; native AArch64): 9 compile, each object
  built by hod (10 commands, `backend` `hod`):
  `-mno-outline` (kiln), `-ggnu-pubnames` (kiln++), `-ftls-model=initial-exec`
  (a `-fPIC` unit's `thread_local(initialexec)` gets the two
  `R_AARCH64_TLSIE_*` relocations), `_Atomic(T*)` initialized and
  assigned from `NULL` (WP-1422), an explicit instantiation of a class
  with a constrained member (WP-1425), `friend S (::g)(int)` and a
  friend literal operator in parentheses (WP-1423), a typedef name equal
  to a struct tag and `T(*)[N]` to `const T(*)[N]` in C, silent
  (WP-1427). 2 still fail in kiln, as expected:
  `offsetof-variable-index.c` ("a non-constant array index in
  '__builtin_offsetof' is not supported yet", kiln WP-1433) and
  `neon-lane-builtins.c` ("code generation for
  `__builtin_neon_vqrdmulhq_lane_v` is not supported yet").
- **The LLVM 19.1.7 `-g` modules hod declined as `debug:invalid`**
  (two `DISubprogram`s for one function): `MachineRegionInfo.cpp`
  rebuilt with its saved command and the new kiln++ for x86-64, and
  `MachineDominators.cpp` with the same flags, each also for AArch64:
  4 objects, `backend` `hod`, `llvm-dwarfdump --verify` clean. The
  reductions `two-subprograms.cc` and `two-subprograms-adt.cc`: `backend`
  `hod`.
- **A member function declared through a function typedef** (kiln's
  PR 703): `typedef int fn_t(int); struct S { fn_t f; static fn_t g; };`
  with `-g`: each `DISubprogram` has a `DISubroutineType`; hod builds
  it, `llvm-dwarfdump --verify` clean (as `llc`'s object), and the
  program runs. The codegen speedup for thousands of stores to one
  global was not seen in a 20000-store function (0.1 s with both kilns,
  C and C++ with `-g`): the shape that was slow is not reproduced here.
- **`-g` and a class-type template value parameter** (WP-1424): the
  7-line reduction of libc++'s `func.not_fn/not_fn.nttp.pass.cpp`
  (`.build/findings/libcxx-debug/kiln-undef-type/repro.cpp`) now gives a
  module that defines the struct type its `DITemplateValueParameter`
  names: `llc` 22 and hod build it, `llvm-dwarfdump --verify` clean.
  libc++'s own source is not in the workspace, so the test itself was
  not rebuilt.
- **WP-1417**: `__attribute__((target("sve")))` gives `+sve` in the
  function's `"target-features"`, built by hod and run;
  `#pragma clang attribute push (noinline)` reaches a friend function
  defined inside it; `-fmerge-all-constants` is accepted and built by hod.
- **The pack capture of `libcxx-debug/x64/trees-differs`** is
  unchanged: kiln still writes the two members of a pack capture under
  one name (`pack-capture.cpp`: two `a`); LLVM's reader merges them, hod
  writes both, as that note says.
- Still open on kiln's side, unchanged: `offsetof` with a run-time
  index (WP-1433, above); the typedef shape of a free function named by
  a using-declaration (WP-1434) was not re-measured.

## Switching (the supervisor; no gate in flight)

`<B>` = `.build`, `<P>` = `<B>/target-wp-235`, `<W>` the workspace root.

1. `8f93304ee` is the workspace kiln's `origin/main` (already fetched):
   `git -C <W>/kiln checkout 8f93304eec6189cb5229c27aab643ecd2a37e6d5`;
   `git -C <W> add kiln && git -C <W> commit -m "kiln: 8f93304ee"`.
   Verify: `git -C <W>/kiln log --oneline -1` shows `8f93304ee BACKLOG:
   WP-1427 done (#704); row WP-1435`.
2. In `<W>/kiln`: `source <W>/scripts/env.sh &&
   CARGO_TARGET_DIR=<B>/target-kiln cargo build --release -j 6`
   (about 2 minutes here). `kiln++ --version` says 1.2.0.
3. `mv <B>/corpus <B>/corpus.old && mv <P>/new/corpus <B>/corpus`;
   `mv <B>/corpus-x64 <B>/corpus-x64.old && mv <P>/new/corpus-x64
   <B>/corpus-x64`; `rm -rf <B>/corpus.work <B>/corpus-x64.work`.
   Verify: `cargo xtask corpus verify --manifest-only` and `cargo
   xtask corpus verify --target x86_64 --manifest-only` pass; the kiln
   rows' revision is `8f93304eec6189cb5229c27aab643ecd2a37e6d5` alone
   (3048 rows in `corpus`, 3015 in `corpus-x64`); `sha256sum` of
   `<B>/corpus/MANIFEST.tsv` starts `23e5179f`, of
   `<B>/corpus-x64/MANIFEST.tsv` `28f94864`.
4. Merge `wp/235-kiln-pin`.
5. Run the gate. Its `roundtrip` step must report the file as for this
   corpus and 6468 as expected. When it is green: `rm -rf
   <B>/corpus.old <B>/corpus-x64.old <P>`.

Status pages that record a measurement (`docs/status/debug.md`,
`libcxx-*.md`, `corpus-x64.md`, `perf.md`) name the kiln they were
measured with and stay until measured again.
