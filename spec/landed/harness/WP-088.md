# WP-088 — libc++ through hod, second measurement

Landed: `docs/status/libcxx-hod.md` (both measurements side by side). WP-077,
the first measurement, has no record of its own. Its results are the
"first" columns of that page.

Measured: `main` at `c4ecc07` (after WP-072, 074, 075, 079, 080, 086, 068),
release `hod`, the shim reading bitcode natively. kiln 1.0.1 at
`bd60e1829`. Raw results are in `.build/libcxx-hod-2/`.

## Results

| | first (WP-077) | current |
|---|---:|---:|
| hybrid pass (baseline 8609) | 8609 | 8608 (the one change is a load timeout, below) |
| strict pass | 6853 | 8446 |
| modules built by hod (of 7226) | 5438 (75.3%) | 7063 (97.7%) |
| hod-only tests | 5430 | 7023 |
| hybrid back end (coverage log) | 588 s | 216 s |
| sample, `llc` / hod | 3.5x over 198 | 4.2x over 360 (old 198: 3.4x) |

- Hybrid differences caused by hod: 0. `atomics.types.operations.wait/lost_wakeup.pass.cpp`
  went from PASS to TIMEOUT (20 s limit). It also times out with plain
  kiln + `llc` at the same load (2/2). Built both ways and run without a
  limit, both binaries pass, and the hod-built one is not slower (31 s
  against 34-37 s). `tests/libcxx-repro/` was not created.
- No coverage line has outcome `error` in hybrid, and every fallback exited
  0. No module went from hod back to the fallback (1616 tests moved the
  other way). `oom_kill` was 0 before and after both runs.
- Strict: every failure that is not the baseline's own is a refused module
  (163 modules, 162 tests), apart from the `lost_wakeup` timeout.
- Remaining first refusals: `inst:extractvalue/fp128` 96,
  `inst:icmp/vector` 35, `inst:insertelement/i128` 17, `inst:sitofp/i128` 6,
  `intrinsic:llvm.umul.with.overflow/i128` 3,
  `linkage:available_externally` 3, `inst:fptosi/i128` 3.
- In the time sample, hod was slower than `llc` on 43 small modules. The
  cause is start-up from the workspace bind mount, not code generation: on
  a 1.2 kB module hod took 11-13 ms from the mount and 3.2 ms from local
  disk, against 15-18 ms for `llc`, whose binary is on local disk.

## What changed

| `scripts/libcxx-hod-report.py` | `/vector` reasons (`inst:icmp/vector`, `inst:fcmp/vector`) count in the vectors family |

## Follow-ups

- WP-084 (`fp128`, `i128`) frees about 112 of the 163 remaining tests, and
  WP-081 (vector compares) about 35.
- `std/experimental/simd` with `i128` lanes (`inst:insertelement/i128`,
  17 modules) has no package.
- The time script should run hod from a local copy, or record where each
  binary lives, so that start-up on the bind mount does not count against
  hod on small modules.
- The gate of a later `cargo xtask libcxx-hod` needs a rerun rule for
  load-sensitive timeouts (`lost_wakeup`).
