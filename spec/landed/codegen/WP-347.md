# WP-347: i386 inline assembly, a 64-bit operand with a register-or-memory constraint

## Where it comes from

The full libc++ run for i686 (WP-339) had one test refused by
`x86:inline-asm:operand-type`: an `i64` with the constraint `r|m` (C's
`"r,m"`) in a `DoNotOptimize` helper, `asm volatile("" : : "r,m"(value)
: "memory")`, the idiom of benchmark libraries.

## What llc does (measured, 19 and 22, `-O0 -global-isel=0 -fast-isel=0`)

On clang 19 and 22's `--target=i686-linux-gnu -O0` modules of the idiom
over `int`, `long long`, `unsigned long long`, `float`, `double`,
`long double`, a pointer and an 8-byte struct (an `i64`), template
`nop # %0` (both majors print the same):

- An input `r|m`: `int`, `i64` take `r` (the first alternative: every
  code weighs 0 for an integer), the `i64` in TWO registers, the next
  two free of the allocation order (`eax, ecx`; after an `i32` operand
  `ecx, edx`; with `eax` clobbered `ecx, edx`), the operand printed as
  the low one. A pointer, `float`, `double`, `x86_fp80` take `m`: the
  value is copied to a stack object and the operand is that object.
- An in-out (`+r,m`, `+m,r`) is `=*r|m` / `=*m|r` with a tied input:
  memory, the variable itself, for every type.
- `i64` with `r` only, `q`, or a constant: two registers as above.
  `rm` and `m|r`: memory (a copy). `double` with `r` only: two
  registers. `*r` of an `i64`: `llc` errors ("indirect register
  inputs"). Four `i64` in `r`: `llc` uses `ebp` too.

## What hod does

`crates/hod_x86/src/asm.rs`: `Place::Halves(low, high)` for a direct
`i64` input in a register (two registers from the order, both written,
loaded from the input's 8-byte slot; printed as the low register); a
direct memory input of class `Mem` that is an integer of at most 64
bits, `float`, `double` or `x86_fp80` is copied from its home to a slot
of its alloc size (at least 8) whose address the template gets (hod's
memory operand is `(%reg)`, as before). Everything that compiled before
is unchanged: the new arms are reached only by operands that were
refused. The rule and what stays refused: `spec/codegen-x86.md` §10.

## Evidence

`crates/hod/tests/i386_asm_wide.rs`: `tests/data/i386/asm_wide/wide.c`
(the idiom over the eight types, plus templates that use the operand:
the low half of a register input, `leal` of a memory input compared to
the value, `addl`/`notl`/`xorl` on in-outs in memory) by LLVM 19 and 22,
CPU `generic` and `i686`, static and PIE: `llc`, hod and `Stress::ALL`
runs equal (8 modules, 72 runs); the template registers of ten
functions in the objects equal `llc` 19's and 22's (`llvm-objdump`); the
refusals by name; the reduced module of the libc++ run compiles.
