Landed: rows in `scripts/oss/projects.toml` and an x86-64 section in
`docs/status/oss.md`; no compiler code.

- Eleven rows copied from kiln's `scripts/oss/projects.toml` at kiln
  `8f93304ee` (tags and configure options unchanged): `ctre`, `entt`,
  `cereal`, `taskflow`, `scnlib`, `glaze`, `daw_json_link`, `mp_units`,
  `reflect_cpp`, `libunifex`, `stdexec`. Kiln's `@OSS@` is `@KILN_OSS@`
  here (daw_json_link reads kiln's `daw-pin-header-libraries.cmake` where
  it is). mp_units leaves out kiln's `control_cxx` (g++-16): hod's control
  is kiln with llc, which builds it.
- Each project ran with `oss-run.sh <p> --target x86_64` (cross-built on
  the AArch64 host, tests under qemu-x86_64), flavours `O0` and `O0g`,
  modes control (`llc`), hybrid (`hod`) and strict, kiln 1.2.0 at
  `8f93304ee` and a frozen hod named per row: `hod-f59b4cc6` (ctre, entt),
  `hod-8ec6b21e` (cereal, taskflow), the 1.0 candidate `hod-02fe2d02`
  (the rest).

## Results

- Equal to the control test by test, every object by hod, no refusal:
  ctre, entt, cereal, taskflow (`-O0`), scnlib, mp_units, reflect_cpp.
- daw_json_link: all 159 objects by hod, but 47 of 158 links fail on an
  undefined `daw::ensure::ensure_compile_error(bool)`: hod emitted the
  call in the arm of a branch on `llvm.is.constant.i1` of a non-constant,
  which llc folds to false and removes. Fixed by WP-261.
- libunifex: 17 of 114 objects stop hod with an internal error ("a label
  that code refers to was never bound") in coroutine `connect_impl`
  functions that `invoke` `llvm.coro.await.suspend.*`. Under the
  project's `-Werror` kiln's fallback warning is an error, so the hybrid
  build loses them too.
