## 1. `callbr`

`llc` 19 and 22 build an empty-template `callbr` as the template's
barrier and the fallthrough; the indirect destinations are ordinary
blocks reached from elsewhere. hod does the same. Evidence:

- `tests/callbr.rs`: five functions (a `r,!i` input, a tied output, two
  labels in a loop, an indirect destination also reached by `indirectbr`
  through its `blockaddress`, a memory operand with an indirect
  destination equal to the fallthrough) on inputs -3..8, hod plain and
  stressed, `llc` 22 and 19, under bfd, lld and mold: the expected values.
- `irdiff --target x86_64 tests/ir/asm_goto_empty.ll`: 3 PASS (bfd, lld,
  mold), hod built 1 of 1; `irdiff_real` (both targets) green.
- The corpus: `goto-cleanups-run` and `goto-in-template-run` (LLVM 19 and
  22) compile with `hod --strict` and print what `llc`'s build prints
  under qemu (exit 0, 11 and 8 lines). `asm-goto.cpp` stays refused: its
  `_Z1gv` has a non-empty template (`call:inline-asm`).
- Mutation: branching to the first indirect destination instead of the
  fallthrough was caught by `tests/callbr.rs`, then reverted.

Refused: a template that assembles to something (`x64:inline-asm`), a
label count other than the indirect destinations'
(`x64:inline-asm-constraint`). The first landing also refused a result
taken by a destination's `phi` (`x64:callbr-result-phi`); the fourth
commit retires that name (§4 below).

## 2. `preserve_mostcc` and `preserve_allcc`

The saved sets were measured on `llc` 19 and 22 (`-O0`, every return
kind, from their `.cfi_offset` rows): the same on both. `ccc`'s
callee-saved registers and `rax`, `rcx`, `rdx`, `rsi`, `rdi`, `r8`, `r9`,
`r10` (`preserve_allcc`: also `xmm0`..`xmm15`), but the registers the
result comes back in:

| result | not kept |
|---|---|
| `i64`, `i32`, `i1` | `rax` |
| `i128` | `rax`, `rdx` |
| `{i64, i64, i64}` | `rax`, `rdx`, `rcx` |
| `float`, `double`, `<4 x float>` | `xmm0` |
| `{double, double}` | `xmm0`, `xmm1` |
| `{i64, double}` | `rax`, `xmm0` |
| `x86_fp80` | none (`st0`) |
| `void`, `sret` | none: `rax` is kept, the caller's back over the `sret` address |

`r11` is not kept. A result returned in memory (four `i64`s, four
`double`s) gives sets off this rule (`xmm0`/`xmm1` unsaved for four
`double`s), so it is refused as `x64:preserve-cc-return-memory`; a
`musttail` exit is `x64:preserve-cc-tail-call`; a coroutine body
`x64:coro-preserve-cc` (no test case: a coroutine of these conventions
was not built).

The caller's side is `ccc`'s: the callee keeps a superset of `ccc`'s
callee-saved registers, and a caller compiled for `ccc` assumes only
those.

Evidence:

- `tests/preserve_cc.rs`: 27 callees (`ccc` control, and every kind
  above, a variadic one, under each convention) called by a snapshot
  routine that loads every register, calls, and stores every register.
  The callee calls `clobber`, which first walks the stack
  (`_Unwind_Backtrace`) and checks that the callee's rows recover every
  kept general register and find every kept `xmm` register, then
  overwrites every caller-saved register. Run for the callees built by hod
  plain, hod stressed, `llc` 22 and `llc` 19, each under bfd, lld and
  mold (12 runs): every kept register is intact and found by its row,
  every result is right, and the sums of a hod-built and an `llc`-built
  caller agree. `llc`'s callees pass the same checks, which confirms
  the table.
- `irdiff --target x86_64 tests/ir/preserve_cc.ll`: 3 PASS, hod built 1
  of 1; `irdiff_real` (both targets) green.
- The one corpus module that uses the conventions,
  `dcl.attr.cconv/cc-run.cpp`, also calls `win64cc`, `x86_regcallcc` and
  `x86_vectorcallcc` and stays refused (`abi:cc`).
- Mutation: `rcx` dropped from `PRESERVED` was caught by
  `tests/preserve_cc.rs`, then reverted.

## 3. Baseline SSE intrinsics

`clang` writes these for `_mm_setcsr`/`_mm_getcsr` (and the
`_MM_SET_*` macros), `_mm_rcp_ps`/`_ss`, `_mm_rsqrt_ps`/`_ss`,
`_mm_clflush`, `_mm_maskmoveu_si128`. Each is the instruction `llc`
writes. `rcp`/`rsqrt` are approximations whose bits are the CPU's:
hod and `llc` both write the same instruction, so their results are
compared in the emulator. `ldmxcsr`/`stmxcsr` are tested by a function
that sets the rounding mode from the input with the flags cleared, runs
`cvtss2si`, `addss` and a division in that mode, stores the MXCSR they
leave, and then restores the caller's.

Evidence: `tests/x86_intrinsics.rs` now covers 106 intrinsics in 264
functions (10560 cases) on legs hod plain (bfd, lld), hod stressed,
`llc` 22 and `llc` 19, and all agree; `.text` hod 20084 bytes, `llc` 22
5276. The encoders are swept against llvm-mc (`hod_mc_x64` `tests/l1`).
Mutation: `rsqrt.ps` lowered to `rcpps` gave 105 disagreements, then
reverted. `sse3.monitor`/`mwait` stay refused by `classify` under their
names (no encoding).

## 4. A `callbr` result taken by a successor's `phi`

Found while landing §1: the driver's terminator step wrote every
successor's `phi` stores before lowering the terminator, `invoke` alone
excepted. For a `callbr` whose result a successor's `phi` takes, that
store read the result before the template defined it: a home value read
a stale slot, a register value stopped with an internal error. On
AArch64, which builds `callbr` through its assembler, this was a
miscompile: a loop carrying an `asm goto` tied output printed
`-15 551286798 -5 0 5 10 15` where `-12 -8 -4 0 4 8 12` was meant.

Both lowerings already write a successor's stores after the result:
x86-64 on the fallthrough (its indirect edges are never taken), AArch64
on the fallthrough and on each indirect destination's trampoline. The
driver now skips, for a `callbr`, each successor one of whose `phi`s
takes the result for this block, and keeps the pre-store for the others.
It does not skip the `callbr` wholesale as it skips `invoke`: a
successor listed twice (an indirect destination equal to the
fallthrough, or a label listed twice) is two code paths on AArch64, and
the per-terminator stamp of `phi_stores` writes the second path's stores
not at all; the pre-store covered that for values defined before the
template. A result-taking successor listed twice is refused as
`call:callbr-result-repeated-edge`. `x64:callbr-result-phi` is retired.

Evidence:

- `crates/hod_a64/tests/callbr_phi.rs`: a loop whose header `phi` takes
  the result (a home value), a fallthrough `phi` of a result the template
  can branch away from (`cbz` to the indirect destination), and a void
  `callbr` with a repeated edge whose `phi` takes a value defined before
  it, on inputs -3..3: hod plain and stressed, `llc` 22 and 19, under
  bfd, lld and mold (12 runs), all agree. Before the fix both hod legs
  failed (12 wrong values each, e.g. `loop_home(x, 4) = -6, not -12`).
- `crates/hod_x64/tests/callbr.rs`: `cb_phi` (the result taken by the
  fallthrough's `phi` and used besides) and `cb_only` (the `phi` is its
  only use) now run with the other five functions, 12 runs; the
  formerly ignored `callbr_result_used_only_by_a_phi` builds plain and
  stressed.
- Seed `tests/ir/asm_goto_empty.ll` gains `carry` (the loop, empty
  template): `irdiff` 3 PASS on each target (bfd, lld, mold), hod built
  1 of 1; `irdiff_real` green.
- Census (`grep`-level, over every `.ll` of both corpora): `corpus` 6454
  modules, 6 with a `callbr`, 2 with a `callbr` result, 0 where a `phi`
  takes one; `corpus-x64` 6450, 6, 2, 0. No shipped object was affected.
- Mutation: the repeated-edge refusal loosened to a successor listed
  three times was caught by `callbr_phi.rs`, then reverted.

**Bug found, outside this package** (`crates/hod_a64/src/inline_asm.rs:838`):
AArch64's `callbr` defines the result again on each indirect
destination's trampoline. For a register value (the `phi` its only
use) the fallthrough's stores have already released it, and a
destination that does not use it leaves the register held: "block ends
with a value in a register" (internal error, not a miscompile). Kept as
the `#[ignore]`d `a_result_only_a_phi_takes` in `callbr_phi.rs`.
