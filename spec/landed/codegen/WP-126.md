# WP-126 — the x86-64 `Mem`-class group (X-aggr)

Landed: `crates/hod_x64/src/aggr.rs`, `crates/hod_x64/src/constaddr.rs`;
`spec/codegen.md` §5.6.5; the support-matrix
rows below; `tests/aggr.rs` with `tests/common/aggr_gen.rs`.

## What is lowered

The AArch64 group's set (WP-040), on x86-64:

- `add`, `sub`, `mul`, `and`, `or`, `xor`, `shl`, `lshr`, `ashr`
  (constant or variable amount) on integers wider than 64 bits;
  `udiv`, `sdiv`, `urem`, `srem` up to 128 bits through `__udivti3`,
  `__divti3`, `__umodti3`, `__modti3`;
- `icmp` with every predicate; `select`, `freeze`, `phi` (the glue);
- `trunc`, `zext`, `sext`, `ptrtoint`, `ptrtoaddr`, `inttoptr`,
  `bitcast` with a wide side; `fptosi`, `fptoui`, `sitofp`, `uitofp`
  between `half`/`float`/`double`/`fp128` and 65 to 128 bits through
  `__fix[uns]*ti` / `__float[un]ti*`;
- `load`, `store` (exactly the store size), `extractvalue`,
  `insertvalue`, copies of `Mem` vectors and `x86_fp80` images;
- `llvm.{s,u}{add,sub,mul}.with.overflow` at every width up to 2048
  (`mul`) or unbounded (`add`, `sub`);
- `Mem` constants (`materialize_mem`), and every constant holding
  addresses (symbol, PLT, symbol differences, a number minus an
  address, any field width at any offset) computed in code;
- a value returned in memory (`spec/abi-x64.md` §8.2.3): `ret` writes
  it through the address WP-125's prologue saved
  (`CallState::ret_addr`); the epilogue reloads it into `rax`.

## Refused, by name

- `x64:wide-division`: division wider than 128 bits.
- `x64:wide-mul` / `x64:wide-shift`: `mul` and variable shifts wider
  than 4096 bits; `x64:wide-mul-overflow`: `{s,u}mul.with.overflow`
  wider than 2048.
- `x64:wide-fp-cast`: integers wider than 128 bits to or from floating
  point, and `bfloat` with a `Mem` integer.
- `x64:mem-cast` (`addrspacecast`), `x64:overflow-intrinsic` (a vector),
  `x64:todo:aggr` (forms the dispatch should not send).
- `x64:constant-relocation`: a block-address difference in a constant;
  a vector constant with a relocation other than an aligned 8-byte
  symbol address.
- Other groups' names: an atomic `Mem` `load`/`store` is
  `x64:todo:atomic`; a vector `icmp`, `select` condition or element-wise
  cast `x64:todo:lanes` (a mask one `x64:todo:mask` first). A block
  address in a constant is `control::block_address` (WP-124).

## Evidence

Each function is compiled once into an object of thousands of
functions; the same wrapper (`@fN(ptr %out, ptr %in…)`) is compiled by
hod (plain and `Stress::ALL`), `llc` 22 and `llc` 19 (`-O0
-fast-isel=0 -relocation-model=pic`), linked `-pie` with one C driver
and run once under qemu per object. Two mixed legs link hod's wrappers
calling `llc` 22's direct-call twins, and the reverse, so every call of a
direct-call function crosses between the compilers. Every integer function is also called
directly (`@fN_v`, after 0 to 5 leading `i64` arguments) with random bits
above the widths. The expected image is `hod_interp`'s, else
`llc` 22's. `llc` 19 is compared on direct calls only when every piece
is in a register: LLVM 19 keeps a wide integer that does not fit whole on
the stack (`spec/abi-x64.md` §4.2).

| suite | functions | cases | direct | hod/llc22 text |
|---|---|---|---|---|
| binary (13 ops × widths 65..256, constant shift amounts) | 730 | 8,540 | 7,040 | 3.96 |
| consumers of unextended results | 600 | 7,200 | 5,664 | 3.23 |
| compares, `select`, `freeze`, `phi` | 300 | 4,530 | 4,224 | 3.16 |
| casts (ptr, vector bitcasts, fp↔int) | 245 | 3,660 | 2,404 | 1.95 |
| aggregates | 251 | 1,426 | 0 | 1.87 |
| overflow intrinsics (widths 1..256) | 672 | 10,584 | 3,240 | 4.21 |
| random | 600 | 2,400 | 1,592 | 5.76 |

In all, 38,340 cases (24,823 against the interpreter), 24,164 direct calls; text 1,539,442 bytes against `llc` 22's 406,871 (3.78×). No disagreement on any leg. Seeds (`irdiff --llvm 22 --target x86_64`, with WP-122..125 merged): `exit_odd_widths` and `odd_width_store` pass on three linkers; the other 50 are declined before this group (`global:variable-definition` 48, `module:global-ctors` 1; `const_operands`, this group's, is marked `unsupported(x86_64)` and defines variables). Also: constants with addresses
(differences, negated addresses, relocated fields of 1/2/4/8 bytes,
local, preemptible and weak undefined symbols, block addresses in an
image taken by `indirectbr`) and the calling
convention (byval, return in memory, `i128` pairs at every register
position, split `i256`) exit 42 on all four legs; refusals are checked
by name.

Mutations caught (each reverted):

- `adc` turned into `add` in the carry chain: 682 disagreements;
- `shld`/`shrd` swapped in variable shifts: 2,696;
- the extension of an `insertvalue` field dropped: 188.

## Where hod differs from `llc`

- Constants with addresses are computed in code, never placed in a
  constant pool with data relocations.
- `select` of a `Mem` value chooses an address by `cmovz` and copies
  once; `llc` branches or selects per register.
