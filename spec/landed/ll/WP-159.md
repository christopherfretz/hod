# WP-159 — reader speed (`hod_ll`, `hod_bc`)

Landed: ten cuts in `crates/hod_ll/src` (`lexer.rs`, `names.rs`,
`attrs.rs`, `index.rs`, `body.rs`) and `crates/hod_bc/src`
(`bitstream.rs`, `bitstream/tests.rs`, `body.rs`, `inst.rs`), one commit
each, with the counts before and after in its message. No change to
emitted bytes, refusals, error messages or error positions (below). No
edit outside the two crates. Safe Rust, no new dependency.

## Method

Callgrind instruction counts (`valgrind --tool=callgrind`,
`HOD_THREADS=1`, the release profile with `debug = 1`), attributed by
each instruction's own function (`callgrind_annotate --inclusive=no`;
with fat LTO and one code unit inclusive costs mean nothing). Command:
`hod --strict --filetype=obj -o out.o in`. The host is AArch64 Linux;
x86-64 runs are cross. Inputs: the bench inputs (stl-heavy, templates,
huge-function, tiny-functions for both targets, containers for x86-64)
and three large corpus modules for AArch64 (regex-match-libstdcxx,
run-wide-function-unwind-O2, cleanup-scopes-30k), each as text and as
bitcode (`llvm-as-22`), and templates with `-g` for the WP-149 study.
Hot spots inside a function were read from `--dump-instr=yes` profiles
against `objdump`.

No check was removed. Cut 70325b6 moves the 4 GiB check: a larger
source lexes from an empty slice and the check is made where the end
of the input is met, which gives the error token it gave before.
336f405's fast path takes only a `%N` already defined (or declared
forward) with the requested type; everything else, including every
error, takes the old path. 4dd4e67 keeps only groups that were built
without error, checks the group id at the slot, and makes the group's
notes again at each use, in the order they were made. The VBR fast
paths decode only numbers whose chunks all lie in the word at the
current byte, whose payload is under 57 bits, so the over-64-bit
errors cannot arise there; anything else starts over chunk by chunk
from the number's first chunk. Tests added: `vbr_in_one_word_and_across_words_agree`
(every value at every bit offset and chunk width, with and without bits
after it, and an unfinished number's error position),
`hash_is_of_zero_padded_words`, `packed_is_the_zero_padded_word` (every
length to 20, a zero at every place), `decimal_numbers` (lengths
around 19 and 20 against `str::parse`, invalid digits).

## Debug lowering (profiled, not edited)

`hod_ll` `meta.rs`/`debug.rs` and `hod_bc` `debug.rs`/`body_debug.rs`
are under 0.2% without `-g`. With `-g` the readers' metadata share is
dominated by `hod_ir::DebugInfo::node` hashing and the location
interner, not by the readers' own code; nothing to change in those
files first.

## What is left, and a redesign proposal

The remaining reader cost is structural:

1. **The text lexer, ~110 instructions a token, 22% of a text build.**
   It is per byte (a class table and a branch a byte) and returns a
   token that the parser then compares as bytes (`at_word`, the
   instruction dispatch is a match on byte strings, `expect` is about
   40 instructions plus the lexer). An unrolled class loop was tried
   and was slower. The redesign: one first-byte dispatch table, and
   keyword codes assigned in the lexer (a perfect hash of the word
   bytes into a `Kw` enum carried in the token), so that `at_word`,
   `parse_type`'s word types and the instruction dispatch compare one
   byte. A large but mechanical parser change; estimated −30 to −40%
   of the lexer and parser compare work.
2. **`scan_labels` re-lexes about 20% of the tokens** (the rest of a
   body at its first forward block reference). Either record label
   positions during the index scan (which already passes every body
   with `skip_group`) as a byte-level superset (`name:` at a line
   start) checked against the real tokens later, or give forward block
   references placeholders that `hod_ir`'s builder remaps at the end
   (a `hod_ir` change). Both must keep the error a malformed body
   gives today, which is why neither was done here.
3. **`skip_group` (3.7%)** already runs eight bytes at a time; it is a
   whole extra pass over each body. Folding it into the lexer pass is
   the parallel-parse design (docs/design/0002) and out of scope.
4. **Bitcode:** after these cuts the bitstream is 11.7%, of which
   `Cursor::record` (operands pushed one at a time into a `Vec`) is the
   largest; a record API that hands the body reader a slice of
   operands decoded in a batch, and abbreviations compiled once into a
   small decoder per block, would remove most of the remaining
   per-operand dispatch. `Fx::get` (9.4M, value lookup with type
   checks) and `Fx::instruction` (8.9M) are next.
5. **Not the reader's:** `TypeTable::kind` (15M on stl-heavy) is
   called mostly from the x86-64 back end (`class_of`, `lower`,
   `abi::walk`); `DefaultHasher` (SipHash, 7.8M) is `hod_cg`;
   `SplitInternal` (6M) is `hod_x64`'s target-features parsing per
   function. Together these are larger than any single reader item
   left.
