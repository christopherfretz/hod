# WP-344: walking the metadata section once (measured, not built)

Base `f20f08b6`. No code change: every candidate was measured as a
whole program and none gains enough to be worth its code or its risk.
This record holds the numbers.

## Method

Whole-program instruction counts under callgrind, `hod --strict -O0
-filetype=obj -relocation-model=pic`, `HOD_THREADS=1`, the AArch64
inputs of the bench (`clang22/<input>.ll`), on the AArch64 build host.
The base binary was built from the unmodified tree and copied aside
before any edit; each variant was built from the same tree and compared
with it. Every variant's object for `stl-heavy-g` is equal by `cmp` to
the base's.

## What the extent finding costs

The figure of 48.1 M (WP-326, WP-328) is the own cost of every
`skip::skip_group` call on `stl-heavy-g`: metadata nodes, function
bodies and the other groups the index steps over. The metadata nodes'
share, measured by a variant that walks each node twice (`Scanner::node`
calls `group` again from the `(`):

| Input | base | node walked twice | one walk |
| --- | ---: | ---: | ---: |
| stl-heavy-g | 972,692,066 | 1,001,370,609 | 28.68 M (2.9%) |
| templates-g | 692,584,708 | 706,240,511 | 13.66 M (2.0%) |
| tiny-functions-g | 325,159,074 | 330,733,495 | 5.57 M (1.7%) |

On `stl-heavy-g`: 84,571 node lines, 9.30 MB, 37,513 strings holding
2.22 MB, about 122,600 bytes outside strings that stop the walk (one
`)` or `}` per node, the opening quotes, a few inline nodes), no `;` and
no `/*` on any node line. The walk costs 3.1 instructions per byte,
340 per node. What the index needs from a node: its number, its kind,
`distinct`, the inside of its brackets (start and end) and the offset of
its `!`; the parser re-derives nothing else from the index's walk.

## Candidates and their measured gains (whole program, M)

| Candidate | stl-heavy-g | templates-g | tiny-functions-g |
| --- | ---: | ---: | ---: |
| (a) line rule, unverified: the node ends at the `)`/`}` before the next `\n` (SWAR newline search; wrong for valid text, a floor only) | -11.38 | -5.87 | -2.47 |
| (a) the same, newline searched sixteen bytes at a time | +4.14 | +1.35 | +0.44 |
| exact walk, three word tests instead of five (`(`/`)` as `b \| 1 == ')'`, `;`/`/` as `b \| 0x14 == '?'`) | -0.63 | -0.15 | +0.13 |
| exact walk, sixteen bytes per test, five tests | +2.74 | +2.08 | +1.18 |
| exact walk, sixteen bytes per test, three tests | -1.98 | -0.34 | +0.10 |

The exact walk is at its floor in scalar safe Rust: the five-test SWAR
loop compiles to about 27 instructions per eight bytes and the
three-test one barely fewer (LLVM already folds the tests). A test of
sixteen bytes that the compiler vectorizes (`cmeq`, `umaxv`) costs about
21 instructions; node lines are short (110 bytes) with a stop every 40
bytes or so, and finding the stop's position in a chunk gives back what
the test saved. A bit mask per byte (`mask |= hit << i`) is not
vectorized on AArch64 and costs more.

(a) cannot be made correct cheaply. `llvm-as` 22 accepts a node split
over lines, a string holding a raw newline (`!"x)` then `"` on the next
line: the first line ends with a `)` that is inside the string) and two
nodes on one line (`!1 = !{} !2 = !{!"x"}`). An index that checks its
guess must find the matching bracket, which is the exact walk. A guess
checked by the readers instead (each reader of a node confirms that its
own closing token is the guessed end; any failure re-indexes with the
exact walk and parses again) would gain at most the floor above, 11.4 M
(1.2%) on `stl-heavy-g`, less the checks; every node would have to be
read to its end for the check to be sound (an unread node with a wrong
guess shifts every later entity), and the readers are many
(`meta.rs`, and in `debug.rs` `node_body`, `location_body`,
`quick_location`, `quick_field`, `expr_body`, the tuple readers).
Not built.

(b) the index recording what the parser re-derives: the parser reads a
node from the inside's start; the kind is already recorded; field
starts would have to be found by the index's walk, which does not look
at fields. No gain to record.

(c) parsing nodes during the index walk: the gain is bounded by the
walk's 28.7 M (2.9%) on `stl-heavy-g`. It would move node reading into
the scan, which runs in pieces on several threads (§4.4) while the
debug reader reserves every node's handle before reading any (two
passes in file order, forward references). With more than one thread
the walk is already spread over the scan's threads. Not built.

## Not done

No change to `index.rs`, `debug.rs` or `skip.rs`; no test added (the
edge-case tests the package named belong to a cheap rule that was not
built). The bench was not run over all inputs: no binary differs from
the base.
