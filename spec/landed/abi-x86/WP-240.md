# WP-240 — design 0008 (32-bit x86 Linux) and the skeleton of `spec/abi-x86.md`

Landed: a design and its probes; no code. hod still refuses every 32-bit
module as `unsupported-target`.

## What it did

- `docs/design/0008-i386.md`: what each crate assumes about a 64-bit
  target (§1, with counts and places), the i386 ABI as LLVM 19 and 22
  implement it (§2), PIC, TLS, exceptions and DWARF (§3), the oracle and
  the lane (§4), the baseline instruction set (§5), and fifteen packages
  I1-I15 with dependencies, sizes and three milestones (§6), risks (§7)
  and open questions (§8).
- `spec/abi-x86.md`: the skeleton, every rule with the probe that shows
  it; the sections the ABI package (I6) completes are marked.
- `docs/design/0008-data/`: the probes (`abi/`, `mc/`, `run/`) with the
  scripts that rerun them.
- `docs/ROADMAP.md`: track T-X86 and the third-target paragraph.

## Findings a later package should not rediscover

- clang's default `i686` CPU has no SSE (`+cmov,+cx8,+x87`): scalar
  floating point is x87 in a default build; the CPU name, not the
  feature list, enables SSE2 (`pentium4`).
- A default clang i686 build is PIE (`-pic-level 2 -pic-is-pie`).
- llc uses `calll .L$pb; popl` for the GOT pointer at `-O0`, not
  `__x86.get_pc_thunk`; `ebx` holds the GOT pointer at every `@PLT` call.
- The callee pops an `sret` pointer (`retl $4`); every C struct returns
  through `sret`.
- LLVM 22 aligns `i128`/`fp128` stack arguments to 16, LLVM 19 to 4.
- ld.lld 22 does not relax `R_386_GOT32X`; bfd and mold do. wild 0.11.0
  does not link i386.
- `fptosi`/`sitofp` with `i64` use x87 even with SSE2; `i128` division is
  expanded inline (libgcc has no `__divti3` for i386).
