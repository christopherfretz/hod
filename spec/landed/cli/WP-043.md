## Threads

The default is one thread. `HOD_THREADS=<n>` grants `n`; under a make
jobserver (fifo form) hod takes idle tokens for a large module, never
waiting, up to 16 threads. A module gets one thread per
`PARALLEL_MIN_INSTS` = 4096 instructions.

Break-even (`crates/hod/tests/back.rs` `break_even`, release build, the
code generation phase alone, best of 15, µs, host load about 15 on 24
cores):

| instructions | 1 thread | 2 | 4 | 8 |
|---:|---:|---:|---:|---:|
| 480 | 43 | 61 | 129 | 249 |
| 3,840 | 340 | 262 | 295 | 476 |
| 7,680 | 687 | 447 | 372 | 573 |
| 15,360 | 1,336 | 772 | 560 | 715 |
| 30,720 | 2,750 | 1,504 | 906 | 877 |
| 61,440 | 5,303 | 2,851 | 1,573 | 1,223 |
| 245,760 | 22,625 | 11,879 | 6,367 | 3,834 |

About 90 ns per instruction on one thread; a thread costs 20-60 µs to
start and join. Two beat one from 2-4k instructions, four beat two near
7.7k, eight beat four near 30k: 4096 per thread follows the curve.

## Decisions where the spec was silent

- **Internal errors** fall back in hybrid mode (a build should not break
  on a hod bug) but exit 1, never 2, in strict mode, and log
  `internal-error`: a harness counts them as failures.
- **The first refusal in module order** is the answer whatever thread met
  it: workers skip functions after the earliest known failure, and the
  minimum index wins.
- **`-mattr`** is judged before any body, as a module refusal; a
  function's attribute in that function.
- **Relocation model unset** is `static` (`llc`'s default on Linux
  AArch64); `ropi`/`rwpi` and `-split-dwarf-output` are refused by name.
- **The optimization level** is ignored: the same code at every `-O`.
- **Jobserver**: only the fifo form; the descriptor forms are ignored
  (hod runs on its implicit token). The fifo is opened at first use, so
  a small module never touches it.
