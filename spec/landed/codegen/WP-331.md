## Stage 1: no i386 lowering pins more than two pool registers

`MIN_POOL_GPR_32` is 2 (`crates/hod_cg/src/reg.rs:130`; it applies to
4-byte targets only, so the 64-bit targets are unchanged). The `min_pool`
stress mode then runs every function with `ebx`, `esi`. The rule, and
the borrowing rule, are in `spec/codegen-x86.md` §2 and
`crates/hod_x86/README.md`.

The stressed suite was run until it passed. Run 1 (with only `icmp`
fixed) failed in 14 test binaries: `call` 14 (memory intrinsics, a
funnel shift), `atomicrmw` 6, `cmpxchg` 1. Run 3 failed in 1 binary:
`call` 1 (a funnel shift with a variable amount). Run 4 passed. The
sites changed, and what replaces the third register:

| site | before | now |
|---|---|---|
| `alu::icmp` (`alu.rs:305`, `compare_in` at `alu.rs:267`) | `def_reg` + both operands | the result takes the left operand's register (dead after the compare); `setcc` through `cl` when it has no low byte |
| `atomic::rmw`, 1 to 4 bytes (`atomic.rs:299`, `:324`) | operand + pointer + `def_reg` | the operand straight into `edx` (`FnCx::put`); the result in the pointer's register |
| `atomic::cmpxchg`, 1 to 4 bytes (`atomic.rs:520`) | expected + replacement + pointer | pointer, expected in the pool; the replacement straight into `ecx`, then `mov eax, expected` |
| `atomic::store` (`atomic.rs:212`) | value + pointer | the pointer first, then the value straight into `ecx` |
| `bytes::copy` / `bytes::set` (`bytes.rs:70`, `:149`) | length + destination + source | the pointers in the pool; the length straight into `ecx` (`Len::Ecx`), the byte of `memset` into `eax` after it |
| `bits::funnel`, variable amount (`bits.rs:443`, `:452`) | `a`, `b`, `c` | `a`, `b` in the pool; `c` straight into `ecx` (32 bits) or `edx` |

The order matters: placing an operand may call (a TLS address) and write
`eax`, `ecx`, `edx`, so a value put into a scratch register is placed
after every operand that is placed in a pool register.

**Borrowed registers.** One mechanism for each: `ebx` (`cmpxchg8b`, the
8-byte and floating `atomicrmw`, a PIC PLT call, `___tls_get_addr`) is
taken with `FnCx::take_reg` (its value displaced first); `esi` / `edi`
(`rep movs`, `rep stos`) are pushed before the sequence and popped after
it, with no frame access between the first pop and the last. A
coroutine's `esi` is therefore intact at every frame access. No code
changed for this: it is the existing shape, now stated as the rule. Stage
2 must test it with a coroutine that does a `memcpy` of a non-constant
length and a 64-bit `cmpxchg` between suspends.

The i686 code of ordinary functions changes (fewer temporaries); the
64-bit targets do not (below).
