# WP-236 — the last debug-information refusals of the optimized `-g` census

Spec: `spec/dwarf.md` §6.36 (and the edits to §6.35 and the refusal
tables). No new abbreviation family.

## What was built

1. **One stored address declared twice** (`hod_dwarf` `func.rs`
   `collect_entities`, `inline.rs` `FnInline::first_of`). The shape,
   reduced with `llvm-reduce` from libc++ `ctor.pass` (x86-64, `-O2`):
   `__format_buffer<float, float>` holds two copies of the inlined body
   of `__format_buffer_hexadecimal_lower_case`, each with
   `#dbg_declare(ptr %0, !result, !DIExpression(), !loc)` of the same
   variable, the same `inlinedAt` and the same `sret` pointer argument.
   `llc` 22 (`-O0 -fast-isel=0`, `-global-isel=0` on AArch64) writes one
   abstract and one concrete `DW_TAG_variable`, the concrete one with a
   single location `DW_OP_fbreg n, DW_OP_deref` (the pointer's spill
   slot), the same tree as for one record. In the reduced module, where
   the pointer has no other use, `llc` writes no variable at all (the
   pointer is not spilled and the record outside the entry block is
   lost); with the record in the entry block it writes `DW_OP_breg5`
   (x86-64). hod now skips a second record of one `(variable,
   inlinedAt)` whose place is the same stored address
   (`LocalPlace::FrameIndirect`, same offset) with the same expression,
   so the variable is located by the first. Two records at different
   pointers stay `debug:variable-twice`: `llc` 22 writes one location
   for the whole scope (`DW_OP_fbreg -16, DW_OP_deref` on x86-64), right
   in one block and wrong in the other.
2. **An imported definition neither placed nor inlined** (`hod_dwarf`
   `import.rs` `import_target`, `inline.rs` `create_abstract`). libc++
   `isnormal.pass` imports `std::__math::isnormal`, a definition with a
   retained parameter `__x` and no code or inlined instance in the
   module. `llc` 22 writes an abstract instance (linkage name, name,
   declaration, type, `DW_AT_external`, `DW_AT_inline DW_INL_inlined`)
   under the function's namespace, without children (the retained
   parameter is not written, with or without `retainedNodes`), and the
   import names it. hod makes the same DIE. A definition whose retained
   nodes include imports keeps `debug:import-entity`.
