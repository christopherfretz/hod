# WP-070 — the AArch64 intrinsics, second set

Landed: `crates/hod_a64/src/fpintr.rs` (new), the WP-070 parts of
`crates/hod_a64/src/intrinsic.rs`, `crates/hod_a64/tests/fpintr.rs` with
`tests/common/fpintr_gen.rs`, the WP-070 tests of `tests/intrinsic.rs`
with `tests/common/intrinsic2_gen.rs` (on `aggr_gen`), the C++ program
`tests/data/intrinsic/typeid.cpp` (its clang++ `-O0` code `typeid.ll`,
its driver `typeid_driver.cpp`), 80 runtime functions in
`hod_cg::RuntimeFn`, the heading "Intrinsics, the second set (WP-070)" in
`spec/codegen.md` §5.5.1, the `WP-070` line of `tests/common/groups.rs`,
and the support-matrix rows.

Integers: `{s,u}{add,sub}.sat` at i1..i64 and i128; `scmp`/`ucmp` of
i1..i64 and i128 operands to i2..i64 and i128 results; WP-041's `ctlz`,
`cttz`, `ctpop`, `bswap`, `bitreverse`, `abs`, `smax`, `smin`, `umax`,
`umin`, `fshl`, `fshr` at i128 (class `Mem`). `eh.typeid.for` of a
symbol (`FnCx::type_id`); `clear_cache` (`__clear_cache`). The
sequences are in `spec/codegen.md` §5.5.1.

## What is refused, by name

- `a64:intrinsic-vector`: every vector form.
- `a64:intrinsic-bfloat`: the floating-point intrinsics of `bfloat`.
- `a64:intrinsic-fp128`: `fptosi.sat`/`fptoui.sat` of `fp128`.
- `a64:intrinsic-wide`: an integer intrinsic wider than 64 bits but not 128.
- `a64:intrinsic`: `powi` with an exponent wider than 32 bits, a
  variable `is.fpclass` mask, and what neither file lowers.
- `a64:eh-typeid`: `eh.typeid.for` of a value that is not a symbol.
- `a64:readcyclecounter`: `readcyclecounter` (`mrs CNTVCT_EL0`; the
  encoder's `SysReg` has no `CNTVCT_EL0`).
- `sshl.sat`/`ushl.sat` are not in `hod_ir`'s list: classify refuses
  them as `intrinsic:llvm.sshl.sat`, the lowering as `a64:intrinsic`.

## Evidence

- `fpintr::every_form_agrees_with_llc_c_and_the_interpreter`: 316
  functions, 25,023 calls, each intrinsic at the four types; plain and
  `Stress::ALL`, every linker. 24,223 compared with llc (31 differ in a
  NaN's bits only), 20,727 with C (gcc, `noipa` oracles; the bit
  operations exactly), 3,012 with `hod_interp`, 4,296 with the Rust model
  of the saturating conversions.
- `fpintr::every_fpclass_mask_agrees`: all 1,024 masks at each type (32
  masks per function, the bits returned), every class's specials and
  random patterns, 11,286 calls against the model and llc.
- `fpintr::live_values_survive_called_intrinsics`: ten `double` and ten
  `i64` values live across `sin`, `pow`, `powi`, `ldexp`, `fma`,
  `maxnum` at each type, against C.
- `intrinsic::saturating_arithmetic_agrees` (12,112 cases, exhaustive
  to i5), `three_way_compares_agree` (7,590), `wide_integer_intrinsics_agree`
  (3,808): against the interpreter and llc, from memory and from
  registers with garbage above the widths.
- `intrinsic::eh_typeid_for_selects_the_clause`: clang++'s code of a
  C++ file with six catch clauses in one pad, nested try blocks, a
  rethrow and a destructor, called by a g++ driver throwing nine types;
  hod plain, stressed and llc under ld, lld, mold.
- The differential harness: 1,000 of 1,000 programs agree
  (`many_programs_agree`), none skipped (WP-041 saw 87 skipped by
  `a64:intrinsic`).

## Mutations (each caught, then reverted)

1. `csel ..., vs` -> `vc` in 32/64-bit signed saturation: 1,572 cases.
2. `is.fpclass`: the infinity bound counted with `hs` instead of `hi`
   (infinities classed as NaNs): 425 calls.
3. `fmuladd` of `half` without the rounding after the multiply: 1 call
   against C and llc.

## Found elsewhere

- llc 22 cannot select `minimum`/`maximum` of `fp128`, nor `llround`/
  `llrint` to `i32` of `half`/`float`/`double`; those functions are not
  given to llc (C still checks them).
- llc passes an `i64` `ldexp` exponent to `ldexp(double, int)`
  unconverted; hod clamps it to the `int` range.
- The C oracle must be `noipa`: gcc folds `__builtin_powi` of constants
  exactly, unlike `__powisf2`.
