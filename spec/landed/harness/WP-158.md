# WP-158 — hosted CI, second part

Landed: the sweep's first run, the lane's test step in parts, `main`'s
runs never cancelled, a marked place for the random-program job. Rules:
`spec/harness.md` "CI".

## What changed

- **`cargo xtask ci --step test --part <name>`** (`xtask::ci::TEST_PARTS`:
  `a64`, `x64`, `harness`, `front`, `rest`; `rest` is `--workspace
  --exclude` every package the others name). Without `--part` the step is
  the whole workspace, as before. Tests: `steps_are_selected_by_name`,
  `the_test_parts_cover_the_workspace_once`,
  `the_hosted_lane_runs_the_quick_gates_steps` (the lane's matrix lists
  every part once).
- **`ci-lane.yml`**: the `test` job is a matrix over the parts; the
  `harness` part saves the cargo cache. Run 43461262398 (both runners):
  the longest job 11 min 22 s (`arm / test a64`; before: one 23 to 31 min
  job).
- **`ci.yml` concurrency**: `cancel-in-progress` only off `main`; on
  `main` a newer run waits.
- **`sweep.yml`**: each shard uploads its wall time and the per-test hod
  logs (`HOD_LIBCXX_LOGDIR`). **`hod-ci`** installs `csmith`; the
  random-program job's place is marked in `ci-lane.yml`.
