# WP-225 — value records with fragments and conversions

Spec: `spec/dwarf.md` §6.31 (and §6.23's refusal list). No new
abbreviation family: the base type DIEs use the existing `BASE_TYPE`
family.

## What was built

- `hod_cg` `dbg_value.rs`: each record carries its fragment's bits; a
  record closes only the open ranges of its variable whose bits overlap
  its own (`llc`'s `DbgEntityHistoryCalculator`).
- `hod_dwarf` `loclists.rs`: `check_value_expr` accepts a final
  byte-aligned fragment and `DW_OP_LLVM_convert` to a signed or
  unsigned integer of 1 to 64 bits; `compose` builds a fragmented
  variable's entries (pieces sorted by offset, gaps as empty
  `DW_OP_piece`, a trailing gap omitted, equal adjacent entries merged);
  `entry_ops` writes `DW_OP_convert` with a 4-byte padded ULEB of the
  base type DIE's unit offset, folds a constant's leading conversions
  (`DIExpression::constantFold`), and writes `llc`'s legacy
  `emitLegacySExt` / `emitLegacyZExt` forms in a split unit. Constants
  follow LLVM 22 (`i1` true is 1; a boolean's nonzero constant is
  `DW_OP_lit1`; a signed type's constant is `DW_OP_consts`).
- `die.rs`: the unit's `DW_TAG_base_type` DIEs (`DW_ATE_signed_N` /
  `DW_ATE_unsigned_N`) are written as the compile unit's first
  children, in first use.

## Census and measurement

886 `-g` modules (libc++ tests and `tests/debug/` sources through kiln
at `-O1` and `-O2`, plus the PR28469 test at `-O2`; AArch64 and x86-64,
443 each). Every shape was compiled by `llc` 19 and 22 and hod's output
matched to 22's (`DW_OP_fbreg` against `DW_OP_breg`, and `DW_OP_deref`
against `DW_OP_deref_size 8`, aside). 19 and 22 differ only in the `i1`
and boolean constants. All 389,019 fragments of the census are byte
aligned.

## Evidence

- `crates/hod/tests/dbg_value.rs`: `pieces_and_conversions` (both
  targets, plain and split) and `refusals_are_named`; 6 of 6 tests pass.
- Sessions (gdb, `cargo xtask debug run`): `tests/debug/dbg_value_pieces.c`
  (fragments of a home and a constant; conversions on a home; a boolean
  constant), `dbg_value_convert_pieces.c` (fragments of three sizes with
  conversions and a shift; a conversion followed by `plus_uconst`; clang
  22 only, since clang 19 adds a declaration fragment) and
  `dbg_value_fragments.c` (one fragment changed at a time; a poison
  fragment). Every printed value equals `llc`'s. AArch64 native: 27 of 27
  PASS with `dbg_value.c` (54 sessions; bfd, lld, mold); x86-64 under
  qemu's gdb stub: 27 of 27 PASS (54 sessions).
- libc++ `PR28469_undefined_behavior_segfault.sh.cpp` through kiln at
  `-O2 -g`, hod `--strict`, linked and run: passes on AArch64 and on
  x86-64 (qemu); both objects verify clean. The saved module of WP-210
  (`findings/libcxx-debug/debug-retained-nodes/`) builds and verifies
  clean; base refuses it for `debug:dbg-value-expr`.
- `cargo xtask debug trees --llc 22` over the 886 modules: 54 same, 513
  differ, 319 declined, 0 failed. The first differences are the known
  classes of §6.7 and §6.23: `DW_AT_loclists_base` (hod writes
  `DW_FORM_sec_offset` lists), x86-64 `DW_AT_frame_base`, `llc`'s
  `DW_AT_const_value` where hod writes a list, and 39 modules where `llc`
  has base types hod lacks (conversions of register values, which hod
  does not locate). hod never wrote a base type `llc` did not.
- Byte identity, base 6cf97db7 against WP-225, every 10th corpus entry
  (`scripts/corpus-bytes.py`, `-j 4`): AArch64 669 modules, 669 objects
  identical; x86-64 684 modules, 684 objects identical; 0 differ, 0 declines on either side.

## Not done

- `-debugger-tune=lldb` on ELF: `llc` uses the legacy forms there; hod
  ignores the tuning and writes `DW_OP_convert`.
- Register values (most `-O1` records) still have no entry, so some
  converted variables `llc` shows are `<optimized out>` in hod (§6.23).
- In the x86-64 measurement module `llc` 22 had no location for an
  `i32` argument's conversion (and the first piece built on it) where
  hod writes the argument's home (not run under a debugger).
- `debug:dbg-value-arglist` and a declaration's fragment
  (`debug:fragment`) are separate packages; reduced modules are kept
  outside the repository.
