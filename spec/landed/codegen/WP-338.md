# WP-338 — i386: vectors in a function without SSE

Base: `8e6e852c` (wave 45's i386 state, the two-register pool). Spec:
`spec/codegen-x86.md` §20 (appended as "section V", numbered §20 at the join of wave 45) and
the §7 rows `x86:vector:no-sse2` (now SSE without SSE2 only) and
`x86:vector:no-sse2:*`.

## Where it comes from

A sample of 1,026 libc++ tests built for i686 by clang 22 at clang's
default i686 CPU (`+cmov,+cx8,+x87`, no SSE) left 7 tests refused as
`x86:vector:no-sse2`. Their regenerated modules contain (counted over
all 7): vector types `<1..32 x i8/i16/i32/i64>`, `<1..32 x
float/double>`, `<1|2|4|8|16|32 x i1>`; instructions `load`, `store`,
`insertelement` (constant and variable index, every lane type),
`extractelement`, `add`, `sub`, `xor`, `icmp eq/ne`, `sext` from `i1`
lanes, `fadd`, `fsub`, `fneg`, `fcmp oeq` on `float`/`double` lanes,
`shufflevector` of `<1 x i1>`, `bitcast` of `<8 x i1>`/`<32 x i1>` to
an integer, `llvm.vector.reduce.and/or` of `i1` lanes. Vectors cross
calls: arguments of up to 256 bytes (`<32 x double>`, `<1 x T>`) and a
`<32 x i8>` result (in memory). No `byval` vector, no `phi` or
`select` of vectors, no `llvm.masked.*`, no float casts.

## Measured (llc 19 and 22 identical)

Section V's "Measured" paragraph: the same memory image as §17; each
lane an argument of its own at the scalar's slot (alignment 4); results
as an aggregate's leaves (three words, one or two x87 values, else
memory with callee pop 4; `fastcc`: words in `eax`/`edx`, memory
pointer in `ecx`); floating lanes on the x87 with `llc`'s excess
precision inside the block (`(a + b) - a` of `<2 x double>` not rounded
between); a float lane passed as an argument goes through
`flds`/`fstps`.

## As built

`vecscalar.rs` and the gate in `vector.rs`: without SSE, `vecscalar`
lowers floating lanes on the x87, inserts of wide lanes and `i1` lanes
at a variable index; every other form is §17's integer code (no `xmm`,
no `cmov`). `abi.rs` passes a vector lane by lane without SSE.
Departure from the direction: hod keeps no 80-bit copy per lane; a read
of a lane that `llc` holds at 80 bits is refused
(`:excess-precision`) instead (a per-lane copy needs a `FnState` field
and `x87::barrier`, outside this package; none of the 7 tests needs
it).

## Evidence

- The 7 modules: 6 compile (`mismatch`, `ranges.prev_permutation`,
  `is_always_lock_free`, `simd_unary`, `reference_assignment`,
  `lazy.split...increment`); `get_float` passes its vector functions
  and stops at `x86:i64:wide` (an integer wider than 64 bits in
`__do_get_integral<long long>`, not this package). Not linked
  against the i686 libc++ (not run).
- `i386_vecscalar.rs`: `lanes.c` + `edge.c` (53 result lines) by clang
  19 and 22 at `i686` and `i586`, static and PIE: 8 configurations equal
  `llc`'s, also hod callee with `llc` caller and back, and under
  `Stress::ALL`. Refusal names: 10 cases.
- irdiff i686, LLVM 22: 135 PASS, 0 FAIL, 0 ERROR (base 132; LLVM 19:
  135 PASS, 0 FAIL, 0 ERROR).
- compare-binaries against `8e6e852c`, corpora `tests/ir`, the kiln
  corpus, the x86-64 kiln corpus: AArch64 and x86-64 0 different, 0
  changed outcome; i686 0 different, 10 changed outcomes, all allowed:
  `drift_lanes.ll` compiles now (2), `vector_arith.ll` →
  `x86:vector:intrinsic`, `vector_lanes.ll` → `x86:vector:i64-op`,
  `vector_masks.ll` and `vectors.ll` → `x86:vector:no-sse2:select`.

## Edits outside the package's files

- `vector.rs`: helpers made `pub(crate)` for `vecscalar`.
- `control.rs` `ret`: a vector result in memory goes to
  `vecscalar::ret_memory` (`agg::ret_memory` refuses vectors).
- `lib.rs`: `pub mod vecscalar`.
- `crates/hod/tests/i386_vector.rs`, `i386_join_e.rs`: two refusal
  cases at `generic` moved to `pentium3` (they compile now).

## What remains

A per-lane 80-bit copy (removes `:excess-precision`); float casts;
`select` and `min`/`max` reductions without `cmov` (they are x87
barriers in `llc`); `<N x i1>` at the boundary; `<2 x float>` results
(`st0`/`st1`, `x86:abi:x87-pair` as for aggregates).
