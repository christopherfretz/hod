# WP-301: inline assembly in 32-bit mode (design 0008's I13)

Rules: `spec/asm.md` §22; `spec/codegen-x86.md` §10.

## What landed

- `hod_asm::x86` (`assemble`, `print_operand`): §10's assembler in
  `Mode::X86`. The x86-64 code gained a mode parameter in three private
  places (`operand::parse_in`, `x64::instruction_in`,
  `x64::assemble_in`); `Mode::X64` keeps every byte as it was.
- `hod_x86::asm` (`call`): operand binding, the asm arm of
  `call::lower`. `hod_x86` now depends on `hod_asm`.

## Decisions

- Naming: refusals of the binding are `x86:inline-asm:<detail>` (the
  i386 table's scheme); the assembler's stay `asm:*`, the mode's
  `x86-mode:*`.
- Register names that do not exist in 32-bit mode are refused when read
  (`asm:operand/register`, as llvm-mc errors), not left to
  `Mode::admit`: `pushq %rax` would otherwise encode as `push %eax`.
- A branch or call to a symbol: `R_386_PC32` without `@PLT` (llvm-mc
  i686), unlike x86-64's `PLT32`.
- Several direct outputs: the struct result is written (`def_mem`), but
  its `extractvalue` is `x86:aggregate` (I11, `target.rs:175`); the run
  programs put the other outputs through memory.
- `A` is implemented against a frame slot (8 bytes); its 64-bit
  consumers are I7's.

## Open

- Module-level assembly for i386 is not wired (`hod_asm::module` has
  only the x86-64 entry).
- `%h` / `ah`..`dh` need a high-byte view in the encoder.
