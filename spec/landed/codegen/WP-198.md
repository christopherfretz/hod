# WP-198: stack frame size at -O0

abseil's `Demangle.DemangleStackConsumption` (x86-64) failed under hod,
9680 bytes of stack against a bound of 9670, and passed under `llc`: the
demangler's frames were 2.4 times `llc -O0`'s. The rules are
`spec/codegen.md` §5.1 "Value slots", with §2.2 and §4.1 adjusted.

## Where the bytes went (before)

Frame bytes per function are read from the prologue (x86-64: `pushq`s and
`subq $n, %rsp`; AArch64: `sub sp` and the pre-indexed `stp`/`str`).
The oracle is `llc` 22 `-O0` (AArch64: `-global-isel=0 -fast-isel=0`).
`demangle.ll` is kiln's -O0 IR of abseil's `demangle.cc` (100 functions);
the corpus sample is 200 kiln modules per target (every 7th module of the
corpus under 2 MB, no stress inputs; 1,415 functions on x86-64, 1,434 on
AArch64).

| cause (x86-64, `demangle.ll`) | bytes | needed |
|---|---|---|
| homes of values used in another block, a register wide (490, mostly `i1` `invoke` results) | 3,920 | 1,099 |
| `Mem` homes (landing-pad pairs, the `insertvalue` chain before `resume`) | 2,976 | |
| homes of values used twice in their block | 136 | |
| incoming slots of `phi`s | 56 | |
| alignment padding | 987 | |
| body slots (`alloca`s) | 4,215 | 4,215 |
| save-set pushes over `llc` (`rbx`, `r12`..`r15`; `llc -O0` pushes none) | 1,792 | |

On the x86-64 corpus sample, 17,416 bytes of hod's 40,464 over `llc` were
save-set pushes; another cause, measured after the change, is the red
zone: 11,472 bytes (`llc` allocates nothing for a leaf function's locals,
hod writes below `rsp` nowhere). AArch64 has
neither cause: its excess was all value slots (`ParseExpression`: 108
`i1` homes of 8 bytes each).

## What changed

- **Size.** Homes and incoming slots are the value's size: an integer's
  store size rounded to a power of two, 4 for `float`, 8 for `double`.
  Safe: §2.2 leaves the bits above an integer's width unspecified in a
  register, and every load and store of the slot (phi copies included)
  uses the same width; stack-argument homes were already this narrow.
  Coroutine bodies keep register-wide homes (their shadow homes are).
- **Holes.** Value slots fill the bytes alignment skipped. Safe: a hole
  is bytes no slot owns; body slots never move, so the stack protector's
  guarded block and every named variable keep their offsets.
- **Block slots.** A home whose value is defined and only used in one
  block is free again in the next block, in size classes taken in order
  (constant time). Safe: every read of the value is emitted in that
  block, after the definition, so no execution reads it after a later
  block has written the slot, unless code runs twice: functions with a
  `returns_twice` call (or `never_reuse_spill_slots`) are compiled again
  without block slots, and coroutine bodies and functions with
  `#dbg_value` records (whose ranges may outlast the block) never get
  them. `#dbg_declare` homes, arguments and `phi`s are never block slots.
- **`insertvalue` takeover.** A `Mem` `insertvalue` in a block slot
  reuses its aggregate operand's block slot when it is that operand's
  only use. Safe: both targets' `copy_value` skip a copy to itself, then
  write the field; nothing reads the operand afterwards.

## Results

Frame bytes, hod over `llc`:

| | before | after |
|---|---|---|
| x86-64 `demangle.ll` | 15,280 / 6,400 (2.39) | 9,184 / 6,400 (1.44) |
| x86-64, its 67 `Parse*` functions | 13,400 / 5,736 (2.34) | 7,384 / 5,736 (1.29) |
| x86-64 corpus sample | 82,584 / 42,120 (1.96, median 2.33) | 73,624 / 42,120 (1.75) |
| AArch64 `demangle.ll` | 14,368 / 9,392 (1.53) | 8,144 / 9,392 (0.87) |
| AArch64, its 67 `Parse*` functions | 12,800 / 8,400 (1.52) | 6,672 / 8,400 (0.79) |
| AArch64 corpus sample | 77,968 / 62,416 (1.25, median 1.50) | 72,144 / 62,416 (1.16, median 1.33) |

`absl_demangle_test` relinked with hod's new `demangle.o` passes all 128
tests under `qemu-x86_64`, `DemangleStackConsumption` included; with the
old object it fails (9680 vs 9670).

What x86-64 still has over `llc` on `demangle.ll` (2,784 bytes): 1,792
save-set pushes, 536 the red zone, the rest the landing-pad pair's 16-byte
home and rounding to 16. On the `Parse*` functions without the pushes,
hod is 1.07 times `llc`; with them, 61 of 67 are over 1.1 times. On
AArch64, 6 of 67 are over 1.1 times `llc` (32-byte frames that are 48).

Compile cost (`callgrind`, `HOD_THREADS=1 hod --strict -O0`, the 36 bench
inputs): +0.11% instructions in total, at most +0.65%
(`x86_64-exceptions`). Peak memory: PEAKRSS.

## The tracked number

`crates/hod_x64/tests/frame_size.rs` and `crates/hod_a64/tests/frame_size.rs`
compile the seeds of `crates/hod_x64/tests/data/frame_size.ll` (three
parser-shaped functions: a guard object, an `invoke` chain of `i1`
results, a cleanup pad and `resume`, short-circuit `phi`s, values of
every scalar width across blocks) with hod and `llc -O0`, print the
table, and fail above a stated ratio: x86-64 total 1.6 (now 1.52; 2.33
before), per function 1.85; AArch64 total 1.1 (now 1.00; 1.61 before),
per function 1.25. A `returns_twice` program in the same files runs under
both targets, plainly and under `Stress::ALL`, and fails if a block slot
is shared across a `_setjmp`.

## Left out

| cut | bytes it would save | why not |
|---|---|---|
| no save-set pushes (x86-64) | 1,792 on `demangle.ll`; 17,072 on the corpus sample | the pool is the callee-saved set (§4.4); a caller-saved pool is a redesign of calls, unwinding and the save set (WP-146) |
| the red zone in leaf functions (x86-64) | 536; 11,472 | lowerings write below `rsp` (bounced stores, outgoing areas); needs an audit of every target writer and of signal and unwind safety |
| scratch slots a lowering takes with `FnCx::alloc_slot` | `matchRaw` (an SSE test) is 568 bytes against 8 | allocated in many target files outside this package; never reused |
| body slots sorted by alignment | about 31 on `demangle.ll` | moves named variables; the debugger's view and the guard block's place would change |
| the landing-pad pair's 16-byte home | 16 per function with a cleanup | it is read by two `extractvalue`s; keeping it in registers needs a cross-instruction register policy |
| reuse of a block slot within its block after the last use | not measured | needs a last-use point per value, a liveness fact |
