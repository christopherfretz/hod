# WP-310 — the harness's runs and the hosted lanes with mortar

Landed: the `xtask` runs were made with mortar (commit `ea9b94f`,
`hod_testutil::linkers::MORTAR_COMMIT`) beside GNU ld, on the AArch64
development machine for both 64-bit targets, and the hosted lanes build
mortar at the pinned commit. Results: `docs/status/linkers.md` "mortar",
"The harness's runs with mortar".

## Results

Every run with `--linker bfd --linker mortar` (`fuzz`: `--linker
mortar`, one linker per run), LLVM 22 unless said, `HOD_REQUIRE_TOOLS=1`:

- `irdiff`, full `tests/ir` tier: AArch64 92 PASS + 1 UNSUPPORTED per
  linker; x86-64 94 + 1. i686 is not run with mortar: `--linker mortar
  --target i686` is a usage error, since the harness links i686 programs
  dynamically and mortar links only `-static` for i386 (`EXCEPTIONS`,
  case `elf-i386`, WP-281).
- `debug` (every test, front end and debugger): AArch64 244 PASS + 4
  XFAIL per linker; x86-64 224 PASS + 2 XFAIL + 6 SKIP. gdb and lldb read
  mortar's executables with hod's DWARF as they read GNU ld's
  (breakpoints, backtraces, variables: the same transcripts).
- `roundtrip`, the corpus with LLVM 22 and 19: 6468 entries as
  expected.
- `corpus verify`, hybrid: AArch64 6468 PASS per linker; x86-64 6462
  PASS + 2 SKIP (the list's undefined entry) per linker.
- `fuzz --seed 310000 --count 300`: AArch64 and x86-64 each 269 agree,
  31 skipped, 0 findings.

No result differs between the two linkers: no finding, no REFUSED cell
and no exception row was added.

## Harness changes

- `cargo xtask corpus verify --linker <name>` (repeatable; default every
  linker found), passed to its `irdiff` runs: the run had no linker
  choice (`spec/harness.md` "corpus", "verify").
- `fuzz --linker`: every program linked (`Bench::link_all`, gcc's
  program of the 128-bit cases) must carry the asked linker's signature
  (`irdiff::tools::check_signature`), else the link is an error
  (`spec/harness.md` "fuzz"). Before, a driver that ignored `-B` would
  have linked with its own `ld` unseen.

## Hosted lanes

- `scripts/mortar-commit.sh` prints `MORTAR_COMMIT` from
  `crates/hod_testutil/src/linkers.rs` (fails unless exactly one
  40-digit commit is there); the commit is written nowhere else.
- `.github/actions/mortar`: the commit; `actions/cache/restore` of
  `/opt/mortar` under `mortar-<commit>-<arch>`; on a miss (where
  `build` is true) a checkout of `christopherfretz/mortar` at the commit
  into `.ci/mortar-src`, `cargo build --release -p mortar`, a copy to
  `/opt/mortar/mortar`, and (where `save` is true) `actions/cache/save`;
  then `mortar --version` and `HOD_MORTAR` for the later steps.
- `ci-lane.yml`: the `kiln` job builds and saves it, the `test` jobs
  restore it (a miss fails the job), the `irdiff` job builds it on a
  miss without saving. `lints` links nothing and has none.
- `MORTAR_REQUIRED` stays false until a hosted run has shown the step,
  as `WILD_REQUIRED`.
