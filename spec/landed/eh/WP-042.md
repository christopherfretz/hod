# WP-042 — `hod_eh`: call-frame information (`.eh_frame`)

The contract is `spec/eh.md` §1 to §8. This file records what the work
package did, what it measured, and what it left.

## What landed

- `crates/hod_eh/src/lib.rs`: `Op`, `Row`, `Lsda`, `Fde`, `Error`,
  `write_eh_frame`, `personality_ref`, `write_advance`, `write_op`; the
  FDE layout (counting sort by CIE, then by `order`), CIE and FDE writers
  with a stack staging buffer per FDE.
- `crates/hod_eh/src/target.rs`: `CfiTarget`, `AARCH64`, `X86_64`,
  `for_arch`, the `pe` (`DW_EH_PE_*`) constants.
- `crates/hod_eh/src/leb.rs`: LEB128.
- Tests: `tests/common/mod.rs` (an ELF64 reader and section splicer, a
  reader of `llvm-dwarfdump --eh-frame`, the llc round trip),
  `tests/llc_oracle.rs` (§7.1), `tests/unwind.rs` with
  `tests/data/unwind.{cpp,ll}` (§7.2), `tests/encoder.rs` (§7.3),
  `tests/throughput.rs` (§8).
- `spec/eh.md`, the `eh.md` row of `spec/README.md`.

## Evidence

- `cargo test -p hod_eh`: 9 encoder units, 3 oracle tests, 2 unwinding
  tests, 1 doctest.
- §7.1, per LLVM major (19 and 22, identical results): 9 modules × 2
  targets = 18 objects, 88 FDEs per target, each round trip also with the input
  reversed. Byte-identical section and relocations: all 9 x86-64 objects
  and 7 of 9 AArch64 objects. The two AArch64 objects with landing pads
  (`personality_shared_cie`: 2 CIEs, 6 FDEs; `two_personalities`: 3 CIEs,
  4 FDEs) are rule-equal: `llc` uses `DW_CFA_remember_state` after the
  mid-function epilogue, which hod's rows restate (§4.3). The cases are
  checked to exercise all four advance opcodes, `DW_CFA_offset_extended`
  and `DW_CFA_restore_extended` (AArch64 `d8`/`d15`), and
  `DW_CFA_def_cfa_register` (x86-64). The `DW.ref` slot matches `llc`'s.
- §7.2, per LLVM major (19 and 22): bfd 2.44, lld 22 and mold 2.37.1 each
  with `--eh-frame-hdr`: the program with hod's `.eh_frame` prints the 13
  expected lines and exits 0, as the original. Without the header, the
  original and the replacement both terminate at the first throw (libgcc
  finds FDEs only through `PT_GNU_EH_FRAME`); the test checks they agree
  and that the linked program indeed has no `.eh_frame_hdr`.
- Hand mutation, reverted: the LSDA relocation's addend off by 4 (with
  the round trip's relocation check disabled) makes the bfd program
  terminate ("terminate called after throwing an instance of 'Error'"),
  so the unwinding test sees a wrong table on its own.
- Throughput (`cargo test -p hod_eh --release --test throughput --
  --ignored --nocapture`): 100,000 AArch64 FDEs of 8 rows each, one in
  eight with a personality and an LSDA, 4.88 MB of `.eh_frame` and
  112,501 relocations: 5.5 to 7.2 ms over repeated runs on the shared
  machine, **55 to 72 ns per FDE** (about 700 MB/s). About 1.1 ms of it is
  the kernel faulting in the fresh 5 MB buffer. Staging each FDE on the
  stack instead of pushing into the section's `Vec` byte by byte halved it
  (from 125 ns).

## Decisions

1. `hod_eh` keeps its dependency on `hod_obj` only, so its input `Op`/`Row`
   duplicate `hod_cg`'s `CfiOp`/`CfiRow` one for one; the caller maps them
   (§1.1).
2. `Fde::order` makes the output independent of the input order (§5);
   duplicates that would break that are errors.
3. CIE order: none first, then personalities by first use, which is
   `llc`'s order in every case tried, including two personalities.
4. hod restates rules instead of `DW_CFA_remember_state` (§4.3); byte
   identity with `llc` is asserted only where `llc` did not use it.
5. `personality_ref` is here, not in the LSDA package, because the CIE
   needs the slot whether or not the LSDA exists yet.
6. x86-64 is in the table and byte-identical to `llc` in §7.1; it has no
   real-unwinding test (no x86-64 runtime on this host).

## Gaps in the record (for `emit_module` and the LSDA package)

- `FuncRecord` has no personality: the caller takes it from the IR
  function (`SymbolKind::Function { personality }`).
- `FuncRecord` has no `nounwind`/`uwtable`, which decide whether a
  function gets an FDE (§1.1); the caller reads the IR attributes.
- `FuncRecord` has no section placement; the caller supplies `start` and
  `start_addend` after the merge (§9.7).
- For the LSDA package: `call_sites`, `pads`, `clauses`, `type_ids`,
  `filter_ids` look sufficient for the table itself; the LSDA's symbol and
  offset must be known before `write_eh_frame` runs (it takes `Lsda` per
  function), so the LSDA is laid out first or in the same pass.
