# WP-336: libc++ on i386, the sample, the refusal census, the status page (design 0008, I14 second part)

Landed: the sample of 1,026 tests run in control, hybrid and strict,
the per-test table, the ranked refusal census with a reduced module per
name, and `docs/status/libcxx-hod-i686.md`. Not done: the full run
(9,247 tests). This builds on WP-330 (the archives and the runner,
`spec/landed/harness/WP-330.md`).

## Reproducing

From the worktree, with the WP-330 build dir:

    export CARGO_TARGET_DIR=<build>/kiln-target            # kiln's xtask
    export HOD_I686_SELECTION=<build>/sample.txt           # 777 lines
    export HOD_I686_HOD=<build>/release/hod                # built from 436a3755
    export HOD_JOBSERVER_FIFO=/run/hod/lanes.fifo HOD_JOBS=4
    for mode in control hybrid strict; do
      for k in 1 2 3 4; do nice scripts/libcxx-hod-i686.sh $mode <run> --shard $k/4; done
      scripts/libcxx-hod-i686.sh merge <run> $mode
    done
    python3 -I scripts/libcxx-i686-table.py <run> <run>/tables

`tables/` receives `table.tsv` (per test: the three outcomes, modules by
hod, strict refusal, hybrid census reasons), `totals.md`, `census.md`
and `suspects.tsv` (the pass-in-control, fail-with-hod list: empty
here). Back-end time sums come from `<run>/<mode>/time.tsv` (field 3 per
step) and `<run>/<mode>/cov/*.tsv` (field 7 hod, field 8 fallback).

The intrinsic behind each `x86:intrinsic` comes from regenerating the
module and reading the function that hod names. Re-run the test's first
compile line from `<run>/strict/args.tsv` through
`scripts/libcxx-i686-clang.sh` with `HOD_I686_MODE=control
HOD_I686_KEEP=1 ... -c -o <dir>/t.o` (the `.ll` is kept beside it).
Then run `hod -O0 -filetype=obj -mtriple=i686-unknown-linux-gnu
[-relocation-model=pic] --strict <dir>/t.o.ll` and list the `@llvm.*`
calls of the function in its message.

The reduced modules (each refused by hod under its name, and accepted
by `llc`) are kept outside the repository with the table:
`is-fpclass-{f32,f64,f80}.ll`, `vector-no-sse2-v4i32.ll`,
`atomic-libatomic-cmpxchg-i64-align4.ll`, `modf-f64.ll` and
`fp80-cast-bitcast-i80.ll`. Each is about six lines, for example:

    target triple = "i686-unknown-linux-gnu"
    declare i1 @llvm.is.fpclass.f32(float, i32)
    define i1 @f(float %x) {
      %r = call i1 @llvm.is.fpclass.f32(float %x, i32 3)
      ret i1 %r
    }
