# WP-058 — `hod_dwarf`: the type graph

The design is `spec/dwarf.md`. The contract of what landed is §2 (the
type-graph row, the constant pool), §6.1 (families 49 to 68), §6.2, §6.5
to §6.8, §7.2 and §8.6. This file records what the work package did,
what it measured, and what it left.

## What landed

- `crates/hod_dwarf/src/types.rs` (new): the type graph of §6.8. It has
  a work list that follows `llc`'s `getOrCreateTypeDIE`, the context
  lookup, validation at creation, the construct steps per kind, and the
  writer of every type DIE. Its entry point is
  `UnitPlan::reference_type(from, field, t)`.
- `src/die.rs`:
  - the plan walks `globals`, then `enums`, then `retainedTypes`;
  - `UnitPlan::of_module(&Module, unit)`, the plan with static member
    constants;
  - a nameless global is written without a name (family 67);
  - the DIE kinds of the type graph;
  - the WP-053 `discover_type` is gone; its work is the type graph's.
- `src/abbrev.rs`:
  - 20 families appended (49 to 68; `CODE_END` 754 → 8733);
  - the slot order of the WP-058 reserved families 29 and 36–37 refined
    to `llc`'s;
  - the tag `template_alias` and eight attributes added.
- `src/lib.rs`: the errors `MemberOutsideType`, `TypeCycle` and
  `MissingSize`.
- Tests:
  - `tests/type_graph.rs`, `tests/type_oracle.rs`,
    `tests/type_debugger.rs`, and `type_graph_throughput` in
    `tests/throughput.rs`;
  - `tests/common/types.rs`: C++ to `-g` IR, the oracle input of §6.7,
    `module_sections`;
  - `tests/data/types/`: `types.cpp`, `stl.cpp`, `hand.ll`,
    `hand_c.ll` and `hand22.ll`;
  - `tests/dies.rs`: the unsupported example is now an address-space
    pointer, since `const` is written;
  - `crates/hod_dwarf/Cargo.toml`: dev-dependency `hod_ll` (a workspace
    crate), so that the tests read IR with hod's own parser.
- `spec/dwarf.md`:
  - §2, §6.1, §6.2, §6.5 to §6.7, a new §6.8, §7.2 and §8.6;
  - the §10 row marked landed.
- The `dwarf.md` row of `spec/README.md`.

## Evidence

- `HOD_REQUIRE_TOOLS=1 cargo test -p hod_dwarf`: all green.
  - `type_graph.rs` has 7 tests, `type_oracle.rs` 4 (the corpus test is
    a note without `HOD_DWARF_CORPUS`), and `type_debugger.rs` 2.
  - WP-052's and WP-053's tests are unchanged except for the one
    variant above.
- Tree equality with `llc` (§8.6). Both objects verify with `--verify`
  on both targets, and every compared object is in `llc`'s order:
  - hand-written IR: 10 objects, 332 DIEs;
  - `types.cpp`: clang 19 (llc 19 and 22), clang 22 and kiln++: 8
    objects, 3,164 DIEs;
  - `stl.cpp`: clang 19 and 22: 4 objects, 25,560 DIEs;
  - the corpus: 12 DWARF 5 debug modules (all kiln's; the other two ask
    for DWARF 4), 24 objects, 668 DIEs. The swapped corpus has 14 `-g`
    modules, not the 26 the brief names.
- Debuggers: gdb 16 and lldb print the same for hod's shared library as
  for `llc`'s. That holds for `llc` 19 and 22, on GNU ld, lld and mold,
  with 315 lines of gdb and 253 lines of lldb each.
- Throughput and size on `stl.cpp` (§7.2):
  - 138 ns per DIE (plan 67, writer 71);
  - `.debug_info` 1.067× `llc`'s; all DIE sections 1.011×.

## Decisions

- **`llc`'s order, not a sorted one.** The construct steps follow
  `DwarfUnit::constructTypeDIE` and its helpers attribute by attribute,
  so that the trees match `llc`'s with no reordering. Where §6.7 allows
  any order, hod still matches on every object compared.
- **One family per common shape, an "any" family for the rest.** The
  reserved families keep the codes WP-053 promised. The appended ones
  cover the remaining combinations of options with a code that is a few
  ORs (§6.1).
- **Cycles.** A DIE's slot is set at creation, before construction, so
  reference cycles stop at the map lookup. A value cycle is the named
  `TypeCycle`, found by looking at the open frames (no extra pass).
- **The oracle input** (§6.7) narrows the comparison to what WP-058
  writes. Both writers read the same text, so nothing is compared
  against a different input.

## Left for later

- Function-local types are WP-057's: refused until the subprogram's DIE
  exists (§6.8).
- Template parameters, `DW_AT_specification`, static members'
  definitions, imported entities and variable templates are WP-059's.
- Address spaces, strides, variable and expression bounds, runtime
  languages, variant parts and static constants wider than 64 bits are
  refused by name (§6.8). Enumerators wider than 64 bits never reach
  the writer: `hod_ll` records them as `debug:DIEnumerator.wide`.
- Size: two-byte codes for the type families (open question 7). One
  form per slot costs two bytes where `llc` uses `strx1`/`data1` for
  values from 128 to 255.
