# WP-134 — thread-local storage on x86-64 (X-tls)

Landed: `crates/hod_x64/src/tls.rs`; the hook in
`crates/hod_x64/src/common.rs` (`sym_address`'s `Access::Tls` arm calls
`tls::address` instead of refusing); `crates/hod_x64/tests/tls.rs` with
`tests/data/tls/{lib.ll,main.ll,driver.c}` (WP-073's AArch64 program plus
x86-64 cases); the matrix rows `intrinsic:llvm.threadlocal.address` and
`intrinsic:llvm.thread.pointer` on for x86-64 (`hod_ir`
`classify/matrix.rs`, `docs/status/support.md`); `tests/ir/tls.ll` runs
on x86-64; `spec/codegen.md` §5.6.11.

## What is lowered

| model | when (`hod_cg::sym_access`) | sequence | relocations |
|---|---|---|---|
| general dynamic | shared object, preemptible | padded `lea rdi` + `call __tls_get_addr@PLT`, 16 bytes | `TLSGD`, `PLT32` |
| local dynamic | shared object, `dso_local` (or asked) | `lea rdi` + `call`, 12 bytes; `lea rd, [rax + x@dtpoff]` | `TLSLD`, `PLT32`, `DTPOFF32` |
| initial exec | executable, preemptible (or asked) | `mov rd, [rip + x@gottpoff]`; `+ fs:[0]` by `lea` under a pushed `r11`/`r10` | `GOTTPOFF` |
| local exec | executable, `dso_local` (or asked) | `mov rd, fs:[0]`; `lea rd, [rd + x@tpoff]` | `TPOFF32` |

`llvm.threadlocal.address` (a dynamic model as a call after displacing
every register value; a static one as the operand sequence),
`llvm.thread.pointer` (`mov rd, fs:[0]`), and a thread-local address as
any operand with any constant offset (call argument, stored value, `phi`
and `select` arm), which keeps every register but `rd` and the flags
(§5.6.11).

## Refused, by name

- `tls:direct-operand`, `tls:address-in-constant` (classification, as on
  AArch64); `x64:code-model` for a code model other than small.
- `debug:tls-location` (`hod_dwarf`, `crates/hod_dwarf/src/global.rs:99`,
  `:157`): the DWARF location of a thread-local variable on x86-64,
  left for WP-136.
- `x64:todo:tls` is no longer returned (the constant stays in `tls.rs`).

## Evidence

- `tls::every_model_links_runs_and_relaxes`: six builds (non-PIE, PIE,
  the library a shared object with the real `__tls_get_addr`, the
  dynamic models linked into a PIE, `-static`, `-static-pie`) × five
  object sets (hod; `llc` 19; `llc` 22; hod's library with `llc`'s
  executable module; the reverse: accesses of one compiler to the other's
  definitions) × bfd, lld, mold, run under `qemu-x86_64` in the main
  thread and four others (own copies, initialized `.tdata`, zero `.tbss`,
  over-aligned 64 and 128, a 2 MB array, ±2^40 offsets, a variable of the
  executable used by the shared object and the reverse, another shared
  object's variable). 84 linked programs, all `checked`. Relocation kinds and
  symbols equal `llc` 22's in every build. Linked code read back with
  `llvm-objdump -d`: the shared object keeps 49 dynamic calls (`llc`:
  38) and 4 static accesses; into executables no call remains; bfd/lld
  relax every initial exec of the executable to an immediate (45 of 53
  thread-pointer loads in exe/PIE, 52 static), mold keeps another
  object's variables in GOT entries (8 static, 15 relax) and relaxes
  local dynamic as `xor eax, eax; mov rax, fs:[rax]; sub rax, imm`.
- `tls::flags_survive_a_dynamic_access_under_every_predicate`: `select`
  of two general-dynamic addresses under all 10 predicates on `i64` and
  `i8`, 15 × 15 edge values, in a shared object: 4500 results equal C's.
- `tls::each_model_is_the_psabi_sequence`: the bytes of each model and
  the operand form (`66 48 8D 3D`, `66 66 48 E8`, `48 8D 3D` + `E8`,
  the `GOTTPOFF` `mov`, `64 48 8B 1C 25 00000000`, the `TPOFF32` `lea`
  against `.Lle$local`).
- `irdiff --target x86_64 tests/ir/tls.ll`: PASS under bfd, lld, mold,
  LLVM 19 and 22; the whole x86-64 seed run has no FAIL.
- `.text` of the library module against `llc` 22: PIE 2532 / 950 bytes
  (266 %); shared object 25332 / 1512 (1675 %): each direct operand of a
  dynamic model carries its 336-byte save area and the flag rebuild
  (~300 bytes). Kiln, like clang, reaches thread-locals through
  `llvm.threadlocal.address`, which is the 16-byte call.

Mutations, each caught and reverted: the general-dynamic pair without its
prefixes (bfd: "TLS transition from R_X86_64_TLSGD to R_X86_64_GOTTPOFF
... failed"); `TPOFF32` subtracted from the thread pointer instead of
added (every executable crashes); `rsi` not saved around the call in the
operand form (`lib_args`, `lib_fp` fail in the shared object);
`llvm.threadlocal.address` without displacing (`lib_live` fails); the
flags not rebuilt (`lib_select`, `lib_over_addr` fail; without the `rol`,
968 of 4500 predicate results differ).
