# WP-245: AArch64 exclusive-access intrinsics

Spec: `spec/codegen.md` §5.6.39 "AArch64 exclusive accesses (WP-245)".

The corpus entry `target.acle/exclusive-sysreg-run.cpp` (kiln, `-O2`,
LLVM 22 and 19) calls `llvm.aarch64.ldxr`/`stxr` at every size,
`ldaxr`/`stlxr`, `ldaxp`/`stlxp` and `clrex`; strict hod refused it as
`intrinsic:llvm.aarch64.ldxr`.

## What was built

- `crates/hod_ir/src/intrinsic.rs`: the nine names (`ldxr`, `ldaxr`
  overloaded on the pointer, `stxr`, `stlxr` on the pointer, `ldxp`,
  `ldaxp`, `stxp`, `stlxp`, `clrex`); `classify/matrix.rs`: their rows
  (supported on AArch64 for int, ptr and aggregate operands, `clrex`
  on; rejected on x86-64 as an AArch64 property); `classify/walk.rs`:
  `elementtype` accepted on the pointer argument of the four single
  forms.
- `crates/hod_a64/src/exclusive.rs`: one instruction per intrinsic, the
  one `llc -O0 -global-isel=0 -fast-isel=0` of LLVM 19 and 22 emits
  (the size from `elementtype`, `i8` to `i64`); the pair result is
  stored to its `Mem` slot; a store-exclusive's status register is
  never one of its operands.
- `docs/status/support.md` blessed with the nine rows.

## Refused, by name

- `a64:exclusive-element-type`: a single form without `elementtype`
  (LLVM's verifier rejects it) or with one other than `i8`..`i64`
  (`llc` aborts).
- `a64:exclusive-type`: a call whose types are not the intrinsic's.
- On x86-64 each name as `intrinsic:llvm.aarch64.<name>`.

## The reservation granule

The table's first native run hung. Cause, measured: its retry loops
had their target in their own frame, and on hardware a non-exclusive
store into the target's reservation granule (64 bytes here, `CTR_EL0`
ERG 4) clears the monitor, so every attempt fails. hod's -O0 code
stores values to frame slots between a pair (the `{i64, i64}` result
of `ldxp`/`ldaxp`; more under stress); `llc -O0` does too for what it
spills (its `ldaxp`/`stlxp` loop of the table stores both halves).
Whether a run hung was a function of the stack address modulo 64, for
`llc`'s object as for hod's (12 runs each, printed `fp % 64` against
hang). A microbenchmark: an `str` 8 or 56 bytes from the target fails
1000 of 1000 attempts, 64 bytes or more away 0 of 1000; an `ldr` 8
bytes away 1 of 1000. Under `qemu-aarch64` nothing hangs (it reserves
an address, not a granule). The rule is written in §5.6.39: hod adds
no store of its own between a pair except into the function's frame;
it cannot promise success when the target shares a granule with the
frame. Targets of the table are now a global filling a 2048-byte
granule.

## Evidence (all executed, none ignored)

- `crates/hod_a64/tests/exclusive.rs`:
  `instructions_match_llc` (21 instructions equal to `llc` 19 and 22,
  plain, stressed, far); `intrinsics_run_as_specified` (109 calls, hod
  plain, stressed, far and `llc`, under every linker present, natively;
  run 8 times in a row green); `frame_target_is_bounded` (retry loops
  with the target in their own frame, 1000 attempts at most, single
  and pair: each stops within the bound and memory matches its status;
  success not asserted); `threads_count_exactly` (four threads at each
  size and with pairs, natively and under `qemu-aarch64 -cpu
  cortex-a53`); `intrinsics_run_under_qemu` (both tables, hod plain and
  `llc`); `the_rest_is_refused_by_name`.
- `crates/hod/tests/a64_exclusive_corpus.rs`:
  `the_corpus_module_builds_and_runs_as_llc_s` (the corpus module for
  LLVM 22 and 19, `hod::compile` and `llc`, linked by bfd, lld, mold
  and wild: 16 runs print the recorded `ok 9`);
  `x86_64_refuses_each_by_name`.
- `crates/hod_ir/tests/body_llvm.rs` `intrinsic_names_are_llvms`: the
  nine declarations round-trip through LLVM 22.
- Suites with `HOD_REQUIRE_TOOLS=1`: `hod_ir`, `hod_a64`,
  `hod_mc_a64`, `hod` green; `cargo fmt --all --check`; clippy for the
  workspace with warnings denied.

## Not done

- Keeping a load-exclusive's result in registers up to the
  store-exclusive of the same block, so that no frame store lies
  between them (§5.6.39 counts them); it changes where a `Mem` value
  lives (§4.1), not this lowering.
