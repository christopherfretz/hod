# WP-056 — line tables in `emit_module`

The design is `spec/dwarf.md`. The contract of what landed is §3 (the
line-table additions), §4 (`DW_LNCT_LLVM_source`), §5.3 (the block-start
rule), §5.7 (the bridge and its permitted differences), §7.1 (encoded
programs), §8.7 and §9; and `spec/codegen.md` §9.5 (`LineRow::block_start`)
and §9.7 (debug information, the refused names). This file records what
the work package did, what it measured, and what it left.

## What landed

- `crates/hod_dwarf`:
  - `src/line.rs`: `LineProgram` (sequences encoded as pushed, with
    their address fields; `append`), `LineUnit`, `LineUnits`,
    `write_debug_line_units` (several units, one `.debug_line_str` pool,
    the units' offsets); `write_debug_line` is now `push` plus one unit.
    `FileEntry::source` and the `DW_LNCT_LLVM_source` column;
    `FileTable::new_with_source`/`add_with_source`; `Error::ArchMismatch`.
  - `src/policy.rs`: `Transition::block_start` and `Transition::at`;
    rule 2 writes line 0 for a location-less block start.
  - `src/die.rs`: the plan's file table carries `DiFile.source`.
- `crates/hod_cg`:
  - `src/record.rs`: `LineRow::block_start`; `src/driver.rs` sets it.
  - `src/emit/lines.rs` (new): `DebugLines` (§9); `src/emit/mod.rs` calls
    it (`new` after the declarations, `add_function` as each function is
    placed, `finish` after the unwind tables) and names the refusals
    `debug:emission-kind` and `debug:die-unsupported`.
  - `Cargo.toml`: depends on `hod_dwarf`.
- Tests in `crates/hod_a64/tests`: `lines.rs`, `lines_debugger.rs`,
  `lines_throughput.rs` (ignored), the support in `lines_support/`, the
  sources in `data/lines/` (`hand.ll` by hand; `prog.ll`, `tu1.ll`,
  `tu2.ll` by `clang-19 -g -O0 -S -emit-llvm
  -fdebug-prefix-map=$PWD=/hod/tests/lines` from the `.c`/`.cpp` next to
  them; `main.c` and `comdat_main.cpp` are compiled by the host's gcc
  and g++ in the tests).

## Evidence

- `--debug-line` header and `.debug_line_str` with `DW_LNCT_LLVM_source`
  byte-identical to `llc` 19 and 22 for a unit where every file has
  source and for one where only some have (checked by hand during the
  package; the encoding is `write_header`'s, covered by `hod_dwarf`'s
  byte-identity oracle for files without source).
- The oracle (`lines.rs`, LLVM 19 and 22): 7 functions, 71 rows (`llc`
  75), equal per function modulo §5.7's P1 to P3; a table one line off
  fails the comparison for every function.
- Determinism: `prog`, `hand` and `tu1` give the same object bytes for
  1, 2, 3 and 8 chunks, compiled on one thread or one thread per chunk,
  and on a second run.
- Debuggers (`lines_debugger.rs`, gdb 16 and lldb 19, each with GNU ld,
  lld and mold): stepping from `main` through `prog.c` stops 45 times in
  hod's program (38 in hod's code) and 49 in `llc`'s; the 4 extra are
  P1 stops (lines of fall-through branches, such as the `}` of a loop
  body). The breakpoint session (`break
  prog.c:18`, `bt`, `info line`, `next` ×3) matches. COMDAT: the linked
  program of `tu1`, `tu2` (both defining `shared`) and the C++ driver is
  `--verify --debug-line` clean with every linker, for hod's objects as
  for `llc`'s; stepping stops 15 (gdb) and 19 (lldb) times, as in `llc`'s
  program; `break shared.h:3` has one location, hit twice.
- Two returns (open question 4): the shared epilogue's line-0 row is
  not a statement (`hand_written_rows`), and debuggers stop by line only
  at statements; not yet driven in a debugger session.

## Speed and memory

`lines_throughput.rs`, release, 2 000 functions of 100 statements
(206 000 rows; one file, an inlined line every 17 statements):

| | hod | `llc -O0` |
|---|---|---|
| full debug | 33.5 ms, 88.7 MB | 2 807 ms, 277 MB |
| `NoDebug` unit | 28.8 ms, 84.2 MB | 2 504 ms, 250 MB |
| no debug information | 28.5 ms, 54.3 MB | 1 563 ms, 144 MB |

Times are compile plus ELF writing, the parse excluded; memory is the
peak RSS of a process that parses and compiles once (the parse of the
metadata is most of the difference between the rows). Line tables and
the unit DIE add 4.9 ms: **24 ns per row, 2.5 µs per function**, and
4.5 MB of peak memory over the `NoDebug` build.

No-debug cost: the same test on the base commit (`d5c11af`) gives 31.0 ms
and 54.5 MB without debug information, and 30.8 ms for the `NoDebug`
unit; within the noise of this machine of the 28.5 ms and 54.3 MB above.
Without a unit nothing is allocated or walked (`DebugLines::new` returns
`None`), and the driver's only addition is one bool per block.

## Left

- `LineTablesOnly` (§9 lists what it needs): the plan accepting such a
  unit, subprogram DIEs (WP-057), lifting `debug:emission-kind` here and
  `classify`'s `debug:*` refusals in `crates/hod`.
- A unit the DIE core refuses (`debug:die-unsupported`) refuses the whole
  module, its line table included: e.g. a global of function-pointer type
  (`UnitPlan` writes base and pointer-to-base types only). The COMDAT test
  sources use `void *` globals for that reason.
- The workers do not encode sequences (§7.1): the merge does, in module
  order; at 24 ns per row it is small next to code generation.
- `spec/README.md`'s `dwarf.md` row and `docs/BACKLOG.md`'s WP-056 row
  are the coordinator's to update.
