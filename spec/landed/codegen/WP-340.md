# WP-340: `llvm.modf` on x86-64 and AArch64; one rule for an 80-bit pseudo-denormal

Spec: `spec/codegen.md` §5.5.1 "Calls" (AArch64), the x86-64
intrinsics (the SSE paragraph) and §5.6.12 (`modfl`; `is.fpclass` of
the encodings only the x87 has). Modules: `hod_a64::fpintr` (`modf`),
`hod_x64::fpintr` (`modf`), `hod_x64::x87` (`modf`, `Extra::Out`,
`fp_class`, `pseudo_denormal_in`). Classifier row `intrinsic:llvm.modf`.
Tests: `crates/hod/tests/modf64.rs`,
`crates/hod_x64/tests/leftovers2.rs` part 9.

## Measured (`llc` 22, `-O0 -global-isel=0 -fast-isel=0`)

| type | x86-64 | AArch64 |
|---|---|---|
| `float` | `modff`, integral part in a stack slot | `modff`, the same |
| `double` | `modf` | `modf` |
| `x86_fp80` | `modfl` (the operand in memory, `rdi` the integral part's address, the fractional part in `st0`) | not valid |
| `fp128` | `modff128` | `modfl` |
| `half` | cannot select (`fmodf` of `f16`, an abort) | `modff`, both parts narrowed |
| `bfloat` | `modff` and two `__truncsfbf2` | `modff` |
| vector | one call per lane | one call per lane |

The pair is `{ fractional part, integral part }`: the routine's result
first. LLVM 19 does not know the intrinsic (it calls a function named
`llvm.modf.f64`): the tests are LLVM 22 only, and no `tests/ir` seed is
added. clang 22 writes `llvm.modf.*` for `modf`/`modff`/`modfl` on both
targets (checked by the test).

## What landed

1. `modf` of `float`, `double`, `x86_fp80` on x86-64 and of `half`,
   `float`, `double`, `fp128` on AArch64, as measured. `RuntimeFn::Modfl`
   (`(FP128, PTR) -> FP128`) fits AArch64's `long double`; on x86-64 the
   x87 call sequence does not read the signature (as `frexpl`).
2. Refused by the classifier row (`intrinsic:llvm.modf` of the type):
   x86-64 `half` (no oracle) and `fp128` (`modff128` is not in the
   runtime table, `crates/hod_cg/src/sym.rs`, outside this package);
   `bfloat` and vectors on both (as `frexp`).
3. `is.fpclass` of an `x86_fp80` pseudo-denormal on x86-64 follows
   `llc` 22 (as i386 since WP-337): index 11/12 and
   `x87::pseudo_denormal_in`, equal to `hod_x86::fpclass`'s at every
   mask and sign (`modf64.rs`). Ordinary classes and the other odd
   encodings keep their answers: the table test checks every mask
   against operands of every class and both signs, hod plain, stressed
   and `llc` 22 all equal to the rule.

## Evidence at landing

- `modf64.rs`: clang 22's module of `modf`/`modff`/`modfl` (and a
  `half` function on AArch64) built by `llc` 22 and by hod (plain and
  `Stress::ALL`), static and PIC: 12 runs print the same bits (x86-64
  under `qemu-x86_64`, AArch64 natively); the refused forms name the row.
- `leftovers2.rs` part 9: 1024 masks x 25 `x86_fp80` operands; hod
  plain, hod stressed and `llc` 22 each equal to the rule.
- compare-binaries against 6984a71d over `tests/ir` and both kiln
  corpora: 14114 comparisons, 4 different (x86-64, plain and PIC, the
  LLVM 19 and 22 copies of `c/run/static-init-float-ieee.c.ll`, which
  calls `llvm.is.fpclass.f80`), 0 changed outcome; AArch64 and i686 0
  different. No corpus module calls `llvm.modf`.
- irdiff, head equal to base: x86-64 475 PASS (LLVM 22 and 19),
  AArch64 465 PASS (22 and 19), 0 FAIL, 0 ERROR.
