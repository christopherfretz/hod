# WP-050 — x86-64 base integer encoder and its L1 differential harness

Landed: `spec/mc-x64.md` (all sections; scalar SSE is the follow-up row).

## What it did

- `crates/hod_mc_x64`: the operand model (`Reg`, `Size`, `Index`, `Scale`,
  `Seg`, `Cond`, `Mem`), the encoded instruction `Inst` with its
  PC-relative `Site`, one layout routine for prefixes, REX, opcode, ModRM,
  SIB, displacement and immediate (`src/inst.rs`), 164 instruction
  constructors (52 with a checked `try_` twin) in one module per spec
  section, `lock` as a checked wrapper over lockable instructions, and
  `Fixup` for the `rel8`/`rel32`/RIP `disp32` fields.
- `crates/hod_mc_x64/tests/l1`: the harness (`harness.rs`), the
  constructor-to-mnemonic table, independent text formatters and operand
  samples, one sweep per spec section, the tool-free fixup tests, the
  relocation-site and laid-out-function tests, the coverage test and the
  harness's negative self-tests.
- 160,256 encodings in nine batches equal `llvm-mc`'s bytes and
  disassemble to the intended instruction, at LLVM 22 and at LLVM 19. Of
  417 operand combinations the checked forms reject, the 190 that have
  text LLVM does not silently re-express are errors to `llvm-mc` too, at
  both majors. 68 relocation sites (offset, addend, type) agree with the
  relocations LLVM writes. The test binary runs in about ten seconds.

## Encoding choices

Each is LLVM's assembler's choice for the same text, at both majors; none
differs.

- Memory: shortest displacement; `rbp`/`r13` bases take `disp8 0`;
  `rsp`/`r12` bases take a SIB; no base is SIB with base 101 and `disp32`;
  `[index*1]` is not rewritten as a base; base and index never swap.
- ALU register-register: the `r/m, r` opcode (`01`, not `03`).
- ALU immediates: `83 ib` when the value is a sign-extended byte, else the
  accumulator short form, else `81`; for 8-bit operands, the accumulator
  form `04+8n` before `80`. `test` has no `imm8` form; the accumulator
  form `A8`/`A9` is used.
- `mov r, imm`: `B8+r` for 8/16/32 bits; for 64 bits `C7 /0 id` when the
  value sign-extends from 32 bits, else `movabs` (`B8+r io`). `mov r32`
  is never substituted for a 64-bit move of a small positive value: that
  is the caller's choice.
- Shifts by an immediate 1: `D0`/`D1`.
- `xchg`: the `90+r` form with the accumulator, except `xchg eax, eax`
  (`87 C0`) and `xchg rax, rax` (`90`).
- `nop(len)`: the SDM table to 9 bytes, then `66 2E` and extra `66`
  prefixes to 15.
- Prefix order: segment, `66`, `F0`/`F2`/`F3`, REX.

## Decisions, and why

- **`Inst` is a fixed 15-byte `Copy` value, not a write into a caller
  buffer.** It keeps every constructor a `const fn` with no state, like
  `hod_mc_a64`'s `u32`, and the caller appends `bytes()`; the extra copy is
  at most 18 bytes.
- **The instruction records its own PC-relative field.** On x86 the field's
  offset and the bytes after it (an immediate after a RIP-relative
  operand, a `lock` or segment prefix before it) depend on the encoding,
  so only the encoder can say where a relocation goes and with which
  addend. `Site::addend` is the psABI addend, so internal fixups and
  relocations use one formula.
- **Displacements are field values (from the end of the instruction).**
  That is what the processor adds and what a relocation's `S + A - P`
  computes; a start-relative convention would need the length at every
  call site.
- **The size is an operand, not part of the register**, as on AArch64; the
  8-bit REX requirement for `spl`..`dil` is the encoder's job.
- **Short versus near branches are separate constructors.** The encoder
  never relaxes; the code generator decides.
- **`lock` is a checked wrapper**, not a parameter of every
  memory-destination constructor: the common case stays one call, and
  "lockable" is a property the encoder records on the instruction.
- **Every installed LLVM major is an oracle.** The x86 assembler's choices
  have changed across versions before (`lea` with `@GOTPCREL` gets a
  different relocation in 19 and 22, which is why the spec does not
  cover that form); checking both catches the next change.

## Gaps

- Not provided, listed in the spec: high-byte registers, string
  instructions, bit tests, `cmpxchg8b`, register-destination `xadd`/
  `cmpxchg`, `enter`, far and loop branches, system instructions, the TLS
  sequences with fixed padding prefixes and the local-exec `TPOFF32`
  field, SSE and VEX/EVEX.
- `hod_x64` does not use the crate yet.
