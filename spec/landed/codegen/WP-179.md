# WP-179: `"disable-tail-calls"`, `noredzone`, and the function-attribute sweep

## What is implemented

- **`"disable-tail-calls"`** (was `attr:disable-tail-calls`, the first
  refusal of the LLVM build by kiln and hod: googletest's
  `GTEST_NO_TAIL_CALL_` in `gtest-all.cc`). A kept function string,
  `FnStr::DisableTailCalls`, value kept as written; both readers carry it
  through `hod_ir::kit::string_attr` with no reader change; matrix row
  `attr:disable-tail-calls` `ON` on both targets. LLVM's rule
  (`TargetLowering::isInTailCallPosition` and the targets' eligibility
  checks): in a function with `"true"` no call is a tail call except a
  `musttail` one. hod makes no tail call but a `musttail` one in any
  function (`spec/codegen.md` §7.1 "Tail kinds", `hod_cg::call`,
  `hod_a64::call`, `hod_x64::call`: only `TailKind::MustTail` reaches the
  tail exit), so the rule is hod's everywhere and no code changes.
  `llc -O0 -global-isel=0 -fast-isel=0`, plain `-O0` and `-O2`, 19 and
  22, both targets, agree on this shape (one module, one call each):

  | function | `tail` | plain | `notail` | `musttail` |
  |---|---|---|---|---|
  | no attribute | llc jump, hod call | call | call | jump |
  | `"true"` | call | call | call | jump |
  | `"false"` | llc jump, hod call | call | call | jump |
  | callee with `"true"` | as its caller's row | | | |

  The `tail` jump `llc` makes where the attribute is absent or `"false"`
  is permitted, not obliged; hod's call there is the existing behaviour.
- **`noredzone`** (was `attr:noredzone`; clang with `-mno-red-zone`).
  A kept function flag, `FnAttrs::NO_RED_ZONE` (bit 20), row `ON` on
  both targets. hod keeps no data below the stack pointer on either
  target (x86-64: `spec/codegen.md` §5.6 and design 0006 §2.9; AArch64
  addresses the frame from `x29` above `sp`), so it changes no code:
  hod's object is byte-identical with and without it. `llc` 22 without
  it puts a leaf's locals at `-0x14(%rsp)` on x86-64 and with it
  allocates first, which is what hod always does.

## Evidence

- `tests/ir/disable_tail_calls.ll`: `"true"`/`"false"` with `tail`,
  plain, `notail`, `musttail`, on a caller and on a callee. `@probe`
  compares its return address with its caller's (stored in `@ra`), so
  the program prints whether each looked-at call was a tail call; calls
  where llc and hod legitimately differ are used, not looked at.
  `tests/ir/noredzone.ll`: leaves, a loop, a caller, header and group.
  `cargo xtask irdiff --witness` on both: PASS on aarch64 and x86_64,
  LLVM 19 and 22, bfd/lld/mold (6 results each run, 0 FAIL/ERROR).
- `crates/hod/tests/disable_tail_calls.rs`: the seed's object is the
  same from text and from `llvm-as` 19 and 22 bitcode on both targets;
  per function, the call/jump shape of hod's object against
  `llc` 19 and 22 (the table above); `noredzone` changes no byte, text
  and bitcode.
- The finding: `hod --strict -O0 -relocation-model=pic -function-sections
  -data-sections -filetype=obj gtest-all.cc.ll` (kiln's AArch64 module,
  94k lines) now builds, 0.52 s, 22 MB peak. The two
  `GTEST_NO_TAIL_CALL_` functions
  (`UnitTestImpl::CurrentOsStackTraceExceptTop`,
  `GetCurrentOsStackTraceExceptTop`) have the calls `llc` 22 has, in the
  same order (`bl` + `blr`, and `bl` + `bl`), no jump.

## What stays refused: the sweep

A tiny C++ file under each flag, `kiln++` and `clang++-22`, `-O0 -S
-emit-llvm`, both targets, then `hod --strict`. Every refusal is by
name; the attribute rows (functions) that ordinary flags produce:

| attribute | produced by | hod answer | what building it takes |
|---|---|---|---|
| `ssp`, `sspstrong`, `sspreq` (+ `"stack-protector-buffer-size"`) | `-fstack-protector`, `-strong`, `-all` (clang, kiln) | `attr:ssp*` in function, both targets | canary load from `__stack_chk_guard` (AArch64) / `%fs:0x28` (x86-64) in the prologue, check before each return, `__stack_chk_fail`; LLVM's choice of protected functions (arrays, address-taken locals) for `ssp`/`sspstrong`, slot layout with arrays next to the canary |
| `"patchable-function-entry"`, `-prefix` | `-fpatchable-function-entry=N,M` | in function | N-M `nop`s at the entry and M before it, the `__patchable_function_entries` section with a link-order flag |
| `"probe-stack"="inline-asm"` | `-fstack-clash-protection` | in function | inline probing of frames larger than the probe size (and of dynamic allocas) |
| `"stack-probe-size"` | `-mstack-probe-size` (clang only) | in function | read with `probe-stack` |
| `"split-stack"` | `-fsplit-stack` | in function | the `__morestack` prologue |
| `"zero-call-used-regs"` | `-fzero-call-used-regs=` | in function | clearing the chosen registers before each return |
| `noimplicitfloat` | `-msoft-float` (clang, x86-64; kiln has no flag) | `attr:noimplicitfloat` | no `xmm` for anything the IR does not ask for: the variadic register save area, memory copies |
| `nonlazybind` | `-fno-plt` (clang, kiln) | first refused as `module-flag:RtLibUseGOT` | calls through the GOT (`call *f@GOTPCREL(%rip)`, `adrp`/`ldr` + `blr`) for such callees, and the module flag for library calls |
| `strictfp` | `-ffp-exception-behavior=strict` (clang; kiln refuses the flag) | `attr:strictfp` | constrained intrinsics; no reordering of FP operations, which hod does not do, but the intrinsics and exception-flag semantics |
| `"stackrealign"` | `-mstackrealign` (clang; kiln has no flag) | `attr:stackrealign` (not in the table) | realign `rsp`/`sp` in every prologue; locals then need a base other than `rbp` |
| `sanitize_address`, `sanitize_thread` | `-fsanitize=address`, `thread` | first refused as `module-flag:nosanitize_*` | the instrumentation runs before a backend; what is left is module flags, `asan.module_ctor` and globals metadata |
| `branch-target-enforcement` etc. | `-mbranch-protection=standard` (AArch64) | first refused as `module:branch-target-enforcement` | BTI landing pads, PAC signing |
| `cf-protection` | `-fcf-protection=full` (x86-64) | first refused as `module:cf-protection-branch` | `endbr64`, the GNU property note |

Accepted under the other flags of the brief: `"frame-pointer"`
(`-fno-omit-frame-pointer`, `-fomit-frame-pointer`,
`-mno-omit-leaf-frame-pointer`; hod always keeps a frame pointer),
`"no-builtins"`/`"no-builtin-*"` (`-fno-builtin*`), `"tune-cpu"`
(`-mtune`), `"min-legal-vector-width"`, `"no-trapping-math"`,
`cold`/`hot`, `noinline`/`optnone`, `-ffast-math`'s strings,
`-fno-unwind-tables`, `-ftrivial-auto-var-init=zero` (front-end stores),
`-ffunction-sections`, `-fno-exceptions`, `-g`. `naked` stays refused
by design (`attr:naked`, never). `nomerge` is dropped (not produced by
these flags; `__attribute__((nomerge))`).

## The refusal's detail

A refused function attribute is still answered without the function
(`unsupported construct 'attr:noredzone'` before this package). The
readers note it with the function's symbol and `classify`'s module pass
reports it, but the facade's module pass names no function
(`crates/hod/src/session.rs:442`, `from_rejection(.., false)`). The fix
is in the facade, outside this package's ownership; an `#[ignore]`d
test (`crates/hod/tests/disable_tail_calls.rs`,
`a_refused_function_attribute_names_its_function`) states it. Kept
attributes that the matrix refuses (`attr:ssp` ...) are already named
with their function.
