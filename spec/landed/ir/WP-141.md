# WP-141 — x86 calling conventions in classify

Landed:
- `spec/ir.md` §5.7 (`CallConv::keyword`, `keyword_since`,
  `from_keyword`), §8.4 (the row count, which was stale), §8.5 (the `cc:<keyword>`
  family), §8.6 (the conventions refused by design; the rule for
  conventions per target), §9 (the printer's `cc`).
- `spec/codegen.md`: one reason renamed in WP-082's notes.

## What it did

| where | change |
|---|---|
| `hod_ir` `attrs.rs` | `CallConv::keyword` is LLVM 22's keyword for every number that has one (64 of them, `riscv_vls_cc(N)` included), `keyword_since` the first major with it (22 for 112 and above, else 19), `from_keyword` the inverse; constants for the x86 conventions |
| `hod_ir` `classify/matrix.rs` | 11 new `cc:*` rows (below); `coldcc`, `ghccc`, `anyregcc`, `tailcc`, `swifttailcc`, `preserve_nonecc` are `unplanned` on x86-64 as on AArch64 (were `T-X64`); the family `cc:<number>` is `cc:<keyword>` |
| `hod_ir` `classify/walk.rs` | a convention without a row is named by its keyword, by its number only where LLVM has none |
| `hod_ir` `print/module.rs` | the keyword where the dialect has it, else `cc N` |
| `hod_ll` `attrs.rs`, `call.rs`, `globals.rs` | one `Parser::call_conv` for both sites; the keyword table is `hod_ir`'s (it dropped `m68k_intrcc`, which LLVM does not read, and corrected 108/109, which are `riscv_vector_cc` and `aarch64_sme_preservemost_from_x1` at 110/111 in LLVM); `riscv_vls_cc(N)` |
| `hod_bc` | nothing: it reads numbers |

## The rows

| row | AArch64 | x86-64 |
|---|---|---|
| `cc:x86_stdcallcc`, `cc:x86_fastcallcc`, `cc:x86_thiscallcc` | refused: an x86 convention | refused: a 32-bit x86 convention |
| `cc:intel_ocl_bicc`, `cc:hhvmcc`, `cc:hhvm_ccc` | refused: an x86 convention | unplanned |
| `cc:x86_64_sysvcc` | refused: an x86 convention | **supported**, assigned as `ccc` |
| `cc:win64cc` | refused: a Windows construct | refused: a Windows construct |
| `cc:x86_vectorcallcc` | refused: an x86 convention | refused: a Windows construct |
| `cc:x86_intrcc` | refused: an x86 convention | refused: interrupt handlers |
| `cc:x86_regcallcc` | refused: an x86 convention | refused: `__regcall` |

`llc` 19 and 22 for AArch64 abort ("Unsupported calling convention") on
each x86 convention except `win64cc`, which AArch64 Windows uses.

## Evidence

- `x86_64_sysvcc` against `ccc`: one module with arguments of every class
  (`i32`, `i64`, `ptr`, `double`, `float`, `i128`, `x86_fp80`,
  `<4 x float>`, `fp128`, `byval`, `signext`/`zeroext`), more than six
  integer and eight `double` arguments, two-register and memory struct
  returns, `sret`, a variadic call and `<8 x float>`: `llc` 19 and 22,
  `-O0` with fast instruction selection and without, SSE2, `+avx2`,
  `+avx512f`, write identical assembly for the two conventions.
- `hod_bc` `tests/x86_64.rs` `calling_convention_keywords_are_llvms`: for
  LLVM 19 and 22, `llvm-dis`'s spelling of each number 0 to 130 and 1023
  is `keyword()`'s (or `ccN`) per `keyword_since`; `hod_ll` and `hod_bc`
  read them to the same numbers; the printer's text of each dialect goes
  through `llvm-as` and `llvm-dis` unchanged.
- `hod_ir` `tests/classify_rules.rs`
  `x86_conventions_are_named_by_keyword`,
  `what_has_no_row_is_named_after_itself` (`cc:arm_apcscc`,
  `cc:riscv_vls_cc(32)`, `cc:42`).
- `cargo xtask x64census --shipped -j 4` over WP-138's sample (375
  modules). Before (WP-138): 370 ready; front-half refusals `cc:78` (the
  two `fp80` probes), and `cc:79`, `cc:80`, `cc:92` (kiln's
  `dcl.attr.cconv` test). After: the two `x86_64_sysvcc` probes are
  ready; the `dcl.attr.cconv` test is refused as `cc:win64cc`,
  `cc:x86_regcallcc`, `cc:x86_vectorcallcc`. Still 370 ready: two
  modules that were ready under WP-138 are now refused by names other
  packages added since (`module:asm`, `abi:byval-align`); the 2
  `ll:ParserUnsupported` probes are unchanged.
