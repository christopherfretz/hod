## Proposal: slot moves (cut 4, not implemented)

A census of hod's text after cut 3 over every third module of the
corpus (966 modules, 1,455,401 bytes, `llvm-objdump` per instruction):

| pattern | count | bytes a cut saves | share of text |
|---|---|---|---|
| `[rbp - d]` with a 32-bit displacement that fits 8 bits | 63,826 of 78,556 `[rbp - d]` operands | 191,478 (3 each) | 13.2% |
| a store to a slot followed by a load of the same slot | 4,015 | 19,188 (the load, or a 3-byte `mov r, r`) | 1.3% |
| an immediate stored to a slot through `r10`/`r11` | 264 | 528 | 0.04% |
| `mov r, r` to itself | 238 | 647 | 0.04% |

The largest shapes by bytes: `mov r32, [rbp - d]` 11.0%, RIP-relative
`lea` 9.5%, `mov r, r` 5.8%, `call` 5.8%, `mov r64, [rbp - d]` 4.3%,
stores to slots 7.5%.

1. **Short frame displacements** (13%). Every local access is emitted
   with a 32-bit displacement because `FRAME` and the save set are
   known only at the end (`common::frame_inst`, `LOCAL_SITES`). Those
   sites are already recorded; once the final bias is known, a site
   whose displacement fits a signed byte is rewritten in place (ModRM
   `mod` 10 → 01, the byte written) and its 3 high bytes cut with
   `FnCx::cut`, the same mechanism as the prologue. Cost: one more
   `Edits` range per site (8 bytes of scratch each; a few hundred
   thousand on the largest function), one map over each row table, which
   `shrink` already does; with relaxation, the fixpoint runs over more
   ranges (a binary search per lookup). Expected compile time: below
   the noise of the measurements above, as cut 2 was; it should be
   measured on `cleanup-scopes-30k`. Debug information: none, since
   every row moves with the code, and `DW_OP_fbreg` offsets are
   frame-relative, not encoding-relative. Ordering local slots so the
   most used are nearest `rbp` raises the share further.
2. **Store-then-reload** (1.3%): a peephole in `hod_cg`'s spill of a
   value it reloads at once (`policy`): keep the register for the next
   instruction. It changes which register holds a value at a line
   boundary, so the variable rows (which name the slot) stay right
   only if the store is kept; the load alone can go. Cost: a
   one-instruction look-behind in the driver.
3. The other two are too rare to pay for themselves.
