# WP-112 — module-level assembly (AArch64), `callbr` with outputs

Landed: `crates/hod_asm/src/module.rs` (`assemble_module`, `ModuleCode`),
`asm:unaligned` in `reason.rs`; `crates/hod_cg/src/emit/module_asm.rs`
(placing the text's sections and symbols, one hook in
`ModuleEmitter::new` and one in `module_asm_symbols`);
`crates/hod_a64/src/inline_asm.rs` (outputs of a `callbr` on each
indirect edge); the matrix row `module:asm` (supported on AArch64, still
not implemented on x86-64); `spec/asm.md` §9, `spec/codegen.md` §5.5.3
and §9.7.3.

## What changed for a module

- AArch64: module text that is not only symbol directives is assembled
  (`spec/asm.md` §9) and placed first in its sections, as `llc` places
  it. What `hod_asm` does not read is refused at emission by its
  `asm:*` name; `classify` passes the module. Text of symbol directives
  only is WP-075's as before.
- x86-64: unchanged, `module:asm` (in `classify` and in emission); the
  text never reaches the AArch64 assembler.
- `callbr` with outputs is no longer `a64:inline-asm-form`.

## LLVM 19 against 22

- A code section the text creates (`.section .text.foo,"ax"`): LLVM 19
  gives it alignment 1, LLVM 22 gives 4. hod follows 22; the test
  normalises 19's.
- `callbr` with two outputs (seed `goto_out2`): LLVM 19 reloads a
  spilled output on the indirect edge before storing it, so the indirect
  path reads a stale value (`goto_out2(0)` returns garbage + 500); LLVM
  22 stores first. hod follows 22; the seed test expects that one
  failure of `llc` 19's object.

## Evidence

- `crates/hod_cg/tests/emit_module_asm.rs`: 23 module texts (the corpus
  shapes; every data directive spelling; strings; `.zero`/`.space`/
  `.skip` with fill; data and code alignment with and without fill;
  `.bss`; standard and suffixed section names with flags; section stack;
  symbol directives on labels; `.set`/`.equ`/`=`; `.L` temporaries;
  local, global and undefined references from code and data; numeric
  labels; code and data mixed; text before a function and before
  variables; declarations defined by the text, with IR visibility) equal
  `llc` 19's and 22's objects: sections with bytes, symbols,
  relocations, code-section mapping symbols. 18 refusals by name; x86-64
  stays `module:asm`.
- `crates/hod_a64/tests/inline_asm.rs`: seeds `goto_out` (one output, two
  indirect labels) and `goto_out2` (two outputs) run under bfd, lld and
  mold, dynamic and static, for hod (plain, stress, far) and `llc`.
- Corpus: the 3 module-asm modules (`ext.gnu.extension/extension-asm`,
  `expr.call/run-aarch64-overaligned-aggregate{,-gcc}`), `dcl.asm/asm-goto`
  and the two `stmt.goto` modules with `callbr`, plus
  `basic.start.main/stdin` (directives only), LLVM 19 and 22: `corpus
  reasons` 14 of 14 compiled (base: 6 compiled, 6 `module:asm`, 2
  `a64:inline-asm-form`); `corpus verify --strict`: 42 of 42 PASS (bfd,
  lld, mold).
- Unchanged output: 614 corpus modules without module assembly
  (every third LLVM 22 module, every tenth LLVM 19), base `6357a12` and
  this package: 567 objects byte-identical, 47 refused identically.
- Mutations caught: code padding of zeros instead of `nop`s
  (`code-align`); a PC-relative reference to a global label resolved in
  place (`references`); no output written on the indirect edge
  (`goto_out`, `goto_out2`).

## Tests elsewhere

`module asm "nop"` was the fixture of a stable module-pass refusal
(`crates/hod/src/lib.rs`, `crates/hod/tests/{front,session}.rs`,
`crates/hod/tests/data/front.{ll,bc}`, `crates/hod_cli/src/driver.rs`,
`crates/hod_cli/tests/cli.rs`): now the tiny code model
(`module:code-model-tiny`, unplanned). `crates/hod_cli/tests/kiln_e2e.rs`'s
fallback program adds `.ident` to its file-scope `asm`
(`asm:directive/ident`). `crates/hod_cg/tests/emit_llc.rs` names
`asm:directive/cfi_startproc` instead of `module:asm`. `kiln_e2e.rs`'s
`is_construct` takes the `asm:` family.
