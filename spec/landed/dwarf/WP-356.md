# WP-356: the parser's metadata nodes and the DIE writer: own costs (two cuts kept)

Base `422cfcb3`. Kept: `node_body` checks a node's required fields with
one mask per kind and remembers the fields outside the record lazily
(`56026792`); `Made::define` builds the node in place instead of
returning it (`cfac7ede`). Reverted after measuring: the fed node loop
moving the lexer only when needed, and `quick_location` matching by
length first. Measured and not built: the copy of the node under
construction in `constructing_node`. Not built (memory): a larger
recording cap, keeping the headers' tokens, keeping decoded nodes for
`Writer::die`. Whole program at the head over the 20 bench inputs:
-13.17 M (AArch64) and -13.09 M (x86-64); `stl-heavy-g` -0.6%. Every
bench object byte-identical to the base's.

## Method

As WP-349: whole-program instruction counts (callgrind, `HOD_THREADS=1`,
`--strict -O0 -filetype=obj -relocation-model=pic`, `-mtriple` for
x86-64) of two binaries on the same input, counted by one script in one
session for both, the base copied to `bin-base/hod` before the first
edit and each variant to a directory of the same name length. Ranking by
a function's own cost; the cost of a site measured by doubling it (a
measurement-only change, never committed). A cut that shows less than
1 M on `stl-heavy-g` in the whole-program count is not kept on its own.

## The cuts, each measured whole-program

1. `56026792`: `node_body` checks a node's required fields with one
   mask per kind (`required_mask`, built once); the check by name still
   runs to find the first missing field, so the message is the same. The
   fields outside the record are kept in a `Vec` set up only when one
   appears (it was an array of 48 slices set up for every node).
   `stl-heavy-g` -4.80 M (x86-64) / -4.95 M (AArch64); `templates-g`
   -2.30 / -2.31 M.
2. `cfac7ede`: `Made::define` builds the node in place (`Made::fill`)
   instead of getting it back from `Made::node`, so the returned node is
   not copied. `stl-heavy-g` -1.10 M (x86-64) / -1.00 M (AArch64, 0.996 M:
   at the threshold); `templates-g` -0.46 / -0.46 M. Kept: at least 1 M
   on x86-64, the primary target.

## Measured and reverted

- The fed node loop moving the lexer (`seek`) only for nodes read
  through the lexer: `stl-heavy-g` -0.03 M (x86-64) / +0.01 M (AArch64).
  With `HOD_THREADS=1` the node loop is not fed. Never on the branch.
- `quick_location` matching a field name by its length first, then its
  bytes: `stl-heavy-g` -0.49 M (x86-64) / -0.68 M (AArch64);
  `templates-g` -0.27 M. Under 1 M; never on the branch.

## Measured and not built

- `constructing_node` (`hod_dwarf` `types.rs`) copies the decoded
  `DiNode` (at most 176 bytes) out of the `constructing` stack at every
  construction step. Doubled (the found node passed once more through
  memory), the head against the doubled build on `stl-heavy-g` x86-64,
  one script: 957.17 -> 956.82 M, -0.35 M, i.e. the copy costs less than
  the counts' noise, far under the 2 M that would justify making
  `construct` borrow the node. Not built.
- The recording cap (`Recording::MAX`): `huge-function` has one body of
  about 94,000 lines; its peak memory at the base is 11.3 MiB (14.2 MiB
  with `-g`). Recording the whole body at 16 bytes a token costs several
  MiB, more than the 2% / 3 MiB peak memory may grow by. Not built.
- `define` / `declare` headers lexed twice: keeping the index's tokens
  for every header until the parse costs 16 bytes a token for the whole
  module. Not built (memory).
- `Writer::die`'s full decode per DIE (3.32 M by WP-349's doubling):
  keeping the nodes decoded while planning costs memory per DIE. Not
  built (memory).

Without `-g` the cost is the mask table of cut 1, built once at the
first node `node_body` checks (about 5.4 k per input). All 40 bench
objects equal the base's by `cmp`; `llvm-dwarfdump --verify` (LLVM 22)
passes on `x64 stl-heavy-g` and `a64 templates-g`.

Peak memory (`/usr/bin/time -f %M`, the least of five interleaved runs
of each binary): no input moved beyond the measurement's noise. The ten
inputs without `-g`, which run none of the changed code but the mask
table, moved by -736 to +1,100 KiB (up to 10%) from one set of runs to
the head; the `-g` inputs moved by -1,704 to +532 KiB, several with
opposite signs on the two targets (`containers-g` +532 / -568,
`exceptions-g` -188 / +528; `stl-heavy-g` 33,488 -> 32,816 KiB AArch64,
33,888 -> 33,204 KiB x86-64; `huge-function-g` +524 / -568 KiB). Both
cuts hold less memory, not more (no 48-slice array per node, no
returned copy).
