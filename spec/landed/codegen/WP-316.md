# WP-316 — i386: varargs bodies, atomics, dynamic stack (design 0008 I11b)

Landed: `crates/hod_x86/src/va.rs`, `atomic.rs`, `dynstack.rs`.
Behaviour: `spec/codegen-x86.md` §12 (and the §7 rows). Tests:
`crates/hod/tests/i386_va.rs`, `i386_atomic.rs`, `i386_dynstack.rs`
(run harness `crates/hod/tests/i386_i11b/mod.rs`).

Edits outside the three modules: `lib.rs` (`pub mod atomic; dynstack;
va;`); `target.rs` (ordered `load`/`store` and the `extractvalue` of a
`cmpxchg` result before the x87 arm; the `Fence`/`CmpXchg`/`AtomicRmw`
arm, the dynamic `alloca` and `va_arg` arms; `begin_function` calls
`dynstack::check`; the `dynamic_slot` glue calls
`dynstack::dynamic_slot`); `call.rs` (the `va_*` and
`stacksave`/`stackrestore` arms); `x87.rs` (one arm of `x87::barrier`
into `atomic::barrier`). No encoder, `hod_cg`, `hod_ir` or `hod_obj`
change.

## What `llc` 19 and 22 do (measured, `-O0 -global-isel=0 -fast-isel=0`)

Each construct alone in a function, at CPU `generic` and `i686`, both
versions alike:

| construct | `llc` | label (block boundary) | call |
|---|---|---|---|
| `atomicrmw xchg`/`add`/`sub`, 1 to 4 bytes | `xchg`, `lock xadd` | no | no |
| `atomicrmw and`/`or`/`xor`, 1 to 4 bytes, result used | `lock cmpxchg` loop | yes | no |
| the same, result unused | `lock and`/`or`/`xor` | no | no |
| `atomicrmw nand`/`max`/`min`/`umax`/`umin`, 1 to 4 bytes (used or not) | `lock cmpxchg` loop (min/max: 3 labels at `generic`, 2 with `cmov`) | yes | no |
| every `atomicrmw` at 8 bytes | `lock cmpxchg8b` loop | yes | no |
| `atomicrmw fadd`/`fsub` (`float`, `double`) | loop: `fld`, `fadd`/`fsub`, `fstp` at the type, `lock cmpxchg`/`cmpxchg8b` | yes | no |
| `atomicrmw fmax`/`fmin` | the same loop around `fmaxf`/`fmax`/`fminf`/`fmin` | yes | yes |
| `cmpxchg` strong and weak, 1 to 8 bytes | `lock cmpxchg`, `lock cmpxchg8b` | no | no |
| ordered load / store, 1 to 8 bytes; `fence` | `mov`/`xchg`; `fild`/`fistp` (8 bytes without SSE2); `mfence` or `lock or [esp], 0` | no | no |
| `va_start`, `va_copy`, `va_end`, `va_arg` (`i32`, `double`) | pointer arithmetic | no | no |
| dynamic `alloca` (align 4 and 32), `stacksave`, `stackrestore` | `esp` arithmetic | no | no |

## Decisions

- Barriers (§11, §12.4): the `atomicrmw`s with a label above,
  `atomic::barrier`. Shapes: `i386_atomic.rs::barrier_shapes_run_as_llc_s`
  (28 constructs between an x87 result and its use, `float` and
  `double`, `generic` and `pentiumpro`, `llc` 19 and 22, hod plain and
  under `Stress::ALL`: 224 shape lines equal `llc`'s). Without the new
  arm the test fails (`and32`, the first barrier shape). The x87 shape
  counts did not move: 288 equal `llc`, 72 equal the model, 190 integer
  intrinsic runs equal `llc`, 2 follow LLVM 22.
- The IR `va_arg` instruction stays refused by the shared classifier
  (`inst:va_arg`) on every target; `va.rs`'s lowering is tested through
  `hod_x86` directly.
- libatomic stays refused (`x86:atomic:libatomic`, `x86:atomic:no-cx8`):
  `hod_cg`'s runtime table has only 64-bit-`size_t` signatures of the
  generic routines and no `__atomic_*_8`.
- **Deviation:** 64-bit atomic loads and stores through x87
  `fild`/`fistp` also with SSE2 (`llc`: `movq`); same behaviour.
- **Deviation:** over-aligned slots through `hod_cg`'s per-slot dynamic
  area instead of `llc`'s frame realignment; same behaviour.
- Stack probes stay refused (`x86:probe-stack`).
- `cmpxchg` result layout: value at offset 0, flag at
  `field_offset(ty, 1)` (the general `extractvalue` must agree).

## Refusals

Removed: `x86:atomic`, `x86:dynamic-alloca` (both now unreachable; the
constants stay in `mem.rs` and `frame.rs`). Narrowed: `x86:varargs`
(`va_start` outside a variadic function). New: `x86:varargs:va-arg-type`,
`x86:atomic:no-cx8`, `x86:atomic:libatomic`, `x86:atomic:float-op`,
`x86:atomic:op`, `x86:atomic:type`, `x86:probe-stack`.

## What remains

- `atomicrmw` `fadd`/`fsub`/`fmax`/`fmin` (`x86:atomic:float-op`), which
  C++ `std::atomic<float>::fetch_add` produces. `llc`'s sequence is
  above: the old value loaded, `fld old`, `fadd`/`fsub` the operand (or a
  call of `fmaxf`/`fmax`/`fminf`/`fmin` with both on the stack), `fstp`
  at the type (the value stored is rounded to the type; `double` sums are
  rounded twice, 64-bit then 53-bit, as `llc`'s), `lock cmpxchg` /
  `lock cmpxchg8b`, `jne` back. `llc` passes the old value through
  `fld`/`fstp`, which quiets a signalling NaN in memory and then never
  matches it (an endless loop): an implementation moving the bits
  through integer registers differs only there. Under PIC the libm call
  needs `ebx` free at the loop's start (`pic::emit_call` takes it).
- libatomic calls (a `hod_cg` runtime-table change), stack probes (the
  prologue in `frame.rs`).
- Tests outside this package that still exclude i686 with a comment
  naming `x86:dynamic-alloca`: `crates/hod/tests/alwaysinline_vla.rs:44`
  (could now run on i686 with an i686 module),
  `crates/hod/tests/hardening.rs:43`,
  `crates/hod/tests/kiln_forwarded_options.rs:92`,
  `crates/hod/tests/stack_probe.rs:38` (probes: now `x86:probe-stack`).
