# WP-165 — moving kiln's pin from `bd60e1829` to `22905b77d`

Landed: kiln 1.1.0 at `22905b77d` (215 commits after the pin, kiln 1.0.1
at `bd60e1829`) built beside the pinned one, both corpora's kiln groups
captured again with it, what changed for hod measured, the switch
written down (`docs/VALIDATION.md` "Moving kiln's pin") and rehearsed,
and every in-repository file the switch needs regenerated against the
new corpora. Two small harness fixes found on the way.

GCC groups were kept, not captured again (they do not depend on kiln).

- **Refusals.** None new, on either target, by first refusal or by
  census: the declined modules and their reasons are the same set
  (AArch64: `cc:win64cc`, `debug:dbg-value`,
  `intrinsic:llvm.aarch64.ldxr.p0`, one module each per major; x86-64:
  the 14 of `docs/status/reasons-x64.md`). `cargo xtask x64census
  --shipped` over the x86-64 kiln groups: the same front-half and
  shipped-matrix reasons, by the same module counts, before and after.
- **No test was removed**; 111 were added (103 AArch64 entries per
  major, 104 x86-64, after skips). Of the tests in both captures, 20
  modules per major and target differ beyond kiln's `ident` string
  (coroutine frames: allocas outside the frame, `basic.contract.eval`,
  module interface units, the reflection debug-info tests); the other
  1414 (AArch64, LLVM 22) are the same text.
- **Against `llc`.** Every changed or added kiln entry (123 and 121
  AArch64, 124 and 122 x86-64, LLVM 22 and 19) through `irdiff` strict
  with bfd, lld and mold, x86-64 under `qemu-x86_64`: every module hod
  builds passes (366 + 360 + 369 + 363 results); the one decline per
  major is `debug:dbg-value` of
  `kiln/llvm*/conformance/class.temporary/lifetime-markers-O2-g-fpic-run.cpp.ll`,
  declined the same before. No hod panic, no `internal-` error.
- **What kiln now writes that it did not** (text of the kiln groups, both
  targets, both majors): `!DIImportedEntity` and `!DINamespace` with
  `!DICompileUnit(imports:)`
  (`conformance/meta.reflection.define.aggregate/define-debuginfo-run.cpp`);
  `vtableHolder:` on a `!DICompositeType`
  (`conformance/expr.reflect/debuginfo-run.cpp`); the intrinsics
  `llvm.sadd.with.overflow.i40`, `llvm.smul.with.overflow.i34`, `.i40`,
  `.i50` and `llvm.abs.i64` (`c/c23/llc-o0-narrow-load-sext-run.c`). No
  new debug-record kind, attribute, section, linkage, comdat kind,
  calling convention, module flag or named metadata. hod builds all of
  them and their programs agree with `llc`'s.
- **Skips.** `needs-env` 3 to 7, `marked-xfail` 8 to 10,
  `needs-toolchain` 33 to 34, `requires` (LLVM 19) 77 to 79 (x86-64 90 to
  92); one new `oracle-unconfirmed` on AArch64,
  `tests/c/c23/llc-o0-i1-compare-run.c`: `llc -O2`'s program differs from
  the reference's (the test is kiln's record of an LLVM selector bug);
  hod's program prints the test's expected output, as the reference's
  does.
- **The two corpora agree**: `corpus compare --target x86_64`, 6404
  tests in both, none behaving differently.
- **Debug information**: `debug run --frontend kiln` with the new
  kiln++, 84 results, 84 PASS (144 debugger sessions, lines and columns
  as before); `debug verify` of the new corpus, 12 of 14 `-g` modules
  built, all clean, 2 declined (`debug:dbg-value`).
- **`roundtrip`** of the new corpus: 6454 entries, all pass; the
  expectation file lists none (the five it listed pass since packages
  landed before this one).
- **Tests with the new kiln++** (`HOD_KILN`, `HOD_REQUIRE_TOOLS=1`):
  `cargo test` of `hod`, `hod_cli`, `hod_ir`, `hod_dwarf`, `hod_a64` and
  `xtask`: all pass.
- **Benchmarks**: `bench/manifest`'s inputs are produced by clang, not by
  kiln; the pin does not move them.
- **The hosted lane** builds kiln with its `cargo xtask dist`, which did
  not change between the two revisions.

## Harness fixes

- `corpus reasons` named its coverage logs `worker-<N>.tsv` in
  `<build>/corpus-reasons`: two runs in one build directory wrote the
  same files. They are now `worker-<pid>-<N>.tsv`
  (`reasons::worker_log`; test `worker_logs_are_per_process`).
- `x64census` read a corpus entry of several modules as one module, and
  refused it as `ll:ParserError` (280 entries of the new x86-64 kiln
  groups). Each module is now checked alone: over the new x86-64 kiln
  groups, 3329 modules, 3319 ready, 10 refused by the front half (the
  reasons above), none unread (`x64census::units`; test
  `several_modules_are_units`; `spec/harness.md` "x64census").

## Where hod's time goes on units of the new kiln

For the decision on kiln's in-process seam (`docs/design/0004-in-process-seam.md`):
a release `hod` built from `main` at `d6b006f1c9`, on the AArch64
reference machine (shared and loaded: 1-minute load about 27), each
module run 9 times per row, `--strict -O0 -relocation-model=pic
-filetype=obj` (and `-debugger-tune=gdb` for `-g`), the object written to
the build directory. Wall time is measured around the process; the read
share is the median of (`read` + `parse` + `bodies`) over the median of
`total` of the phase report (`HOD_TIME_PHASES`, `spec/cli.md` "Phase
report"): reading the input, its module level and its bodies, against
the whole run. "default" is the thread count hod takes under the
machine's jobserver (idle tokens only, so few on a loaded machine).
Bitcode is the module's `llvm-as-22`, read natively (no `convert`).

- `regex-O0`: `kiln/llvm22/conformance/re.alg/regex-match-libstdcxx.cpp.ll`
  of the new corpus (the largest STL `-O0` kiln entry of one module
  after the 21 MB `stress/cleanup-scopes-30k`).
- `reflect-g`: `kiln/llvm22/conformance/expr.reflect/debuginfo-run.cpp.ll`,
  the largest `-g -O0` kiln entry (the corpus has small `-g` units only).
- `regex-g`: the same regex test compiled by the new kiln++ with `-g`
  (`-std=c++26 -fclang-compat=22 -g [--target=x86_64-unknown-linux-gnu]
  -S -emit-llvm`), not a corpus entry.
