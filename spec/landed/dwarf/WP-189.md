# WP-189 — debug information of real projects

The contract is `spec/dwarf.md` §6.24. This file records what the package
found and did.

## What landed

- `debug:die-unsupported` names its node: `Error::detail` gives the
  kind, the tag and the node number (`DIDerivedType DW_TAG_pointer_type
  (node 12): a pointer with an address space`). `hod_cg` carries it as
  `CgError::UnsupportedDetail`, and the facade as the detail of the
  `Named` construct.
- The abseil statusor_test.cc refusal was an explicit member function
  declaration with a name and a ref-qualifier, or deleted. Family 113,
  "subprogram (member declaration, explicit, qualified)", writes it in
  `llc`'s attribute order. DWARF 4 transcodes it (`checked_later`).
- The abseil numbers_test.cc refusal (`debug:template-address`) was a
  template value parameter that is the address of a symbol the object
  does not define. The bridge now places an undefined symbol at the
  object's symbol of the same index, offset 0. `DW_OP_addrx,
  DW_OP_stack_value` is written as `llc` writes it.
- Split DWARF on x86-64 writes thread-local variables:
  `DW_OP_GNU_const_index N, DW_OP_GNU_push_tls_address`, with the
  `.debug_addr` entry relocated by `R_X86_64_DTPOFF64`. `llc` 22 writes
  the same.
- `debug:template-address` and `debug:tls-location` are kept as names,
  but no path returns them.

## Evidence

- `crates/hod/tests/debug_real_projects.rs` has four tests. Each runs on
  both triples and, where the shape exists, on DWARF 5 and 4. Each is
  compared with `llc` 22's trees and relocations.
- Mutations, each caught by one test and then reverted:
  - explicit before accessibility;
  - addend 1 for an undefined symbol;
  - a detail without the tag;
  - split TLS through a plain symbol relocation.
- Abseil, `hod --strict` with the saved arguments:
  - statusor_test: 0.95 s, 97 MB;
  - numbers_test: 0.33 s, 36 MB.

  Both verify clean. The DIEs these packages touch are identical to
  `llc` 22's:
  - statusor: 6 explicit qualified members;
  - numbers: 6 template address parameters.

  The rest of the full tree comparison stops at the existing
  `fbreg`/`breg31` frame-base residual.
- `cargo xtask debug trees` on 24 probe modules: 20 same, 4 permitted
  (realigned frame), 0 differ. The
  modules cover kiln, clang 19 and clang 22, both targets, DWARF 5 and
  4, and inline/COMDAT and static symbols.
- gdb, linked with bfd, lld and mold: `template_argument` of function,
  variable, member and null pointer parameters is equal to `llc`'s. lldb
  19 `frame variable` type names are equal. For split TLS, `info address`
  and `info scope` are identical (offsets 0x0, 0x8, 0x4).
- `llvm-dwarfdump --verify` is clean on objects and on executables linked
  with lld and mold. bfd executables report "invalid string offset"
  (string tail merging). `llc`'s executables report the same.
- Text and bitcode give the same object for the probes. For the abseil
  modules they differ in the `.debug_line` file and directory order and
  in 9 bytes of `.debug_info`. `llc`'s output is identical across text
  and bitcode, so this is a bug in hod's bitcode reader. It is outside
  this package and recorded as a follow-up.

## The sweep

There are 35 probes:

memptr, variadic, tmpltmpl, lambda, anonunion, bitfield, tls, inlinevar,
enumclass, fnqual, int128, bitint, complex, char8, vector, vla, labels,
blockstatic, imports, callsite, nested, virt, ctors, exc, stl,
structbind, constexprs, nullptrt, attrs, flexible, restrict,
funcstatic_inline, concepts, modulestyle_using, coro_free_local_class.

Each probe went through kiln, clang 19 and clang 22, on both targets
(210 runs). Two flag sweeps were added:

- the first: 10 probes with -gdwarf-4, -g1, -gz, -gline-tables-only,
  -gno-column-info, prefix maps, standalone, pubnames, types, lldb
  tuning and split;
- the second: 6 probes with plain, embed, key instructions, simple
  template names, strict DWARF, template aliases, DWARF 2/3/64,
  no-inline-line-tables and -O1.

At -O0 every run built and verified, except the rows below.

| name | reached by | how to build it |
|---|---|---|
| `debug:template-address` | abseil numbers_test (kiln) | built here |
| `debug:die-unsupported` (explicit qualified member) | abseil statusor_test (kiln) | built here |
| `debug:tls-location` | `-gsplit-dwarf` and `thread_local`, x86-64, all frontends | built here |
| `debug:die-unsupported` "a global variable expression that is not empty" | kiln `-O1`, blockstatic | a `DW_OP_constu`/`stack_value` global location (a constant-folded static) |
| `debug:local-type-scope` | kiln `-O1`, stl | a local type of a function `llc` places elsewhere at -O1 |
| `debug:retained-nodes` | kiln `-O1`, ainline | WP-162 leftover: the abstract entities of an inlined subprogram's retained nodes |
| `debug:dbg-value-*` | `-O1` only | WP-162 leftovers (listed only) |
| `debug:dwarf-version` | `-gdwarf-2`, `-gdwarf-3`, all frontends | a version 2/3 transcoder; not a kiln default |
| `debug:split-dwarf-4` | `-gsplit-dwarf -gdwarf-4`, all frontends | GNU fission forms (`DW_AT_GNU_dwo_name`, `DW_FORM_GNU_addr_index`) |
| `debug:split-dwarf-name` | the harness: clang's dwo name from the source file, not from `-split-dwarf-file` | none (a harness artefact) |
| `module-flag:debug-info-assignment-tracking` | clang `-O1` | `#dbg_assign` (clang only) |
| `module-flag:DWARF64` | clang `-gdwarf64` (kiln rejects the flag) | 64-bit DWARF offsets |
| `attr:no-inline-line-tables` | clang `-gno-inline-line-tables` | inlined code's rows at the call site |

No probe reached any other `debug:*` name (call sites, imports, globals,
inlining, split, line-tables, key-instruction, expression and variable
shapes). Their constructs are the hand-written cases of the WP-087 to
WP-163 tests. kiln does not accept these flags: `-gdwarf64`,
`-gembed-source`, `-gkey-instructions`, `-gsimple-template-names`,
`-gstrict-dwarf`, `-gtemplate-alias`, `-gpubnames`, `-ggnu-pubnames`,
`-fdebug-types-section`, `-glldb`. With clang, `-fdebug-types-section`
becomes an `llc` option (type units) that hod has no flag for.

## Follow-ups

- The order of `.debug_line` files and 9 bytes of `.debug_info` differ
  between text and bitcode for the abseil modules (hod's bitcode reader).
- kiln `-O1`: a non-empty global variable expression, and
  `debug:local-type-scope`.
- `llc` dedups its address pool by symbol; hod keeps one entry per
  attribute. The comparison masks the indices (§6.7).
- Split DWARF 4, and DWARF 2/3.
