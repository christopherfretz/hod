# WP-326: the own cost of the `-g` path (one cut)

Base `73165b3c`. One cut kept: `crates/hod_ll/src/kw.rs` `keyword`, a
word longer than the hashed keywords is compared with the eight long
keywords only. No object byte changes; no public signature of `hod`
changes. The package stopped at its token budget after step 0 and one
cut; a second cut (below) was built and not measured, and was dropped.

## Method

As WP-322: callgrind instruction counts, release profile,
`HOD_THREADS=1`, `hod --strict -O0 -filetype=obj -relocation-model=pic
[-mtriple=x86_64-unknown-linux-gnu] -o out.o in.ll` on the bench inputs
(`cargo xtask bench --generate`, and `--target x86_64`), on the AArch64
build host. Ranking by OWN (exclusive) cost only: `callgrind_annotate`'s
`file:function` lines summed per function over the files its inlined
code comes from (and over its recursion levels). Claims of a gain are
whole-program differences against the base binary, per input, both
targets. Call counts from the call graph are not used for any figure.

Note on the harness: the binary's path and the output path are part of
`argv`, and the dynamic loader and `getenv` read them: a variant binary
under a path of another length shows a constant +2.7 k instructions on
every input (seen on `small-c`, own diff in `__GI___tunables_init`,
`getenv`, `_dl_relocate_object_no_relro`). Paths of equal length remove
it; the head-against-base table below is measured that way.

### The allocator and `memcpy`

The whole program's `malloc` + `_int_malloc` + `free` own cost is
21.5 M on `stl-heavy-g` against 17.9 M on `stl-heavy`: `-g` adds 3.7 M
of allocator work in all. `memcpy` + `memmove` + `realloc` +
`finish_grow` add 5.7 M in all. Who calls them was NOT measured by
doubling or a counter (budget); the call graph was not used.

## Cut kept: long words against the long keywords only

`kw::keyword` (`crates/hod_ll/src/kw.rs`) handles a word longer than the
16 bytes the keyword table hashes by comparing it with every keyword
text (about 250). Debug metadata is full of such words (`DW_TAG_*`,
`DW_ATE_*`, `DIFlag*`, field labels like `templateParams:`). Now a
static list of the eight keywords longer than 16 bytes is searched.
Same result for every word (the existing `every_keyword_maps_to_itself`
test, extended with long non-keywords and a count of the list).

## What remains, by own cost

1. The metadata text parse in `crates/hod_ll/src/debug.rs`
   (`field_value`, `field_name`, `node_ref`, `node_body`,
   `build_debug_fed`, `Made::node`: about 130 M on `stl-heavy-g`, flat:
   no line above 2 M own; per field about 90 + 70 instructions). The

   straight into cells would remove two of the three representations.

3. `MdKind::from_name` (above), `names::dw_tag` binary search with a
   `memcmp` per probe (2.9 M, 9,180 calls), `required` fields found by
   name with `field_index(.., 0)` per node.

   reference check (`stored_refs` + `ref_cells` 12.9 M) and the per-body
   location check (`debug_ids` 8.3 M; `function_of` is computed for
   every location by `DebugInfo::verify` and again per body). A doubling
   of each is the next measurement.
5. DIE planning and writing, about 34 M in all, none above 9.2 M own.
