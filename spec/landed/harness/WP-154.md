# WP-154 — random differential testing (`xtask fuzz`, L10)

Landed: `cargo xtask fuzz` (`xtask/src/fuzz.rs`, `xtask/src/fuzz/`), its
end-to-end tests (`xtask/tests/fuzz_real.rs`), layer L10 in
`docs/VALIDATION.md` ("Random programs (L10)") and the numbers of the
first long runs in `docs/status/fuzz.md`. This file is the command's
contract until `spec/harness.md` has a "fuzz" section.

## Options

`cargo xtask fuzz [--seed N] [--count M] [--target aarch64|x86_64]
[--llvm 22|19] [-j J] [--linker bfd|lld|mold|wild] [--timeout S]
[--reduce-budget P] [--hod <binary>] [--out <dir>] [-v]`

- Seeds `N` to `N+M-1` (defaults 1 and 100). The run is a function of
  the seeds, the target, the LLVM major and the tools' versions: the
  same arguments give the same programs and the same verdicts, whatever
  `-j` is (except for a timeout under load).
- `--llvm` picks `clang-<N>` and `llc-<N>` together (default 22).
- `-j` seeds at once (default 4, at most 16); each child also holds a
  jobserver token (`spec/harness.md` "Jobserver").
- `--linker` links with that linker through the driver's `-B`; the
  default is the driver's own `ld`.
- `--timeout` the time limit of each program (default 5 s), the same on
  both targets, emulated or not: a fuzzed program is only worth running
  if it is quick under the emulator.
- `--reduce-budget` probes a reduction may run (default 300; 0: none).
- `--hod` the hod to test; the default builds the workspace's.
- `--out` where findings, the results file and the work directory go
  (default `<build>/fuzz`).

## Generator

csmith with `--seed S --max-funcs 6 --max-block-depth 4
--max-array-len-per-dim 6`, and `--float` when `S % 3 == 2` (the
flavours `c` and `c-float`). Most programs end in well under a second
natively and in about a second under `qemu-x86_64`. csmith's C++ mode is
not used: clang rejects most of its programs (`(x, NULL) != &p` compares
a pointer with an integer). clang gets `-O0 -S -emit-llvm -w
-Wno-error=incompatible-pointer-types -Wno-error=int-conversion
--target=<triple> -I<csmith include>`: csmith passes a `float *` to its
checksum helper's `char *`, which newer clangs reject by default.

YARPGen is not supported: it is not installed here, and it writes
several files (a driver and the tested functions), which would make
each seed a multi-module program. It is a follow-up behind a tool check.

## What a seed does

In its own directory under the run's work directory:

1. csmith writes `prog.c` (60 s limit, as for every tool);
2. clang writes `prog.ll`;
3. the oracle: `llc -O0 -global-isel=0 -fast-isel=0 -filetype=obj
   -mtriple=<triple> -relocation-model=pic` writes `oracle.o`;
4. hod: `hod --coverage-log=<file> --strict` with the same code-generation
   arguments (no selector) writes `hod.o`;
5. both are linked with `-pie` by the target's driver (`gcc`,
   `x86_64-linux-gnu-gcc`);
6. both run, a cross target's under its emulator with the target's
   system root and baseline CPU (`hod_testutil::Target::emulator_args`),
   with the time limit and 1 GiB of address space. A hod program that
   times out where the oracle's did not is run again with four times the
   limit.

The directory is deleted afterwards unless the seed is a finding.

## Verdicts

| verdict | when | exit status |
|---|---|---|
| agree | same end (exit status or signal), same stdout | 0 |
| refused | hod exited 2 with a coverage-log line whose outcome is `error`; counted by the reason | 0 |
| skipped | `csmith-failed`, `clang-failed`, `both-timed-out`, `oracle-timed-out` | 0 |
| error | `llc` failed or the oracle's link failed: about the oracle's side | 3 |
| finding | `disagree` (end or stdout differs), `hod-failed` (any other end of hod, a panic, no object or coverage log), `hod-link` (hod's object does not link), `hod-hang` (hod's program did not end in four times the limit) | 1 |

A run that cannot start (a tool is missing, a bad option) exits 3 or 2.

## Findings

A finding's directory is moved to
`<out>/findings/<arch>-llvm<N>-seed<S>/` and holds `prog.c`, `prog.ll`,
the objects and programs, `commands.sh` (every command run, in order,
as shell lines with the final paths), `oracle.stdout`, `hod.stdout`,
`hod.stderr`, `verdict.txt` and, from the reduction, `reduced.ll` and
`seed.ll`.

The witness: the module is built with `llc -O2`, linked and run with
four times the limit; the verdict says whether its program agrees with
the oracle's (hod is suspect), with hod's (the oracle or undefined
behaviour of the program is suspect), with both (not reproducible) or
with neither.

## Reduction

The module's text is cut in passes, each a list of edits that keep it
valid IR; a pass tries them in chunks of all, a half, a quarter, ..., one,
and keeps a chunk when the probe still shows the finding. The passes:
function bodies replaced by `ret <type> zeroinitializer` (or `ret void`);
functions nothing names deleted; stores to globals and `call void`
dropped; `br i1` made `br` to its second target; blocks no path reaches
deleted; stores to a local nothing reads dropped; instructions whose
value nothing uses dropped (gaps in the numbering of unnamed values are
accepted by LLVM 19 and 22 and by hod); globals and declarations nothing
names deleted. Rounds repeat while they remove lines, at most six, within
the probe budget.

A probe shows the finding when: `llc` builds it; for `hod-failed`, hod
still fails; otherwise hod builds it, both link (for `hod-link`, hod's
does not), the oracle's program ends as the original oracle's did, and
hod's disagrees with it (for `hod-hang`, times out). The edits are those
that keep a defined program defined, so a probe that still disagrees is
the same kind of finding; the witness on the original module is the
evidence for the triage.

## Seed tests

`seed.ll` is the reduced module as a `tests/ir` seed: a comment with the
command that finds it, `covers`, `llvm: <N>+` (clang's text is read by
its own LLVM and later ones), `xfail(<arch>): <kind>: <detail> (triage
pending)`, an `exit` when the oracle's program did not exit 0, and the
oracle's stdout as `stdout` lines. The target triple, the data layout,
the module id, the source file name, `; Function Attrs` comments and the
`target-cpu`, `target-features` and `tune-cpu` attributes are removed, so
that the seed is built for both targets and names no path of the run.
Checking it in is a person's (or an implementer's) step, after triage:
the `xfail` reason is rewritten to say what is wrong and where.

## Summary

The configuration line, the seeds and the rate (programs per minute),
then one row per verdict, refusals by reason (most first), skips by
why, each error, and each finding with its witness, its directory and
the reduction (`lines before -> after (probes)`); the 50th and 90th
percentile and the longest run time of the oracle's programs; the
results file, `<out>/results-<arch>-llvm<N>.tsv`, one line per seed:
seed, flavour, verdict, detail, the oracle's run time in ms.

## In the gate

`cargo xtask ci` does not run the command: csmith is not a required tool
and `xtask/src/ci.rs` has no step for tools that may be absent. The gate
runs `xtask/tests/fuzz_real.rs` (three seeds on the host, and a hod
wrapper that builds every `xor` as an `or`, which must be a finding that
is saved, blamed on hod by the witness and reduced to a seed test); both
tests skip with a note without csmith, clang 22, `llc` 22 or gcc,
whatever `HOD_REQUIRE_TOOLS` says. A hosted lane would need the `csmith`
package (headers in `/usr/include/csmith`) and a step that runs a fixed
range, for example `cargo xtask fuzz --seed 1 --count 200 -j 4` per
target.
