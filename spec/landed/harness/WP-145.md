# WP-145 — hosted CI on both architectures

Landed: the gate on GitHub's hosted runners of both architectures, in the
development container's Debian 13 with every tool the tests use, ported
from kiln's lanes; a libc++ sweep with kiln and hod natively on x86-64.
Rules: `spec/harness.md` "CI"; what runs where: `docs/VALIDATION.md`
"Hosted CI".

## What changed

- **`.github/workflows/ci.yml`** calls **`ci-lane.yml`** once per runner
  (`ubuntu-24.04-arm`, `ubuntu-24.04`); fan-in jobs `check` and
  `check-x86_64`. A lane's jobs: `kiln`, `lints`, `test`, `irdiff`, each
  in `buildpack-deps:trixie` with `HOD_REQUIRE_TOOLS=1`.
- **`.github/actions/hod-ci`**: the packages (LLVM 19 and 22 with clang
  and lld, binutils, mold, gdb, gdb-multiarch, lldb-19, `qemu-user`, the
  other architecture's cross gcc, g++, binutils, C library and libstdc++),
  Rust 1.95.0, the cargo cache.
- **`.github/actions/kiln`**: kiln++ from kiln's `cargo xtask dist` at
  the commit in **`.github/kiln-revision`** (`bd60e1829`, the revision
  `docs/status/libcxx-hod.md` measured with; hod recorded no revision
  before), cached per commit and architecture, installed in `/opt/kiln`,
  `HOD_KILN` set.
- **`cargo xtask ci --step <name>`** (`xtask::ci::Args`): the lane runs
  `xtask::ci::HOSTED_STEPS` (fmt, clippy, test, irdiff) as parallel
  jobs; `roundtrip` (`NOT_HOSTED`) needs the corpus, which is build
  output of the development machine. Tests:
  `steps_are_selected_by_name`,
  `the_hosted_lane_runs_the_quick_gates_steps` (the workflow and xtask
  agree; the sweep has no gating trigger).
- **`.github/workflows/sweep.yml`**: `sweep/**` pushes and
  `workflow_dispatch`; hod_cli release and kiln++, `cargo xtask shim`,
  kiln's `cargo xtask libcxx std libcxx` in six shards natively on
  x86-64 (strict by default), merged by kiln's `libcxx-results.py`.
- **`hod_testutil::find_tool`** no longer takes the plain name of an
  LLVM tool from `PATH` (`is_unversioned_llvm_tool`; test
  `llvm_tools_are_found_only_by_supported_major`). The hosted runner's
  stock clang++ 18 had written the IR `atomic_cxx` failed on (`expected
  a type`, red on every push since 2026-11-12): an unsupported major,
  not a reader bug.
- **Host-gated tests now on both hosts** through
  `Toolchain::for_target(Target::Aarch64)` or `Target::tool`: `hod_obj`
  `link`, `link_tls`, `link_conventions`; `hod_cg` `emit_link`,
  `emit_eh`; `hod_ir` `print_run`. The ones still AArch64-only, and why:
  `docs/VALIDATION.md` "Hosted CI".
