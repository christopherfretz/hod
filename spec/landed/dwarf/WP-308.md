# WP-308 — the cost of writing debug information, first cuts (`hod_dwarf`)

Item 8 of WP-288's ranked list (`spec/landed/harness/WP-288.md` §6):
`-g` DWARF emission. Three commits on `crates/hod_dwarf/src/` (`types.rs`,
`die.rs`, `func.rs`, `inline.rs`, `early.rs`), each with its counts in its
message. No change to emitted bytes, refusals, error messages or error
positions. Safe Rust, no new dependency, nothing outside `hod_dwarf`.

## Method

As WP-168 / WP-290: Callgrind instruction counts, `HOD_THREADS=1`, the
release profile (fat LTO), `hod --strict -O0 -filetype=obj
-relocation-model=pic [-mtriple=x86_64-unknown-linux-gnu] -o out.o in.ll`
on the bench inputs (`cargo xtask bench --generate`, clang 22), both
targets; base is 1631202c built into its own target directory. Self cost
per function (`callgrind_annotate --inclusive=no`).

Inclusive costs were not usable, as WP-288 found: with fat LTO and the
type graph's recursion callgrind's call graph is cyclic (inclusive costs
above the program total), `--toggle-collect` on `add_chunk` or `finish`
also counts code they do not call, and a build without LTO (tried,
`CARGO_PROFILE_RELEASE_LTO=false`) attributes no better. What is exact
is the number of calls at each call site: with `--dump-instr=yes` each
call carries the source line of its call instruction, and summing the
calls of `DebugInfo::node` by that line ranked the decodes below.

## The profile

The largest cost of the area is not in `hod_dwarf`'s own functions but
in decoding debug nodes for it: `DebugInfo::node` (the store's decode of
a node's fields from its cells, `hod_ir`) was 60.2 M of stl-heavy-g's
1100.5 M on x86-64 (5.5%), 19.4 M of tiny-functions-g's 370.3 M, about

## Cuts

Instructions in millions, base 1631202c -> head.

| input | a64 base | a64 head | x64 base | x64 head |
|---|---:|---:|---:|---:|
| stl-heavy-g | 1079.2 | 1071.2 (−0.74%) | 1100.5 | 1092.2 (−0.75%) |
| templates-g | 760.8 | 754.3 (−0.85%) | 788.0 | 781.5 (−0.82%) |
| containers-g | 224.2 | 222.4 (−0.78%) | 229.9 | 228.1 (−0.77%) |
| tiny-functions-g | 360.8 | 357.6 (−0.88%) | 370.3 | 369.9 (−0.12%) |

1. **A DIE's node decoded once for all its construction steps**
   (`types.rs`, `die.rs`). `construct` runs one step a call and decoded
   the DIE's node again at every step, N+2 decodes for a class of N
   elements, and a member function's subroutine type at every step of
   its signature. The plan keeps the decoded node (and signature types)
   of each DIE whose construction is open, innermost last (the steps of
   the DIEs a step makes run before its next step), and drops it when
   the construction ends. A one-entry cache (tried first) hit half the
   time: a step's `Ensure` starts the construction of another DIE.
2. **A function's subprogram and its unit decoded once**
   (`func.rs`, `inline.rs`, `early.rs`). `UnitPlan::add_function`
   decoded the subprogram node, then again in `collect_entities`,
   `retained_vars` and `record_retained`; it passes the decoded node
   down. `check_functions` decoded the compile unit for every function;
   it keeps the answer for the last unit.
3. The lookup of cut 1 in its own function (clippy).

## Tried, and not taken

- Inclusive profiles (above): not usable on this build.
- Carrying the decoded node in `Task::Construct`: every task of the work
  stack would grow to the size of a `DiNode`, and every push copy it.

## What remains, ranked

1. **The other decodes of `DebugInfo::node`** (48.7 M on stl-heavy-g,
   still 4.5%): one per DIE in `Writer::die` (51 600 on stl-heavy-g),
   `node_of` for class elements (30 300), `scope_field` and `ensure` in
   the type graph (15 500 each), `method_attrs` (twice per method,
   15 800), and about ten per function across phases (`early.rs`,
   `seal`, `seal_imports`, `seal_definition`, `finish_entities`,
   `hod_cg`'s `debug_calls`). Each site alone is 0.1 to 0.5% of an
   input; together they are the one cost of the area above 1%. Cheaper
   decoding (one field without the rest, in `hod_ir`) or a per-plan table
   of what each DIE's writer needs would pay more than more call-site
   caches.
2. `DebugStrings::index` (7.0 M on stl-heavy-g, 0.6%): hashes each name's
   bytes; the store's strings are interned, so an index by the store's
   string id would skip the hash, but `DiNode` hands out bytes, not ids.
3. The rest of the area is spread thin: no other function above 0.4%.
