# WP-156: x86-64 refused debug modules that AArch64 builds

The contract is `spec/dwarf.md` §6.22. This file records what the work
package found, what it changed and what it measured. The oracle is `llc
-O0` 19 and 22 (x86-64 `-fast-isel=0 -relocation-model=pic`, AArch64
`-global-isel=0 -fast-isel=0`).

## The cause

The benchmark inputs `containers-g`, `exceptions-g` and `stl-heavy-g`
stopped at `debug:declare-address` (`hod_cg` `driver.rs` `finish_vars`)
for x86-64 only. The address was not a register value, an argument
slot, a realigned frame or a `byval`/`sret` pointer: it was the constant
`poison` (clang 22, kiln++) or `undef` (clang 19). Clang declares an
empty-class parameter of an `always_inline` callee there, because the
SysV x86-64 ABI passes no argument for an empty record and the inlined
copy of the parameter has no storage. In the bench inputs that is
libstdc++'s unnamed `random_access_iterator_tag` parameter of
`std::__distance`. On AArch64 the tag is an `i8` argument with a slot.
The smallest reproducer is `tests/debug/empty_tag_inlined.cpp`:

```
#dbg_declare(ptr poison, !38, !DIExpression(), !39)   ; t, arg 3 of span, inlined
```

`llc` 19 and 22 drop that declaration
(`SelectionDAGBuilder::visitDbgDeclare` returns on an `UndefValue`) and
write no DIE for the variable, neither in the inlined instance nor in
the abstract one.

## The fix

`declares_undef` in `crates/hod_cg/src/driver.rs`: a declaration of
`undef` or `poison` has no row, the same decision as a dropped address
or a `phi` (§6.18). A retained variable declared there gets §6.4's DIE
without a location, as `llc`. It is target-neutral. No AArch64 input
of the corpus, the `-g` set or `tests/debug` has such a declaration, so
AArch64 objects do not change (below).

## Evidence

- The three bench inputs (clang 22, `--target=x86_64`): `--strict`
  builds, `llvm-dwarfdump --verify` clean (hod and `llc`). `cargo xtask
  debug trees`: containers and exceptions have trees equal to `llc`'s and
  differ only in the count of `.debug_info` relocations against
  `.debug_rnglists` (hod 15 and 85, `llc` 1). AArch64 has the same
  counts, so this was already there (see "Found elsewhere"). stl_heavy
  differs by the classes its AArch64 tree has too: extra pointer and
  reference types in hod, `__alloc_on_move`'s abstract subprograms and
  member typedefs (`iterator_category`) only in `llc`. The ten
  `__distance` subprogram DIEs are equal.
- `crates/hod/tests/declare_undef.rs`: `poison` and `undef`, both
  targets, compiled; trees equal to `llc` 22's, both objects verified;
  the dropped parameter has no DIE; the retained local has one with no
  location.
- `tests/debug/empty_tag_inlined.cpp` (quick tier): gdb and lldb stop in
  the inlined callee and in its caller and print `n`, `*first`,
  `last - first`, `len` and `got`, the same as `llc`'s program. Each
  target has 18 PASS: clang 19, clang 22 and kiln++, times bfd, lld and
  mold, times gdb and lldb.
- Full runs with the release hod: AArch64 540 results (525 PASS, 15
  XFAIL), 1008 sessions; x86-64 520 results (498 PASS, 22 SKIP), 924
  sessions; no FAIL, ERROR or XPASS.
- Objects before (f1e2502) and after: 184 modules (4 refused by both, `debug:dbg-value`), which are the corpus `-g`
  modules for both targets, the bench `-g` inputs for both targets and
  `tests/debug` by clang 19 and 22 for both targets. The only objects
  that changed are the 5 x86-64 modules that were refused before, and
  all AArch64 objects are byte-identical. Over the `-g` set
  (`scripts/debug-gset.sh` with `--target`, 198 modules per target),
  every AArch64 object is byte-identical.
  The 28 x86-64 modules built now: 3 trees equal `llc`'s, 22 differ
  only by the `.debug_rnglists` relocation count, and the 3 stl_heavy
  ones differ by the classes above.

## Census of refusals (first refusal per module, `--strict`)

| reason | aarch64 before | aarch64 after | x86_64 before | x86_64 after |
|---|---|---|---|---|
| corpus `-g` (14) and bench `-g` (10): `debug:dbg-value` | 2 | 2 | 2 | 2 |
| same: `debug:declare-address` | 0 | 0 | 3 | 0 |
| `-g` set (198): `debug:declare-address` | 0 | 0 | 28 | 0 |
| `-g` set: `intrinsic:llvm.x86.sse2.pause` | 0 | 0 | 3 | 3 |
| built | 220 | 220 | 186 | 217 |

The `debug:dbg-value` refusals are the corpus's kiln
`lifetime-markers-O2-g-fpic-run.cpp` (an `-O2` unit, LLVM 19 and 22) on
both targets. No `debug:` reason is x86-64 only now. The one x86-64-only
reason left is not debug information: libstdc++'s
`std::stop_token::_S_yield` calls `__builtin_ia32_pause`
(`thread.jthread/assign.move.pass.cpp`, clang 19, clang 22 and kiln++).
It is already listed in `docs/status/reasons-x64.md`.

## Mutations (caught, reverted)

1. The `undef`/`poison` check removed: `declare_undef` both tests fail,
   and `tests/debug/empty_tag_inlined.cpp` FAILs on x86-64 ("hod declined
   module 0: debug:declare-address").
2. Only `poison` handled: both tests fail on the `undef` (clang 19)
   case.
3. A row given to the declaration (the previous variable's place, a
   wrong location): `trees_equal_llc` fails (a DIE for `t` with a
   location).

## Found elsewhere

- On both targets hod writes one relocation against `.debug_rnglists`
  per `DW_AT_ranges` (a `sec_offset`), where `llc` writes
  `DW_FORM_rnglistx` and relocates only `DW_AT_rnglists_base`. The trees
  comparison reports this as a difference. It is not in the DIE tree and
  is not WP-156's.
- `spec/codegen.md` §9 (the `vars` paragraph, "`debug:declare-address`
  (a `#dbg_declare` of a constant ...)") should now read "a constant
  other than `undef`/`poison`". That file is not in this package's
  ownership.
