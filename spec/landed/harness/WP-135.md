# WP-135: libc++ on x86-64 through hod (L8, emulated)

Landed: `docs/status/libcxx-hod-x64.md` and `scripts/libcxx-hod-x64.sh`
(contract: `spec/harness.md` "libc++ on x86-64 under qemu", "hod in place
of `llc`"). No product code changed.

Measured: `main` at `3a98566` (after WP-146 and WP-147) merged into the
branch, release `hod`, kiln 1.0.1 at `bd60e1829`, under
`qemu-x86_64` 10.0.13, against WP-121's baseline.

## Results

| hybrid | first run (`97f1ccf`) | second run (`3a98566`) |
|---|---:|---:|
| pass (baseline 8,608; 8,609 with the right `target=`) | 8,609 | 8,607 |
| modules built by hod (of 7,226) | 7,088 | 7,191 (99.5%) |
| fallback modules | 138 | 35 |
| hod-only tests | 7,080 | 7,183 |
| back end: hod (hod-built) / `llc` (fallback) | 135.9 s / 97.8 s | 184.6 s / 44.1 s |
| wall time, `-j 3`, 4 shards | 7,889 s | 11,371 s |

- No test that passes with `llc` fails because of hod, in either run.
  The two changes from the first run are environmental:
  `several_threads.pass.cpp` (thread creation under the 3 GiB cap and
  qemu; the `llc`-built binary fails the same way, 1 run in 6) and the
  `offset_range.pass.cpp` timeout (a baseline timeout). Saved under
  `.build/findings/wp135/several_threads/`.
- Fallbacks by first refusal: `abi:byval-align` 14,
  `inst:insertelement/x86_fp80` 13, `x64:vector-wide-element` 5,
  `abi:vector-element` 3. Each is the only module of a test.
- No strict run (the second run has fallbacks); strict is derived from the
  coverage log: those 35 tests fail, 8,572 pass.
- The strict run started on the first binary was stopped at the
  coordinator's request (it would only restate the coverage log).

## Follow-ups

- `crates/hod_x64/src/abi.rs:581` (`byval` aligned above 16) frees 14
  tests, the `num_get` facet tests and `is_always_lock_free`.
- `x86_fp80` and `i128` lanes (`inst:insertelement/x86_fp80`,
  `crates/hod_x64/src/vector.rs:73`, `crates/hod_x64/src/abi.rs:292`) free
  the other 21, all but one in `std/experimental/simd`.
- A rerun rule for load-sensitive tests now covers `several_threads`
  (thread creation under emulation) besides `lost_wakeup`,
  `buffered_reads` and `offset_range`.
