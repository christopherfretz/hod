# WP-239 — wild in the linker matrix

Landed: the wild linker, a pinned release (0.11.0), is the fourth linker
of every linking test, beside GNU ld, lld and mold, on both targets from
the AArch64 development machine; the hosted set-up installs the same
release with its checksum verified. Results and exceptions:
`docs/status/linkers.md`.

## What changed

- `hod_testutil::linkers` (new): the matrix (`MATRIX`), discovery
  (`find_linker`, `present`, `find_wild`: `HOD_WILD`, then
  `.toolchain/wild/0.11.0/wild` in the checkout or above it, then `wild`
  or `ld.wild` on `PATH`), selection (`driver_flags`), the signature of
  each linker in `.comment` (`signer`), and the one table of exceptions
  (`EXCEPTIONS`, `exception`, `tolerated_warning`). `spec/harness.md`
  "Linkers" is the contract.
- The linker lists of the tests now come from it:
  `crates/hod_obj/tests/common/linking.rs` (every `Toolchain`, so every
  test that iterates `toolchain.linkers`), `crates/hod_dwarf/tests/common/session.rs`,
  `crates/hod_eh/tests/common/mod.rs`, `crates/hod_mc_x64/tests/l1/link.rs`;
  `crates/hod/tests/inlining.rs` and `tls_cxx.rs` take the selecting flags
  from the `Linker` (`Linker::driver_flags`) instead of rebuilding them.
  `Toolchain::link_ok` checks wild's signature like lld's and mold's.
- The harness (`xtask`): `Search::from_env` searches the directory of
  `hod_testutil`'s wild first; wild's signature (`Linker: Wild <digit>`)
  is checked; wild is given `--thread-count=1` and `--no-gc-sections`.
- `.github/actions/hod-ci`: a step downloads the release for the
  runner's architecture, verifies its sha256 and exports `HOD_WILD`.

## Decisions

- **Selection by `-B` and `ld`.** GCC 14 refuses `-fuse-ld=wild`; a `-B`
  directory holding wild as `ld` is the program the driver runs (checked:
  the output's `.comment` carries wild's signature, for the host's and
  the cross driver).
- **`--no-gc-sections`.** wild discards unused sections by default. The
  matrix compares linkers on the same inputs, so wild gets the other
  three's default; a test's own `--gc-sections` comes later and wins.
  Without it, the debugger tests' globals that nothing refers to vanished
  with wild only, and a plain section group's unreferenced copy looked
  deduplicated: both were the collection, not a defect.
- **Optional on the hosted lanes.** `WILD_REQUIRED` stays false until a
  hosted run proves the set-up step; then it becomes true and a missing
  wild fails under `HOD_REQUIRE_TOOLS=1` like any other tool.
- **Exceptions as one table.** Five cases, each with a reproduction from
  objects hod did not write (`llvm-mc`, clang, gcc): `section-start`,
  `plt-names`, `link-order` and `merge-constants` (class b), `z-text`
  (class c). No hod defect (class a) was found. A test changes one assertion for an excepted case,
  to the excepted behaviour where it is known.
