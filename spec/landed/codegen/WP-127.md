# WP-127 — x86-64 scalar floating point (X-float)

Landed: `crates/hod_x64/src/float.rs` (instructions of class `Fpr`,
`fcmp` fused into `select` and `br`), `crates/hod_x64/src/fpintr.rs`
(the floating-point intrinsics), the `FUSED_FCMP` hook in
`crates/hod_x64/src/control.rs` (`cond_br`), the `x86_64` column of the
floating-point rows of `crates/hod_ir/src/classify/matrix.rs`,
`docs/status/support.md`, `spec/codegen.md` §5.6.7, the tests
`crates/hod_x64/tests/{float,fpintr}.rs` with their harness
`tests/common/float_gen.rs`, and nine `tests/ir` seeds that now run on
x86-64.

## Differences from `llc` found, and how each was settled

| difference | settled |
|---|---|
| an integer of more than 24 bits to `bfloat`: `llc` rounds to `float`, then to `bfloat` (`uitofp i33 0x1feffffff` is `0x5000`) | hod rounds once (to odd in `float` first); the test's oracle is a model |
| `ldexp` with an `i64` exponent: `llc` truncates it to `i32` (`2^32 + 1` scales by 2) | hod clamps it to `int` (the value LangRef defines); `float`/`double` checked against a model, `half`/`fp128` against `llc` with exponents inside `int` |
| `powi` of `half` in `llc` 19: `(-0.0)^n` for odd `n` is `+0.0` | hod keeps the sign (`llc` 22 agrees); compared with 22 only |
| `minimum`/`maximum` of `fp128`: `llc` cannot select them | hod calls `fminimumf128`/`fmaximumf128`; checked against a model on values that are no NaNs |
| two `fp128` NaNs into `minimumnum`/`maximumnum`: `llc` returns the second unquieted, hod the first quieted | both NaNs, the payload is open: not compared |
| a signalling `bfloat` NaN through a `phi`: `llc` 22 quiets it | hod keeps the bits (a `phi` is a move): not compared |
| `x + -0.0` of a constant: `llc` folds it to `x` | hod computes it (the bits of a NaN `x` differ): not compared |
| `fmul` of `bfloat` with commuted operands in a loop: `llc` picks the other NaN | both NaNs: not compared |
| `canonicalize`, `lround`/`lrint`/`llround`/`llrint` of `half`: `llc` 19 cannot select them | compared with `llc` 22 only |
| `llround`/`llrint` to `i32`, `powi` with an `i8` exponent: no `llc` selects them on x86-64 | hod lowers them; not compared |

`half` `fma` was three pinned pool registers into one call: under the
minimum pool (two vector registers) that is an internal error. It is now
`mulsd` (exact: two `half` significands are 22 bits) + `addsd` in
`double`, which rounds exactly as `llc`'s call of `fma` in `double`.

## Rows

Switched on for x86-64: `type:half`, `type:bfloat`, `type:float`,
`type:double`, `type:fp128`; `inst:fadd` .. `inst:fneg`, `inst:fcmp`,
`inst:fptrunc`, `inst:fpext` for the five floating-point classes (`fcmp`
also `int`); `inst:fptoui`, `fptosi`, `uitofp`, `sitofp` for `int`,
`i128` (WP-040's calls) and the five classes; `inst:bitcast`,
`inst:select`, `inst:freeze` gain the five classes; the intrinsics
`fabs` .. `is.fpclass` for `half`, `float`, `double`, `fp128` (and `int`
where they have an integer operand or result, `aggregate` for `frexp`;
`fptosi.sat`/`fptoui.sat` without `fp128`), as on AArch64 without
vectors.

Named refusals inside those classes: `x64:bfloat-fp128` (a conversion
between `bfloat` and `fp128`), `x64:intrinsic-bfloat` (any intrinsic of
`bfloat`), `x64:intrinsic-fp128` (`fptosi.sat`/`fptoui.sat` of
`fp128`), `x64:fp-intrinsic` (a non-constant `is.fpclass` mask, a `powi`
exponent wider than 32 bits), `x64:intrinsic-wide` (an integer result
wider than 64 bits), `x64:wide-fp-cast` (WP-040: `i128` with `bfloat`).

Left: `x86_fp80` (WP-131), vectors (WP-132).
