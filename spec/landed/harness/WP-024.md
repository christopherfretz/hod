# WP-024 — the harness and the tests as make-jobserver clients

Landed: `spec/harness.md` "Jobserver". Every process a test binary or
`xtask` starts holds a token of the pool `MAKEFLAGS` names, for its
lifetime. Ported from kiln (`xtask/src/jobs.rs`, `xtask/src/util/process.rs`
and its `spec/harness.md` "Jobserver"), by the operator's instruction to
copy rather than redesign.

## What it did

- `crates/hod_testutil/src/jobs.rs`: the client. `Client` (`none`, `open`,
  `describe`, `acquire`, `release_all`), `Token` (released by `Drop`;
  `is_from_pool`), `global()` (the pool of `MAKEFLAGS`, read once),
  `fifo_from_makeflags`, `refill` and `Refill` (the non-blocking count and
  top-up), `idle`, and for tests `PrivatePool` and `LocalDir`.
- `crates/hod_testutil/src/lib.rs`: `run_with` (and so `run`,
  `write_script`, `Scratch::write_script`) takes a token before it starts
  the child and drops it after the child has ended and its output is read;
  the time limit starts once the token is held.
- `xtask/src/jobs.rs`: `global()` (the same client, plus the
  SIGINT/SIGTERM thread), `signals_caught()`, and `cargo xtask jobserver
  status|refill [--fifo <path>] [--jobs <n>]`.
- `xtask/src/jobs/children.rs`: the table of live children
  (`begin_spawn`, `Spawning::spawned`, `LiveChild`, `Stop`),
  `kill_live_children`, `kill_group`, `interrupted`,
  `park_if_interrupted`, and `run_step` for cargo steps.
- `xtask/src/irdiff/process.rs`: `run` takes a token, registers the child
  in the table, and does not return once xtask is interrupted.
- `xtask/src/irdiff.rs`: the header names the pool; the `cargo build` of
  the workspace's hod is a `run_step`. `xtask/src/main.rs`: the `jobserver`
  command; the cargo steps of `ci` are `run_step`s. `xtask/src/shim.rs`:
  `llvm-config --version` goes through `process::run`.
- `Cargo.toml`, `xtask/Cargo.toml`, `Cargo.lock`: `signal-hook` 0.3
  (`default-features = false, features = ["iterator"]`), for `xtask` on
  Unix only; `hod_testutil` is now a dependency of `xtask`, not only a
  dev-dependency. `hod_testutil` and every shipped crate still have no
  third-party dependency. The lock file gained `signal-hook`,
  `signal-hook-registry`, `libc`, `errno` and, for Windows targets only,
  `windows-sys` and `windows-link`.
- `docs/AGENTS.md` "Shared machine": children are started through the two
  functions that count them.

No `unsafe`. `scripts/jobserver.sh` and `scripts/env.sh` are main's
(kiln's helper, ported by the supervisor), unchanged.

## From kiln as it is

The client's state machine and its comments (`Pool`, `State`, `Kind`,
`acquire`, the helper thread, `Drop for Token`), `fifo_from_makeflags`,
`refill` and the `O_NONBLOCK` table, the signal thread, the table of live
children with its `Stop::Kill`/`Stop::Term` and the 3 s and 10 s graces,
`run_step`, the `jobserver` command and its messages, and the tests of all
of these under kiln's names.

## Changed, and why

- **Where the client lives.** In `hod_testutil`, so that test binaries
  and `xtask` share one implementation: hod's tests start most of their
  oracle processes (`llc`, `llvm-mc`, linkers, `gcc`, programs) from the
  test binaries. The signal thread cannot live there (`hod_testutil` has
  no dependency), so `xtask::jobs::global()` wraps
  `hod_testutil::jobs::global()` and starts it.
- **`release_all` waits for the helper** (at most 200 ms). The helper can
  be in a read nobody waits for any more; the bytes `release_all` writes
  wake it, it takes one and writes it back. kiln's signal thread ends the
  process right after `release_all`, so it can end with that byte in the
  helper's hands. Eighty interrupts (the interrupt test forty times, with
  SIGTERM and SIGINT each) did not lose one before the change; the wait
  makes the property a deterministic test
  (`release_all_waits_for_the_helpers_read`) instead of a likelihood.
  `release_all` also zeroes the helper's pending reads, so that it starts
  no other. Worth taking back into kiln.
- **`process::run` parks when xtask is interrupted.** kiln returns an
  `Interrupted` error to runners that know they are about to be ended.
  hod's `irdiff` engine would turn the error, and the "terminated by
  signal 9" of a child the interrupt killed, into ERROR and FAIL records,
  and `ci` would go on to print them; parking the thread, as kiln's
  `run_step` does, needs no change in the engine and leaves no wrong
  result anywhere.
- **Signalling a group** uses `/bin/sh -c 'kill ...'` (what
  `irdiff::process` did already): `irdiff`'s tests run xtask with a `PATH`
  of fake tools only, where kiln's `kill` on `PATH` is not found.
- **Defaults**: the fifo is `MAKEFLAGS`' `fifo:` path, else
  `$HOD_JOBSERVER_FIFO`, else `/run/hod/jobserver.fifo`; the size is
  `$HOD_JOBS`, else the number in `jobserver.jobs` beside the fifo (which
  kiln's command does not read), else 12.
- **Warnings** say `jobserver: warning: ...; running without it` rather
  than `xtask: warning: ...; falling back to -j`: a test binary prints
  them too, and has no `-j`.
- **Not ported**: `run_measured`, `MemLimit`, the RSS probe and
  `run_step_hiding` (hod has no measured runs yet, and its limits are
  already set by `irdiff::process`'s wrapper).
- **Tests make their fifos in the system's temporary directory**
  (`LocalDir`), as kiln's do, not in `Scratch`: the build directory is a
  bind mount here, where the pool script's notes call a fifo unreliable.
  The names are unique per process and call, and the directories are
  removed on drop.

## The refill contract

`scripts/jobserver.sh refill` counts as held one token per child process
of every process that has the fifo open. The client keeps the fifo open
for the life of the process and holds a pool token only around one child
of its own ("What the pool's refill sees" in the spec).
`the_pool_script_does_not_mint_tokens_for_this_client` starts the script
on a pool of its own, runs `refill` twice while a client holds two pool
tokens for sleeping children, and finds the pool exactly full afterwards.

## Evidence

Measured in the shared container (12 tokens in the machine's pool, seven
other agents building through it), `source scripts/env.sh` first.

- `cargo test -p xtask -p hod_testutil`: `hod_testutil` 17 unit tests
  (1.0 s) and `tests/jobserver.rs` 4 passed, 1 ignored (the client the
  others re-run; 3.8 s); `xtask` 51 unit tests (3.2 s),
  `tests/irdiff_fakes.rs` 21 (11.7 s), `tests/irdiff_real.rs` 5 (13.3 s),
  `tests/jobserver.rs` 5 (2.0 s).
- The same with `env -u MAKEFLAGS CARGO_BUILD_JOBS=1` (no ambient pool),
  and the two jobserver test files six times in a row with the pool: all
  pass.
- The interrupt test forty times in a loop (SIGTERM and SIGINT each time):
  every run found the private pool full afterwards.
- **Starvation**: `HOD_REQUIRE_TOOLS=1 cargo test --workspace` with
  `MAKEFLAGS` naming a private pool of one token (so every child of every
  test binary shares two slots with cargo and rustc): passes, 254 s
  including the build; that pool was full afterwards. `irdiff_fakes` took
  45.8 s instead of 11.7 s and `irdiff_real` 27.7 s instead of 13.3 s; no
  wall-clock assertion failed.
- The gate, `HOD_REQUIRE_TOOLS=1 cargo xtask ci --quick`, with the pool:
  `ci: ok`, 129 s wall clock (build, fmt, clippy, the workspace's tests,
  irdiff's quick tier; its header reads `-j 4 (jobserver
  fifo:/run/hod/jobserver.fifo)`).
- Afterwards `scripts/jobserver.sh status` on the machine's pool: "idle
  tokens 12 of 12", and its refill log has no line other than "no refill"
  over the whole session: nothing was lost and nothing minted.

## Open questions

1. **Timing assertions under starvation.** Three tests of WP-016 bound a
   whole `irdiff` run by wall clock (`xtask/tests/irdiff_fakes.rs:434`,
   `:607`: 30 s; `:683`: 40 s; around runs whose children hang for 3 s).
   Before this WP a busy machine made them slow; now it can also make them
   wait for tokens. With a one-token pool they still passed ("Evidence"),
   so the conservative choice was to leave the bounds alone. The per-child
   time limit is not affected: it starts once the token is held.
2. **Children of a private pool are not on the machine's.** A test of the
   jobserver runs a client on a pool of its own; that client's children
   (shell scripts that sleep, fake tools) are counted there, not in the
   machine's pool. The client itself holds a token of the machine's. At
   most 3 such children run at a time per test.
3. **`hod_cli`'s fallback `llc`** (`crates/hod_cli/src/driver.rs:307`,
   `:379`) is started by the shipped `hod`, which is not a client: it runs
   on the token its parent holds for `hod`, one process at a time.
4. **Test binaries that run children through `xtask`** (its own unit
   tests; `hod_cli`'s `tests/kiln_e2e.rs`, through `xtask::shim`) get the
   signal thread, since `xtask::jobs::global()` starts it. That is kiln's
   behaviour for its `xtask` tests; an interrupted `cargo test` then
   returns their tokens too. Test binaries that use only `hod_testutil`
   install nothing, and a SIGKILL or a signal to one of those loses the
   tokens it held until the pool script's next refill (60 s).
5. **A normal exit can lose one byte**: a process that returns from `main`
   while the helper holds a byte nobody waits for ends before the byte is
   written back. The window is the few instructions between the helper's
   `read` and its `write`; kiln has it too. The refill loop is what
   covers it. Not seen in any run.

## Follow-ups

None blocks this WP. The pool script and `env.sh` are main's and were not
changed: nothing found in them made a test fail.

- `scripts/jobserver.sh:196`: `stop` leaves `jobserver.jobs` and
  `jobserver.deficit` beside the fifo, and the refill loop's `sleep 60`
  lives on for up to a minute as an orphan (the loop's shell is killed,
  not its child).
- `scripts/jobserver.sh:171`: `HOD_JOBS=0` makes a pool of one token
  (`printf '%.0s+' $(seq 0)` prints one `+`).
- `scripts/jobserver.sh:164`: `start` when the holder is alive but the
  fifo is gone makes a new fifo and holder and forgets the old holder
  (which keeps the old, unlinked fifo open for ever).
- `scripts/env.sh:26`: names the pool whenever the fifo exists, alive or
  not. A fifo left by a holder that died has no tokens: clients then run
  one job at a time on their implicit slots (they do not hang; `cargo
  xtask jobserver status` shows 0 idle).
  `a_pool_without_tokens_serializes_and_does_not_hang` pins that.
- `scripts/jobserver.sh:183`: `status` on the machine's pool has shown
  "idle tokens 12 of 12; rustc 8": some builds on the machine do not draw
  from the pool (shells that sourced `env.sh` before the pool existed, or
  kiln's builds on their own pool).
- `xtask/src/irdiff/process.rs:168`: when a child's pipes are still held
  after the drain grace, `kill_group` runs after the leader is reaped, so
  the group id could in principle have been reused (as before this WP);
  the table entry also stays for those 2 s, so an interrupt in that
  window signals the same id.
- `crates/hod_testutil/src/jobs.rs`: the `release_all` wait and the
  zeroing of `requested` are candidates for kiln's `xtask/src/jobs.rs`.
- `xtask/src/corpus*`, `xtask/src/bench*` (WP-017, WP-018): any child
  they start must go through `irdiff::process::run` or
  `jobs::children::run_step`; they were not touched here.
