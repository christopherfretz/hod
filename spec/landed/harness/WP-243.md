# WP-243 — the release-candidate checklist of 1.0

Landed: two documents, no code.

- `docs/RELEASE.md` is the procedure for cutting a release candidate: fix
  the candidate commit, kiln's pin and a frozen `hod` binary; then, per
  condition of `docs/VALIDATION.md` "Release candidate", the command or
  lane that produces the evidence, on which target, about how long, the
  page it lands in and what "pass" means; the status pages page by page;
  and the version bump (the workspace `Cargo.toml`, `Cargo.lock`,
  `README.md`; `hod --version` follows `CARGO_PKG_VERSION`), with the
  tag made only on the owner's word.
- `docs/status/release.md` is the checklist: one row per condition with
  the evidence required, the evidence on `main` (page, hod and kiln
  commits, date, the numbers as the pages give them) and a state (`met
  at <commit>`, `re-measure`, `partly`, `missing`, `in progress`). It also
  compares kiln's open-source project set (`kiln/scripts/oss/projects.toml`)
  with the rows hod has measured.

Written 2026-11-14 against `main` `56a4695f` and kiln pin `21b9110a4`:
29 rows, 3 met, 7 to re-measure, 11 partly, 7 missing, 1 in progress.

## Keeping them current

- When a package lands a measurement, the supervisor moves its row in
  `docs/status/release.md`: the page, the hod and kiln commits, the date
  and the state. A row is `met at <commit>` only for a measurement of
  that commit; a later code-generation change makes it `re-measure`.
- When the kiln pin moves (`docs/VALIDATION.md` "Moving kiln's pin"),
  every row measured with kiln becomes `re-measure`.
- When `docs/VALIDATION.md` "Release candidate" or `docs/ROADMAP.md` M6
  changes, both documents change with it in the same commit: a condition
  without a row, or a row without a condition, is a defect.
- At a candidate, `docs/RELEASE.md` is executed top to bottom and every
  row is brought to `met at <candidate>`; the version line and the tag
  row wait for the owner.
- Nothing checks either file mechanically: the repository has no link
  or format check for documents (none in `xtask`, none in
  `.github/workflows`). The only generated page with a test is
  `support.md` (`classify_support_doc`).
