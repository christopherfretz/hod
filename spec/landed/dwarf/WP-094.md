# WP-094 — the debug declines left after WP-087

The contract is `spec/dwarf.md` §6.13 (family 89 appended to §6.1's
table; three entries in §6.7; §6.10's `debug:line-tables-inlined`
narrowed). This file records what the work package did, what it
measured, and what it left.

## What landed
- `crates/hod_dwarf/src/import.rs`: imports scoped in a function's
  lexical blocks, under the blocks' DIEs (a block with an import is
  written; an import whose block has no code is not).
- `src/inline.rs`: `record_entities` / `finish_entities`, `llc`'s
  `finishEntityDefinitions` order of the variables' types; minimal
  abstract instances for line-tables-only units.
- `src/func.rs` (hooks): `record_entities` after each function, the
  types of the variables at seal, template parameters before the return
  type, and a function's own early DIE claimed by its body.
- `src/global.rs`: a function's thread-local `static` without
  `DW_AT_location` on AArch64 (it had `DW_OP_addrx`, an address that is
  not the thread's variable).
- `src/reduced.rs`: line-tables-only functions with inlined code (family
  89).
- `src/early.rs`: `check_functions`, the function-DIE refusals that need
  no code, called by `crates/hod/src/back.rs` before code generation.

## Refused by name (new or changed)
`debug:line-tables-inlined` narrowed to shapes no producer writes;
`debug:import-scope` narrowed to block files, other functions' blocks and
functions with an abstract instance. Checked before code generation:
`debug:subprogram-not-definition`, `debug:subprogram-attribute`,
`debug:variable-without-type`, `debug:variable-alignment`,
`debug:fragment`, `debug:expression`, `debug:label-attribute`,
`debug:import-scope`, `debug:import`, `debug:subprogram-twice`.
`debug:inlined-member` stays: no source reaches it through clang 19,
clang 22 or kiln++.

## Tests
- `crates/hod_a64/tests/dies_decline.rs`: 19 trees equal to `llc`'s
  (imports in blocks, type order, a function's own early DIE,
  thread-local statics, `-gline-tables-only` with inlined code; clang 19,
  clang 22, kiln++), both objects `--verify` clean; the three permitted
  differences, each held to its shape; 36 gdb and lldb sessions (imports
  in blocks, thread-local statics) equal to `llc`'s under GNU ld, lld and
  mold.
- `crates/hod_dwarf/tests/early.rs`: each early refusal by name, a
  subprogram with two bodies, a line-tables-only unit left alone.

## Mutations (caught, reverted)
1. The variables' types in DIE order (`inline.rs` `finish_entities`):
   `order.cpp`'s tree differs (a reference type moves).
2. A function's own early DIE not claimed (`func.rs` `function_body`):
   `own_early.cpp` by kiln++ refused `debug:local-static`.
3. A thread-local static left to the plain path (`global.rs`
   `discover_scope_global`): `tls_static.c`'s variable gets a location.

## The two `debug:dwarf-version` modules
Both are kiln's `meta.reflection.define.aggregate/define-debuginfo-run.cpp`
(the `llvm19` and `llvm22` conformance lists), compiled with
`-gdwarf-4` (`"Dwarf Version", i32 4`). Writing DWARF 4 would take a
second form set for every family of §6.1 (`DW_FORM_strp` into
`.debug_str` for `strx` and the string-offsets table, `DW_FORM_addr`
with a relocation for `addrx` and `.debug_addr`), a version 4 unit
header, `.debug_ranges` and `.debug_loc` for the range and location
lists, a version 4 `.debug_line` header (string include directories
and file names, no MD5, files from 1), static members as `DW_TAG_member`
(family 55 exists), and `DW_OP_addr` in expressions. gdb and lldb read
version 5, so the refusal costs only the tools that read only version 4;
it is a work package of its own, worth doing when a user needs it.
