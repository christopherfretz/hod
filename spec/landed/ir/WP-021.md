# WP-021 — pre-opt modules: `available_externally` and `alwaysinline`

hod accepts a front end's module before LLVM's `-O0` pipeline
(`-S -emit-llvm -O0 -Xclang -disable-llvm-passes`) in place of
`opt -passes='default<O0>'` + `llc -O0`, when `alwaysinline` is the only
trigger of that pipeline in it. The rules are `spec/cli.md`
"Always-inline"; the copy's layout `spec/codegen.md` §9.7.2; the design
`docs/design/0001-input.md` point 6.

## What it did

| where | change |
|---|---|
| `crates/hod/src/session/inlining.rs` (new) | `Inlining`: `available_externally` bodies are verified and held or discarded (`divert`); accepted bodies whose meaning depends on being inlined are noted (`note`); `conclude` walks the direct calls of every accepted body, then of the copies it reaches, declines a call that may have been inlined into a sensitive body, and returns the copies to compile. `hod::inline_reason` (6 stable names) |
| `crates/hod/src/session.rs` | hooks: `judge_body` → `inlining.divert` (the old body of `judge_body` is `judge_built`), `accept` → `inlining.note`, `conclude` → `inlining.conclude` before sorting |
| `crates/hod_cg/src/emit/copy.rs` (new) | `<name>.alwaysinline` local `STT_FUNC` copy; branch relocations to it, the rest to the external symbol |
| `crates/hod_cg/src/emit/mod.rs` | hooks: `add_func` (skip a non-copy `available_externally` function, place a copy), the code relocation loop and `finish`'s pending loop (`copy_target`), `finish` skips an `available_externally` alias |
| `crates/hod_ir/src/classify/matrix.rs` | `linkage:available_externally` ON on AArch64 (x86-64 stays `todo`); `attr:alwaysinline` note |
| `crates/hod_cli/src/driver.rs` | under `--strict`, a command line rejected as `unknown-option` exits 2 (`usage` stays 1); `spec/cli.md` "Exit status" |
| `scripts/preopt-corpus.sh`, `scripts/preopt-census.sh` (new) | the pre-opt form of every single-module kiln corpus test, and the first-refusal census of both forms |

The readers' linkage mapping needed no change (`available_externally`
was already read on both). A copy is made at object level, not by
rewriting IR: a copy is the same code under a second, local name, and
only branch relocations choose between the names.

## Accepted, declined, refused

- Accepted: the trigger set is empty or exactly {`alwaysinline`}.
- Declined by name (status 2 in strict mode), when a direct call may have
  been inlined: `alwaysinline:frame-address`, `alwaysinline:return-address`,
  `alwaysinline:stacksave-escapes`, `alwaysinline:returns-twice`,
  `alwaysinline:returns-local-address`, `alwaysinline:frame-register-asm`.
  "May have been inlined": the callee is a copy, or the module has any
  `alwaysinline` attribute set (call-site sets are in the same table and
  the readers do not say which call carries one, so this is
  conservative). LLVM leaves `returns_twice` out of line; it is declined
  by request. Today non-empty inline assembly is refused anyway
  (`call:inline-asm`), so `frame-register-asm` fires only on empty
  templates whose constraints name a frame register.
- Refused by name today, so declined: the other triggers of `default<O0>`
  (`attr:instrument-function-entry`, `-entry-inlined`, `-exit`,
  `attr:presplitcoroutine`, `intrinsic:llvm.coro.*`,
  `attr:sanitize_alloc_token`), each pinned by
  `the_other_triggers_of_the_o0_pipeline_are_refused_by_name`.

Experiments behind the rules (`opt -passes=always-inline`, then
`llc -O0 -global-isel=0 -fast-isel=0`, identical on LLVM 19 and 22):
inlined are `frameaddress`, `returnaddress`, `stacksave`, a returned
static `alloca` (with `lifetime` markers; `llc -O0` keeps the slot for
the whole caller), dynamic `alloca` (wrapped in
`stacksave`/`stackrestore`: same lifetime as out of line),
`is.constant`/`objectsize` (arguments substituted), `musttail` inside
the callee (demoted to a plain call at an ordinary site), `naked`, a
call-site `alwaysinline` with an ordinary callee, and an
`available_externally` `alwaysinline` callee (then deleted). Not inlined:
a `returns_twice` call, `va_start`, recursion, `indirectbr`, `noinline`
call sites, a call with a mismatched type. An address-taken
`available_externally` `alwaysinline` function stays, and `llc` writes
it as an external reference.

## Evidence

- `crates/hod/tests/inlining.rs` (9 tests): the object layout (local
  `STT_FUNC` copies with code; transitive; `CALL26`/`JUMP26` to the copy,
  the address relocations in data and code to the undefined symbol; no
  copy for the non-`alwaysinline`, the uncalled and the alias-only
  function); an uncalled body holding a refused construct compiles, the
  same body called is refused by that construct; a malformed discarded
  body is still `MalformedInput`; each reason declined in `linkonce_odr`,
  `internal`, `external` and `available_externally` bodies and not
  declined when nothing is `alwaysinline`; a call-site `alwaysinline`
  turns the check on; an address of a sensitive body, a
  `stacksave`/`stackrestore` pair, an uncalled sensitive copy candidate
  are accepted; the other triggers refused by name. End to end with
  clang++ 22 and kiln++ pre-opt output of a libstdc++-style extern
  template whose `always_inline` members nothing else defines: alone it
  links only because of the copies; with a second object that
  explicitly instantiates the template, the function pointers taken in
  both compare equal; hod objects mixed with `opt` + `llc` objects in
  both roles and both link orders; all under bfd, lld and mold; with
  `-g`, both objects pass `llvm-dwarfdump --verify` and the copy of
  `get` has a subprogram with code.
- The corpus through `cargo xtask irdiff --hybrid -j 4` with the oracle
  `opt -passes='default<O0>'` + `llc -O0 -global-isel=0 -fast-isel=0`
  (a wrapper `llc` under `.build/target-wp-021/preopt-llvm{19,22}`) over
  the pre-opt forms: LLVM 22: 1320 tests, 3954 PASS, **0 FAIL**, 6 ERROR;
  LLVM 19: 1285 tests, 3771 PASS, **0 FAIL**, 34 ERROR. Every ERROR is
  the oracle's: two `-O2` tests whose expected output needs `-O2` (the
  script builds every test at `-O0`), kiln's LLVM-22 coroutine
  intrinsics that LLVM 19's `opt` rejects, and
  `llvm.thread.pointer.p0` that LLVM 19 does not know. hod built 1259 of
  the 1320 LLVM 22 modules; the rest fell back by name.
- Census (`scripts/preopt-census.sh`, `-j 4`): 2605 pre-opt modules (47
  tests could not be generated: kiln multi-output tests, "cannot specify
  -o when generating multiple output files"). Of the 2539 whose post-opt
  form builds, **2484 pre-opt forms build** (97.8%). First reasons of the
  55 others:

  | reason | modules | why |
  |---|---|---|
  | `attr:presplitcoroutine` | 50 | coroutines: kiln lowers them with `opt`; refused by design until `hod_xform` |
  | `alwaysinline:frame-address` | 4 | `gnu-always-inline-*` tests that read `__builtin_frame_address` in an `always_inline` function: true declines |
  | `intrinsic:llvm.aarch64.neon.tbl1.v16i8` | 1 | the inliner's simplification folds it away in the post-opt form; a vector package's row |

  No post-opt module is newly declined by an `alwaysinline:*` reason
  (the 66 post-opt refusals are all other packages' reasons).
- Mutations, each caught then reverted: M1 branch relocations to the
  external symbol and addresses to the copy (`copy_target`'s
  `!is_branch` inverted): 3 tests fail; M2 copies not transitive (the
  worklist does not visit copies): 2 fail; M3 a returned local address
  not declined: 1 fails.

## Speed and memory

Interleaved, 7 rounds, medians; load average 22-24 on 24 cores (the
machine was shared). `hod -O0 -relocation-model=pic -filetype=obj`;
`opt -passes='default<O0>'` then `llc -O0` (kiln's route) on the same
pre-opt input.

| unit | hod pre-opt | hod post-opt | opt + llc on pre-opt |
|---|---|---|---|
| `regex-match-libstdcxx.cpp` | 0.06 s, 15.1 MB | 0.06 s, 13.6 MB | 0.42 s (opt 0.11, llc 0.33), 79 MB |
| `trial-folds.cpp` | 0.27 s, 49.7 MB | 0.28 s, 49.9 MB | 2.32 s (0.67 + 1.65), 172 MB |
| `registration-wide-obj.cpp` | 0.36 s, 87.5 MB | 0.35 s, 87.6 MB | 3.65 s (0.99 + 2.72), 222 MB |

The two bench units have no `alwaysinline` function: kiln already runs
no `opt` for them and the two forms are byte-identical; their rows
measure noise. For the regex unit hod on the pre-opt form costs what it
costs on the post-opt form and removes the `opt` step (0.11 s here).

Size: `always-inline` deletes the discardable bodies it inlined; hod
keeps them. Regex unit: hod pre-opt object 1,409,808 bytes, `.text`
223,464, 1876 defined functions (1871 weak) and 4 copies; hod post-opt
1,281,792 / 216,064 / 1641; `llc` 1,090,928 / 171,736 / 1641. So +231
`linkonce_odr` functions, +3.4% `.text`, +10% file; the linker folds them.

Run time: 13 libstdc++-using corpus programs (the most `std::`
functions, and the regex test), each built from the pre-opt module by
hod and by `opt` + `llc -O0`, same output for all; 30 runs each: per
program 1.6-4.2 ms for hod, 1.6-3.4 ms for llc, all of it process start;
the out-of-line `alwaysinline` calls make no difference that shows.

## Follow-ups

- x86-64: the copy maps `R_X86_64_PLT32`; the row stays `todo(X64)`
  until x86-64 code generation exists.
- The front end could skip parsing discarded `available_externally`
  bodies (`crates/hod/src/front.rs`); not done: they are few and are
  verified.
- kiln: the contract in `spec/cli.md` "Always-inline".
