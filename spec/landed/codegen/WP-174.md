# WP-174: x86-64 leftovers of the corpus and of WP-171

## What is implemented

- **`<1 x i64>` and `<1 x ptr>` across calls** (was
  `call:part-register-class`, 8 generated modules of WP-167's family).
  `llc -O0 -fast-isel=0` of LLVM 19 and 22 agree: the vector is
  scalarized to an `i64` (a general argument register, an 8-byte stack
  slot, `rax`). hod keeps the value in an `xmm` (`target::vector_class`),
  so `abi.rs` gives the whole argument or result one part of kind
  `Lanes { bits: 64, lane: 8, first: 0, len: 1 }` (`abi::LONE_LANE`,
  `is_lone_gpr_vector`); `vcall.rs` (`lone_out`, `lone_in`) moves it with
  `movq r64, xmm` / `movq xmm, r64`, or an 8-byte store or load at a
  stack slot. `hod_cg` already hands such a value in a scratch register
  of its own class on every path (WP-167), so nothing outside `hod_x64`
  changed. In an aggregate the value is memory and travels as bytes, as
  before.
- **`init:block-diff`** (2 corpus modules on LLVM 22, 3 on 19:
  `gcc-torture pr70460.c`, kiln's `c/run/static-local-label-difference.c`
  and, LLVM 19 only, `…-short-19.c`). Module emission already folds the
  difference into a number for both targets (WP-095); the x86-64 block
  rows are moved by `shrink.rs`, so the number is that of the final code.
  Only the classification row was `x64:todo`; it is now `ON` on both
  targets (`docs/status/support.md` regenerated).

## What stays refused

- `inst:callbr` (3 modules: kiln's `dcl.asm/asm-goto.cpp`,
  `stmt.goto/goto-cleanups-run.cpp`, `stmt.goto/goto-in-template-run.cpp`).
  `asm-goto.cpp` has non-empty templates (`jmp ${0:l}`): x86-64 has no
  inline assembler, so it stays `call:inline-asm` whatever `callbr` does.
  The two `stmt.goto` modules use an EMPTY template with `r` inputs and one
  `!i` label: as `llc` builds it, that is the inputs placed and a
  fall-through to the normal destination (an empty template never jumps,
  so the indirect destinations are entered from nowhere here). The work:
  `barrier.rs` (`Ops::parse` counting `!i` constraints as labels, `asm`
  branching to the normal destination with its `phi`s, as its `invoke`
  arm does), the matrix row, and a test against `llc` — about 30 lines,
  but `barrier.rs` and `target.rs` are not this package's files. Left for
  the barrier's owner.
- `cc:preserve_mostcc`, `cc:preserve_allcc` (one module, kiln's
  `dcl.attr.cconv/cc-run.cpp`, which also has `win64cc`,
  `x86_regcallcc` and `x86_vectorcallcc` and so stays refused anyway).
  LLVM 19 and 22 agree: the arguments are the C convention's; a
  `preserve_mostcc` callee also saves `rcx`, `rdx`, `rsi`, `rdi`, `r8`,
  `r9`, `r10` (pushed before the frame); a `preserve_allcc` one also `rax`
  when it does not return in it and `xmm1`..`xmm15` (`xmm0` too when not
  the result). A hod caller may treat both as C (it assumes more
  clobbered); a hod callee needs the prologue and epilogue to save and
  restore those registers with their CFI, in `frame.rs` and
  `frame::saved_set` (WP-146), plus `abi::cc_is_c`. About 100 lines and a
  mixed test whose `llc` caller holds values in all of them; no module
  would compile from it today.

## Evidence

- `vcall_i128::lone_i64_vectors_cross_calls`: 92 signatures (each lone
  vector alone and after full registers; after 0 to 8 `i64`s around
  `double` and `<1 x double>`; beside an `i128`; in structures; as named
  arguments of a variadic callee; 58 random ones over the byte vectors,
  18 of them through a pointer, `invoke` and `musttail`), 184 one-case
  modules all built, 51,884 leaves compared over 17 programs (hod plain
  against `llc` 22 both ways under bfd, lld and mold; hod stressed
  against `llc` 22 and 19 both ways; hod against hod; `llc` against
  itself). The random pool leaves out the vectors passed element by
  element in general pieces, where `llc` 19 and 22 differ
  (`spec/abi-x64.md` §4.2 "LLVM 19").
- WP-167's 81 signatures on x86-64 (`vcall_i128::wp167_i128_signatures_cross_calls`):
  no `call:part-register-class` left; 126 of 162 one-case modules build
  (was 112 with WP-171's count of 8 `call:part-register-class`), the rest
  `x64:vector-i128-split`; 26,112 leaves compared over the same 17 programs.
- `tests/abi`: `table::vectors` expects the lane part for `<1 x i64>`;
  the hand-written emitter (`emit.rs`) moves only mask lanes as lanes.
- `block_diff::label_differences_agree_with_the_interpreter_and_llc`:
  32-, 64- and 16-bit tables, one with an addend, two negative entries;
  64 calls, `hod_interp` against hod plain and stressed and `llc` 22 and
  19, each under bfd, lld and mold. The five corpus modules built by hod
  `--strict`, linked and run under `qemu-x86_64`: exit 0 and the same
  output as `llc` 19 and 22.
- Mutations, each caught and reverted: `movq` as `movd` in `lone_out`
  (4,320 disagreements); an incoming stack slot loaded as 4 bytes in
  `lone_in` (976); an outgoing stack slot written 8 bytes off (603); the
  block difference reversed in `hod_cg` emission (the block-diff test).

Differences from `llc`: none in placement.
