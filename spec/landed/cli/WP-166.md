# WP-166 — peak memory and the last copies in the facade

Landed: `hod::compile_releasing` (`crates/hod/src/front/read.rs`), the
driver's owned input (`crates/hod_cli/src/driver.rs`),
`ModuleEmitter::add_chunk(&mut Chunk)` and the serial streaming of
`back::compile_serial` (`crates/hod_cg/src/emit/mod.rs`,
`crates/hod/src/back.rs`), the per-attribute-set feature memo
(`back::groups`, `hod_x64::X64::of_attrs`, `X64::own`), and the single
move of a delivered `Body` (`Session::body`, `judge_last`,
`crates/hod/src/session.rs`). `Session::body`'s signature is unchanged, so
`EMBED_API` stays at 1. Each item is its own commit.

## What landed
1. **The input is freed once read.** `compile_releasing(&mut Cow<[u8]>, ..)`
   empties an owned input after the bodies are read and before code
   generation. `compile_with` borrows, and a borrowed input is never
   touched. The driver hands over its read buffer, except on a pipe with
   a fallback set, where the fallback needs the bytes again. A conversion
   drops the bitcode before compiling the text.
2. **Chunks are moved into the module emitter.** `add_chunk` lays out a
   chunk and empties it (`Chunk::clear`, so the allocations are kept).
   With one thread, `compile_serial` streams `plan(bodies,
   PARALLEL_MIN_INSTS)` through one `Scratch` and one `Chunk`, so the
   relocations and code of the whole module are never held twice. With
   more threads, the chunks are emptied in module order.
3. **`target-features` are parsed once per attribute set.** `back::groups`
   judges each `FnAttrsId` used by a body once. On x86-64 it also makes the
   set's `X64` there; `for_function` returns `None` for that target
   (`own`). Verdicts and code are unchanged, and the feature parsers'
   tests are untouched.
4. **A delivered body is moved once.** `Session::body` pushes the body
   onto `bodies` before the guard and judges it in place. `try_reserve`
   first, so the push outside `catch_unwind` cannot panic. A rejection
   pops the body, and an `available_externally` body is popped and
   diverted. The old path moved the `Body` into the contained closure, the
   extra `memcpy` WP-093 recorded.

## Choices
1. glibc's mmap threshold: freeing a mapped block of 32 MiB or less raises
   the threshold to that block's size, which later costs
   `malloc_consolidate` +0.2% to +0.6%. `clear(); shrink_to(1)` (a
   shrinking `mremap`) before the drop avoids the raise, and instructions
   stay neutral.
2. The serial chunk size is `PARALLEL_MIN_INSTS`. 16× that saved no
   instructions and cost memory.
3. `emit_module(&[Chunk])` keeps its signature for its many test callers,
   through a private `add_functions(&Chunk)`.

## Not here
The reading peak: `hod_ll::body::parse` clones each body it hands over
(`crates/hod_ll/src/body.rs:274`), so input and bodies are both alive at
the end of reading. That belongs to the readers (WP-159).
`docs/status/perf.md` was not regenerated, because it needs a
`cargo xtask bench` run on the gate's host.
