# WP-186: stack probing (`-fstack-clash-protection`) and neighbours

## What is implemented

- **`"probe-stack"="inline-asm"` and `"stack-probe-size"`** (was
  `attr:probe-stack`, `attr:stack-probe-size`, both refused). clang 22
  with `-fstack-clash-protection` writes `"probe-stack"="inline-asm"` on
  every function on both targets and no `"stack-probe-size"` (that is
  `-mstack-probe-size=N`); kiln accepts the flag and writes neither.
  `hod_ir::StackProbe` (`FnAttrsView::stack_probe`, `spec/ir.md` §5.7)
  reads the pair; rows `attr:probe-stack`, `attr:stack-probe-size` `ON`;
  new rows `attr:probe-stack-function` (another value, a probe function
  to call) and `attr:stack-probe-size-value` (not a decimal multiple of
  4096 in `[4096, 2^24)`). What the targets build: `spec/codegen.md`
  §5.6.27, in `crates/hod_x64/src/probe.rs` and
  `crates/hod_a64/src/probe.rs`.
- `llc` 19 and 22 agree on every shape below (only the `.p2align` fill
  differs). Measured with `-O0 -global-isel=0 -fast-isel=0`:

  | | x86-64 `llc` | AArch64 `llc` (SelectionDAG) |
  |---|---|---|
  | default probe size | 4096 | 4096 (not the 64 KiB guard) |
  | frame `<= P` | `sub` | `sub`, then `str xzr, [sp]` if more than 1024 |
  | unrolled | up to `8P` (32768: 7 probes; 32784: loop) | up to 4 pages (16384: 4; 20480: loop) |
  | loop | `mov r11, rsp` · `sub r11` · `sub/movq $0/cmp/jne` | `sub x9, sp` · `sub/str xzr/cmp/b.ne` |
  | rest | unprobed (`push rax` for 8) | probed above 1024 bytes |
  | CFI in the loop | none with a frame pointer (`r11` without) | none with a frame pointer (`x9` without) |
  | `alloca` | `cmp; jge; xorq $0,(%rsp); sub; jmp`, align after | `sub; cmp; b.le; str xzr; b`, then `ldr xzr, [sp]` |
  | realigned frame | `and r11, -A` and a probe loop to it | `and x9` and the alloca-style loop |
  | `"stack-probe-size"` 1000 / 0 | 1000 / no probing at all | 992 / 16 (aligned down) |
  | `"x"` | error | error |

  hod's x86-64 prologue and `alloca` are `llc`'s shapes (hod aligns `r11`
  before the loop). hod's AArch64 frame record is at the bottom, so the
  top 16 bytes are touched first (`str xzr, [sp, #-16]!`), whole pages
  below them as `llc` (unrolled up to 4, else a loop on `x17` with the
  CFA on `x17`), and the frame record's `stp` is the probe of the rest.
  hod has no frame realignment (an over-aligned slot is a dynamic slot,
  probed as an `alloca`). An outgoing argument area is probed too
  (x86-64: always, starting with the word below `rsp`; AArch64: above
  1024 bytes). The coroutine stubs' copy of the prologue goes through
  the same function.

- **`"zero-call-used-regs"="skip"`** (kiln writes it for
  `-fzero-call-used-regs=skip`; clang writes nothing) is accepted: it
  zeroes nothing. `llc` 19 and 22 give a byte-identical object with and
  without it on both targets, and so does hod
  (`zero_call_used_regs_skip_changes_nothing`); `used-gpr` and `all`
  stay `attr:zero-call-used-regs`.

## Evidence

- `crates/hod/tests/stack_probe.rs`, both targets (x86-64 under
  `qemu-x86_64`), hod and `llc` 19 and 22 linked with one C harness:
  - values: 36 frame sizes (`P`, `2P`, `4P`, `5P`, `8P`, `9P` each ± 16
    and ± 32, 16, 1000, 3000, 3072, 3088, 1 MiB), `alloca` of 0 to 1 MiB
    aligned 16 and 64, a 128-aligned 40000-byte slot: every buffer filled
    and checked after a call;
  - the guard: a thread on `[4 MiB mapped | 64 KiB PROT_NONE | 256 KiB
    stack]`; a 1 MiB frame and a 1 MiB `alloca` with the attribute fault
    with `si_addr` in `[top - 4096, top)` of the guard, and `backtrace()`
    in the handler (on `sigaltstack`, through the signal frame and the
    CFI at the faulting probe inside the loop) reaches the caller;
    without it the first fault is at the guard's bottom (the frame
    landed below the guard). hod, llc 19, llc 22 print the same, both
    targets. `llc` needs `uwtable` for this on AArch64 (without it its
    rows come after the loop and the unwinder crashes in the loop), so
    the test's functions carry it as clang's do;
  - shape: per size class (1, 2, 4, 5, 8, 9, 256 pages, ± 64), x86-64
    probe count and loop equal to `llc`'s; AArch64 hod's count is its
    own rule and the loop decision equals `llc`'s;
  - text and `llvm-as` 19 and 22 bitcode give the same object;
  - refusals: `"__probestack"`, sizes 1000, 0, `0x1000` by name;
    `"stack-probe-size"` alone and 65536 accepted.
- `tests/debug/stack_probe.cpp` (clang 22, `-fstack-clash-protection`,
  a 40000-byte frame, so a loop on both targets): `cargo xtask debug run
  --debugger gdb` natively on AArch64 and `--target x86_64` (qemu gdb
  stub): breakpoint in the probed function, `bt 3`, the exception thrown
  out of it caught in the caller; 3 PASS each (bfd, lld, mold), lines
  and columns the same as `llc`'s.
- Mutation: the x86-64 loop bound one page short (`FRAME - FRAME % P -
  P`) makes the x86-64 program crash in
  `probed_frames_fault_in_the_guard_and_unwind`; reverted.
- Unit tests: the longest allocation fits the reserved room for every
  frame up to 20 pages and the largest frame, the loop branches to its
  start, AArch64 CFA rows end at `sp + FRAME`.
- A function without the attribute is byte-identical (the reserve and
  every probe are emitted only with it).

## What stays refused

| attribute | produced by | measured with `llc -O0` | what building it takes |
|---|---|---|---|
| `"probe-stack"` other than `inline-asm` | none of clang's Linux flags | a call of the named function | the call in the prologue with its convention (`attr:probe-stack-function`) |
| `"stackrealign"` | clang `-mstackrealign`; kiln has no flag | x86-64: `and rsp, -16` (or `-8`) after `mov rbp, rsp`, locals then `rsp`-relative; AArch64: changes too | a base register other than `rbp` for locals (hod addresses them from `rbp`), the prologue `and`; stays `attr:stackrealign` |
| `noimplicitfloat` | clang `-mno-implicit-float`/`-msoft-float`; kiln has no flag | x86-64: nothing changes at -O0 in a memcpy, aggregate or variadic function; AArch64: a 64-byte `memcpy` goes through `x` registers instead of `q` | proof by disassembly that hod emits no `xmm`/`q` use the IR does not ask for (the x86-64 variadic save area stores `xmm0`-`xmm7`, as `llc`'s does): stays `attr:noimplicitfloat` |
| `"zero-call-used-regs"` | clang and kiln `-fzero-call-used-regs=`; clang writes nothing for `skip`, kiln writes the value | x86-64 `used-gpr`: the used GPRs zeroed before `ret`; `all`: every GPR, `xmm`, x87; AArch64: `all` zeroes `x`/`q`, `used-gpr` nothing at -O0 | zeroing a superset (the `all-*` set of the class asked) before every return and tail exit; stays `attr:zero-call-used-regs` for every value but `skip` |
| `"patchable-function-entry"`, `-prefix` | clang and kiln `-fpatchable-function-entry=N,M` (kiln: entry `N-M`, prefix `M`) | `N-M` `nop`s at the entry, `M` before the symbol, an entry in `__patchable_function_entries` (`SHF_LINK_ORDER`, linked to the function's section) | the object writer's link-order section and its relocations, the NOPs and the symbol offset; stays refused |

## Notes

- x86-64 keeps `llc`'s unprobed rest below the last probe (up to `P`),
  which the next push or call touches: as in `llc`, two touches can be
  `P + 8` apart.
- Touched shared frame code: `crates/hod_x64/src/frame.rs` (`FrameState
  ::probe`; `begin`: the reserve after the `sub` placeholder;
  `prologue`: the reserved length and the allocation by
  `probe::write_allocation`; `adjust_sp`; `dynamic_slot`'s `mov rsp,
  r11`), `crates/hod_x64/src/mem.rs` (`alloca`'s `mov rsp, r11`),
  `crates/hod_x64/src/coro_body.rs` (the stubs' `sub`),
  `crates/hod_a64/src/frame.rs` (`FrameState::probe`; `begin`: the
  reserve after the two `sub`s; `end`: the allocation and its rows, the
  cut, `at` moved past the room; `prologue_rows` without the `sub` rows;
  `adjust_sp`; `dynamic_slot`'s `mov sp, x16`),
  `crates/hod_a64/src/mem.rs` (`alloca`), `crates/hod_a64/src/coro_body.rs`
  (the stubs' two `sub`s).
