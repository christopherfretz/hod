# WP-012 — AArch64 base integer encoder and its L1 differential harness

Landed: `spec/mc-a64.md` (all sections; floating point and SIMD are WP-013).

## What it did

- `crates/hod_mc_a64`: the register model (`Reg`, `RegZr`, `RegSp`), the
  operand kinds, 190 instruction constructors for the base integer set
  (97 of them with a checked `try_` twin), exact logical-immediate encoding
  and decoding, the constant materializer `mov_imm`, and `Fixup` for the
  six PC-relative fields. One module per spec section; `fp` and `simd` are
  empty and reserved.
- `crates/hod_mc_a64/tests/l1`: the L1 harness (`harness.rs`), the
  constructor-to-mnemonic table (`table.rs`), independent assembly text
  formatters (`text.rs`), one sweep module per spec section, the tool-free
  tests for logical immediates, the materializer and fixups, the coverage
  test, and the harness's negative self-tests.
- 98,496 encodings in twelve batches agree with `llvm-mc` 22 word for word
  and disassemble to the intended instruction. Of 2,881 operand
  combinations the checked forms reject, the 1,249 that have assembly text
  are errors to `llvm-mc` too; and each of 3,419 sampled constants that
  `mov_imm` needs more than one instruction for is refused by LLVM's
  `mov Rd, #imm`. The whole test binary runs in about four seconds.

## Decisions, and why

- **Three register types instead of one with a flag.** Whether 31 is SP or
  ZR is a property of the operand position, so it belongs in the signature.
  A constructor that could be handed "register 31" without saying which
  would move the classic AArch64 encoder bug into the code generator.
- **The operand size is an operand, not part of the register.** The code
  generator tracks values, not `W`/`X` names; one register type keeps
  conversions out of its hot path.
- **`f` and `try_f` come from one macro (`checked!`).** The precondition is
  written once, so the checked form's `None` and the unchecked form's
  `debug_assert!` cannot disagree. Infallible constructors have no `try_`
  form: an `Option` that is always `Some` would invite `unwrap`.
- **Immediates are values, not fields.** `add_imm` takes the amount and
  picks `LSL #12` itself; logical instructions take the mask; loads take a
  byte offset; branches take a byte displacement. The alternative pushes
  the field arithmetic, and its bugs, to every caller.
- **Unpredictable combinations are rejected.** Writeback with the base as a
  transferred register, a load pair into one register, a store-exclusive
  status register that is also an operand: the checked form says `None`
  rather than encode something no core is required to run sensibly.
- **No automatic choice between scaled and unscaled offsets.** LLVM's
  assembler turns `ldr x0, [x1, #-8]` into LDUR. A constructor that did the
  same would hide which instruction was emitted; the code generator asks
  `try_ldr_off` and falls back to `try_ldur` explicitly.
- **`mov_imm` returns a small `Copy` array (`MovSeq`)**, not a closure
  callback and not a caller buffer: it stays a `const fn`, and the caller
  appends `as_slice()`.
- **`mov_imm` takes a `Reg`.** ORR (immediate) reads 31 as SP in the
  destination and the wide moves read it as ZR; an early version took
  `RegZr` and would have written SP for the ORR path.
- **The materializer's ORR-then-MOVK search is small and complete.** If a
  logical immediate agrees with the constant outside one or two chunks,
  then one does whose replaced chunks are each `0x0000`, `0xffff` or a
  chunk of the constant, so at most 24 candidates are tried for one MOVK
  and 216 more for two. The test checks minimality against an exhaustive
  search over all 5334 immediates, which does not rely on that argument.
- **`mov_imm` does not use LLVM's two-logical-immediate or bitfield
  tricks.** They shorten some constants by one instruction at the price of
  a search; the guarantee is stated for the MOVZ/MOVN/ORR + MOVK family and
  can be widened later without changing the signature.
- **The reverse check compares mnemonics against a table**, per
  constructor, not hod's word against a second assembly of LLVM's
  disassembly: the point is to catch a constructor and its test text being
  wrong in the same way, and the mnemonic is the part of the disassembly
  that does not depend on operand spelling.

## What LLVM's assembler does that the sweeps had to learn

- `-M no-aliases` does not turn off `mov` (for MOVZ, MOVN and ORR from ZR)
  or the bitfield aliases (`lsl`, `ubfx`, `sxtw`, ...); it does turn off
  `cmp`, `tst`, `mul`, `cset`, `ror`, `mov sp` and the rest. LLVM's own
  names for LSLV/LSRV/ASRV/RORV are `lsl`/`lsr`/`asr`/`ror`.
- `lsl x0, x1, #0` prints back as `lsr x0, x1, #0` (the same word); an
  insert at bit 0 prints as the extract.
- `ldrb w0, [x1, x2, lsl #0]` sets the `S` bit; `ldrb w0, [x1, x2]` does
  not. A bare `lsl` with no amount is a syntax error, while a bare `uxtw`
  is fine.
- A negative ADD/SUB immediate is rewritten to the opposite instruction,
  and an offset the scaled load/store form cannot hold is rewritten to
  LDUR/STUR when it fits there. Such operands have no "LLVM must refuse
  this" text.
- `llvm-mc` reports parse errors and stops before layout, so out-of-range
  branch displacements are only reported in a run with no parse errors.
  The rejection check re-runs the lines that have not errored yet until a
  run reports nothing new.
- `.+N` displacement expressions are resolved at assembly time, without a
  relocation, for every PC-relative instruction except ADRP, which always
  gets a relocation; ADRP is checked through its immediate form
  (`adrp x0, #N`).
- `mov x9, #imm` picks MOVZ, then MOVN, then ORR, the same order as
  `mov_imm`, and is an error for a constant that needs two instructions,
  which gives an independent check of "one instruction exactly when
  possible".
- LLVM accepts `ldxp x3, x3, [x9]` and `ldpsw x9, x17, [x9], #-4`, both
  CONSTRAINED UNPREDICTABLE, though it rejects the same overlap for LDP and
  for pre-indexed LDPSW. hod rejects all of them.
- `tbz x0, #3, label` is accepted with an `X` register for a bit below 32
  and encodes like `w0`; `cinc x0, xzr, eq` is accepted and is CSET.
- `llvm-objdump` takes `--mattr=`; with one dash it parses `-mattr` as
  `-m -a -t -t -r=...`.
