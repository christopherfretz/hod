# WP-069 — core call fixes from the AArch64 call group

Landed: `spec/codegen.md` §7.1 ("Effective attributes", "Extended
integers", "Odd leaves of incoming `Mem`-class arguments", "The
`musttail` hook"), §13 (the declaration-attributes point closed);
`spec/abi-a64.md` §6.4 (`alignstack` on a function), §7.1 (odd and wide
widths, measured); `hod_ir::classify::attrs`; `hod_cg::abi::
TargetStackArgs`.

## What it did

- **Effective attributes.** One helper in `hod_ir`
  (`call_arg_attrs`, `call_ret_attrs`, `merge_call_attrs`) gives a
  call's attributes as `llc` 19 and 22 lower them: the declaration's
  only through the callee's own function type, merged per kind; a
  passing attribute on each side that differs is
  `call:attribute-conflict`. `classify` and the call sequence both use
  it. `a64:call-mismatched-declaration` is gone.
- **Extended integers of every width.** The last 64-bit piece of an
  `iN zeroext`/`signext` wider than 64 bits (N no multiple of 64) is
  extended, in a register and on the stack; an extended integer a
  general register carries is stored on the stack as a whole register.
  `a64:call-wide-int-extension` and `a64:call-narrow-ext-stack-arg` are
  gone (one cause: the missing extension and the store width).
  `A64::extend_arg` extends the last piece for N > 64.
- **Odd leaves of incoming arguments.** A `Mem`-class argument's home
  has the bits above its odd-width integer leaves cleared at entry
  (§2.2's memory invariant; the ABI promises nothing there).
- **`attr:alignstack`** supported on AArch64: the parameter form (all
  the corpus has) is `assign`'s; the function form needs no code.
- **`tail:musttail`** supported on AArch64 behind the `StackArgs` hook,
  which `hod_cg::abi::TargetStackArgs` implements for any target. The
  facade (`crates/hod/src/front.rs`) does not hand it to its classifier
  yet, so there every `musttail` call is still
  `musttail:stack-args-unknown`.

## Tests (`crates/hod_a64/tests/call.rs`)

- `declared_attributes_follow_the_function_type` (`attrs.ll`) and
  `classify_and_the_call_sequence_see_the_same_attributes` (600 random
  declaration/site combinations, five call shapes).
- `extended_integers_of_every_width_run` (`ext.ll`, 14 widths and
  places, junk above every width), `a_wide_signext_return_is_extended`.
- `odd_leaves_of_incoming_arguments_are_cleared` (`odd.ll`).
- `alignstack_arguments_and_functions_run` (`alignstack.ll`).
- `the_stack_args_hook_decides_musttail`.
- The run tests: caller and callee module by hod and `llc` in every
  pairing, hod stressed, gcc's driver, GNU ld, lld and mold where hod is
  involved. The random signatures (600 per run by default) now draw
  extended integers of every width in every position and clang's
  `alignstack` on HFA arguments.
