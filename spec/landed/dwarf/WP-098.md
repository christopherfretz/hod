# WP-098 — debug information after WP-094

The contract is `spec/dwarf.md` §6.14. Family 90 is appended to §6.1's
table, two normalizations are added to §6.7, and `debug:label-attribute`
is dropped from §6.4 and §6.13. This file records what the work package
did, what it measured and what it left.

## What landed
- `crates/hod_a64/tests/dies_support/mod.rs`, the comparison's artefacts
  (both are cases §6.7 permits, and each is named in the code):
  - `name_bare_reference`: a reference the dump prints bare is compared
    by its target's tag;
  - `same_attrs`: one range equals several (`low_pc`/`high_pc` against
    `ranges`), for every DIE but the unit's;
  - `permitted`: names the code-generation class of a difference: the
    `sret` loclists base, (a) a fallthrough inlined call, (b) an
    `is.constant` block, or `llc` 19's blocks.
- `crates/hod_a64/tests/dies_e2e.rs`: the census counts trees that are
  equal, permitted (by class) and different.
- `scripts/debug-census.sh` makes the census's inputs (WP-094's were
  gone) and runs it.
- `crates/hod_dwarf/src/label.rs`: family 90 (`label (any)`), in `llc`'s
  `applyLabelAttributes` order. Hooks:
  - `func.rs` `local_die`, the `Label` arm: concrete labels.
  - `inline.rs`, the `AbstractLabel` arm: abstract labels.
  - The refusals are removed from `func.rs` `collect_entities` and
    `early.rs` `check_records`.
- `func.rs` `collect_entities`: a record goes under its variable's or
  label's own scope (`llc`'s `findLexicalScope` of `getScope()`), as
  `CoroSplit`'s moved records need.
- `align >= 8` replaces `align != 0` in every writer of
  `DW_AT_alignment`. A sub-byte `align: 4` on a coroutine frame type's
  member made hod's unit unreadable: the abbreviation bit was set but no
  value was written. The writers are in `types.rs`, `die.rs`,
  `global.rs` and `func.rs`.
- WP-099's three findings (part B2, added to the package after it
  merged `main`):
  - `inline.rs`, the `AbstractVar` arm: an `alignas` local of an
    abstract instance (family 88, no location).
  - `src/local_type.rs`, hooked by `early.rs` `local_type_parent`: a
    type local to a function that is only inlined goes under its
    abstract instance.
  - `inline.rs` `abstract_entities`: a variable's type is made before
    its DIE, as `llc` does.
  - `src/call_sites.rs`, hooked by `func.rs` `subprogram_parent` and
    `early.rs` `check_subprogram`: `DIFlagAllCallsDescribed` is refused
    as `debug:call-sites` (`DEBUG_CALL_SITES`).

## Refused by name
- `debug:label-attribute` is no longer refused.
- `debug:variable-alignment` is narrowed to unnamed aligned variables
  and aligned parameters.
- `debug:local-type-scope` is narrowed to a type reached before its
  function's abstract instance exists.
- `debug:call-sites` is new. It is narrowed from
  `debug:subprogram-attribute` for `DIFlagAllCallsDescribed`, which
  needs the generated code's call return addresses.
- `debug:dwarf-version` stays (see the plan below).

## DWARF 4: the plan (not done here)
Measured:
- 2 of the corpus's 14 `-g` modules are DWARF 4. Both are kiln's
  `meta.reflection.define.aggregate/define-debuginfo-run.cpp` (llvm19
  and llvm22).
- No census input is DWARF 4.
- `llc` 19 and 22 write the same shape for `-gdwarf-4`.

What it takes, as `llc` writes it (checked on `labels.c` with `clang
-gdwarf-4`):
- **The unit header**: version 4, then `debug_abbrev_offset` and then
  `address_size`. Version 5 has `unit_type` and `address_size` before
  the offset.
- **Strings**: `DW_FORM_strp` into `.debug_str`, with no
  `.debug_str_offsets` and no `DW_AT_str_offsets_base`. That is 76
  `strx` slots in §6.1's families.
- **Addresses**: `DW_FORM_addr` with a relocation, and `DW_OP_addr` in
  expressions. There is no `.debug_addr` and no `DW_AT_addr_base`. That
  is 17 `addrx` slots.
- **Range and location lists**: `.debug_ranges` and `.debug_loc`, by
  `DW_FORM_sec_offset`. There are 3 `rnglistx` slots, and the
  `rnglists_base` and `loclists_base` attributes go.
- **The line table**: a version 4 header with string include
  directories and file names, files counted from 1, no MD5, and no
  `.debug_line_str`.
- **Static data members** are `DW_TAG_member` with `DW_AT_external` and
  `DW_AT_declaration` (family 55 exists).

So DWARF 4 needs a second form for every string and address slot, which
is a version parameter in the table, not new families. It also touches
the unit header and the string and address sections, which WP-062
(split DWARF: skeleton unit, `.dwo` string offsets) is reshaping now.
Doing it on top of WP-062 avoids writing those parts twice. The order:
1. a `Version` in `UnitPlan`, selecting `strp`/`addr` forms per slot in
   `abbrev` (the table keeps one code per shape);
2. the header and sections;
3. the line-table header;
4. `.debug_ranges`/`.debug_loc`;
5. evidence on the two kiln units and `-gdwarf-4` clang sources, under
   `llc` 19 and 22.

gdb and lldb read version 5, so the refusal only costs tools that read
nothing but version 4.
