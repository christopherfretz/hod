# WP-298 — i386, design 0008 I7: integers of 33 to 64 bits

Landed: `crates/hod_x86/src/int.rs` (all of it), its dispatch arms in
`crates/hod_x86/src/target.rs` (`binary`, `freeze`, casts, `icmp`,
`load`, `store`, `select`, and `materialize_mem`), four runtime functions
in `hod_cg` (`RuntimeFn::{UDivDi3, DivDi3, UModDi3, ModDi3}`,
`crates/hod_cg/src/sym.rs`: the "Arch::I386 arm in the runtime tables"
design 0008 §1.4 names). Behaviour: `spec/codegen-x86.md` §8.

## Decisions

- An `iN` of 33 to 64 bits is of class `Mem` (it already was:
  `class_of` says `Gpr` only for `i1`..`i32`, `ptr`). Its slot is 8
  bytes with the bits above `N` unspecified, the x86-64 rule for `i128`
  one size down; consumers extend the high word.
- No lowering takes a pool register for the halves: `eax`, `ecx`, `edx`
  carry everything, so `Stress::ALL` (`min_pool`) changes nothing here.
- `select` is a branch around two slot copies on every CPU (no `cmov`
  in `generic`, and the branch is right on all of them).
- Division calls libgcc itself (push, `call`, `add esp, 16`) rather than
  through `FnCx::call_runtime`, whose signature would go through
  `abi.rs` (I6), which refuses `i64` arguments today. No value lives in
  a caller-saved register between instructions, so nothing is displaced.
- Wider than 64 bits: `x86:i64:wide` for everything; nothing here
  generalizes to more words for free (the multiply, the shifts and the
  division are two-word sequences).

## Not done (refused by name)

- `x86:i64` remains for an `i64` passed or returned by value (I6), a
  `switch` on one, a `ptradd` index of one (`control.rs`, `mem.rs`:
  WP-293's files).
- The overflow intrinsics, bit counts, `bswap`, min/max, funnel shifts
  of `i64` stay `x86:intrinsic` (as for `i32`): the intrinsic dispatch is
  `call.rs` (not this package's), and the overflow ones return `{i64,
  i1}`, an aggregate (`extractvalue`, I11). llc 19/22 do
  `smul.with.overflow.i64` inline on i686 (design 0008 §5.2), so no
  `__mulodi4` will be needed.

## Evidence

`crates/hod/tests/i386_i64.rs`: three programs (`arith.c`: every
operation over 16 edge values pairwise, shift counts 0/31/32/63 by a
variable, constant shifts 0..63, casts, 300 pseudo-random pairs;
`bitint.c`: `_BitInt(33/40/48/63)`, signed and unsigned, 10 edges
pairwise and 200 random pairs; `select.ll`: `select`, `phi`, `freeze`,
`i40`, constants), by clang 19 and 22, no `target-cpu` and
`-march=pentium4`: 12 modules, each run as llc's, hod's and hod's under
`Stress::ALL` object, linked by GNU ld, lld and mold: 36 runs, all equal.
