# WP-105 — coroutine handle operations and the noop frame (design 0005, C2)

Landed: `crates/hod_a64/src/coro.rs`, `crates/hod_cg/src/coro.rs`,
`crates/hod_cg/src/emit/noop.rs`, the hooks below,
`crates/hod_a64/tests/coro.rs`, the irdiff directives `input: pre-opt`,
`dialect: N` and `oracle-skip(llvm=N[,M]): <reason>` in `xtask`, the seeds
`tests/ir/coro/{handles,noop}.ll`, `spec/codegen.md` §7.6 "Coroutines",
`spec/harness.md` "Pre-opt input, dialects and oracle skips" and "Oracle
skips", and the support-matrix rows.

## What is lowered

In any function that is not itself a coroutine (bodies are C3, WP-106),
as `coro-early` lowers them:

- `llvm.coro.resume(p)` / `llvm.coro.destroy(p)`, as call and as invoke:
  load `[p+0]` / `[p+8]` and call it `fastcc` with `p`
  (`hod_cg::call::call_through`, `Callee::Temp`; an invoke keeps its
  normal and unwind edges, `invoke_edges`).
- `llvm.coro.done(p)`: `[p+0] == null`.
- `llvm.coro.promise(p, align, from)`: `p ± alignTo(16, align)`, the
  frame header of two pointers rounded up to the promise's alignment.
- `llvm.coro.noop()`: the address of the object's noop frame.
- The noop frame, generic in `hod_cg` (`emit/noop.rs`), with one Target
  hook, `Target::NOOP_CORO_FN` (the code of a function that returns):
  `__NoopCoro_ResumeDestroy`, a local `STT_FUNC` in `.text` after every
  other function (`.text.__NoopCoro_ResumeDestroy` with function
  sections), no unwind entry; and the private `NoopCoro.Frame.Const`
  `{fn, fn}` in `.data.rel.ro` (PIC) or `.rodata` (static), suffixed
  `..LNoopCoro.Frame.Const` with data sections, reached through its
  section symbol. One frame per object: noop handles are equal within an
  object and unequal across objects, as with `llc`.

## What stays refused, by name

- `attr:presplitcoroutine` and the body intrinsics (`coro.id`,
  `coro.begin`, `coro.suspend`, ...): coroutine bodies, WP-106.
- `a64:coro-promise`: a promise whose alignment or direction is not a
  constant, or whose alignment is not a power of two below 2^31.
- `coro:noop-target`: `coro.noop` for a target without `NOOP_CORO_FN`.
- `a64:code-model` for `coro.noop` under the large code model.

## Evidence

- `crates/hod_a64/tests/coro.rs`, 5 tests. Pre-opt IR from clang 19,
  clang 22 and kiln (`opt -passes='default<O0>'` for the references) of a
  C++ driver with `alignas(32)` promises, noop handles passed in both
  directions and the noop identity, mixed with hod's object of the
  hand-built `HANDLES` module: 27 programs under bfd, lld and mold, every
  output equal to the opt+`llc -O0 -global-isel=0 -fast-isel=0` build;
  "same object: 1 1 / across objects: 0". Shapes disassembled per
  function; the noop frame read with `llvm-readelf` for PIC, static and
  split sections; the refusals above.
- Mutations, each caught by `the_handle_operations_have_their_shapes` and
  `coroutines_of_other_compilers_are_driven_from_hod`, and reverted: (1)
  `done` reads the destroy slot; (2) the promise offset is always 16; (3)
  destroy calls the resume slot.
- irdiff, `tests/ir/coro`: LLVM 22 and 19, 2 tests, 6 results, 6 PASS;
  hod built 2 of 2 objects. Harness tests: `irdiff_fakes.rs`
  (`a_pre_opt_test_goes_through_opt`, `a_dialect_test_runs_only_with_its_llvm`,
  `an_oracle_skip_compares_with_the_directives_only`), `irdiff_real.rs`
  (`a_pre_opt_seed_goes_through_opt`,
  `dialects_come_in_pairs_and_oracle_skips_are_listed`).
- libc++ `noop_coroutine.pass.cpp`, `HOD_STRICT=1`, kiln through the
  shim, LLVM 22.1.8: 1 PASS, hod built its object (coverage log), no OOM
  kill.

## Census

Release hod, `scripts/preopt-corpus.sh -j 4` (2605 kiln modules, 47
kiln failures) and `scripts/preopt-census.sh -j 4`:

- 34 modules (17 per LLVM major) have handle operations (resume 26,
  destroy 32, done 20, promise 32, noop 2); all 34 are among the 50
  modules with coroutine bodies. No module has handle operations outside
  a coroutine-bearing module, so this package compiles no corpus module
  on its own.
- What stops these 34: `attr:presplitcoroutine`. The full refusal set of
  each (`HOD_CENSUS=1`) holds only body constructs (`coro.id`, `alloc`,
  `size`, `begin`, `save`, `suspend`, `await.suspend.*`, `free`, `end`,
  `is_in_ramp`, `align`, `type:token`); none of the five handle
  operations is refused.
- libc++'s `noop_coroutine.pass.cpp` is the module of this kind outside
  the corpus: it compiles strict (Evidence).
