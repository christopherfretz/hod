# WP-293 — i386 I5: the `hod_x86` skeleton, milestone A (design 0008)

Landed: the crate `crates/hod_x86` (`#![forbid(unsafe_code)]`, no new
dependency), `hod_x86::X86` implementing `hod_cg::Target` for
`i[3-6]86-*-linux-gnu` in the static model, wired into the facade
(`crates/hod/src/back.rs`: `compile_one`, `check_features`; the
`x86:not-implemented` refusal and `hod::X86_NOT_IMPLEMENTED` are gone) and
the tool's help. `Target::I686` joins `Target::COMPILED_BY_HOD`.
Specified in `spec/codegen-x86.md`; the module table for I6 to I13 is
`crates/hod_x86/README.md`.

## What compiles

`i1`..`i32` and `ptr`: every integer binary operation, `icmp`, `select`
(a branch), `freeze`, the casts among them; `load`, `store`, `ptradd`,
static `alloca`; `br`, `condbr`, `switch`, `ret`, `unreachable`,
`llvm.trap`; direct and indirect calls with stack arguments (variadic
calls included), the result in `eax`; `llvm.memcpy`/`memmove`/`memset`
with a 32-bit length (`rep movsb`/`stosb`). Everything else is refused
by one of the names of `spec/codegen-x86.md` §7.

## Edits outside the crate

- `crates/hod_cg/src/reg.rs`: `MIN_POOL_GPR_32` = 3 and
  `RegInfo::min_pool_gpr` (3 general registers for a 4-byte target);
  `check` and the `min_pool` stress mode (`driver.rs`) use it.
- `crates/hod_cg/src/emit/mod.rs`: `ArchInfo` keyed by `Machine`
  (`R_386_32`/`PC32`/`PLT32`, 4-byte addresses for `.init_array`,
  `nop` padding), `Object::for_machine(I386)`, refusals
  `x86:debug-info` (a module with compile units) and `x86:cf-protection`
  (the `.note.gnu.property` flags) where `Object::arch()` has no answer.
- `crates/hod_cg/src/emit/unwind.rs`: no unwind tables for `EM_386`
  (I10).
- `xtask/src/irdiff/engine.rs`: on i686 every refusal is expected
  without a directive while the back end is partial (the seeds are
  written for 64-bit targets).
- Tests kept on AArch64 and x86-64 with a one-line reason:
  `crates/hod/tests/{hardening,stack_probe,alwaysinline_vla,exclude,
  inlining,kiln_forwarded_options}.rs`, `crates/hod_cli/tests/kiln_e2e.rs`
  (`hod_builds_integers`: kiln's i686 module is PIC).

## Evidence

- `crates/hod/tests/i386_run.rs`: `ret i32 42` and five C programs
  (`tests/data/i386`: loops, `switch`, calls with 1 to 8 stack arguments
  and recursion, globals and pointer arithmetic, memory intrinsics),
  clang 19 and 22 → hod, hod under `Stress::ALL`, and `llc` → GNU ld,
  lld, mold → `qemu-i386 -cpu pentium2,-mmx`: equal status and output
  (36 runs, `HOD_REQUIRE_TOOLS=1`).
- `cargo xtask irdiff --target i686` over `tests/ir` (LLVM 22; 19 alike):
  0 PASS, 0 FAIL, 195 UNSUPPORTED, 77 ERROR, 19 SKIP; hod built none of
  the 90 objects: `x86:pic` 43, `coro:target` 17, `x86:i64` 12,
  `x86:float` 7, `musttail:stack-args-unknown` 4, `x86:cf-protection` 2,
  one each `attr:alignstack`, `x86:abi:attr`, `x86:abi:cc`,
  `x86:aggregate`, `x86:vector`. The 77 ERRORs are the reference side
  (llc's own i686 programs of 64-bit seeds), the same seeds as with the
  hod of `dbc395b0`.
- `cargo xtask compare-binaries` against `dbc395b0` over `tests/ir`,
  `gcc-torture` and `kiln`: 7044 modules, 14088 comparisons, 13868
  identical, 0 different, 0 changed-outcome, 220 identical-failure.

## Open

- With i686 in `COMPILED_BY_HOD`, a default `cargo xtask irdiff` (no
  `--target`) includes i686, whose 77 reference-side ERRORs make it exit
  nonzero until the seeds carry i686 directives (`target:` or
  `unsupported:`) or are made portable.
- The shared classifier: an i686 session has no `stack-args` rule, so
  every `musttail` is `musttail:stack-args-unknown` (I6).
