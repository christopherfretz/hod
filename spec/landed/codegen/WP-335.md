# WP-335 — i386: coroutine bodies (stages B to D of WP-327)

Landed: `crates/hod_x86/src/coro_body.rs` (written in WP-327, parked
because i386 lowerings then pinned three pool registers; WP-331 made it
two). Behaviour: `spec/codegen.md` §7.6 and `spec/codegen-x86.md` §18.1.
Base: `8e6e852c` (WP-327 stage A + WP-331).

## Decisions

- **`esi` is the frame base for the whole function** (supervisor's
  decision; WP-327's answer 1 says why not `ebx`, `edi` or `ebp`). A
  body's general pool is `ebx`, `edi`. Under PIC `ebx` is also the GOT
  pointer of every PLT call: `pic::emit_call` displaces what it holds,
  so across a PLT call only `edi` keeps a value in a register. No
  lowering was changed: WP-331's bound of two pinned registers holds.
- **Input**: what the 64-bit targets receive, a module before LLVM's
  passes (`presplitcoroutine` bodies, clang `-Xclang
  -disable-llvm-passes`, kiln), the same plan (`hod_xform::coro`) and
  the same refusal names. `coro:target` no longer names any shipped
  target.
- **Hooks**: `crate::coro` takes the body intrinsics too (one arm of
  `call::lower` and of `x87::barrier` for the family), so neither
  `call.rs` nor `x87.rs` changed.

## Edits outside `coro*.rs`

- `hod_x86/src/target.rs`: `X86::coro` (set by `for_function` from
  `presplitcoroutine`), `CORO_BODIES`, `reg_info`, `FnState::coro`, the
  three `coro_*` items.
- `hod_x86/src/frame.rs`: `coro_body::enter` after the prologue's `sub
  esp`; `test_mode` / `ret_pop` for a ramp that pops.
- `hod_x86/src/common.rs`: `FrameRef::Coro(o)` is `[esi + o]`; each
  access reported to the structural check.
- `hod_x86/src/asm.rs`: `esi` never chosen in a body; writing it is
  `x86:coro:asm-base`.
- `hod_x86/src/lib.rs`: the module. `hod_x86/README.md`: the row.
- `hod/src/session/coro.rs`: `bodies_compiled(I386)` from the target.
- `hod_xform/src/coro/analysis.rs`, `mod.rs`: the header is two
  pointers of the data layout (16 on the 64-bit targets: byte-neutral).

## Evidence

- `crates/hod/tests/i386_coro.rs`:
  - `bodies_run_as_llc_s`: `gen.cpp` (generators of `int` — the clang 22
    one that failed at an `icmp` before WP-331 —, `long long`,
    `double`; an `sret` object; 12 mixed parameters), `transfer.cpp`
    (100,000 symmetric transfers, the stack used measured below 64 KiB),
    `throws.cpp` (a throw caught in a body, one thrown out of a resumed
    body through the unwinding `coro.end`, frame destructors) by clang 19
    and 22, CPU `generic` and `i686`, static and PIE: hod plain and
    under `Stress::ALL` print what `opt` + `llc` print.
  - `bodies_with_debug_information_verify_and_run`: `-g` bodies verify
    and run. By hand, `tests/debug/coroutine.cpp`'s gdb script
    (`gdb-multiarch` on `qemu-i386 -g`) printed the same values for
    hod's program as for `llc`'s (parameter, loop variable, local,
    promise, in the ramp, after a resume and in the destroy path); only
    the clone names (`[clone .resume]`) and addresses differ.
  - `a_double_across_a_suspend_is_rounded`: a `double` computed before
    a suspend and used after it is rounded (hod prints 0). The oracle
    prints `2^-60`: `CoroSplit` rematerialises the `fmul` in the resume
    clone and `llc` computes it again in 80 bits (19 and 22, `generic`
    and `pentiumpro`). This is excess precision of the oracle's; the
    IR's `double` gives 0. The suspend barrier changes no output: the
    plan requires the suspend's `switch` right after it
    (`coro:suspend-shape`), so a block ends there anyway. Measured by
    turning the arm off and running these tests.
  - `what_is_refused`.
- The 26 `i386*` test binaries of `-p hod` (`HOD_REQUIRE_TOOLS=1`): 100
  tests pass. Every program in them runs plain and under `Stress::ALL`
  (a pool of 2; a body has `ebx`, `edi`).
- irdiff i686, full tier: LLVM 22 gives 147 PASS, 0 FAIL, 0 ERROR (60
  UNSUPPORTED, 44 SKIP). LLVM 19 gives 147 PASS, 0 FAIL, 0 ERROR (57
  UNSUPPORTED, 45 SKIP). The base was 132 on both. Every `tests/ir/coro`
  seed passes, and `coro:target` is gone from the declines.
- compare-binaries, base `8e6e852c` against the head, over `tests/ir`
  and the two kiln corpora:
  - AArch64: 3488 × 2 compared, 0 different, 0 changed outcome;
  - x86-64: 3457 × 2 compared, 0 different, 0 changed outcome;
  - i686: 112 × 2 compared, 0 different, 68 changed outcomes. All 68 go
    from `coro:target` to compiling (the 34 body seeds of `tests/ir/coro`,
    plain and PIC).
