# WP-197: the always-inliner's leftovers (frame intrinsics, `returns_twice`)

Spec: `spec/cli.md` "Always-inline" ("Which calls LLVM inlines", the
table, "Frame bias"). No `spec/codegen.md` section taken.

## The lane's refusals

The real-project refusals (`alwaysinline:return-address`: abseil
`symbolize_test.cc`, `stacktrace_test.cc`, glog `symbolize_unittest.cc`,
also abseil on x86-64; `alwaysinline:returns-twice`: glog
`logging_unittest.cc`, `utilities_unittest.cc`) were made by a hod
before WP-188: each named body is `noinline optnone`, called at a plain
site, so `opt` inlines none of them and WP-188's per-call-site rule
already compiles them. With this branch, `hod --strict -O0
-relocation-model=pic` compiles all seven saved kiln-built modules (five
AArch64, the x86-64 abseil one and its reduction), 0.03 to 0.13 s, 4 to
26 MB peak; the five AArch64 ones also compile retargeted to x86-64
(triple, data layout, CPU and features rewritten). The x86-64 sample's
`min.ll` had lost the `noinline` in reduction.

## What `opt -passes=always-inline` does (19 and 22, measured)

- `llvm.returnaddress`, `llvm.frameaddress`, `llvm.addressofreturnaddress`
  are copied unchanged into the caller, through nested inlining too
  (WP-188 had this; re-measured).
- A body with a `call` of `setjmp` (`returns_twice` on the declaration,
  on the call, or on an indirect call) is not inlined, also into a
  `returns_twice` caller. But an `invoke` of `setjmp` is inlined, and so
  is the `setjmp` call of a body that is `returns_twice` itself
  (`isInlineViable`: "exposes returns-twice" is checked for a
  `CallInst` in a callee without the attribute). hod's `inline_viable`
  counted every such call: for the last two shapes it compiled the body
  out of line, where `longjmp` returns into a dead frame. Now they
  decline by `alwaysinline:returns-twice` (hod does not inline).
- A body with a block address of its own is inlined only when every use
  is a `callbr`; hod treats it as unknown (declines if sensitive).

## Frame bias

A local `alwaysinline` body (or an `available_externally` copy) whose
only sensitive constructs are `llvm.returnaddress` and
`llvm.frameaddress` is accepted with depth `n + b` when every way it
runs is `b >= 1` frames below the frame `opt`'s inlined code runs in.
Every hod function has a frame record, so this is the same value, not
an approximation. `inlining.rs` `frame_bias`: the graph of direct calls
among compiled bodies and reached copies; a body runs in its own frame
when not local, named by anything but a direct callee (code operand,
constant, structor, personality, `llvm.used`), or called by a kept
call; an inlined edge adds one when `opt` certainly inlines it (viable,
no `callbr`, no bundle, the callee's function type, no `musttail`, no
pre-split coroutine caller, no personality conflict). A set of biases
that is not one `b >= 1`, or unknown, keeps the decline. `deepen`
rewrites the depth constant (`hod_ir::Body::set_call_arg`, new).

Kept refused, by their names: a body reached at two depths (directly
and through another `alwaysinline` body: real inlining would be
needed), one that must also run out of line (`linkonce_odr`, external,
a kept call, an address taken: needs a second local copy), one with
`llvm.addressofreturnaddress`, `llvm.sponentry` or another construct of
the table; `returns_twice` bodies `opt` inlines (above).

## Evidence

- `crates/hod/tests/inlining.rs`:
  `a_frame_bias_gives_the_inlined_frame` (the biased object is
  byte-identical to the same module with depth `n + b` written in and
  every call `noinline`: bias 1, bias 2 through an inlined intermediate,
  a copy); `no_frame_bias_where_the_frame_is_not_one` (12 shapes keep
  the decline) and `no_frame_bias_across_personalities`;
  `a_setjmp_opt_inlines_is_declined`;
  `bodies_that_need_inlining_are_declined_by_name` updated (internal and
  `available_externally` frame/return-address bodies compile;
  `returns_twice` bodies decline).
- `frame_intrinsics_and_setjmp_behave_as_opt_inlined_them`: two C
  programs (clang-22 `-O0 -Xclang -disable-llvm-passes`, with and
  without `-g`) built by hod and by `opt -passes=always-inline` + `llc
  -O0 -global-isel=0 -fast-isel=0`, AArch64 native and x86-64 under
  qemu: frame intrinsics at depth 0 and 1, nested, in a loop, each equal
  to the caller's own value (`same`), each return address inside `main`
  by `llvm-nm -S`; `setjmp`/`longjmp` round trips with plain and
  `volatile` locals changed between, `always_inline` helpers inlined
  into the `setjmp` caller, a loop of five jumps, an `always_inline`
  body with a `setjmp` call: identical output, 8 builds.
- Mutation: `deepen` disabled fails the runtime test (`DIFFERENT`) and
  the byte-identity test; reverted.
