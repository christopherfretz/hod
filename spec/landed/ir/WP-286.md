# WP-286 — 32-bit x86 Linux in the front half (design 0008, part I3)

Landed: `Arch::I386` (`crates/hod_ir/src/target.rs`), the triples
`i386`/`i486`/`i586`/`i686-[vendor-]linux-gnu`, the built-in layout
`I386_LINUX_DATA_LAYOUT`, folds that wrap at 32 bits
(`crates/hod_ir/src/fold.rs`), the 32-bit CPU table
(`crates/hod_ir/src/x86_cpu.rs`), the ignorable `NumRegisterParameters`
flag (`crates/hod_ir/src/props.rs`), and in the facade and the tool the
one refusal `x86:not-implemented` after the front half
(`crates/hod/src/back.rs`, `crates/hod_cli/src/driver.rs`). Specified in
`spec/ir.md` §2.1 and §4.2 and `spec/cli.md` ("Reasons", "The back
half" step 2a, `--help`).

## Measurements

- Layout: clang 19 and clang 22 write the same string for `i386`, `i486`,
  `i586` and `i686` (`-target <name>-linux-gnu`):
  `e-m:e-p:32:32-p270:32:32-p271:32:32-p272:64:64-i128:128-f64:32:64-f80:32-n8:16:32-S128`.
  `struct { long long; double; char; }` is 20 bytes, aligned to 4, the
  `double` at offset 8.
- clang's default for every one of the four is `"target-cpu"="i686"`,
  `"target-features"="+cmov,+cx8,+x87"`; it writes the module flag
  `NumRegisterParameters` = 0 in every module.
- `llc` 22 takes 131 CPU names for `i686`, `llc` 19 128 of them. With no
  CPU anywhere `llc` uses `generic` (`x87`, `cx8`, no `cmov`), whatever
  the arch component. A function's `target-cpu` beats `-mcpu`; `-mattr`
  applies after the function's `target-features`; any SSE level makes
  `llc` use `cmov`.
- Folding by `llc` (both versions): `gep (i8, @g, i64 4294967300)` is
  `g+4`; an offset of 2^31 is `g-2147483648`; `ptrtoint (gep (i8, null,
  -1)) to i64` is 4294967295; `inttoptr i64 4294967298` is address 2;
  `ptrtoint @g to i64` in an initializer is refused ("unsupported
  expression in static initializer").

## Corrections to design 0008

- The layout is one string at 19 and 22; no per-version layout is
  needed.
- The CPU table must follow `llc`'s CPU definitions, not clang's
  front-end lists: clang's `-march=pentium4` list is `+sse` without
  `+sse2`, yet `llc` uses SSE2 for `pentium4`; clang's `k8` list has no
  `cmov`.
- `llc`'s default CPU with neither `target-cpu` nor `-mcpu` is `generic`,
  not `i686`: no `cmov`.
- SSE implies `cmov` in LLVM (`canUseCMOV`), which the table applies.
- The front half must accept `NumRegisterParameters` (0), or every clang
  module is refused as `module-flag:NumRegisterParameters`.
- LLVM 19 folds `ptrtoint (inttoptr (i64 X)) to i64` to X with 32-bit
  pointers; LLVM 22 truncates, as hod does. The LLVM 19 differential uses
  pointer-width integers for these.
- LLVM's verifier requires a `ptrtoaddr` result to be the address width;
  `hod_ir`'s verifier was not checked for this.

## Tests

- `crates/hod_ir/src/target.rs`: the triple table, `i386_layout_fields`.
- `crates/hod_ir/src/fold.rs`: `gep_and_casts_wrap_at_32_bits_on_i386`.
- `crates/hod_ir/src/x86_cpu.rs`: table order, defaults, precedence,
  implications.
- `crates/hod_ir/src/props.rs`: `num_register_parameters_is_ignorable_at_zero`.
- `crates/hod_ir/tests/layout_diff.rs`, `fold_diff.rs`: against `llc` 19
  and 22 for `i686`.
- `crates/hod_ir/tests/x86_cpus.rs`: every CPU against `llc` 19 and 22 by
  the instructions selected; `-mcpu`/`-mattr` cases.
- `crates/hod/tests/i386.rs`: every triple declined by the one name,
  other 32-bit triples `unsupported-target`, front-half refusals first,
  clang 19 and 22 modules (`a.c`, `dbg.c`, `eh.cpp`; text and bitcode;
  default and `pentium4`) reach the back half.
- `crates/hod_cli/tests/cli.rs`: an i686 module falls back with
  `x86:not-implemented`; `-mtriple=x86_64-unknown-linux-gnux32` with
  `unsupported-target`. `crates/hod_cli/src/driver.rs`: the help text.

## Files touched outside `hod_ir`, `hod`, `hod_cli`

- `crates/hod_cg/src/emit/mod.rs`: `ModuleEmitter::new` refuses
  `Arch::I386` as `x86:not-implemented`.
- `crates/hod_cg/src/sym.rs`: `fp_routine` has no routines for I386.
- `crates/hod_cg/tests/runtime_names.rs`: an I386 arm.
- `crates/hod_ll/tests/common/mod.rs`, `crates/hod_ll/tests/differential/flags.rs`:
  I386 arms in the test helpers.

## Not done

- No code generator: every i386 module is `x86:not-implemented` (I4, I5).
- No classification column of its own: i386 uses x86-64's, so
  `regparm`/`fastcall` (`attr:inreg`) are refused, `musttail` is
  `musttail:stack-args-unknown` (no stack-arguments rule), and coroutine
  bodies are refused (`bodies_compiled` is false).
- `hod_interp`'s varargs check (`crates/hod_interp/src/interp/varargs.rs`)
  treats every target that is not x86-64 as AArch64; not changed.
