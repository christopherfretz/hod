# WP-006 — hod_ir printer: LLVM text, LLVM 19 to 22

Landed: `spec/ir.md` §9 (the printer, its dialects, the split, the error
constructs, and the rules LLVM has that `hod_ir` does not check). Not
here: debug information in the text (hooks only, §9.7), a parser.

`crates/hod_ir/src/print/`:

| file | contents |
|---|---|
| `mod.rs` | `Dialect`, `Part`, `PrintError`, `IoSink`; `Module::print`, `print_part`, `print_body`; names, quoting, types, constants, linkage |

Outside the print module:

  (visibility only), for `print/random_tests.rs`.
- `crates/hod_ir/src/lib.rs`: `mod print;`, the re-export of `Dialect`,

## Decisions where the spec was silent

- Unsupported is an answer: where LLVM cannot say what hod means, or the
  IR does not keep what the text needs, `PrintError::Unsupported` names
  the construct (§9.6 lists them). Nothing is approximated.
- Struct types are literal types: the IR keeps no names.
- The split (§9.6): local symbols become external `hidden` in both parts,
  anonymous ones `@__hod_anon.<id>`; `Main` holds the variables'
  definitions, module assembly, structors, linker options and dependent
  libraries; a COMDAT stays only where all its members are defined.
- LLVM 19 on AArch64 gets LLVM 19's own data-layout string, and an `i1`
  global's alignment is written explicitly, so that LLVM 19 lays data out
  as §3 does.
- `Body::verify` was not changed: §9.8 lists what LLVM refuses and hod
  accepts.

## What LLVM does that was not expected

- LLVM 22's verifier crashes (segfault) on `callbr` of a function that is
  not inline assembly, e.g. `callbr void @llvm.hod.first() to label %a
  [label %b]`.
- ELF `llc` stops with `invalid llvm.linker.options` unless each option
  is a pair; the verifier accepts any list.
- Branch-protection module flags mean something else in LLVM 20 and later
  at value 1 than at 2 (§9.2).

## Disagreements between `hod_ir` and LLVM

Counts are of 1500 generator seeds from `FIRST_SEED = 100`
(`print/random_tests.rs`), LLVM 22. `Body::verify` accepts, LLVM refuses:

| rule | count |
|---|---|
| a use not dominated by its definition | 263 |
| a self-use in a reachable block | 73 |
| `callbr` of a callee that is not inline assembly | 114 |
| `invoke` of an intrinsic | 47 |
| tail markers on `invoke` / `callbr`, and `musttail`'s rules | 92 |
| an `immarg` parameter given a non-constant (LLVM 22: or `undef`) | 79 |
| a `"kcfi"` bundle without exactly one operand | 58 |
| `signext` on a value that is not an integer | 76 |

Also: uses of an `invoke`/`callbr` result off the normal edge; parameter
attributes not checked against types or positions (`sret`); found by
`tests/print_module.rs`: `FnAttrs` takes `sanitize_realtime` with
`sanitize_realtime_blocking`, `set_module_flag` takes a string for
behavior 5 (append), `add_linker_option` takes a one-element option that
ELF `llc` refuses. Model gaps are in §9.8. `flatten` agreed with LLVM
everywhere it was tested.

## Measurements

`cargo test --release -p hod_ir --test print_perf -- --nocapture`, a
shared machine: 5000 functions, 75000 instructions, 2.80 MB of text in
9.7 ms into a `String` (288 MB/s) and 10.5 ms through an `IoSink` into a
`Vec<u8>` (266 MB/s). Not a gate.
