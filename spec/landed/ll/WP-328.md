## Step 0: `stl-heavy-g` (x86-64 inputs, the same text for AArch64)

16.4 MB of text, 9.30 MB of it numbered metadata lines, 84,574 nodes:

| Kind | Nodes | Bytes | Fields per node |
| --- | ---: | ---: | ---: |
| `DILocation` | 35,285 | 2,095,145 | 3.0 |
| `DISubprogram` | 11,636 | 3,924,686 | 10.0 |
| tuples `!{...}` | 9,243 | 353,715 | - |
| `DILocalVariable` | 8,146 | 867,945 | 5.5 |
| `DIDerivedType` | 7,491 | 809,151 | 4.3 |
| `DISubroutineType` | 6,627 | 275,154 | 1.0 |
| `DILexicalBlock` | 2,329 | 196,636 | 4.0 |
| `DICompositeType` | 1,279 | 559,309 | 9.1 |
| `DITemplateTypeParameter` | 1,065 | 66,339 | 1.9 |
| others (10 kinds) | 1,473 | 147,000 | 1 to 12 |

About 300,000 fields in all. What the parser does per field today, for
every kind with a record (`DILocation` has its own reader,
`location_body`, debug.rs:976, straight into `DiLocation`):

1. tokens: the lexer makes a `Label` (`name:`), the value's one to
   three tokens and a `Comma` (`field_name` debug.rs:787, `field_value`
   debug.rs:843); words go through `kw::keyword`. No allocation.
2. `(Key, Val)` pushed to `DebugScratch::fields` (debug.rs:138, :741),
   strings as source ranges or copied into `scratch.strs` when they
   hold an escape, lists into `scratch.lists`: reused vectors, no
   allocation per node.
3. `DiNode` built by `Made::node` (debug.rs:1149) from
   `DiNode::llvm_default` and `set_at` per field: on the stack.
4. the stored form: `kit::define_di_node` -> `DebugInfo::define_as`
   encodes the node into cells (`hod_ir`), interning strings.

Bytes walked more than once: the index (`index.rs:363` `group`, i.e.
`skip::skip_group`) walks every numbered node's parentheses byte by
byte to find its extent (all 9.30 MB), then the parser lexes the same
bytes as tokens: every metadata byte twice. A node or tuple written in
place inside a field (`!{...}`, `!DIExpression(...)`, an inline
`!DI...(...)`) is walked a third time (`skip_brackets` in `node_ref`,
`list_ref`, `inline_node`, `expr_ref`, then lexed). `skip_group` is the
index's (not this package's files); the parser's second walk is what a
byte path removes.

## Built, tested, not measured: fields read from the bytes

`e0b442e8` (reverted by `bdc6f481`): `quick_field` reads a field of a
node with a record as LLVM's writer prints it (`name: value` followed
by `,` or the node's `)`; values: `"..."` without escape, `!N`, `N`,
`-N`, a word, flags joined by ` | `, a list by number or `null`)
straight from the source bytes, without the lexer; `quick_location`
reads `!DILocation(line: N, column: N, scope: !N[, inlinedAt: !N])`.
Anything else (another spelling, a field outside the record, a field met
twice, an expression, a bound, a value the token path would refuse or
record) gives `None` before anything is read into the module, and the
token path reads the node from that field on, so diagnostics are its
own. `cargo test -p hod_ll` passed with it, with a new test
(`debug_fields_read_from_the_bytes_are_the_tokens_reading`: modules
respelled so that the token path reads every field, or takes over in
the middle of each node, print the same and record the same
constructs). Whole-program counts, compare-binaries and peak memory were
NOT run: the package's budget ran out. It covers about all of the
300,000 fields of `stl-heavy-g` and replaces three to four tokens per
field; expected to be the largest cut left, unproven.
