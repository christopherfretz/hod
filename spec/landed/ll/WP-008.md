# WP-008 — hod_ll: function bodies

Landed: `spec/ll.md` §11 (function bodies into `hod_ir::Body`, on the
interface of §6) and the body names of §3.4. Not here: debug nodes
(WP-005; the text of attachments and records is kept, §11.9), a printer
(WP-006), the command line (WP-043).

## What it did

`crates/hod_ll`:

| module | contents |
|---|---|
| `body` (new) | `BodyParser`, `parse_bodies`, `ParsedBody`, `BodyDebug`, `DebugRecordText`; local names and numbers, blocks, the label scan and the numbering pass, statements, attachments, the debug seam (§11.1 to §11.3, §11.9) |
| `inst` (new) | every instruction but calls, with LLVM's type checks and `hod_ir`'s lowering (§11.4, §11.5) |
| `call` (new) | `call`, `invoke`, `callbr`: callees, inline assembly, intrinsics and the no-code rule, call-site attributes, bundles, metadata operands (§11.6, §11.7) |
| `parser` | `Parser<'a, 'm>` borrows the module, and in body mode reads names through `ModuleText`; `Scratch` keeps its stacks between bodies |
| `types`, `globals`, `meta` | the body-mode lookups of named types, globals and metadata nodes |
| `consts` | `blockaddress` inside a body resolves the function through `text.functions()` |
| `names` | `hash` is shared with the local-name table |

Tests (`spec/ll.md` §11.11): `tests/syntax` has 74 body rows and 11 body
unsupported rows, each run through `llvm-as` 19 and 22; the three rows
that were `ok` only because bodies were not read now give LLVM's
verdict. New: `tests/roundtrip.rs` (generated programs printed as LLVM
text, read back, run in `hod_interp` against the originals; 290 in the
gate, 4,440 in the ignored batch), `tests/differential/bodies.rs` (the
test corpus: parse, verify, written against canonical, block counts
against `llvm-dis`; parallel parsing on clones), `tests/corpus.rs` (the
captured corpus, with `HOD_LL_CORPUS`). `tests/robustness.rs` parses
bodies in every case and has 12 body inputs. `tests/perf.rs` measures
"module and bodies" and "bodies alone" and the peak memory with bodies.

## Evidence

- Captured corpus (`HOD_LL_CORPUS=.build/corpus cargo test --release -p
  hod_ll --test corpus`), 5,760 modules: LLVM 19, 2,864 modules, 24,009
  bodies, 24,005 delivered and verified, 4 unsupported, 0 errors; LLVM
  22, 2,896 modules, 24,230 bodies, 24,226 delivered and verified, 4
  unsupported, 0 errors. The 8 unsupported are all
  `call:forwarded-varargs`. 155 MiB/s of body text (one thread;
  67.7 and 68.0 MiB of bodies).
- Test corpus: 10,138 bodies with block counts equal to `llvm-dis`'s;
  every unsupported name within `CLANG_BODY_UNSUPPORTED`.
- Round trip: 4,440 generated programs (the ignored batch, three sizes) read back and run alike.
- `perf` (release, best of 5, shared host):

| text | module-level parse | module and bodies | bodies alone | peak memory, with bodies | `llvm-as` |
|---|---|---|---|---|---|
| clang 22 `stl.cpp` | 4.6 ms | 18.7 ms, 195 MiB/s | 192 MiB/s, 4.96 ns/byte | 1.43 MiB | 105 ms |
| clang 22 `-g` | 10.9 ms | 27.6 ms, 351 MiB/s | 203 MiB/s, 4.69 ns/byte | 3.17 MiB | 298 ms |
| clang 19 `stl.cpp` | 4.3 ms | 18.1 ms, 198 MiB/s | 193 MiB/s, 4.94 ns/byte | 1.45 MiB | 90 ms |
| clang 19 `-g` | 11.4 ms | 27.8 ms, 343 MiB/s | 203 MiB/s, 4.71 ns/byte | 3.02 MiB | 308 ms |
| synthetic | 6.5 ms | 103 ms, 183 MiB/s | 188 MiB/s, 5.08 ns/byte | 1.34 MiB | |
| synthetic `-g` | 7.0 ms | 116 ms, 178 MiB/s | 178 MiB/s, 5.36 ns/byte | 1.46 MiB | |

  Bodies cost about three times lexing their tokens; the whole parse is
  about 5 to 11 times faster than `llvm-as` (which also verifies and
  writes bitcode). Peak memory with bodies is within 0.1 MiB of the
  module level's: one body is alive at a time.

## Deviations

- `spec/ir.md` §5.1, parallel parsing against a frozen `&Module`: not
  implementable on `hod_ir` as it is (§11.1). Each worker parses with a
  clone of the module; tested to give the sequential bodies.

## Gaps in hod_ir (not edited here)

- No lookup-only access to `TypeTable` / `ConstPool`, and no immediate
  integers in `Value`: blocks §5.1 as written. Proposal: `find_*`
  lookups, or the snapshot tables of `spec/ir.md` §10.
- `Body::empty()` is `pub(crate)`: the first body of a parser cannot be
  built in given storage (minor).
- `attr_info` (`crates/hod_ir/src/attrs.rs`) scans every keyword row on
  a miss; a call site meets one per call. `call.rs` pre-checks the words
  that follow attribute lists. Proposal: scan only the prefixed rows.
- `verify.rs`'s `cast_is_valid` and `wide::sext64` are private; `inst.rs`
  has copies.
- `llvm.experimental.noalias.scope.decl` generates no code in LLVM and is
  not in `NO_CODE`; its metadata argument makes the body unsupported.
- No metadata operand: constrained floating point and other intrinsics
  with `metadata` arguments are `metadata-arg:<callee>`.

## Follow-ups

- `blockaddress` of a block without a label, inside or outside the
  function (`crates/hod_ll/src/consts.rs`, `block_address`): still
  `blockaddress:unlabelled-block`. A numbering pass of the target body
  (as `body.rs` does for its own) closes it; hand-written text only.
- Body throughput (about 5 ns/byte): profile `Fx::statement` and the
  interning of constants per operand before the next optimization pass.
