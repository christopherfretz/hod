# WP-314: i386 exceptions and debug information (design 0008 I10)

Part 1 (exceptions, sessions 1 and 2) and Part 2 (debug information,
sessions 3 and 4, `x86:debug-info` removed) are complete. Part 2 is
below Part 1's evidence.

## What changed

- `hod_eh`: `CfiTarget.arch` became `machine: Machine`; new fields
  `address_size` and `abs32_reloc`; the `I386` table and
  `for_machine(machine, large)` (`spec/eh.md` §2.1). The `DW.ref` slot,
  the type-info stubs and `.debug_frame`'s locations and ranges are
  `address_size` bytes. The 64-bit tables keep 8 and the relocations
  they had, so their output is unchanged (compare-binaries below).
- `hod_cg/src/emit/unwind.rs`: the early return for `EM_386` removed;
  the FDE table chosen by machine.
- `hod_cg/src/emit/mod.rs` (structors, authorized by the supervisor): an
  `.init_array`/`.fini_array` entry is `arch.address_bytes()` long. It
  was 8 on every machine, so on i386 each `R_386_32` entry was followed
  by a zero word and the program called address 0 at startup
  (`tests/ir/global_ctors.ll`; the `x86:eh` refusal had hidden it). 8 on
  AArch64 and x86-64: unchanged.
- `hod_x86/src/eh.rs` (new), `call.rs` (the `x86:eh` refusal of
  `invoke` and of calls that may unwind removed; `llvm.eh.typeid.for`
  arm), `target.rs` (landing pad, resume, the pad value's
  `extractvalue`/`insertvalue`). `spec/codegen-x86.md` §12.

## Decisions

- PIC encodings in every model, as on x86-64 (`llc`'s static ones are
  absolute and make a PIE text-relocated; measured with `llc` 19 and
  22). A documented deviation (supervisor's decision): the static
  objects' tables differ from `llc`'s by design; they are tested by
  linking and running `-no-pie` programs with GNU ld, lld and mold and by
  decoding the LSDAs (`lsdas_decode_as_llc_s`, static and PIC).
- The landing pad value is class `Mem` and its two fields are handled in
  `eh.rs`; other aggregates stay `x86:aggregate` (I11a's).
- The decoded `.eh_frame` comparison with `llc` covers the CIEs, FDE and
  LSDA counts, the prologue rules per FDE without `ebx`/`esi`/`edi`
  (hod saves all three always), and the relocation kinds; after the
  first exit `llc` writes one exit per `ret` and hod one per function,
  and a module without `"frame-pointer"="all"` has an `esp`-based CFA in
  `llc`, so those parts are not compared.
- The LSDA comparison decodes call sites, actions, catch types (through
  the relocations and the stubs), cleanups and filters; it compares
  whether a call site has a pad, not which: where several `invoke`s
  unwind to one IR pad `llc` has one landing address and hod one per
  `invoke` (measured on `basic.cpp`).
- `x86_stdcallcc`/`x86_fastcallcc` stay refused (`cc:<name>`, the
  shared classifier's) for `invoke` as for `call`; the callee pop hod
  has on i386 is the `sret` pointer, tested by `eh/callconv.ll`.
- x87 (`spec/codegen-x86.md` §11, i386-group-2 rule): an `invoke` is a
  terminator, hence a barrier; no new barrier. Measured in `llc -O0
  -global-isel=0 -fast-isel=0` assembly, LLVM 19 and 22, CPU `generic`
  and `pentiumpro`: a product computed before an `invoke` is stored
  rounded (`fstpl`/`fstps`) before the call and reloaded in both
  successors; one computed and used inside the pad stays in a register.
  `eh/callconv.ll` checks both shapes on `llc`'s run (1e300 * 1e300 / 1e300
  infinite after rounding, finite at 80 bits) and hod's runs equal it.

### Decisions

- **The epilogue row after a landing pad.** hod writes, in `eh.cpp`'s
  `main`, an `is_stmt epilogue_begin` row at line 6 column 3 after the
  landing pad's rows, where `llc`'s `epilogue_begin` row at 6:3 is not a
  statement. This is the existing rule, not an analogy with x86-64:
  `spec/codegen.md` §4 emits the one epilogue at the function's end
  (`Ret` branches to it), `spec/dwarf.md` §5.4 gives the epilogue row the
  single `ret`'s location, and §5.2 marks it `epilogue_begin`, and
  `is_stmt` because its line (6) differs from the last non-zero line
  written (5, the pad's). `llc` places the epilogue in the `ret`'s
  block, right after 6:3, so its row is no new statement. The test
  checks the rule itself on i386 (every `epilogue_begin` row of hod's,
  in order, is at its function's `ret`'s `DILocation`, `is_stmt` exactly
  as §5.2 says) and compares the other statement rows with `llc`'s
  exactly; the x86-64 comparison of session 3 is gone. Rows (LLVM 22,
  static, `main`, from 6:10):

      hod: 6:10 is_stmt | 6:17 | 6:3 | 5:19 is_stmt (pad) | 6:3 is_stmt epilogue_begin
      llc: 6:10 is_stmt | 6:17 | 6:3 epilogue_begin | 5:19 is_stmt (pad)

- **Location lists of optimized IR** (`fits_i386`, session 3; measured
  in session 4). The DWARF stack is 32 bits wide on i386: a range whose
  value expression pushes a wider value (an `i64` or `double` value or
  constant), an address read from a home, or a `DIArgList` gets no
  entry (the variable reads `<optimized out>` there); a home with the
  empty expression is a memory location of any size; a 4-byte home with
  a value expression is read with `DW_OP_deref_size 4` (`llc` writes the
  same operation: `DW_OP_breg4 ESP+36, DW_OP_deref_size 0x4,
  DW_OP_plus_uconst 0x4, DW_OP_stack_value`). `llc` writes 64-bit stack
  values and gdb prints them truncated (below), so no entry is right.

### The debug lane's i686 column (brief for a later package)

`cargo xtask debug --target i686` stops with `NO_I686_LANE`
(`xtask/src/debug.rs:76`, used at `:149` and `:294`): the lane builds
each program with clang and `llc` and with hod, runs both under the
debuggers and compares the transcripts, and none of its parts knows
i386 yet. What the column needs:

- **Build** (`debug/build.rs`, `debug/kiln.rs`): clang
  `--target=i686-linux-gnu` (19 and 22), `llc` and hod with the i686
  triple; the `-gsplit-dwarf` and `-gdwarf-4` cases kept off on i686 by
  their refusal names (`debug:split-dwarf-i386`, `debug:dwarf-4-i386`)
  until those are lowered; `-O1` cases with
  `-fexperimental-assignment-tracking=disabled` (assignment tracking is
  refused on every target).
- **Link** (`debug/xlink.rs`): the i686 linkers as `i386_eh.rs` uses
  them (`linkers::present(Target::I686)`, `driver_flags`): GNU ld, lld
  and mold; not wild (no `elf_i386`), mortar only for `-static`.
- **Run** (`debug/cross.rs`): `qemu-i386 -L /usr/i686-linux-gnu -g
  <port>` and gdb as `gdb-multiarch` with `target remote` and `set
  sysroot /usr/i686-linux-gnu` (the x86-64 cross case's shape with the
  i386 emulator); lldb through `gdb-remote` if its i386 support holds,
  else gdb only, said in the lane's notes. Programs that need SSE take
  `-cpu` from `i386_support::cpu_features`.
- **Transcripts that differ by design** (`debug/permitted.rs`, each by
  an existing rule): parameters are in hod's slots (`spec/dwarf.md`
  §6.17), so `info frame` / `info address` differ where `llc` describes
  them in place; a `byval` parameter is read through the saved pointer;
  after a landing pad laid out last the epilogue row is a statement
  (§5.2, §5.4), so stepping out of a catch block may stop once more at
  the `return` line in hod's program (not measured); at `-O1` a 64-bit
  value with a value expression is `<optimized out>` in hod's program
  and truncated in `llc`'s, so `llc`'s transcript is not the reference
  for it.
- **Expectation**: the x86-64 column's programs, transcripts equal
  modulo addresses and the rules above; session 3's `dbg.c` session is
  the first case.
