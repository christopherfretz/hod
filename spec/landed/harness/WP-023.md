# WP-023 — `irdiff` follow-ups, part 1: the reference compiler and directives

Landed: `spec/harness.md` "irdiff" ("The oracle", "The witness", the
option `--witness`, the hybrid wrapper, several modules), "Test
directives" (`llc-args`, `stdout-no-newline`, `module`,
`link: allow-warnings`) and "corpus" (the capture script's selector,
admission with the witness and the warning retry, bitcode, several
translation units, format `hod-corpus-2`, the `delivered` column);
`docs/VALIDATION.md` "Oracles". Part 2 (emulated cross runs, more seed
tests, wild) is WP-025.

## What landed, per item

1. **The reference compiler.** `engine::REFERENCE_SELECTOR`
   (`-global-isel=0 -fast-isel=0`) is added to the oracle's `llc -O0` on
   every target; hod still gets plain `-O0`. In hybrid mode hod's
   `--fallback=` is a `reference-llc` wrapper in the run's work directory
   that adds the selector. The witness (`--witness`, `Config.witness`,
   `Session.witness`) builds every module with `llc -O2` and runs its
   program once per test; a disagreement, a failed build or a failed link
   is an ERROR whose detail starts with `witness: ` (`engine::WITNESS`),
   for that linker and every later one. The full gate (`cargo xtask ci`)
   runs with it. Seed tests `tests/ir/selector_narrow_load.ll` and
   `tests/ir/selector_i1_compare.ll` are the two reproducers of
   `spec/interp.md` §10.1. The kiln capture script runs the real `llc`
   with the selector, and torture's `llc` step has it too, so expectations
   are read from the reference's program.
2. **Directives.** `llc-args` (allow-list `directives::LLC_ARGS`),
   `link: allow-warnings`, `stdout-no-newline`, `module`; errors and
   canonical form as specified.
3. **Bitcode.** A module kiln gave `llc` as bitcode is written as text
   by the group's `llvm-dis` (`; delivered: bitcode`); new skip reason
   `llvm-dis-fails`.
4. **Several modules.** The engine compiles each `;@ module:` part on its
   own and links the objects in file order (`tests/ir/two_modules.ll`).
   Capture replays kiln's two-step builds (`module:`, `unit:`,
   `two-step`), captures one-command multi-input builds whose object
   names give the link order, and builds torture's `builtins/` tests from
   three files.

Corpus format `hod-corpus-2`: `MANIFEST.tsv` has a 12th column,
`delivered`; the 11-column header is still read. Census: each module of
an entry is scanned on its own; new table "Modules of an entry".

## Decisions, and why

- **x86-64 gets the selector too.** No miscompile is known there, but
  FastISel is the same `-O0`-only design, SelectionDAG is what the `-O2`
  witness uses, and `-global-isel=0` is a no-op on x86-64. Evidence: the
  31 single-module seed tests behaved identically under `qemu-x86_64`
  with LLVM 22 and 19.
- **Both arguments are needed.** On AArch64 with LLVM 22 and 19, the
  narrow load prints `-5408` with plain `-O0` (GlobalISel) and `60128`
  with SelectionDAG and with `-O2`; the i1 compare prints `0` (right)
  with GlobalISel, `1` with `-global-isel=0` alone (FastISel), `0` with
  SelectionDAG and `-O2`. So plain `-O0` fails only the first reproducer;
  the second is failed by `-global-isel=0` alone.
  `the_reference_is_not_plain_o0` checks this on every run and passes
  with a note on stderr once an LLVM stops miscompiling.
- **A witness disagreement is its own ERROR**, never a hod failure; the
  directives are checked first, so a wrong test is reported as a wrong
  test. No real program was found whose `-O0` and `-O2` builds
  legitimately differ without undefined behaviour; the real-tool witness
  test uses an oracle that drops the selector arguments instead.
- **`link: allow-warnings` only where it is needed:** capture sets it
  only when a first admission pass is refused for an oracle link failure
  and a second pass with the flag is admitted.
- **`corpus verify` does not use the witness**: admission already did.
- The coverage line counts tests, not modules: a test of several modules
  is one object hod was asked for.

## Evidence

All on the AArch64 reference machine, LLVM 22 and 19, linkers bfd, lld,
mold (wild is not provisioned).

- `cargo test -p xtask --lib` 89 passed; `--test irdiff_fakes` 24;
  `--test corpus_fakes` 6; `--test irdiff_real` 10 (the five new ones
  included; neither selector bug has gone away in either LLVM: no note
  was printed); `--test corpus_real` 1.
- **Capture** (`corpus capture --out <scratch corpus> -j 3`): 6250
  entries, 191.3 MiB, 2212 s (kiln/llvm22 1434 of 1540 in 687 s,
  kiln/llvm19 1396 in 558 s, gcc-torture/llvm22 1709 of 1812 in 550 s,
  gcc-torture/llvm19 1711 in 417 s). **verify** (hybrid, the workspace's
  hod): manifest 6250 entries, 0 problems; LLVM 22 3143 tests, 9429 PASS;
  LLVM 19 3107 tests, 9321 PASS; no FAIL or ERROR.
- **Against the previous corpus (5,760 entries): 490 gained, 0 lost.**
  By the reason the test was skipped before: `multi-file` 293 (kiln 114
  + 111, torture 34 + 34), `opt-first-optimized` 76, `opt-first-always-inline`
  62, `opt-first-coroutine` 50 (bitcode, now through `llvm-dis`: 99
  entries per kiln group have a bitcode module), `not-reproducible` 9
  (`link: allow-warnings`: kiln `over.match.copy/direct-init-explicit-conversion-to-copy-ctor.cpp`
  for both majors and `dcl.struct.bind/p0963-binding-condition.cpp` for
  22; torture `printf-2.c`, `fprintf-2.c`, `user-printf.c` for both).
  Of the old `multi-file` skips not gained: 4 per kiln group are now
  `libc++` (`module.import/import-std-*`, which need libc++'s `std`
  module), 1 is `pch-run.cpp` (still `multi-file`), 2 in kiln/llvm19 are
  `requires`; of torture's 59 `builtins/` tests 21 are `clang-rejects`
  (`__builtin_setjmp`, unknown builtins) and 4 `program-fails` (they
  abort under clang: `abs-1.c`, `uabs-1.c`, `memops-asm.c`,
  `strstr-asm.c`). No candidate was `oracle-unconfirmed` and none
  `llvm-dis-fails`. `docs/status/corpus.md` is regenerated from it.
- **Plain `-O0` against the reference, over the whole new corpus**: a
  stand-in hod that ignores `--fallback` and builds with plain `llc -O0`,
  run with `irdiff --hybrid -j 3` over a copy of every group: kiln/llvm22
  1434 tests 4302 PASS, kiln/llvm19 1396 tests 4188 PASS,
  gcc-torture/llvm22 1709 tests 5127 PASS, gcc-torture/llvm19 1711 tests
  5133 PASS. **No program of the corpus behaves differently** between
  plain `-O0` and the reference; the two seed reproducers are the only
  known programs that do.
