# WP-117 — shared tables into `hod_cg` (design 0006, R1)

Landed: `crates/hod_cg/src/{memplan,switch,features}.rs`, the leaf walk in
`crates/hod_cg/src/abi.rs`, the routine tables in
`crates/hod_cg/src/sym.rs`, `crates/hod_cg/tests/runtime_names.rs` with
`crates/hod_cg/tests/data/runtime/`, and `spec/codegen.md` §7.2 "The leaf
walk", §7.3 "Runtime routines by type and target", "Memory intrinsics",
"`switch`" and "Target features".

A refactor: target-independent decisions move out of `hod_a64` into
`hod_cg`, keyed by target where the answer differs. AArch64 output is
unchanged byte for byte (the corpus and `tests/ir/` seeds, compared
against the binary of the base commit).

## What moved

| from `hod_a64` | to `hod_cg` | target key |
|---|---|---|
| `abi.rs`: the walk over leaves, piece budget, part merging | `abi::{Classify, Leaf, walk, place_leaf, place_leaves, push, charge}` | the `Classify` hook and the `place` callback |
| `float.rs`, `fpintr.rs`: fp128 arithmetic, compares, conversions, libm names | `sym::{fp_routine, fp_ext_routine, fp_trunc_routine, fp_to_int_routine, int_to_fp_routine, fp128_compare}` | `(FpType, Arch)`; x86-64 column from `llc` 22 |
| `aggr.rs`: the `i128` division routine | `sym::int_divide_routine` | none (both targets agree) |
| `intrinsic.rs`: the memory-intrinsic thresholds and decision | `memplan::{mem_plan, MemOp, MemPlan, INLINE_MAX, INLINE_MOVE_MAX}` | none |
| `control.rs`: case order, deduplication, constant fold, search shape | `switch::{canonical_cases, constant_target, search_step, Step, case_mask, LINEAR_CASES}` | none |
| `features.rs`: the reading of a feature string | `features::{FeatureTable, Refused, UNKNOWN}` | the table (stays in `hod_a64`) |

`hod_a64` re-exports what it published before (`INLINE_MAX`,
`INLINE_MOVE_MAX`, `LINEAR_CASES`, `features::{Refused, UNKNOWN, check,
check_one}`), so no caller changed.

## New `RuntimeFn` variants

For x86-64: the `half` and `x86_fp80` conversions (`__extendhfsf2`,
`__truncsfhf2`, `__truncdfhf2`, `__extendhftf2`, `__extendhfxf2`,
`__truncxfhf2`, `__extendxftf2`, `__trunctfxf2`, `__fixxfti`,
`__fixunsxfti`, `__floattixf`, `__floatuntixf`, `__floattihf`,
`__floatuntihf`, `__powixf2`), the `float`/`double` rounding and `fma`
routines, `fminf`/`fmaxf`, and every `...f128` routine. Variants are
appended; AArch64 creates a symbol only on use, so its objects are
unchanged.

## Observations

- `switch` with two cases of one value (invalid IR): the cases to the
  default are dropped before the deduplication, so if the first goes to
  the default the second is kept, while a constant condition takes the
  first (the default). Preserved as found; `spec/codegen.md` §7.3
  "`switch`" says so.
- `hod_a64/src/tail.rs` and `tail3.rs` keep their own copies of the
  `i128` conversion and `fp128` compare tables (outside this package);
  they can call `hod_cg::sym` next.
- `llc` 19 differs from 22 for `atan2`, `minimumnum`/`maximumnum`, and
  x86-64 `half` `fma`/`powi`; the tables follow 22 and the test lists the
  exceptions.
