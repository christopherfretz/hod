# WP-068 — start-up cost, cost of declining, shim without llvm-dis, `--threads`

Landed: `Cargo.toml` `[profile.release]`, `spec/cli.md` "Threads",
`spec/harness.md` "shim", tests in `crates/hod/tests/front.rs`,
`crates/hod_cli/{src/args.rs,src/driver.rs,tests/cli.rs,tests/kiln_e2e.rs}`,
`xtask/src/shim.rs`.

How it was measured: the host is shared (load average 16-21 on 24 cores
during every run below). Each process was started with `posix_spawn` and
reaped with `wait4`, without a shell. Interleaved runs; medians and minima
are in µs. "bind mount" means the binary and its input sit on the workspace
mount. "local" means copies under the container's `/tmp` overlay, which has
a page cache. `base` is main's binary at 30c146a; `new` is this branch.

## Part 1 — start-up cost

Where the time of a decline goes: hod's own work on a 4-line declined module
is 57 µs (read 4, parse 44.5). Everything else is exec, ld.so, relocations
and page faults. The workspace mount keeps no page cache across opens, so
each exec re-reads the pages it touches (~1.8 MB of the 2.4 MB loaded image,
in 4 ranges) as 12-17 major faults. This floor cannot be reached from
inside the binary. On a local file system a decline is ~1 ms, and `/bin/true`
costs 436 µs there.

300 runs, decline on stdin (median/min, µs):

| case | bind base | bind new | local base | local new |
|---|---|---|---|---|
| decline | 6129 / 3302 (14 majflt) | 5561 / 3543 (12) | 1108 / 758 | 1048 / 691 |
| small module built | 6924 (17) | 7012 (17) | 1181 | 1128 |
| `--version` | 2912 (6) | 2546 (5) | 717 | 676 |
| `llc -O0` decline-size input | 11923 / 9026 | | | |

Variants that were tried, each in its own target directory with
`CARGO_PROFILE_RELEASE_*` / `RUSTFLAGS` (local decline median; major faults
on the bind mount):

| variant | local | bind majflt | note |
|---|---|---|---|
| base (thin LTO, 16 cgu, unwind) | 1108 | 14 | |
| **fat LTO + 1 cgu + panic=abort (adopted)** | 1048 | 12 | 4-6 % faster on big modules too |
| + `-C relocation-model=static` (non-PIE) | 1177 | 11 | no local gain in that run, needs rustflags |
| + `crt-static` | 1017 | 19 | best locally, worse on the bind mount |
| `opt-level="s"` | — | — | +7-20 % on big modules; rejected |

Sizes: 16.8 MB → 14.4 MB (`.text` 1806 → 1671 KiB). Big modules (local, best
of 7): a 7.6 MB module goes from 83.0 to 79.5 ms.

Build-time cost of the profile: clean release build 52 → 48 s. Incremental
release build after touching `hod_ll`: 30.5/29.4 → 23.3/22.4 s.
`cargo test --release -p hod_a64 --test abi --no-run` after touching
`hod_a64`: 21.7 → 18.2 s. Fat LTO over one unit beats thin LTO over 16 units
here, because the thin LTO import/export work dominates.

`panic = "abort"` changes no behaviour. The only `catch_unwind` calls are
in `xtask` (`roundtrip/ingest.rs`), which `cargo xtask` runs with the dev
profile, and in tests, which cargo always builds to unwind.

Verdict against the target: under 1 ms only on a local file system (min 691,
median 1048 under load 17). On the bind mount the page-fault floor
dominates. See the follow-ups.

## Part 2 — cost of declining

The facade (`crates/hod/src/front.rs`) is already in the cheapest sound
order: target checks, then the module level (one index scan), then the
module classification, then the bodies streamed one by one. It stops at the
first refusal unless census is on. The first refusal must not change, and
it depends on that order, so no code changed. The new test
`crates/hod/tests/front.rs` `a_refusal_ends_the_reading` pins two things:
a module-level refusal does not read the bodies, and a function-level
refusal stops before a later malformed body (phases `parse, classify`). The
census still sees both. `cargo xtask corpus reasons` is unchanged by
construction.

The libc++ "62 s of declining" came from three things, none of them the
facade order: census was on in the hybrid recipe, the shim ran `llvm-dis`,
and the bind mount added page faults. 178 declined libc++ modules (local,
best of 3, µs median by first refusal):

| first refusal | modules | non-census | census |
|---|---|---|---|
| attr:convergent | 113 | 1006 (parse 772) | 3199 |
| atomicrmw | 17 | 988 | 1267 |
| inline-asm | 9 | 4152 (walk 3034) | 4303 |

Sums over the 178 modules:
- text: 648 ms without census (read 103, parse 325, walk 173), 1619 ms with census;
- bitcode native: 384 ms vs 972 ms;
- per process: bitcode through hod's reader 535 ms (median 1.65 ms) vs through `llvm-dis` 5821 ms (median 16.8 ms), 10.9x.

## Part 3 — shim without llvm-dis

`xtask/src/shim.rs`: the script is now
`HOD_FALLBACK_LLC=<llc> HOD_BITCODE_VIA=native exec <hod> "$@"`.
`Shim::real_llvm_dis` and `Plan::llvm_dis` are gone.

Equality evidence: the same hod, given the same bitcode, through
`--bitcode-via=native` and through `--bitcode-via=<that major's llvm-dis>`.
- Corpus: every entry assembled with its major's `llvm-as`. 5,617 built
  with byte-identical objects, and 342 declined with the same reason. 289
  entries cannot be assembled by `llvm-as` (multi-module files).
- The 2 differences are
  `kiln/llvm{19,22}/conformance/temp.arg.nontype/class-type-argument-debuginfo-run.cpp.ll`.
  Native gives `debug:module-flags`. On the other route, `llvm-dis` writes a
  `DITemplateValueParameter` whose value is `%struct.U` without the type's
  body, and its own `llvm-as` rejects that text ("initializer with struct
  type has wrong # elements"). That is an LLVM bug, not hod's.
- libc++ kiln bitcode: 541 built byte-identical, 1 declined with the same
  reason.

## Part 4 — `--threads=<n>`

`--threads=<n>` (also `--threads <n>`) is hod's own option and is never
forwarded to the fallback. It wins over `HOD_THREADS`. Either one is granted
outright, with no jobserver token. With neither, a jobserver gives up to
`JOBSERVER_MAX_THREADS` (16) against its tokens; with no jobserver, the
calling thread alone. `--threads=0`, `--threads=` and a non-number are
fatal (exit 1, no fallback). A malformed `HOD_THREADS` is still an error
when the option is given. Tests: `args.rs` (spellings, last wins, mistakes,
help), `driver.rs` `threads_option_environment_and_jobserver` (precedence
over the environment and the jobserver), and `tests/cli.rs`
`threads_option` (objects equal to the single-thread one, errors, not
forwarded).

The 198 keys of the original time sample, regenerated with kiln to `.ll`.
`llc -O0 -relocation-model=pic` vs hod with `HOD_STRICT=1 HOD_THREADS=1`,
input on stdin, best of 3, interleaved. Load 17.4-17.6.

| | hod total | llc / hod | median ratio | min ratio | slower than llc |
|---|---|---|---|---|---|
| original (time-sample.tsv, before WP-068) | 6.1 s | 3.53x | 2.30x | 0.65x | 20 |
| base, bind mount | 3.60 s | 5.18x | 3.34x | 1.14x | 0 |
| **new, bind mount** | 3.47 s | 5.38x | 3.58x | 1.27x | 0 |
| base, local | 2.43 s | 7.67x | 7.60x | 6.21x | 0 |
| **new, local** | 2.33 s | 8.00x | 7.90x | 4.95x | 0 |

llc total 18.64 s; 167 MB of IR. The original row was taken with census on,
via the shim and under a different load, so it is not a like-for-like

on a single module. That is a best-of-3 outlier under load: the totals and
medians both improved.

## Follow-ups

- Non-PIE or static linking would save ~80-170 µs locally, but static costs
  more major faults on the bind mount, and either needs `RUSTFLAGS` (a
  `.cargo/config.toml` decision) rather than the profile.
- The libc++ hybrid timing recipe should time without `HOD_CENSUS` (census
  reads every body after the first refusal: 2.5x the decline cost).
- Parse dominates a convergent decline (772 of 1006 µs). It is the
  module-level index scan of the whole text, and the scan is needed before
  any body.
