# WP-125 — x86-64 calls (X-call; design 0006 §3, §4, §7.3)

Landed: `spec/codegen.md` §5.6.1 "X-call: calls (WP-125)";
`crates/hod_x64/src/call.rs`; the prologue and exit hooks in
`crates/hod_x64/src/frame.rs`; `crates/hod_x64/tests/call.rs` with
`tests/data/call/{hand.ll,hand.c,eh.ll,eh_comdat.ll,eh.cpp}`; the support
matrix rows below.

## What is implemented

- `call::guard` keeps only the x87 condition (WP-131): `sret` parameters
  and variadic signatures are honoured.
- The address returned in `rax` (an `sret` parameter or the hidden
  address of a result in memory) is saved by `call::enter` from the
  prologue and reloaded by `call::before_return` at the epilogue.
  `ret` of a value in memory stays WP-126's (`term.rs`); its slot is
  `CallState::ret_addr`.
- `Target::extend_arg` (`target.rs`, one call into `call::extend_arg`):
  `abi-x64.md` §7 for every width (below 32 to 32, 33..63 to 64, the last
  piece of a wider integer to 64). Before, only 1, 8 and 16 bits were
  extended (`common::extend`), so `i7`/`i17`/`i33` arguments with
  `zeroext`/`signext` reached the callee unextended and a `signext i65`
  result had a 32-bit-extended top piece.
- Odd leaves of a `Mem`-class result cleared in its home after a call.
- Variadic calls (`al`, in `frame::emit_call`) and definitions: the
  176-byte register save area, `al` saved, `va_start`, `va_copy`,
  `va_end`; `musttail` forwarding of the unnamed registers and `al`.
- `invoke`, `landingpad` (`rax`, `edx`), `resume` (`_Unwind_Resume`);
  personality and LSDA through `hod_eh`'s x86-64 table (no per-target
  code).
- `musttail` (also indirect, through `r11`), `tail`/`notail` as hints,
  indirect calls through `r11`.

## `frame.rs` (the exception to the brief's read-only list)

- `FrameState` gains `call: crate::call::CallState`.
- `begin` ends in `crate::call::enter(cx)`.
- `end`: `crate::call::before_return(cx)` after binding the epilogue,
  `crate::call::before_tail_exit(cx)` after each tail exit's `DefCfa`
  row, and `bias_local_sites` moved after the exits, which now address
  locals too.

## Refused by name

`x64:call` (`callbr` that is not inline assembly), `x64:call-bundle`,
`x64:va-intrinsic`, `x64:va_arg`, `x64:landingpad`,
`x64:landingpad-clause`, `x64:resume`; `x64:todo:abi` for an x87 part.

## Matrix rows switched on for x86-64

`function:variadic`, `function:personality`, `attr:returns_twice`,
`inst:call`, `inst:invoke`, `inst:landingpad`, `inst:resume`,
`call:indirect`, `call:variadic`, `tail:musttail`, `landingpad:cleanup`,
`landingpad:catch`, `landingpad:filter`, `intrinsic:llvm.va_start`,
`intrinsic:llvm.va_end`, `intrinsic:llvm.va_copy`. `call:inline-asm`
and `inst:callbr` stay off (no x86-64 inline assembly yet).

## Evidence

- `handwritten_calls_run`: `hand.ll` (41 functions) with gcc's `hand.c`,
  hod PIE, hod static, hod stressed, `llc`; bfd, lld and mold; every
  argument and scratch register clobbered between calls.
- `exceptions_unwind_through_hod_frames`: real C++ exceptions through
  twelve hod functions (cleanup, catch, rethrow, nested frames, two clauses,
  filter, `noreturn`, stack arguments, no personality, a throw from hod,
  a COMDAT function in two objects); static, stressed and PIC in a shared
  object, every linker, `llc` as control.
- `hod_forwards_random_signatures_between_llc_frames`: 300 random `ccc`
  signatures (WP-118's `tests/abi` machinery by path) forwarded by hod
  between `llc` 22's caller and callee at `-O0` and `-O2`, bit-exact.
- Mutations caught: no odd-leaf clearing; `signext` below 32 bits by
  `shr` instead of `sar`; `gp_offset` off by 8.
- Text: `hand.ll` is 5100 bytes of `.text` from hod, 2662 from `llc -O0`
  (1.92).

## Deliberate differences from `llc`

- In a static object the personality and LSDA pointers of the CIE/FDE
  are `pcrel | sdata4` (indirect personality), as in a PIC one; `llc`
  writes `udata4` with `R_X86_64_32`. Both link and unwind.
- A narrow `zeroext`/`signext` result is extended to 32 bits, more than
  §7's 8 or 16.

## Seeds

`eh_invoke`, `varargs_caller`, `varargs_callee`, `indirect_call`,
`byval_sret`, `noreturn_abort`, `recursion` are still refused on x86-64,
first by `global:variable-definition` (module level), then by the
integer, memory and control groups (WP-122, WP-123, WP-124) and the
results in memory (WP-126). None newly passes.
