# WP-090 — `hod::Session`, the one judge (design 0004 H1)

Landed: `crates/hod/src/session.rs` (new), `crates/hod/src/front.rs` (the
front half rebuilt on the session; `Report::bridge`, `Report::session`),
`crates/hod/src/lib.rs` (`pub use session::Session`), `spec/cli.md`
"Session" (and "The facade"), tests `crates/hod/tests/session.rs`,
`crates/hod/tests/session_corpus.rs` (ignored: the corpus walker).

## What landed
- `Session::new`, `with_module`, `module`, `end_module`, `body` (by
  value), `unsupported_body`, `finish` into the caller's buffer
  (`spec/cli.md` "Session"). Bodies in any order; the object lays them
  out in `SymId` order.
- `compile_with` reads the module level, starts a session with it and
  feeds each body from `hod_ll::BodyParser` / `hod_bc::BodyReader` as it
  is read. The judge (`Judge` in `front.rs`) is gone, and with it the
  clone of every accepted body: the session keeps the reader's body.
- Misuse is `CompileError::Internal("session: ...")`, sticky; the table
  is in the spec. `finish` twice is a type error (a `compile_fail`
  doctest).
- The `bridge` phase: `Report::bridge` (the producer's time between the
  calls) and `Report::session` (inside them).

## Deviations from design 0004 §4 (for kiln's maintainers)
1. `Session::with_module(module, options, settings)`: added. The readers
   make their own `hod_ir::Module`; `new(target, ..)` is
   `with_module(Module::new(target), ..)`.
2. `Session::unsupported_body(sym, names)`: added. A producer that could
   not build a body (a reader's `Ok(None)`, the bridge's unrepresentable
   instruction) says so; without it the session could not tell a refused
   body from a missing one, nor name the function.
3. `new` judges `assembly-output` and `unsupported-target` only. The other
   options (`option:relocation-model`, `option:split-dwarf-output`,
   `-mattr`) stay in the back half, at `finish`, where "Reasons" orders
   them, so that one module gets one answer on both routes. kiln never
   passes them (its pre-check, §2.7).
4. Misuse is `CompileError::Internal` with a `session: ` message, not a
   new variant (`CompileError` is matched exhaustively by callers).
5. The `bridge` phase is two `Duration`s in `Report`, not a phase-report
   line: the copy interleaves with judging, so it is a sum, not a moment.

## Evidence
- Corpus (6,250 entries, 6,655 modules; text and its `llvm-as` bitcode;
  first refusal and census; 26,620 compiles): the dump of the branch
  point's release build (`1d82fbf`) and of this branch are byte-identical
  (26,300 objects by length and hash, 320 declines by reason, message and
  census).
- Seed corpus (`tests/ir`, permanent): every module through the public
  session equals `compile`; every built module with its bodies handed
  over last to first gives the same bytes.

## Mutations (caught, reverted)
1. Bodies generated in arrival order (no sort in `conclude`):
   `seed_corpus_through_the_session_is_compile`.
2. The unit plan after code generation (`ModuleEmitter::new` moved after
   `compile_bodies` in `back.rs`):
   `the_unit_plan_comes_before_code_generation`.
3. A decline not kept (`verdict` returns the refusal without stopping):
   the later body is judged and `finish` writes the other bodies' object;
   four tests fail, among them
   `the_object_is_appended_and_an_error_leaves_the_buffer`.

## Speed and memory
Load average 18-23 on 24 cores throughout: ratios only, and the noise is
about ±4% per input (see the control below). `base` is the release `hod`
of `1d82fbf`, `new` this branch.

- `cargo xtask bench --runs 5`, base, new, base, new (19 inputs built):
  hod's fastest time new/base, geometric mean 1.005 (0.65 to 1.23 per
  input), peak RSS 1.009.
- Phase reports (`HOD_TIME_PHASES`), 21 interleaved runs of 8 bench
  inputs, medians: the work after reading the file 1.007 of base, the
  `bodies` phase 1.024, peak RSS 1.007 (0.94 to 1.04; `templates` 1.044,
  `stl-heavy` 1.034). Control: a third binary that put the clone back
  (the reader's storage recycled, a copy handed over: base's work) in
  the same runs measured work 0.980, `bodies` 1.036, RSS 0.974.

So removing the clone does not show at this load, and nothing is slower
beyond the noise. Why it cannot show much: the clone was a copy of
fitted size out of a recycled storage; without it every body is built in
fresh storage, which grows by doubling (more allocations, the same
copying) and keeps its slack while it waits for `finish` (hence the few
percent of RSS on modules of thousands of bodies). What would win: code
generation on arrival (design 0004 §6, stage 3), or a
`Body::shrink_to_fit`/sized storage in `hod_ir` (not this package's).
