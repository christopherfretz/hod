# WP-330 — libc++ on i386: the archives and the runner (design 0008, I14 first part)

Landed: stage A (the i686 libc++, libc++abi and libunwind archives,
built by clang 22) and stage B (the runner with hybrid, strict and
control modes, checked end to end on ten tests). Stage C (the sample
and its census) and stage D (`docs/status/libcxx-hod-i686.md`) were
moved to a successor package by the supervisor; they are not done here.

## Stage A: the archives

`scripts/build-libcxx-i686.sh [--force] <work dir>`. It installs to
`.toolchain/libcxx-22-i686-root`: `include/c++/v1` and `lib/` with
`libc++.a`, `libc++abi.a`, `libc++experimental.a` and `libunwind.a`.
It refuses to run over a complete install unless `--force` is given.

- Sources: `.toolchain/libcxx-llvmorg-22.1.8` holds only `libcxx/test`
  and `libcxx/utils`, so the library sources are not in the container.
  The script makes a shallow, blob-filtered, sparse clone of
  llvm-project at `llvmorg-22.1.8` in `<work dir>/src`. It checks out
  `libcxx libcxxabi libunwind libc runtimes cmake llvm/cmake
  llvm/utils/lit third-party`. `libc/` is needed because libc++'s
  `charconv.cpp` includes llvm-libc's `shared/fp_bits.h`. The first
  attempt, without `libc/`, stopped at 1712 of 1899 steps.
- Configuration: the runtimes build, cross (`CMAKE_SYSTEM_NAME=Linux`,
  `*_COMPILER_TARGET=i686-linux-gnu`), with clang 22 and its own code
  generator, `Release`, static only, exceptions and RTTI, ABI version
  1, threads, the time-zone database, the `std_thread` PSTL back end and
  hardening `none`. libc++abi does not embed the unwinder; Debian's
  archive does not either, so `_Unwind_*` comes from libgcc. The
  installed `__config_site` is byte-identical to Debian's x86-64/arm64
  libc++-22-dev one.
- Cost: 27 s (first attempt) plus 25 s (completion) of `ninja -j 4`
  under `nice`, about 52 s in all. A from-scratch build in one go was
  not timed. The install is 19 MB, the build tree 27 MB (deleted), and
  the sparse source 152 MB plus `libc/`.
- Checks (`clang++ --target=i686-linux-gnu -stdlib=libc++`, the new
  archives, `qemu-i386 -cpu pentium2,-mmx -L /usr/i686-linux-gnu -R
  0x40000000`), each run linked `-static` and as a dynamic PIE with
  `-Wl,-Bstatic -lc++ -lc++abi -Wl,-Bdynamic`. All six runs exit 0:
  - `<iostream>` hello: prints `libc++ 220108`;
  - an exception thrown through five frames with destructors:
    caught, with six destructors run;
  - four `std::thread`s doing `fetch_add` on `std::atomic<long long>`:
    the total is right, and the atomic is lock-free (`cmpxchg8b`), so
    no libatomic is needed.

## Stage B: the runner

1. `scripts/libcxx-hod-i686.sh <hybrid|strict|control> <run dir>
   [xtask libcxx args]` (and `merge`) drives kiln's `cargo xtask libcxx
   --tag llvmorg-22.1.8`, as `libcxx-hod-x64.sh` does. It uses `-j 4`,
   `--timeout 160`, `--run-timeout-long 1920` and `--mem-limit 3072`.
   `--shard K/N` names the outputs, and `HOD_I686_SELECTION=<file>`
   gives the test list.
2. The compiler is `scripts/libcxx-i686-clang.sh`. It answers
   `--version` as clang, so the runner works in its clang mode.
3. Each source becomes IR with `clang++-22 --target=i686-linux-gnu -S
   -emit-llvm`, using the invocation's own flags.
4. The IR goes to `hod` (hybrid: `--fallback=llc` plus `HOD_CENSUS=1`;
   strict: `--strict`) or to `llc -O0 -global-isel=0 -fast-isel=0`
   (control). The mode is chosen once per run.
5. `-relocation-model=pic` is passed when the module has `"PIC Level"`,
   which is clang's default PIE.
6. The runner's libc++ `-isystem .../c++/v1` and `-L.../aarch64-linux-gnu`
   are replaced by the i686 install's.
7. Executables are linked to `<out>.i686`, and `<out>` becomes a
   `qemu-i386` launcher (the CPU and `-R` above).
8. Probes and invocations that write no code from sources (`-x`, stdin,
   `-fsyntax-only`, ...) go to clang unchanged.
9. Logs use the `libcxx-hod-kiln.sh` layout (`args.tsv`, `cov/<key>.tsv`),
   so `scripts/libcxx-hod-report.py <mode dir> <mode>.tsv control.tsv`
   reads a run against its control. `time.tsv` adds wall time per step
   (`ir`, `hod`/`llc`, `link`).
10. Known limit: the runner's `target=` lit feature stays the host's
    (aarch64), as on the x86-64 lane.

Ten-test check (one `pass` test in every 600 of the listing):

| | control | hybrid |
|---|---|---|
| tests | 10 | 10 |
| pass | 10 | 10 |
| modules by hod | - | 9 of 10 |
| fallback | - | 1, `x86:intrinsic` (`ostream.formatted.print/vprint_unicode.pass.cpp`) |
| wall (runner) | 10.5 s | 9.2 s |
| IR step (sum) | 12.0 s | 12.1 s |
| back end (sum) | `llc` 1.59 s | hod 0.53 s (fallback included) |
| link (sum) | 4.4 s | 5.4 s |
