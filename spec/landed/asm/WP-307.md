# WP-307: module-level assembly in 32-bit mode

Rules: `spec/asm.md` §23; `spec/codegen.md` §9.7.3 (i386).

## What landed

- `hod_asm::module::assemble_module_x86` (`Isa::X86`): the x86-64 module
  assembler with 32-bit instructions (`x86::module_instruction`), the
  i386 field kinds (`x86::RefKind`: R_386_32, PC32, PLT32, GOT32,
  GOT32X, GOTOFF, GOTPC and the TLS kinds of `@ntpoff`, `@tpoff`,
  `@indntpoff`, `@gotntpoff`, `@gottpoff`, `@tlsgd`, `@tlsldm`,
  `@dtpoff`), one-byte nop padding, `R_386_16` data.
- `hod_cg::emit::module_asm`: i386 placement, `I386Reloc` mapping,
  in-place addends for the kinds `hod_obj` has no field size for,
  `STT_TLS` for TLS-named new symbols, absolute values modulo 2^32;
  `emit::asm::check` admits i386.

## Decisions

- A specifier is read by stripping it and assembling the field with a
  placeholder (`$sym` becomes the immediate `0x12345678`, checked and
  zeroed after encoding; a memory specifier is stripped and the field
  found by the encoder), so the 64-bit encoder is untouched and every
  form it encodes takes specifiers.
- GOT32X exactly where llvm-mc writes it: a `mov` load (`8B`) whose
  memory operand has a base register and no SIB byte.
- `_GLOBAL_OFFSET_TABLE_` in an instruction is GOTPC with the field's
  offset in the instruction added (llvm-mc's `X86MCCodeEmitter`); in data
  it is R_386_32.
- Kinds of no in-place size in `hod_obj` (`I386Reloc::Other`) get their
  addend written by `hod_cg`, so `hod_obj` stays unchanged.
- The run test links `@tpoff`/`@gottpoff` (`tls32.ll`) by GNU ld only:
  mold rejects both kinds and lld the second, for llc's objects too.

## x86-64 and AArch64 unchanged

The new code runs only for `Isa::X86` / `Arch::I386`. Shared changes:
`Fill::XNamed` carries a `RelocKind` built as `RelocKind::X64` where it
was built before; the jump arm moved into a helper with the same
offsets; three x64 functions became `pub(crate)`. `compare-binaries`
over the three corpora: no object differs.

## Open

- Module text of a module built for a CPU with long nops pads with
  `0x90`s where `llc` writes long nops (correct, not byte-equal).
- A 16- or 8-bit symbol immediate, two symbol fields in one instruction
  and label differences in a field stay refused.
