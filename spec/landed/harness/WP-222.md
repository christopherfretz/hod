# WP-222 — LLVM 19.1.7 (and Clang) by kiln and hod alone, on the new kiln

WP-178's measurement (`WP-178.md`, scripts `scripts/oss/llvm/` and
`scripts/oss/llvm-x64/`) repeated on a newer kiln and hod, with no
translation unit left to kiln's fallback. Each control/strict pair is
built by one kiln and one hod, both frozen before the pair's first
compile.

## Changes to the scripts

- **Job slots.** ninja 1.12 is not a jobserver client. The compiler
  wrapper (`wrap.sh`) takes one token of the real-project pool
  (`/run/hod/lanes.fifo`, `MAKEFLAGS` set by the scripts' `env.sh`) per
  compile or link, `lit.sh` takes 4 (its `-j 4`) and `unittests.sh` 1, all
  through `scripts/oss/llvm/lane-token.py`: a blocking read of one byte
  per token, the same bytes written back once on every exit (also after
  SIGINT, SIGTERM, SIGHUP). hod inside a compile counts the first token
  as its implicit slot. ninja's `-j 6` stays the upper bound.
- `lit.sh` (both): no slice starts below `HOD_OSS_MIN_FREE_GB` (default
  45) free on the volume; native `lit.sh` with `HOD_OSS_LIT_CLEAN=1`
  deletes a slice's `Output` directories after its lists are written,
  unless the slice has a difference.
- Frozen kiln: the native stage sets `HOD_OSS_KILN`,
  `HOD_OSS_KILN_SCRIPTS` and `KILN_RESOURCE_DIR` to a copy of kiln's
  binary, its resource directory and its `scripts/oss`, because the
  workspace's kiln is rebuilt in place when its pin moves.
