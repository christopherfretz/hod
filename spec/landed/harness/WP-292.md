# WP-292 — a benchmark gate that binds on a loaded host

A harness package: no change under `crates/`, nothing hod emits moves.
Landed: `cargo xtask bench --counts` (`xtask/src/bench.rs`,
`xtask/src/bench/check.rs`), the counts baselines of both targets
(`bench/baselines/aarch64-implementer-0x61-part-0x000-24c[-x86_64]-counts.tsv`
with their logs; the wall-time baselines are unchanged), the full gate's
steps `bench-aarch64` and `bench-x86_64` (`xtask/src/ci.rs`), a
`compare-binaries` rule for seeds without a target triple, and the
specification in `spec/harness.md` "bench", "The counts gate" and
"compare-binaries".

## Why

Wall time on the shared host is NOISY at load 20 to 40, so `--check`
could never bind. Instruction counts under callgrind do not depend on
load; peak memory mostly does not.

## Method and noise

- Instructions: callgrind, strict hod, `HOD_THREADS=1`, one counted run
  per input. Five runs of all 20 aarch64 inputs at load 27 to 32: the
  largest spread 0.018% (`small-cxx`, 3.06 M instructions), the median
  about 0.003%. Sum: 5.59 G (aarch64), 5.71 G (x86-64).
- Peak memory: the middle of the measured runs, which in counts mode run
  hod with `HOD_THREADS=1`. Within one measurement an input's peak RSS
  moved by up to 2.2 MiB (`tiny-functions` 13.3 to 15.5 MiB), between
  two measurements the middle by up to 1.5 MiB, with one thread as with
  several.

## Thresholds

Instructions: +1% per input, +0.5% on the sum over the inputs (over 50
times the largest spread). Memory: +2% and more than 3 MiB. Fewer
instructions or less memory beyond the same margins is "improved:
re-record", not a failure. Wall time is shown and not judged.

## Evidence

- Unit tests (`check.rs`): `counts_gate_verdicts` (regression,
  improvement, within noise, memory bounds), `counts_gate_without_a_comparison`
  (missing baseline, missing count, other machine), `counts_gate_sum_and_text`.
  Fakes (`tests/bench_fakes.rs`): `the_counts_gate` (a slower hod passes,
  more instructions fail, no valgrind skips or fails under
  `HOD_REQUIRE_TOOLS=1`). `tests/compare_binaries_fakes.rs`:
  `a_seed_without_a_target_is_compared_per_target`.
- Real runs, 2026-11-16, after recording both baselines (93 s and 95 s):

  | run | load (1 min) | exit | seconds | verdicts |
  |---|---|---|---|---|
  | check aarch64 #1 | 39.1 | 0 | 90 | 20 ok, sum +0.0% |
  | check x86-64 #1 | 35.3 | 0 | 89 | 20 ok, sum -0.0% |
  | edited baseline | 39.7 | 1 | 97 | `tables` REGRESSED (instructions), +2.0%; `tiny-functions-g` +0.4% ok |
  | check aarch64 #2 | 31.4 | 0 | 91 | identical to #1 |
  | check x86-64 #2 | 27.9 | 0 | 88 | identical to #1 |

  The edited baseline is a copy with `tables` at 98% and
  `tiny-functions-g` at 99.6% of their counts; no slowed hod was built.

## In the gate

Step cost about 90 s per target with the release build current, so the
full set runs; there is no subset. The hosted lanes do not run it: a
hosted runner's machine id follows its processor, so it has no baseline
of its own and a check would be advisory, never failing. No valgrind is
added to the hosted package list. Re-recording, one command per target:

```
cargo xtask bench --update-baseline --counts --reason "<why>"
cargo xtask bench --update-baseline --counts --reason "<why>" --target x86_64
```

## Follow-ups
