# WP-082 — vectors across calls (AArch64)

Landed: `PartKind::Lanes` and `LaneLoc` in `crates/hod_cg/src/abi.rs`,
the hooks `Target::lanes_out` / `Target::lanes_in` (default:
`call:part-lanes`), their use in the call sequence (`call.rs`:
arguments, results, results in a temporary buffer) and at a function's
entry (`driver.rs`, `enter_arguments`); in `crates/hod_a64`, the mask
and widened-vector rows of `abi.rs` and the new `vcall.rs` that moves
`Lanes` parts; `crates/hod_a64/tests/vcall.rs`; `spec/abi-a64.md` §4.3,
§8.1, §8.2, §10; `spec/codegen.md` §7.2 and the heading "Vectors across
calls (WP-082)" in §5.5.1.

## What `llc -O0` does, measured (LLVM 22 and 19 agree on places)

| vector | passed as |
|---|---|
| `<2 x i1>`, `<4 x i1>`, `<8 x i1>` | one `D`, lanes `2s`/`4h`/`8b`, 0 or 1 each |
| `<16 x i1>` | one `Q`, `16b` |
| any other `<N x i1>`, `N` ≤ 64 (1, 3, 32, 64 included) | one `W` per element (bit 0), then 8-byte stack slots; a result of more than 8 in memory (`x8`), as its bit image |
| `<2 x i8>`, `<2 x i16>` / `<4 x i8>` | one `D`, `2s` / `4h`, zero-extended (`ushll`) |
| arrays of `D`/`Q` lanes | a block, as any `D`/`Q` member |

A consumer reads only the element bits of each lane: LLVM 19 can leave
junk above them, and `llc`'s caller can pass junk above bit 0 of the
last `W` piece of a mask it loaded.

## Hooks (one call each)

- `crates/hod_a64/src/target.rs`: `A64::assign` no longer calls
  `vector::check_signature` (now dead, with `vector::CALL`; the vector
  group's owner may delete both); `A64::lanes_out`, `A64::lanes_in`
  (to `vcall`).
- `crates/hod_a64/src/term.rs`, `ret`: a `Gpr` value returned in memory
  (a mask of more than 8 `W` pieces) goes through `vcall::ret_image`
  instead of `cx.bug`.
- `pub mod vcall;` and its row in `lib.rs`.
- Tests of other groups that asserted the old refusals, cases removed or
  renamed: `tests/vector.rs` (four `vector::CALL` cases),
  `tests/mask.rs` (three), `tests/abi/errors.rs` (`v4i1` →
  `abi:vector-element` and `v4i8`/`v2i16` → `abi:vector-promoted`
  replaced by `<65 x i1>` / `<128 x i1>` → `abi:mask-wide`).

## Refused, by name

`abi:mask-wide` (a mask of more than 64 elements; replaces
`abi:vector-promoted` in `UNSUPPORTED`). Unchanged: `abi:vector-array`
(an array of vectors of several pieces), `call:musttail-ret-memory`,
`a64:va_arg`. x86-64 keeps the default hooks; its `assign` is unchanged.
