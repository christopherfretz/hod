# WP-116 — the x86-64 target skeleton (design 0006, S0)

Landed: `spec/codegen.md` §5.6 in full (frame, CFI, registers, the
no-deferral rule, two-operand and flag rules, classes, branches,
constants, PIC), §5.6.1 (the decisions the group packages build on) and
§5.6.2 (target features); two clarifications in §2.1 (`holdable`,
`eh_data`); crate `hod_x64` laid out for WP-118 and WP-122..137; the x86
code generator behind the facade; the support-matrix rows below.

## What it did

- `hod_x64::X64` implements `hod_cg::Target`: register description,
  classes, the final dispatch (`src/target.rs`), the glue (loads, stores,
  copies, moves, constants, frame and symbol addresses, argument
  extension; every sequence keeps the flags), the frame (`src/frame.rs`:
  prologue with the patched `sub rsp, imm32`, epilogue and tail exits,
  CFI rows, dynamic slots, stack adjustments, the call instruction with
  `al` for variadic callees), `br`, `ret`, `unreachable` (`src/term.rs`),
  shared helpers (`src/common.rs`), `src/reg.rs` (DWARF numbers).
- Local frame accesses are emitted as `[rbp + o]` with a `disp32`,
  recorded, and biased by `-40 - FRAME` in `end_function`.
- One stub module per group, each refusing `x64:todo:<group>`: `int`,
  `mem`, `control`, `call` (passes a plain call to the driver), `vcall`,
  `aggr`, `float`, `fpintr`, `intrinsic`, `barrier`, `atomic`, `tls`,
  `vector`, `lanes`, `mask`, `x87`, `constaddr`, `coro`. `abi.rs` is a
  stub for WP-118 (`ccc`, ≤ 6 integer/pointer arguments, such a result;
  else `x64:todo:abi`; `nest` is `x64:nest`).
- `hod_x64::features`: the judged table of design 0006 §10.1.
- The facade compiles x86-64 modules with `X64` and judges features by
  the module's target (`crates/hod/src/back.rs`); the
  `codegen-not-implemented` refusal of x86-64 is gone (the `Construct`
  stays, unused by the back half).
- `hod_cg`, two AArch64-neutral edits: `RegInfo::check` requires
  `eh_data` to be general registers, not holdable (`reg.rs`); a call
  result in a register that is not holdable (`rax`) is moved to a
  temporary at once (`call.rs`, `run_call`).
- Rows switched on for x86-64: `module:pic`, `module:pie`,
  `module:uwtable`, `global:function-definition`, `linkage:internal`,
  `function:parameters`, `function:may-unwind`, `cc:ccc`,
  `attr:target-cpu`, `attr:target-features`,
  `attr:min-legal-vector-width`, `attr:no-jump-tables`, `type:int`,
  `type:ptr`, `inst:phi`, `inst:br`, `inst:ret`, `inst:unreachable`,
  `operand:symbol`, `operand:addr-of-int`. `inst:call` and `function:slots`
  stay with WP-125/WP-123.

## The no-deferral rule (design 0006 §2.1)

Already guaranteed by the driver: `hod_cg::call` emits every deferred
argument, and a deferred callee, before it places the first argument, so
no lowering runs while argument registers are live. No `Target` query
was added.

## Data layout

`hod_ir` lays out the x86-64 data layout as LLVM does: `i128` and
`x86_fp80` 16 bytes with 16-byte alignment, pointers 8
(`tests/skeleton.rs`, `data_layout_is_honoured`); `hod_ll` and `hod_bc`
both read `x86_fp80`.

## Tests

- `crates/hod_x64/tests/skeleton.rs`: four PIE programs (`ret 42`; a
  block chain with a backward branch and swapping `phi`s; a direct call
  with six arguments then `exit` through the PLT and `unreachable`;
  dso-local and preemptible symbol addresses with offsets, checked from
  C) linked by GNU ld, lld and mold through `x86_64-linux-gnu-gcc` and
  run under `qemu-x86_64`: 12 runs, exit 42 each. `llvm-readelf` reads
  every object clean (PLT32, PC32, REX_GOTPCRELX; no absolute
  relocation). `llvm-dwarfdump --eh-frame`: the FDE's rows equal design
  0006 §4. Refusals by group name. The cross runner is `hod_obj`'s test
  helper, included by `#[path]`; WP-025 replaces it.
- Unit tests: `REG_INFO.check()`, frame size rounding, the patched
  immediate's encoding, DWARF numbers, the features table.
