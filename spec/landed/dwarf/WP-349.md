# WP-349: the `-g` path after the parse: own costs (five cuts kept)

Base `8b8844f4`. Kept: type nodes decoded once, local variables read
field by field, flag words looked up by length (`9935c269`); words and
digits of metadata scanned by table (`c7914d6c`); `Module::verify_debug`
reads a node's kind before decoding it (`08dbbb2b`); `DebugInfo::verify`
keeps each location's subprogram and `Verifier::debug_ids` reads it
(`2e2f129b`). Not built: the reference check of `DebugInfo::verify`
riding on another pass. Whole program at the head over the 20 bench
inputs: -66.57 M (AArch64) and -71.84 M (x86-64); `stl-heavy-g` -3.1%.
Every bench object byte-identical to the base's.

## Method

As WP-326: whole-program instruction counts (callgrind, `HOD_THREADS=1`,
`--strict -O0 -filetype=obj -relocation-model=pic`, `-mtriple` for
x86-64) of two binaries on the same input, base copied to
`bin-base/hod` before the first edit and each variant to a directory of
the same name length. Ranking by a function's own cost; the cost of a
call site measured by doubling it (a measurement-only switch that runs
the site twice, never committed): the extra run's whole-program count is
what the site costs. Cuts 3 and 4 were counted on `stl-heavy-g` and
`templates-g` alone by a second script. Counts of one binary on one
input are not exactly repeatable: on `stl-heavy-g` three runs of the
head gave 942.48 to 942.76 M (AArch64); on the small inputs runs agree
within a few hundred instructions. Each comparison below uses one
script for both binaries. A cut that shows less than 1 M on `stl-heavy-g` in
the whole-program count is not kept on its own.

## The cuts, each measured whole-program

1. `9935c269`: type nodes decoded once (`types.rs`: `create`'s decode
   kept for the construction), local variables planned through `view`
   (`func.rs`), flag words looked up by length (`hod_ll` `flag_bits`).
   Sums AArch64 4570.85 -> 4566.66 M, x86-64 4690.68 -> 4686.95 M;
   `stl-heavy-g` -2.43 / -2.08 M.
2. `c7914d6c`: `word_end` / `digits_end` by a byte-class table over a
   slice. `stl-heavy-g` x86-64 991.77 -> 967.56 M (-24.2 M, -2.4%).
   The inputs without `-g` gain too (their metadata goes through the
   same scanner): -0.4 k to -0.95 M each.
3. `08dbbb2b`: the constant check of `Module::verify_debug` reads the
   one-byte kind first and decodes only constants. `stl-heavy-g`
   -1.25 M (AArch64) / -1.33 M (x86-64); `templates-g` -0.70 / -0.70 M.
   The doubling said 5.56 M for the whole loop: the decode of a
   non-constant node is cheap next to the loop's own walk.
4. `2e2f129b`: `DebugInfo::verify`'s location loop finds each
   location's subprogram from what it found already (its scope's when
   not inlined, else the earlier location's it is inlined at; a later
   one is walked as before; the scope of consecutive locations is
   looked up once) and keeps the result, valid while the table counts
   no edit since; seeds and forks carry it. `Verifier::debug_ids`
   reads it (`DebugInfo::owner_of`: one array read, the walk for a
   location added or a table edited since). The values are
   `function_of`'s, so every error and its order stay. The loop alone
   (kept, not yet read): `stl-heavy-g` -0.21 / -0.80 M, under 1 M, kept
   only as the way the owners are found; with `debug_ids` reading them,
   from `08dbbb2b`: `stl-heavy-g` -2.32 / -2.89 M, `templates-g` -0.52 /
   -1.24 M. Cost: four bytes per location while the cache lives.

## Measured and not built

- The reference check of `DebugInfo::verify` (most of its 7.78 M:
  `stored_refs` 10.4 M inclusive) riding on the uniquing pass, which
  already walks reference cells: that pass skips distinct nodes (it
  walks them only when something merges), does not know a field's
  allowed classes, and runs before reserved nodes may be defined, so
  the first error reported could change. Not built.
- The flag lookup by length (part of cut 1) measured alone, a scratch
  build of the head without it, over the ten `-g` inputs, one script
  for both: the sums are 1.13 M (AArch64) and 1.11 M (x86-64) lower
  with it; it gains 0.69 / 0.69 M on `stl-heavy-g`, 0.40 / 0.39 M on
  `templates-g`, 0.15 / 0.10 M on `containers-g`, and costs 5 k to 64 k
  on the small ones (`tiny-functions-g` the most: 64 k / 61 k; its
  tables are built at the first lookup). Kept: a net gain on the sum.
