| `DILexicalBlock` | 2,329 | 196,636 | 4.0 |
| `DICompositeType` | 1,279 | 559,309 | 9.1 |
| `DITemplateTypeParameter` | 1,065 | 66,339 | 1.9 |
| others (10 kinds) | 1,473 | 147,000 | 1 to 12 |

About 300,000 fields in all. What the parser does per field today, for
every kind with a record (`DILocation` has its own reader,
`location_body`, debug.rs:976, straight into `DiLocation`):

1. tokens: the lexer makes a `Label` (`name:`), the value's one to
   three tokens and a `Comma` (`field_name` debug.rs:787, `field_value`
   debug.rs:843); words go through `kw::keyword`. No allocation.
2. `(Key, Val)` pushed to `DebugScratch::fields` (debug.rs:138, :741),
   strings as source ranges or copied into `scratch.strs` when they
   hold an escape, lists into `scratch.lists`: reused vectors, no
   allocation per node.
3. `DiNode` built by `Made::node` (debug.rs:1149) from
   `DiNode::llvm_default` and `set_at` per field: on the stack.
4. the stored form: `kit::define_di_node` -> `DebugInfo::define_as`
   encodes the node into cells (`hod_ir`), interning strings.

Bytes walked more than once: the index (`index.rs:363` `group`, i.e.
`skip::skip_group`) walks every numbered node's parentheses byte by
byte to find its extent (all 9.30 MB), then the parser lexes the same
bytes as tokens: every metadata byte twice. A node or tuple written in
place inside a field (`!{...}`, `!DIExpression(...)`, an inline
`!DI...(...)`) is walked a third time (`skip_brackets` in `node_ref`,
`list_ref`, `inline_node`, `expr_ref`, then lexed). `skip_group` is the
index's (not this package's files); the parser's second walk is what a
byte path removes.

## Kept: fields read from the bytes (`quick_field`, `quick_location`)

`quick_field` (`crates/hod_ll/src/debug.rs`) reads a field of a node
with a record as LLVM's writer prints it, straight from the source
bytes: a name `[A-Za-z][A-Za-z0-9_]*` followed by `: `, a value, then
the node's `)` or `, ` and another field. Values: `"..."` without `\`;
`!N` (digits, fits `u32`); `N` or `-N` (fits `u64`, magnitude at most
2^63); `true`, `false`, `null`, a named code (`named_code`); flags
joined by ` | `; a list `!N` naming a tuple, or `null`. It gives up
(`None`, before anything is read into the module or the scratch) on:
any other blank, comment, trailing comma or separator; a number
followed by a letter, `.` or `x`; an overflowing number; a value of a
node field that is a number; an expression or a bound; an escaped
string; an unknown word; a field outside the record, or met before; a
list naming an undefined id or a non-tuple. The token path then reads
that field and every one after it, so its diagnostics stand.
`quick_location` reads `line: N, column: N, scope: !N[, inlinedAt: !N]`
(`line` fits `u32`, `column` fits `u16`, `inlinedAt` after `scope` and
defined, each once, `, ` between) and otherwise leaves the whole node
to `location_body`. A field present with its default value stores the
same `Val` either way.

Reading of the restored cut found one spelling the byte path accepted
on its own reading: a trailing comma (`size: 8,)`, `size: 8, )`). The
token path accepts it too, with the same result; it now reaches the
token path anyway (`, ` must be followed by another field). Nothing
else accepted or diagnosed differently was found.

Tests: `byte_path_spellings_are_judged_as_the_tokens_judge_them`
(`crates/hod_ll/tests/debug.rs`) reads 107 spellings both ways (as
written, and with a blank after each `(` and `!{` so the tokens read
every node) and wants the same print and refusals, or the same error
kind, message and line: integer overflow of `line:` and of `size:`,
`-1`, `-0`, `-2^63-1`, a lone `-`, `8x`, `0x8`, `008`, `1a`, a column
of 70000, undefined ids (`!99`, `!4294967296`), `!1x`, `! 1`, `null`
where a node or a list is wanted, trailing commas, two blanks, a tab,
a comment, no blank after `:` or `,`, a blank before `,`, repeated and
unknown fields (`Size`, `_size`, `size.x`), an escaped string, a string
holding `,` and `)`, a quoted label, unknown and dotted `DW_` words,
fields present with their defaults, every flag shape, and lists by
number, in place, undefined, and of the wrong kind. A mutation (a
number read as `n ^ 8`) makes it fail.

## Kept: tuple elements read from the bytes (`quick_elements`)

`!N` and `null` elements joined by `, ` are read from the bytes, for a
list a field names (`list_span`) and for a tuple named as a node
(`define_tuples_in`); an element is resolved only once the separator
after it is known; from the first other spelling (`i32 7`, `!"s"`,
`!{`, a blank, a comment, a trailing comma) the tokens read the rest.
18 tuple spellings are in the test above.
