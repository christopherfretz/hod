## key_call.c, lldb (6 FAIL, both clangs, all three linkers): stays

The finding, from the clang-22 programs linked by lld:

- hod: `call consume` at 0x16e5; the return address 0x16ea, `lea
  0x10(%esp), %esp`, is in the row 0x16dc `16:3` (the call's own
  position, as the brief wants). `finish` stops at `16:3`; `next` then
  runs to `17:19`.
- `llc`: `call consume` at 0x168b; the return address 0x1690, `mov
  0xc(%esp), %ebx` (the reload of the PIC base after every call), is in
  a row of LINE 0 (0x1690, column 3). lldb's step-out does not stop on
  line 0 and goes on to the next row, 0x1694 `17:19`; `next` from there
  runs to `18:10`.
- x86-64 passes: neither program has an instruction after the void call
  (no argument area, no PIC base), so both return to line 17's first
  row.

So hod's rows already carry the call's position after the call. The
difference comes from `llc`'s line-0 reload, which hod does not have.
`finish` itself is permitted by `return-row`, but the `next` that
follows is a later stop. No rule permits a later stop, and none was
added. Removing the release instruction from the return address means
reserving the outgoing argument area in the i386 prologue. That is a
package of its own and was not attempted. Putting line 0 on the release
would copy `llc`'s row, but it would contradict the call's position
the brief requires, so it was not done.

## Class D: `<.L.str>` under mold (rule `local-label`)

exception.cpp (clang 19 and 22) and variable_twice.cpp (clang 22), gdb,
mold: `what = 0x? <.L.str> "too big"` in `llc`'s session. The witness:
`llc`'s i386 object defines local `.L.str` and `.L.str.1` (`OBJECT
LOCAL` in `.rodata.str1.1`), the targets of its `R_386_GOTOFF`
relocations; hod's object relocates against the section symbol
`.rodata.str1.1` (same string). The same `llc` object linked by mold
keeps `.L.str` in the program's `.symtab`; linked by lld and by GNU ld,
it has no `.L` symbol. So the name is the linker's symbol table, not a
value. The 64-bit lanes have no such case, because RELA objects carry
no `.L.str`, and the linker exceptions (`super::xlink`) only explain an
oracle session that misses a check. So the rule is a session rule:
`permitted: local-label` (`debug::rows::only_local_labels`, i686, gdb
and lldb, `spec/harness.md`). Every differing pair must be `llc`'s line
equal to hod's once each ` <.L…>` is removed whose name is a LOCAL
symbol of `llc`'s linked program and no symbol of hod's (`llvm-nm
--defined-only` of both). Unit test `local_labels_of_llc_only`. All 3
PASS.
