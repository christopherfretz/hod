# WP-005 — hod_ir debug metadata: typed nodes, expressions, locations, debug records, verification

Landed: `spec/ir.md` §6 (§6.1 to §6.10, which replace the sketch that was
there) and the debug sentences of §5.2. Not here: reading debug metadata
out of LLVM IR (the parser), DWARF emission (`spec/codegen.md` §9.5),
`classify` (§8: WP-009), the printer (§9: WP-006).

## What it did

A new module `crates/hod_ir/src/debug/`; `lib.rs` and `error.rs` gained
only appended lines.

| module | contents |
|---|---|
| `debug` (`mod.rs`) | `DebugInfo` (nodes, expressions, locations, compile units, `verify`, `stats`), `DiLocation`, `DebugStats` |
| `debug::node` | `DiKind`, one record per kind (`DiCompileUnit` ... `DiTuple`, `DiOther`), `DiNode` with `set` and `llvm_default`, `DiBound`, `DiFieldValue`, `DiId::NONE` |
| `debug::expr` | `ExprId`, `DiOp` (41 operations and `Other`), `DiOps`, `DI_OPS`, `di_op_named`, the placement rules |
| `debug::names` | DWARF and LLVM vocabulary: `DW_TAG_*`, languages, encodings, `DiFlags`, `SpFlags`, `EmissionKind`, `NameTableKind`, `ChecksumKind` and their name lookups |
| `debug::map` | the field table: `DiMapping`, `DI_FIELD_NOTES`, `DI_KIND_NOTES`, `DI_RECORDS`, `di_kind`, `di_field`, `di_record`, `di_field_table` |

Changes to existing files:

- `module.rs`: the public field `Module::debug`; `attach_global_expr`,
  `global_exprs`, `global_exprs_of` (§6.7); `finish_debug` (§6.3);
  `verify_debug` (§6.8).
- `body.rs`: **`SlotVar` gained the public field `expr: ExprId`** (12 to
  16 bytes); new `DbgDeclare`, `DbgRecord`, `DbgRecordKind`;
  `Body::declares`, `dbg_records`, `dbg_record_count`;
  **`UseFacts::named_by_declare`, and the use count now saturates at
  2^29 − 1 instead of 2^30 − 1** to make room for that bit.
- `builder.rs`: `dbg_declare`, `dbg_value`, `dbg_value_list`,
  `dbg_assign`, `dbg_label`. `set_slot_var` keeps its signature and is
  `dbg_declare` of the slot's address with the empty expression.
- `verify.rs`: the §6.8 body rules, the declare bit in the use-fact
  recompute, and unit tests that damage the private tables.
- `error.rs`: `InvalidDebugInfo`, `DebugRedefined`, `UndefinedDebugNode`.

Tests (all new): `tests/debug_nodes.rs` (14), `tests/debug_body.rs` (8),
`tests/debug_survey.rs` (4, tool-backed: `clang` 19 and 22, `opt` 19,
kiln) with its inputs `tests/data/debug_survey.{c,cpp}` and
`tests/data/debug_survey_stl.cpp`; unit tests in `debug/*.rs`, `body.rs`
and `verify.rs`. A release example, `examples/debug_throughput.rs`,
measures §6.10.

## Sizes

Asserted in tests: a node head 8 bytes, a location 16, `DiLocation` 16,
`ExprId` 4, `SlotVar` 16 (was 12), `DbgDeclare` 16, a debug record 28 plus
4 per value. A node is 8 + 4·(1 + stored cells) bytes; a node with every
field at its default is 12. `size_of::<Body>()` is 544 (was 496: two empty
`Vec`s), `size_of::<DebugInfo>()` 392. An empty `DebugInfo` has allocated
nothing.

A standard-library translation unit (`tests/data/debug_survey_stl.cpp`,
`clang` 22, `-g -O0`): 6953 nodes in 249380 bytes (35.9 each), 253206
bytes of strings, 3808 locations in 60928 bytes, 394 functions. LLVM's
metadata text for the same unit is 1319334 bytes.

## Throughput

`cargo run --release -p hod_ir --example debug_throughput`, on a shared
machine with about 16 of 24 cores busy. 300 functions: 53.6 ns per node or
location built (18.7 M/s); a new interned location 34.3 ns, a location
seen before 18.5 ns, a distinct one 9.8 ns; reading a node 2.9 ns;
`verify` 8.2 ns per node; 41.2 node bytes per node. 100000 functions (2.4 M
locations): 150 ns each, of which location interning is 124 ns (cache
misses in the intern table).

## Survey

`tests/debug_survey.rs` compiles its inputs with `clang` and kiln and
holds every kind, field, record and operation they write against the field
table.

- `clang` 19 and 22 at `-g -O0` (four flag sets, C and C++): 20 kinds,
  the operations `constu deref plus_uconst stack_value`, the records
  `#dbg_declare` and `#dbg_label`. Nothing unsupported, nothing unknown.
  Only `clang` 22 writes `DIGlobalVariable.align` and `DILabel.column`.
- Under other options (`-O1`, `-O2`, key instructions, macro information,
  split DWARF, ...): also `DIArgList DIAssignID DILexicalBlockFile
  DIMacro DIMacroFile`, `#dbg_value`, `#dbg_assign` and eight more
  operations. Unsupported among them: `debug:DICompileUnit.macros`,
  `debug:DIMacro`, `debug:DIMacroFile`,
  `debug:DICompileUnit.splitDebugFilename`.
- kiln: nothing unsupported or unknown; its output loads and verifies.
  `kiln++` writes nothing `clang` 22 does not. It omits
  `DIImportedEntity`/`imports`, `DILabel`/`#dbg_label`, `vtableHolder`,
  `defaulted`, `DIGlobalVariable.align` and `DW_OP_plus_uconst`. On the C
  input kiln writes `DINamespace` and `DICompositeType.identifier/scope`,
  which `clang` does not for C.
- LLVM 19 `opt --write-experimental-debuginfo=false` output (the
  `llvm.dbg.*` call spelling) loads to bodies identical to the record
  spelling.

## Decisions where the spec was silent

- **Locations are a module table, not a body's.** Code generation keeps
  `LocId`s after the body is dropped, and a location's scope and
  inlined-at name module nodes.
- **`add` hash-conses; `add_distinct` and `reserve` + `define` never
  merge.** Equal ids mean one node; equal content does not mean equal ids.
  There is no uniquing of types by `identifier` across a module (LLVM's
  ODR uniquing); `complete` replaces a forward declaration by its
  definition in place.
- **One position-ordered `dbg_records` table** holds value, assign and
  label records, so `Body` grows by two `Vec`s, not three.
- **`SlotVar.expr`** is a new public field, as the old §5.2 text
  announced. Only struct-literal construction outside `hod_ir` breaks; the
  workspace has none. Every other change is additive.
- **`UseFacts` saturates at 2^29 − 1** (was 2^30 − 1) to make room for
  "named by a declare"; `only_use_is_next` ignores that bit.
- **`dbg_assign` takes one value**; a `DIArgList` there is the construct
  `debug:#dbg_assign.DIArgList`. `DIAssignID` is dropped.
- **`Body::verify` checks debug ids only when the module has debug
  tables**, because existing tests (`tests/body_build.rs`, `random.rs`)
  give made-up `DiId`/`LocId` values to bodies of modules without any.
  The body-only rules always run.
- **A function without a subprogram**: its locations must exist and lead
  to a subprogram, which may be any function's (as in LLVM).

## LLVM verifier rules not checked

`verify_debug` checks structure (§6.8), not every rule of LLVM's verifier.
Not checked: a tag valid for its kind; required fields present (the unit
of a definition, the type of a global variable, the file of a compile
unit, the entity of an import); every compile unit listed in
`!llvm.dbg.cu` and every `unit` a listed one; `declaration` is a
non-definition, and a declaration's subprogram is uniqued;
`retainedNodes` belong to the subprogram; reference-flag and
vector/enum/bit-field consistency; subrange `count` versus `upperBound`;
`dwarfAddressSpace` only on pointers; checksum format; a fragment fits its
variable; entry-value restrictions; two arguments with one `arg` number;
`!dbg` required on inlinable calls; `DIAssignID` pairing; a lexical-block
column without a line. Consumers treat every optional reference as
possibly absent.

## Ruled out

- A counting global allocator to test "no allocation per node": it needs
  `unsafe`. The tested form is `node_sizes` (node bytes are exactly head
  plus cells) and the record-size test (an empty table allocated nothing).
- Counting strings in `strings.rs`/`intern.rs`: not this package's files.
  `DebugInfo` keeps its own string count.

## Open questions

- Should `Body::verify` check debug ids whatever the module holds? That
  needs the existing body tests to stop inventing `DiId`/`LocId` values
  (`crates/hod_ir/src/verify.rs`, the `debug_ids` gate).
