# WP-102 — libc++ through hod, third measurement (strict only)

Landed: the "Third measurement" section of `docs/status/libcxx-hod.md`.
It sits beside the first and second measurements. No code changed.

Measured: `main` at `6e6bf9c` (after WP-081, 082, 083, 084, 095 and 021),
release `hod` (`cargo build --release -p hod_cli`), with the shim reading
bitcode natively. The rest of the setup is the second measurement's:
- kiln 1.0.1 at `bd60e1829`
- LLVM 22.1.8 (`/usr/lib/llvm-22`) behind the shim
- the suite at `llvmorg-22.1.8`, target `aarch64-unknown-linux-gnu`

The raw results are in `.build/libcxx-hod-3/`.

- **Quick check:** the 163 tests that the second strict run refused were
  run strictly on their own. 141 pass, 1 is XFAIL as in the baseline, and 21
  are refused for `inst:insertelement/i128` (`std/experimental/simd`, and
  `alg.find/find.pass.cpp`).
- **First refusals:** `inst:insertelement/i128` is the only one left, with
  21 modules and 21 tests. It is at `crates/hod_ir/src/classify/matrix.rs:1217`
  and WP-101 owns it.
- **Tests with all objects by hod:** each has the baseline's outcome, except
  2 load timeouts. They are `lost_wakeup.pass.cpp` (as in the second run)
  and `ifstream.members/buffered_reads.pass.cpp`. Run alone, each timed out
  with plain kiln + `llc` at the same load too. With a 120 s limit,
  `buffered_reads` passes both ways (hod 26-31 s, `llc` 21-33 s).
- No hod bug was found, so nothing was reduced and `tests/libcxx-repro/`
  does not exist.
- `oom_kill` was 0 before and after the run.

## How to repeat

Follow the recipe of `docs/status/libcxx-hod.md` "Repeating the run", with
`L=$R/.build/libcxx-hod-3` and `HOD_STRICT=1`, then:

```sh
# quick check: the tests the previous strict run refused, one positional each
cargo xtask libcxx --tag llvmorg-22.1.8 --compiler $W/scripts/libcxx-hod-kiln.sh \
  $(cat $L/refused-2.txt) --timeout 20 -j 3 --mem-limit 3072 --no-fail --results $L/quick.tsv
# whole run: `std libcxx` instead of the list, --results $L/strict.tsv
python3 -I $W/scripts/libcxx-hod-report.py $L/strict $L/strict.tsv $R/.build/libcxx-baseline/baseline.tsv
# a timeout alone, both ways
cargo xtask libcxx ... std --filter buffered_reads.pass.cpp -j 1   # with and without --compiler
```

`refused-2.txt` lists the tests with an `error` coverage line in the
previous run's `strict/cov/`, mapped to test paths through `strict/args.tsv`
(the path after `/libcxx/test/` in the compile command).
