# WP-294 — AArch64: `llvm.eh.dwarf.cfa`

Landed: `llvm.eh.dwarf.cfa(k)` on AArch64 (`spec/codegen.md` §5.6.38),
`crates/hod_a64/src/unwind.rs` (`dwarf_cfa`, `needs_entry_sp`), the
dispatch arm in `crates/hod_a64/src/target.rs`, the matrix row in
`crates/hod_ir/src/classify/matrix.rs` (now supported on both targets,
`int`/`ptr`). The refusal `intrinsic:llvm.eh.dwarf.cfa` is retired on
AArch64; no new refusal name. Found by the rehearsal of kiln's next pin
(WP-283): kiln's `ext.gnu.builtins/dwarf-cfa-run.cpp`.

## The value: the CFA, not `llc`'s

`llc` 19 and 22 for AArch64, with every selector (`-O0` plain and
`-O0 -global-isel=0 -fast-isel=0`), compute `eh.dwarf.cfa(k)` as
`x29 + k`, in every frame shape: plain, dynamic `alloca`, over-aligned
local (realigned frame), variadic, outgoing stack arguments, a
constant `k`. Their own row in the same function is `.cfi_def_cfa w29,
16`, so their value is 16 below the CFA. GCC's `__builtin_dwarf_cfa()`
is the CFA (`mov x0, sp` in a leaf, `add x0, x29, 64` in a frame of 64
bytes), and libgcc's `_Unwind_GetCFA` returns the CFA. hod returns the
CFA: following `llc` would give a value no unwinder agrees with (the
reason WP-215 refused it), and the CFA has an oracle, the unwinder.

hod's CFA is the stack pointer at entry (`x29 + FRAME`, the frame record
at the bottom, §5.5). `FRAME` is patched at the end of the function, so a
function that calls `eh.dwarf.cfa` keeps the incoming base, as for
`sponentry`, and the value is `ldr rd, [x29, #base]` plus `sext(k)`
(`add`/`sub` immediates for a constant, `ldr x16, [x29, #base]` · `add
rd, x16, wk, sxtw` for a variable). No frame shape changes it, so none
is refused.

### Tried and replaced: `x29 + k`, as `llc` writes it

`eh.dwarf.cfa(k)` as `llvm.frameaddress(0) + sext(k)` (the instruction
`llc` emits) was implemented and measured: its difference to
`frameaddress(0)` is `k` for hod and for `llc` 19 and 22 in all ten
shapes of the run test. It is not the value `llc`'s programs see,
though. `llc` puts the frame record at the top of the frame, so its
`x29` is 16 below the CFA in every shape and above every local; hod
puts the record at the bottom (§5.5), so its `x29` lies below the
locals and at a distance from the CFA that changes with the frame
(48 to 272 bytes over the ten shapes). kiln's test compares the value
with the address of a local: built by `llc` it prints `1 1 0 1 -1`,
built by hod under this rule `0 1 0 1 -1`. The rule was dropped for the
CFA, which has one meaning under any frame layout.

A third value, the stack pointer at entry less 16 plus `k`, would be
the same address `llc`'s code computes in every program; it names
nothing in hod's frame (it can lie inside a local) and no unwinder
agrees with it. Not implemented.

## Evidence

- `crates/hod_a64/tests/frame_intrinsics.rs`
  `dwarf_cfa_is_the_unwinders_cfa`: ten shapes (plain, over-aligned
  local, VLA, variadic, outgoing stack arguments, incoming stack
  arguments, variable 24 and -16, constant -8 and 40). Each value less
  `_Unwind_GetCFA` of its frame (libgcc's `_Unwind_Backtrace`) is `k`;
  each value less the caller's stack pointer before the call is `k`
  (calls without stack arguments). Built by hod (plain, stressed) and by
  `llc` 19 and 22, linked by every linker present, dynamic and static,
  run natively: hod prints the expected values, `llc` every value 16
  lower.
- `tests/ir/dwarf_cfa.ll`: the target-neutral properties (offsets move
  the value by exactly `k`, above the locals, not above the caller's
  frame pointer, the same after a VLA and in a variadic function), so
  `irdiff` compares hod with `llc` on both targets and both LLVM majors.
- kiln's test (the corpus entry saved by the rehearsal) built by hod,
  linked with `c++` and run: prints `1 1 0 1 -1`, exit 0.
- `cargo xtask compare-binaries` base (`975fe0d1`) against head, each
  built in its own target directory, `-j 4`:
  - the corpus (`.build/corpus`, 6932 AArch64 modules, none using the
    intrinsic) plus `tests/ir`: 14090 comparisons, 13868 identical, 0
    different, 0 changed-outcome, 222 identical-failure (the `tests/ir`
    seeds, which name no target and so fail alike under both);
  - `tests/ir` again, each seed without a target given `;@ target:
    aarch64` and `;@ target: x86_64` (copies under the build
    directory): 384 comparisons, 313 identical, 0 different, 69
    identical-failure, 2 changed-outcome: `dwarf_cfa.ll` on AArch64
    (plain and PIC), refused by the base. `dwarf_cfa.ll` on x86-64 is
    identical.
- `irdiff` of `tests/ir/dwarf_cfa.ll` with `--witness`, AArch64 and
  x86-64, LLVM 19 and 22: 4 PASS each; `cargo test -p xtask --test
  irdiff_real`: 12 passed.
