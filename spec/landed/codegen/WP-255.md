# WP-255: module assembly that opens sections of its own name

Spec: `spec/asm.md` §9 "Sections" and §9.1 "Sections of the text's own
name (WP-255)"; `spec/codegen.md` §9.7.3 "Sections of the text's own
name".

Boost (JSON, Unordered) built by kiln + hod on x86-64 (123 translation
units refused) embeds gdb pretty printers as module assembly:
`.pushsection ".debug_gdb_scripts", "MS",%progbits,1`, `.ascii` lines of
an inlined Python script (the first starts with the kind byte `\4`),
`.byte 0`, `.popsection`. Strict hod refused it as `asm:section`: the
x86-64 path (`assemble_module_x64`, WP-204) took only the standard
section names. The spec's sentence that x86-64 module text "stays
`module:asm`" was stale since WP-204 and is corrected.

## What was built

- `crates/hod_asm/src/module.rs`: `SectionKind::Custom { sh_type,
  flags, entsize }`; a name that is not standard (and not reserved) is
  opened with the flags `a w M S R`, the types `@progbits` `@nobits`
  `@note` (and `%`), `M`'s entry size; quoted names; a later directive
  that writes flags, type or entry size must agree with the first, one
  that writes none keeps them (LLVM's rule, probed on llc 19 and 22).
  Strings already had LLVM's escapes (checked against llc: `\4`,
  `\004`, `\x41`, `\x4142` truncated, `\0`, `\377`, `\b \f \n \r \t \"
  \\`; `\e \a \v \8 \q \777 \x` are LLVM errors and refused).
- `crates/hod_cg/src/emit/section.rs`: `Sections::assembly`, the
  section with the generic id; `emit/module_asm.rs` creates such a
  section with its header, alignment and bytes, so that a global of an
  explicit section of the same name joins it exactly when llc's does.
- Classification row `module:asm` text; `docs/status/support.md` blessed.

## Refused, by name

- `asm:section-flags/exec` (`x` on such a section), `/group` (`G`),
  `/tls` (`T`), `/link-order` (`o`), `/exclude` (`e`), `/other`; these
  flags on standard names too (before: `asm:section`).
- `asm:section-type`: a type other than progbits, nobits, note.
- `asm:section-name`: names LLVM gives defaults or hod writes (§9.1's
  list: `.tdata`, `.note*`, `.init_array`, `.eh_frame`, `.comment`,
  DWARF sections, ...).
- `asm:section`: `M` without the entry size, a fourth operand without
  `M` (`unique`, group names), a changed flags/type/entry size, an
  instruction in such a section, a global of an explicit section naming
  a `@nobits` section of the text, `.rodata.str*`/`.rodata.cst*`.

## Evidence

- `crates/hod_cg/tests/emit_module_asm.rs`: five shapes (the gdb-script
  embedding, every flag/type/entry size and the section stack, symbols
  and relocations in allocated and non-allocated sections, globals of
  the same name with the same and with other flags) on AArch64 and
  x86-64 against llc 19 and 22: sections with bytes, symbols and
  relocations equal; refusal tables for both targets.
- `crates/hod_cg/tests/emit_module_asm_link.rs`: the reduced module
  (`tests/data/gdb-scripts-{x86_64,aarch64}.ll`, 8361 bytes of script)
  on both targets: object section header and bytes equal llc 19's and
  22's; linked with a C `main` under bfd, lld, mold (and wild, present
  here) the programs run and their `.debug_gdb_scripts` equal llc's
  programs'; gdb (AArch64, native) runs an inlined script of hod's
  program under every linker.
- The original reduced module: `hod --strict` builds it; its section is
  byte-identical to `llc` 22's.
