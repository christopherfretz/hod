# WP-299 — i386 I8: PIC, PIE and TLS (design 0008)

Landed: `crates/hod_x86/src/pic.rs` and `tls.rs`; behaviour in
`spec/codegen-x86.md` §9. Every symbol reference of the back end goes
through the access choice: `common::sym_address` → `pic::address`,
`common::sym_inst` → `pic::mem_inst`, `Target::emit_call` →
`pic::emit_call`.

## Decisions

- **GOT pointer per use, no reserved register, no frame slot.** `call .L;
  .L: pop r; lea r, [r + _GLOBAL_OFFSET_TABLE_ + 3]` (`R_386_GOTPC`),
  `llc`'s thunk-free sequence (19 = 22 at `-O0`, no
  `__x86.get_pc_thunk.*`) with `lea` for `addl` so the flags are kept.
  Reserving a register would take one of six from `hod_cg`'s fixed pool
  (`REG_INFO` is static) and a slot would need state in `FnState`
  (WP-293's); 11 bytes per use is the price.
- An address is computed in its destination register (writes `rd` only);
  a memory operand over a symbol uses `eax` (no value lives there across
  instructions), and an instruction that would read `eax` over it is an
  internal error (`pic::reads_eax`), never emitted.
- `@PLT` calls in PIC: `FnCx::take_reg(ebx)` displaces its value, the GOT
  pointer goes into `ebx`, then `call f@PLT`; `ebx` is freed after.
- `nonlazybind`: ignored by `llc` 22 for i686 at `-O0`, by hod too.
- Jump tables: none (compare chains). Constant pools: none yet; I9's go
  through `pic::mem_inst` (the hook).
- TLS local exec and initial exec (both forms) as `llc`, in the byte
  forms the linkers relax.
- TLS general and local dynamic (second implementer):
  `hod_cg::RuntimeFn::TlsGetAddrRegparm` (`___tls_get_addr`, the one
  `hod_cg` edit); `llc` 19 = 22's `-O0` bytes (`8D 04 1D` + `TLS_GD`,
  `8D 83` + `TLS_LDM`, `call` + `PLT32`, `TLS_LDO_32`), `ebx` the GOT
  pointer. The intrinsic form is a call (`displace_all`, `take_reg(ebx)`);
  the operand form saves `eax`/`ecx`/`edx`/`ebx` but `rd`, the flags,
  and `xmm0`..`xmm7` when an `xmm` register was used, in a 16-aligned
  area below `esp`. `RtLibUseGOT`'s `call *___tls_get_addr@GOT(%ebx)`
  is not followed (the `@PLT` form is valid and relaxed alike).
  `x86:tls:dynamic` is no longer returned.
- `pic::reads_eax` also flags implicit `eax` (`mul`/`div`/`idiv` of
  memory, `cmpxchg`, `cmpxchg8b`), `cmov`, two-operand `imul`, `xadd`,
  `bt*`, `shld`/`shrd`; it no longer flags the x87 escapes and SSE
  forms. The contract is unreachable today (`eax` neither pool nor
  holdable; spec §9.2); `pic/eax.ll` is the program that would hit it.

## Relocation kinds per symbol class (hod = `llc` 19 = 22, `-relocation-model=pic`)

| symbol class | data / address | call |
|---|---|---|
| local (static, `.L.str`, sections) | `R_386_GOTOFF` | `R_386_PC32` (llc resolves same-section calls itself) |
| hidden definition | `R_386_GOTOFF` | `R_386_PC32` |
| default-visibility definition, shared object | `R_386_GOT32X` | `R_386_PLT32` |
| PIE definition (`dso_local`) | `R_386_GOTOFF` | `R_386_PC32` |
| declaration | `R_386_GOT32X` | `R_386_PLT32` |
| `_GLOBAL_OFFSET_TABLE_` | `R_386_GOTPC` | — |
| pointer in data | `R_386_32` (writable or `.data.rel.ro`) | — |

`i386_pic.rs` asserts the sets equal (outside `.eh_frame`, locals as one
class, `llc`'s `memcpy`/`memset` calls aside) for 40 objects.

## Edits outside `pic.rs` / `tls.rs`

- `crates/hod_x86/src/common.rs`: `sym_inst` and `sym_address` bodies
  (one call each into `pic`).
- `crates/hod_x86/src/target.rs`: `begin_function` calls `pic::check`
  (was `check_static`); `emit_call` dispatches to `pic::emit_call`.
- `crates/hod_x86/src/call.rs`: the `ThreadLocalAddress | ThreadPointer`
  arm calls `tls::intrinsic`.
- `crates/hod/tests/i386.rs`: `pic_is_refused` became `pic_compiles`.

## Evidence

- `crates/hod/tests/i386_pic.rs`: the five I5 programs `-fPIE` (PIE) and
  `-fPIC` (shared library behind a driver), clang/llc 19 and 22, llc /
  hod / hod `Stress::ALL`, GNU ld, lld, mold: 60 program runs (180
  executions) equal; the pair `pic/main.c` + `pic/lib.c` (both modules
  by each compiler, and hod's against llc's): 42 runs equal; no
  `DT_TEXTREL` in any output.
- `crates/hod/tests/i386_tls.rs`: `tls.c` + `other.c` with each of the
  four `-ftls-model=` in a position-dependent program and a PIE (four
  threads behind a barrier), three linkers, two majors: 48 runs (144
  executions) equal, the linkers' IE → LE relaxation included; `other.c`
  as an initial-exec shared library: 6 runs equal; GD and LD in a shared
  library refused as `x86:tls:dynamic`.
- `cargo xtask irdiff --target i686` (LLVM 22), all tiers: before (WP-293)
  0 PASS, 195 UNSUPPORTED, 77 ERROR, 19 SKIP, `x86:pic` 43 of 90 objects;
  after 3 PASS, 0 FAIL, 195 UNSUPPORTED, 77 ERROR, 19 SKIP; hod built 1 of
  91 objects; the former PIC objects are now refused by their next
  construct: `x86:i64` 28, `coro:target` 17, `x86:eh` 12, `x86:float` 9,
  `x86:intrinsic` 6, `musttail:stack-args-unknown` 4, `x86:vector` 3,
  `x86:aggregate` 2, `x86:cf-protection` 2, `x86:tls:dynamic` 2, one
  each `attr:alignstack`, `x86:abi:attr`, `x86:abi:cc`,
  `x86:inline-asm`, `x86:varargs`. `--tier quick`: 25 tests, 3 PASS,
  0 FAIL, 57 UNSUPPORTED, 15 ERROR.

- Dynamic TLS (second implementer), `i386_tls.rs`: `tls.c` + `other.c`
  `-fPIC` GD/LD as shared library + PIE and in one PIE, 3 linkers, 2
  majors: 24 runs (72 executions) equal llc's; `dl.c` + `operand.ll`
  (operand form) loaded by `dl_driver.c` with `dlopen` under

  57 UNSUPPORTED, 15 ERROR (unchanged; no quick test uses dynamic TLS).
- `compare-binaries` d9833483 vs head over `tests/ir` and both kiln
