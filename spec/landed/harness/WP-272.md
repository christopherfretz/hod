# WP-272: comparing two hod binaries, and lanes that keep the modules they hand to hod

Landed: `cargo xtask compare-binaries`, which compiles every module of
corpus directories and of kept-module directories with two hod binaries
and classifies each module and mode; and an opt-in of the real-project
lane, `HOD_OSS_KEEP_MODULES`, that keeps every module kiln hands hod with
its arguments, so the same comparison runs over a project's own
translation units. This replaces the hand-made comparison by which the
1.0 candidate's move from `e98267c0` to `cd6ef6bc` was judged
(`docs/RELEASE.md` section 5, rule 5: 24,404 `equal` and 1,460
`samefail` over the whole corpus, both targets, plain and PIC). Harness
only: nothing under `crates/` changed. Contract: `spec/harness.md`
"compare-binaries" and "Real projects" ("Kept modules").

## The command

```
cargo xtask compare-binaries --base <hod> --head <hod> [--corpus <dir or entry>]...
    [--modules <dir>]... [--out <absolute dir>] [-j <n>] [--timeout <seconds>]
```

- Corpus entries: each module of an entry on its own (the `;@ module:`
  parts), in the modes `plain` and `pic`; arguments `--strict -O0
  -filetype=obj -mtriple=<the entry's target> [-relocation-model=pic]
  <the entry's llc-args> -o <object> -`, the module on standard input.
- Kept modules: each `MODULES.tsv` row replayed with its recorded
  arguments (the `-o` value replaced), mode `kept:<relocation model>`.
- Before anything runs, `--version` and the sha256 of both binaries; one
  that does not answer is an error (exit 2), not zero comparisons.
- Children through `irdiff`'s bounded runner: one jobserver token each,
  at most `-j` modules at a time (default 4, at most 16), every `HOD_*`
  variable removed.
- Classes: `identical`, `different`, `changed-outcome` (one fails, or
  both fail with another end or another standard error, the object's
  path replaced by `<object>`), `identical-failure`, and
  `harness-error` (an unreadable module, a child that cannot start).
- For `different`, the sections whose bytes differ, by name, from a
  small ELF64 section-header reader in `xtask` (the harness had none it
  could call: the ELF readers in the crates' tests are not a library).
- Report under `--out`: `summary.md` (binaries, inputs, jobs, counts per
  target and mode, the totals line, also printed), `results.tsv` (every
  comparison), `differences.tsv` (every failing comparison with what
  differs). Exit 0 only when something was compared and nothing is
  `different`, `changed-outcome` or `harness-error`.

## The lane option

`HOD_OSS_KEEP_MODULES=<absolute dir>` (default off): `oss-build.sh`
gives `scripts/oss/hod-shim` `HOD_OSS_MODULES_DIR=<dir>/<target>/<project>/<flavour>`
in the hod and strict modes. After hod has run, the shim keeps the module
as `<h>.ll` (`<h>`: sha256 of the module and of the arguments with the
object's path left out, 40 hex digits; a temporary file hard-linked into
place) and appends a row to `MODULES.tsv` for a new module only. hod's
input, arguments and status are unchanged; a module that cannot be kept,
or arguments that do not read standard input, fail the compile (status
1, `hod-shim: cannot keep the module in <dir>: <why>`). Documented in the
headers of `hod-shim`, `oss-build.sh` and `oss-run.sh`, in
`docs/VALIDATION.md` "Real projects" and in `spec/harness.md`.

Checked by hand with a fake hod: two identical compiles keep one module
and one row; a refused module is kept; a directory that cannot be
created and an input given as a file fail with status 1 and the message;
the option unset keeps nothing.

**Disk cost**, zlib v1.3.2, AArch64 native, flavour `O0`, strict: 36
modules handed to hod, 32 kept (the 4 others identical to kept ones),
2,761,835 bytes of modules, 2.7 MB on disk with the manifest; about 86 KB
per kept module.

## Tests

- Unit (`xtask/src/compare_binaries*.rs`): the classes from hand-made
  runs (equal, different, one refusing either way, the same refusal,
  refusals naming other constructs, another exit status, exit 0 without
  an object); the triple of a module; the command line (both binaries
  required, an input required, `--out` absolute, `-j` capped); the
  manifest (escapes, a bad hash, a bad size) and the replayed arguments
  (`-o x`, `-ox`, no `-`, no `-o`); the section difference on hand-made
  ELF objects (a differing section, a second section of one name, a
  section in one only, headers only, not ELF).
- `xtask/tests/compare_binaries_fakes.rs`, two fake hods that are shell
  scripts: every class in both modes and the PIC mode alone differing
  (12 comparisons, 6 modules, exit 1, the files and the summary's row);
  a refusal naming the object's path; an entry of two modules and base
  = head passing; an empty corpus failing with "nothing was compared";
  a binary that is not executable and one that is missing (errors that
  name `--version`); kept modules replayed with their arguments (target
  from the module's triple, `kept:pic` and `kept:default`); a manifest
  that does not parse is an error.

## The real runs

All with `-j 4`, binaries `.build/candidate/hod-<commit>`, output under
the build directory's `findings/wp-272/`.

1. `e98267c0` against `cd6ef6bc` over `kiln/llvm22/c` and
   `gcc-torture/llvm22/ieee` of the AArch64 corpus and of the x86-64
   corpus: 371 modules, 742 comparisons, all `identical` (aarch64 185
   plain and 185 PIC, x86_64 186 and 186); PASS, as the hand-made run.
2. `e98267c0` against the older `02fe2d02`, the same slices: 742
   `identical`, no difference there. Over the entries the change between
   the two touches (`llvm.is.constant`, coroutine suspends: kiln's
   `conformance/ext.gnu.builtins`, `templates`, `re.alg`, and
   `gcc-torture/llvm22/bcp-1.c.ll` and `builtin-constant.c.ll`, both
   targets): 106 modules, 212 comparisons, 208 `identical` and 4
   `different` (`conformance/re.alg/regex-match-libstdcxx.cpp.ll` on
   both targets in both modes: `sections differ: .eh_frame .rela.eh_frame
   .rela.text._ZSt9__advance... .symtab .text._ZSt9__advance...`, the
   dead arm of a constant test no longer compiled), exit 1.
3. zlib with the option on (above), then over its 32 kept modules: base
   = head = this branch's release hod (sha256 `aa11c7d3...`): 32
   `identical`, mode `kept:pic`; base `cd6ef6bc`, head this branch: 32
   `identical`. The strict build's result is that of the published row
   (36 objects by hod, `infcover` not offered and its link failing as
   in the control, 5 of 6 tests).

## Not done

- The LLVM lane (`scripts/oss/llvm/wrap.sh`, `scripts/oss/llvm-x64/wrap.sh`)
  runs the frozen hod directly (`KILN_HOD="$tree/bin/hod"`), not the
  shim. Keeping its modules needs, in the `hod` branch of each
  `wrap.sh`: `KILN_HOD=<scripts/oss>/hod-shim`,
  `HOD_OSS_REAL_HOD="$tree/bin/hod"` and
  `HOD_OSS_MODULES_DIR="$HOD_OSS_KEEP_MODULES/<target>/llvm/hod"`; and
  a decision for strict mode, where wrap.sh exports `HOD_OSS_STRICT=1`
  for itself and the shim would then turn hod's status 2 into 1, failing
  in kiln what wrap.sh's statistics check fails today (the shim needs to
  ignore that variable there, or wrap.sh to pass another). Not done:
  more than a few lines, and an LLVM build to prove it takes hours.
- No whole-corpus run (the supervisor's).
