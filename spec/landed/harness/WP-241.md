# WP-241 — the fuzzing budget of 1.0 (L10)

Landed: `cargo xtask fuzz --budget` (`xtask/src/fuzz/budget.rs`, the
options in `xtask/src/fuzz.rs`), its tests (`xtask/tests/fuzz_budget.rs`),
the budget's numbers and its release criterion in `docs/VALIDATION.md`
("Random programs (L10)", "The budget"; "Release candidate"), the
contract in `spec/harness.md` "Random programs", "Budget", and the run on
main with its findings in `docs/status/fuzz.md`. This file records what
was decided and why.

## Decisions

- **A form of the command, not a script.** The slices are runs of
  `fuzz::run` with narrowed options, in one process: the jobserver, the
  limits, the findings' saving and reduction are the command's own, and
  the row of a slice is built from its `Summary`, so the table cannot
  drift from what a run counts. A script would have parsed the text of
  each run.
- **The budget is a constant** (`budget::BUDGET`): profile, mode and
  seeds per target at LLVM 22; LLVM 19 runs a quarter. Changing it is a
  change of the release criterion and of `docs/VALIDATION.md`, reviewed
  as such.
- **Slices of at most 500 seeds**: what an interruption costs (a slice
  that did not finish runs again whole; resuming inside a slice would
  need the per-seed results to be trusted across two binaries of
  `xtask`).
- **Every slice's seeds are fresh and disjoint from every other's**,
  across targets and LLVM majors too: the earlier runs used the same
  seeds on both targets, which shows a difference between the targets
  but tests half as many programs. The plan is a function of the first
  seed; leaving a target out keeps the other's ranges, so a budget run in
  two halves (one per target) covers the same seeds as one run.
- **`--seed` and `--hod` are required**: the default seed 1 would rerun
  the old ranges, and the budget measures a frozen binary (a later
  commit cannot change what was measured).
- **Sized to the measured rates**: the smoke (20 seeds of every line on
  both targets, load about 20 to 30) showed csmith's lines at 10 to 200
  programs per minute, set by the few seeds whose programs run past the
  limit on both sides, and the csmith lines were first halved. The first
  real slice (500 seeds, 114 programs per minute) showed 20 seeds were
  too few to measure that, and the starting sizes (2000 and 1000 per
  csmith line) fit the day; the run was stopped after that slice and
  resumed with the larger plan, which starts with the same slice (same
  key, same seeds), so nothing ran twice.

## The run on main (hod `df415453`)

- 26,250 seeds (100001 to 126250), 62 slices, both targets, LLVM 22 and
  19; hod a frozen release build of `df415453` (sha256
  `052d461d54795c8bb78ed0a361bc9b4e87b057b52c26990ffc16c4eca1cd3097`),
  the harness a frozen release `xtask` of `041db8a2` (sha256
  `4fe117af028d2696f1ebf97a43d93efcc3a69459751e855bc01613f43cef8f6a`). Wall time 4 h 44 min at `-j 4` on the shared
  machine (load 21 to 27), 91 programs per minute overall.
- 23,714 agree, 0 refused, 2,487 skipped (2,309 both timed out), 0
  errors, 49 findings, none hod's wrong code: 20 csmith undefined
  behaviour (out-of-range float-to-integer conversion, gcc UBSan's
  report in the differing function), 8 `debug-lines` rows that the
  oracle's selector alone drops (the harness at `cb8b1ae0` sets all 8
  apart on a rerun), 21 `llc` 19 x86-64 call lowering of `__int128`
  with one register left (gcc and `llc` 22 on the same module agree
  with hod). Each with its evidence in `docs/status/fuzz.md`.
- The budget is therefore not met by this run: it counts findings that
  the later harness sets apart, and class 3 is set apart by none yet.

## Repeating it (the release candidate)

The candidate's budget must be re-run with the candidate's hod and the
harness of `cb8b1ae0` or later (with `ub-float-cast` skips and
`selector-split` set-asides counted as such), on fresh seeds. Freeze
both binaries first (release builds copied out of the build directory,
sha256 recorded), then, under `nohup`:

```
cargo xtask fuzz --budget --seed 200001 -j 4 --hod <frozen hod> --out <dir>
```

(or the frozen `xtask` binary with the same arguments). It takes about
5 hours on the shared AArch64 machine (this run: 4 h 44 min; the
float pre-runs and the selector builds of debug pairs add a little). A
slice that did not finish runs again whole when the same command is
started again; finished slices in `<dir>/budget.tsv` are kept. Until
the harness sets apart the `llc` 19 `__int128` class (or the `abi`
generator avoids it at LLVM 19), the x86-64 LLVM 19 `abi` slices will
report it again.
