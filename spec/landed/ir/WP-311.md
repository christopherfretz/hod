# WP-311 — debug nodes read one field at a time (`hod_ir`, `hod_dwarf`)

Item 1 of WP-308's ranked list (`spec/landed/dwarf/WP-308.md`, "What
remains"): the decodes of `DebugInfo::node` that the DWARF writer pays
for. Three commits, each with its counts in its message:
`crates/hod_ir/src/debug/` (`node.rs`, `mod.rs`) and the re-export in
`crates/hod_ir/src/lib.rs`, `crates/hod_dwarf/src/` (`types.rs`,
`die.rs`, `func.rs`, `call_sites.rs`, `early.rs`, `spec.rs`,
`inline.rs`, `import.rs`), `crates/hod_cg/src/debug_calls.rs`, and
`spec/ir.md` §6.2 (`view`). No change to emitted bytes, refusals or
error messages (below). Safe Rust, no new dependency.

## Method

As WP-308: Callgrind instruction counts, `HOD_THREADS=1`, the release
profile (fat LTO), `hod --strict -O0 -filetype=obj -relocation-model=pic
[-mtriple=x86_64-unknown-linux-gnu] -o out.o in.ll` on the bench inputs
(`cargo xtask bench --generate`, clang 22), both targets; base is
67d656c9 built from `git archive` into its own target directory. Self
cost per function (`callgrind_annotate --inclusive=no`, summed over the
files a function's inlined code comes from); inclusive costs are still
not usable (cyclic call graph under LTO, WP-288). Call sites were
ranked by the calls of `DebugInfo::node` summed by the source line of
the call instruction (`--dump-instr=yes`).

One source of noise is not the code: on tiny-functions-g x86-64, glibc's
`malloc_consolidate` and `unlink_chunk` (2.6 M together) run in some
runs of one binary and not in others (base: 367.3 M in one run, 369.9 M
in the next). The totals below use the runs where it ran for both base
and head; the commit messages say where it differed.

## The accessor

`DebugInfo::view::<R>(id)` (spec/ir.md §6.2) answers a `DiView<R>`, `R`
a kind's record, or `None` for an id that is not a node or not of that
kind. The view holds the node's mask, its tag and its cells; the
`nodes!` table generates one method per field, named and typed as the
record's field (`sp.flags()`, `d.base_type()`, `s.types()`), and
`tag()` for a tagged kind. A field's method tests its mask bit (absent:
the default), steps over the stored fields below it by their cell
counts (`Field::CELLS`: 0 for a `bool`, which is its bit; 1 for a
number, string, node, expression or constant; 2 for a wide or signed
number; 3 for a bound; a list its length cell and its elements) and
decodes that one field. The bit of each field is an enum per record
generated next to the methods (`Bit::$field`), so the position is a
constant. Test: `debug::node::tests::views_read_fields_as_nodes_do`
holds every field of every kind, for 96 random sets of stored fields per
kind (lists of 1, 3 and 5 cells before the field included), against
`node`; with `bool`'s cell count changed to 1 it fails.

## Tried, and not taken

- A `has_<field>()` per field (the mask bit only, for `!name.is_empty()`
  tests): `macro_rules!` cannot make the identifiers, and a string read
  through a view is one pool lookup.
- Putting the decode of `Writer::die`'s remaining kinds on views: the
  global variable, namespace, subprogram and type writers read most of
  their node's fields, so a full decode is the cheaper read there.

## What remains, ranked

1. **The remaining decodes** (26.2 M on stl-heavy-g, 2.4%): `Writer::die`
   for types, subprograms and globals (35 700 calls on stl-heavy-g),
   `create` in the type graph (15 400), `constructing_node` (12 000,
   kept on purpose by WP-308), `template_param_die` (5 900),
   `function_body` (8 400), and two outside this package: `hod_ir`'s
   `verify.rs:1166` (17 300; `crates/hod_ir/src/verify.rs`) and
   `hod_cg`'s `emit/lines.rs:195,213` (8 000). A cheaper full decode
   (fewer branches per field, the string lookups deferred) would pay at
   all of them.
2. **Reading several fields of one view**: `method_attrs` steps over the
   fields before each of its eight reads (6.1 M self). A method that
   reads the fields in order once (or a decode of a chosen field set)
   would cut it to one pass.
3. `DebugStrings::index` (7.0 M on stl-heavy-g, 0.6%), unchanged: an
   index by the store's string id needs `DiView` (or `DiNode`) to hand
   out the id; a view could (`Field::get` for strings reads the id
   first), but every `strx` caller would move to it. Not started.
4. The coordinator's report of 53.9 M in `Vec::append_elements` inlined
   into `die.rs` on stl-heavy-g: not found in this package's profile of
   the same base as self cost. `write_unit_dies`' own cost is below
   0.4 M, the self cost on `alloc/vec` lines inside `Writer::die` below
   1 M, and `memcpy` for the whole run 14.7 M; 53.9 M looks like an
   inclusive figure, which callgrind does not give reliably here.
