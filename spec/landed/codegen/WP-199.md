# WP-199: the x86-64 inline assembler's mnemonics against real code

## What is implemented

- **`prefetchw`** (abseil's `prefetch_test.cc`, found by the x86-64
  real-project lane) and the rest of the prefetch family.
- **A census** of the x86-64 templates real code writes
  (`crates/hod_asm/tests/census_x64.rs`, `spec/asm.md` §13): 102 bodies
  standing for 219 templates and 82 mnemonic spellings, from the lane's
  modules (`.build/corpus-x64` and the lane's saved findings: 50 call
  templates, no `inteldialect`) and from the sources real projects
  include (the C library's `sys/io.h`, `fpu_control.h`, `asm/swab.h`;
  clang's `intrin.h`, `immintrin.h`, `sgxintrin.h`, `pconfigintrin.h`,
  `hresetintrin.h`, `cpuid.h`; libstdc++'s `simd_x86.h`; abseil;
  protobuf; benchmark; gtest; the sanitizer, XRay, OpenMP and builtins
  runtimes; LLVM's `Host.cpp`; BOLT's runtime; valgrind.h). **148 of the
  219 templates assembled before, 193 after**; every accepted body is
  `llvm-mc` 22's and 19's bytes.
- **The mnemonics and forms the census needs**, most frequent first
  (`spec/asm.md` §13 lists them): port `in`/`out` (18 templates), the x87
  and MXCSR state (`fnclex`, `fstcw`, `fnstsw`, `stmxcsr`, `ldmxcsr`,
  `fnstenv`, `fldenv`, `fstenv`; 9), the prefetches (6), the system and
  enclave instructions of clang's headers (`rdmsr`, `enclu`, `encls`,
  `enclv`, `pconfig`, `hreset`; 6), `nopl` with memory (2), `crc32q`
  (2), `divpd`/`divps` (2); and with them the neighbours of each family
  (`wrmsr`, `rdpmc`, the flag instructions, the waiting x87 forms,
  `fsave`/`frstor`, `clflush`/`clflushopt`/`clwb`, the `xsave` family,
  `rdrand`/`rdseed`/`rdpid`/FS-GS base, the packed `addp`..`unpckhp`,
  every `crc32` width, and the string instructions without `rep` and
  with `repe`/`repne`).
- **`hod_mc_x64` constructors** (`src/inline.rs`, `spec/mc-x64.md`
  "Inline assembly"): `prefetch_m`, `nop_r`, `nop_m`, `in_dx`, `in_i`,
  `out_dx`, `out_i`, `string_op`, `fnstsw_m`, `fnstenv_m`, `fldenv_m`,
  `fnsave_m`, `frstor_m`, `crc32_q_rb`, `rdmsr`, `wrmsr`, `enclu`,
  `encls`, `enclv`, `pconfig`, `hreset`, `clc`, `stc`, `cmc`, `lahf`,
  `sahf`, `cli`, `sti`; each swept against `llvm-mc` 19 and 22
  (`tests/l1/inline.rs`).
- **CPU features**: none checked, as `llc`'s assembler checks none
  (verified: `llc-22` with no `target-features` assembles `prefetchw`,
  `clflushopt`, `clwb`, `rdrand`, `vzeroupper`, `crc32b`).
- `rep stosd`, `rep lodsd` (which `llvm-mc` refuses) are now refused
  too; `rep`'s byte is written before the string instruction whether
  joined or not, as LLVM does.

## Evidence

- `crates/hod_asm/tests/census_x64.rs`: every census body accepted or
  refused as the table says (193 of 219 templates); the 91 accepted
  bodies without a symbol field equal `llvm-mc` 22's and 19's bytes.
- `crates/hod_asm/tests/llvm_mc_x64.rs`: about 200 new accepted bodies
  (every form above, `lock` on each lockable instruction, the repeat
  prefixes, the waiting x87 forms) equal to `llvm-mc` 22 and 19; the
  refusal table gains the forms LLVM refuses (`rep stosd`, `lodsd`,
  `nop (%rax)`) and the ones that stay refused.
- `crates/hod_mc_x64/tests/l1/inline.rs`: the new constructors swept
  over registers, memory forms, ports and immediates against `llvm-mc`
  19 and 22's disassembly (`inline_assembly_matches_llvm`).
- `crates/hod_x64/tests/inline_asm.rs`, `tests/data/inline_asm/census.ll`
  and `census.c`: 21 functions of the census's instructions (the
  prefetches, flushes, the multi-byte no-ops, MXCSR, the x87
  environment and state, `crc32` of every width against a C CRC-32C,
  the `rdtscp` stamp, `stc`/`clc`/`cmc`/`lahf`/`sahf`, `lock` on `bts`
  `btr` `btc` `not` `neg` `and` `xor` `or`, the HLE `xchg`, `repne
  scasb`, `repe cmpsb`, the string instructions without `rep`,
  `divpd`/`divps`) built by hod, by hod with the register stress and by
  `llc` 19 and 22, linked dynamically and statically, and run under
  `qemu-x86_64 -cpu max`; the ports and the privileged instructions are
  in functions nothing calls. Every template's bytes equal `llc`'s
  `#APP` block. The WP-187 functions (`lock xadd`, `xchg`, `bsf`/`bsr`,
  `bswap`, `rep movsb`/`stosb`, `syscall` `getpid`) run unchanged.
- Clobber and flag handling are untouched (no change under
  `hod_x64/src`); the WP-187 clobber tests pass.
