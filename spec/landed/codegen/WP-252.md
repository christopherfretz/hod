# WP-252: a line row for a statement whose only code is a branch on a constant

Spec: `spec/dwarf.md` §5.10 "A row at a branch on a constant";
`spec/codegen.md` "`condbr`" (AArch64 and x86-64) and "`switch`
(WP-117)"; `spec/harness.md` "Random programs", "Modes" (Debug), the
`constant branch` class.

The fuzzing budget's `--debug` mode found it (seed 110478, AArch64,
LLVM 22, csmith `default`): `if (((&l_1000 == (void*)0), 0x5326CD0DL))`
is an unused `icmp eq ptr`, its unused `zext` and `br i1 true`. hod
folded the branch to the block it emits next, which writes nothing, and
emitted nothing for the unused values, so the line had no row; `llc
-O0` keeps code there. The harness set the pair apart by rule
(`case::constant_branch`, WP-241). A debugger stopped on that line in
`llc`'s program and on the next line in hod's.

## Evidence: what `llc -O0` keeps at such a line

Reproductions (`if ((x, 1))`, `if ((x, 1)) if ((x == 2, 1))` (two in a
row), `if ((i == 3, 1))` in a loop body, `if ((x == 1, 0))` as the only
statement of a block, `while ((x == 0, 0))`, `switch ((x, 2))`) built by
clang 19 and 22 `-O0 -g` for each target, then `llc` of the same major
with each selector; the row at the line, its instruction:

| target | selector | `br i1 true\|false` | `switch` on a constant |
|---|---|---|---|
| x86-64 | SelectionDAG | constant in `al` at line 0, `testb %al,%al` (is_stmt), `jne`, `jmp` | `testb` (is_stmt), `jne`, `jmp` |
| x86-64 | FastISel | `movb $1,%al` / `xorl %eax,%eax` (is_stmt), `testb`, `jne`, `jmp` | as SelectionDAG |
| x86-64 | GlobalISel | constant from a slot at line 0, `testb $1,%al` (is_stmt), `jne`, `jmp` | as for `br` |
| AArch64 | SelectionDAG | `mov w8,#1` at line 0, `cbnz w8` (is_stmt), `b` | `cbnz` (is_stmt) |
| AArch64 | FastISel | the branch folded to one `b` (is_stmt), kept when its target is the next instruction | `cbnz` (is_stmt) |
| AArch64 | GlobalISel | `mov w8,wzr` / `#1` at line 0, `tbz w8,#0` (is_stmt), `b` | `tbz` (is_stmt) |

LLVM 19 and 22 are the same at every line (offsets aside). No selector
writes nothing at such a line, and none puts the row on the next
instruction: where the chosen block comes next in layout, SelectionDAG
and GlobalISel keep the `jmp`/`b` to it (`-O0` keeps branches to the
layout successor) and FastISel on AArch64 a `b` to the next
instruction. The row is a statement row at the first instruction of
the line, which runs each time the statement is reached.

## What was built

- `crates/hod_cg/src/line_rows.rs`: `FnCx::folded_branch_row(target)`:
  the folded branch writes a `nop` when `target` is the block emitted
  next, the open segment has no code yet (no `phi` edge store), the
  function's rows are written (a location; a subprogram of a unit that
  is not `NoDebug`), the location is not the last row's, and the row
  starts a line: the first code of its block, or the last row at another
  line or file. The lookups past the cheap tests run only for a folded
  branch.
- `crates/hod_x64/src/control.rs`, `crates/hod_a64/src/control.rs`:
  `control::folded_br`, used by `cond_br` on a constant (now also with
  two equal targets: the constant is tested first), by `switch` on a
  constant and by the wide (`Mem`) `switch` on a constant (x86-64 in
  `control.rs`; AArch64 `crates/hod_a64/src/tail.rs` `switch_wide`).
  x86-64 writes `90`, AArch64 `d503201f`: the least code a row can
  name, no fixup, no label, nothing the shrink pass or the far and
  stressed layouts handle but the row's offset.
- `xtask/src/fuzz/case.rs` `constant_branch`: `br i1 true|false` is not
  accepted any more; what is left are lines of `br label` and unused
  values. Unit tests: the seed's shape and the first test's line now
  assert `false`; the `br label` variants of both keep the unused-value
  logic covered (`true`).

## What changed in emitted code, and what did not

Only a function with a branch on a constant whose line has no other code
there, with line rows written, gets one `nop` per such branch. Measured:

- Without debug information, byte-identical objects before and after
  (hod built from the base commit before any edit, in this package's
  target directory, against the head): every eighth module of the
  AArch64 corpus (808 modules: 766 identical, 42 refused by both) and of
  the x86-64 corpus (808: 765 identical, 43 refused by both); 0 differ.
- With debug information: every `tests/debug` C and C++ test built by
  clang 22 `-g` for each target and the corpus modules with locations
  (69 per target): 69 of 69 identical on each target (none has such a
  branch).
- The reproductions: one `nop` per such line, nothing else changes
  (`no_nop_without_line_rows` compares the code with and without rows).

## Tests

- `crates/hod_x64/tests/constant_branch_lines.rs`,
  `crates/hod_a64/tests/constant_branch_lines.rs`: seven functions (a
  `br i1 true`, the seed's `br i1 false` after an unused compare and
  extension, a `switch` on a constant, two in a row, one alone in a loop
  block, one after a load of its own line, one whose block is not next):
  the `nop`s are exactly at the expected lines as statement rows; hod's
  (function, line) set equals the oracle's (SelectionDAG) for LLVM 19
  and 22; each of the three selectors of both LLVMs has the line; no
  `nop` without `!dbg` or with a `NoDebug` unit, and the code with rows
  is the code without them plus the `nop`s.
- `tests/debug/constant_branch.c` (`tier: quick`): breakpoints on `if
  ((x, 1))`, on `if ((i, 1))` in a loop body (hit twice) and on `switch
  ((x, 2))`, gdb and lldb. With the base hod: 16 FAIL (the breakpoint
  moved to the next line), 4 unclassified llc-only pairs; with the head:
  16 PASS, lines unclassified 0 (AArch64, every linker).
