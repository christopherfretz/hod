# WP-262: coroutine suspends in unreachable blocks

Spec: `spec/codegen.md` §7.6 "Suspend points in unreachable blocks".

libunifex v0.4.0 built by kiln + hod on x86-64 (`-O0` and `-O0 -g`): 17
of 114 objects were an internal error, "a label that code refers to was
never bound", all in `unifex::_await_cpo::_fn::connect_impl`
coroutines. Their body never falls off its end and the exception path
ends in a call that does not return, so the final suspend's block has no
predecessors. hod's coroutine plan numbers every suspend and gives each
a re-entry label; the driver does not emit unreachable blocks, so the
final suspend's label was never bound, while the resume and destroy
stubs still branched to it. The `invoke`d `coro.await.suspend.*` calls
of those functions were not the cause.

## What was built

- `crates/hod_cg/src/coro_body.rs`: a suspend point records whether its
  `coro.suspend` was emitted (`FnCx::coro_reentry`, called by the
  target where it binds the label); `FnCx::coro_reentries`, the stubs'
  dispatch list on both targets, lists only those. The indices are the
  plan's, unchanged: a later suspend keeps its index when an earlier one
  is unreachable. An index no emitted suspend stores reaches the stub's
  trap (`ud2` / `brk #1`), as before.

## Tests

- `crates/hod_x64/tests/coro_body.rs`
  `suspends_in_unreachable_blocks_have_no_reentry` and the same test in
  `crates/hod_a64/tests/coro_body.rs`, over
  `crates/hod_x64/tests/data/coro/unreachable_suspends.cpp`: coroutines
  whose final suspend is unreachable; one with an unreachable suspend
  in the middle, destroyed while suspended at the await after it; awaits
  through `invoke`d wrappers whose `await_suspend` throws into the
  body's handler (void form, and the `handle` form, which also transfers
  to another coroutine and to `noop_coroutine`). Clang 19 and 22
  pre-optimisation IR; hod's object plain and with `-g`
  (`llvm-dwarfdump --verify` clean) prints what the `llc` build prints,
  under every linker, plain and with poisoned frees.
- Real code: kiln `-O0 -g` IR of four libunifex examples among the
  failing objects (`async_mutex`, `async_trace`, `asynchronous_sleep`,
  `coroutine_stream_consumer`) compiles for x86-64 (`llvm-dwarfdump
  --verify` clean); linked with the library and run under qemu, each
  prints what its `llc` build prints, apart from measured times and
  addresses.
