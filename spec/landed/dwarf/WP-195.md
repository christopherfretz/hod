# WP-195 — debug refusals real projects meet at `-O0 -g`

Spec: `spec/dwarf.md` §6.25 and §6.26 (the follow-up). No abbreviation family taken.

## What was built

- `debug:variable-twice`: a variable two `#dbg_declare`s of slots name in
  one instance of its scope is one DIE located by the first record's
  slot (`llc`'s frame table keeps the first; `hod_dwarf` `func.rs`
  `collect_entities`, `FnInline::first_of`).
- `debug:local-static`: making a static's subprogram DIE re-checks the
  slot after making its parent, as `getOrCreateSubprogramDIE` does
  (`inline.rs` `static_parent`, `func.rs` `add_function`,
  `call_sites.rs`); the cause was a member declaration whose type is local
  to the same function.
- `debug:retained-nodes`: imports scoped in a subprogram that is only
  inlined are written under its abstract instance at the end of the unit
  (`Inline::imports`, `import.rs` `seal_imports`).
- Every `debug:` refusal's detail names the node and its function
  (`hod_dwarf::Error::detail`, carried by `CgError::UnsupportedDetail`).
- `cargo xtask debug trees`: a dereferenced stack-pointer slot is the
  `realigned frame` class.

## Evidence

- Trees (`cargo xtask debug trees`): every compiled x86-64 module
  `same` or permitted (sret, byval, fallthrough inlined). AArch64
  modules differ only by classes present in the base already, where the
  base compiled (local copies of `available_externally` functions for
  `.alwaysinline`, a lambda's pack-capture members, block ranges against
  low/high pc). fmt `format.cc`: every import matches; the differences
  are `fmt::detail::assume`'s inlined subroutines (hod keeps the load
  before `llvm.assume` that SelectionDAG drops). The reduced seeds are
  equal or permitted on both targets; `crates/hod/tests/
  debug_real_projects_wp195.rs` compares them with `llc` line by line.
- `.text` with and without debug information (`opt -strip-debug`):
  identical for all twelve AArch64 modules; on x86-64 they differ only
  in functions with a `byval` parameter (the declared pointer's home,
  `spec/codegen.md` §4.1), the same as the base's.
- Debuggers (`cargo xtask debug run`, hod against `llc`, bfd, lld and
  mold, gdb and lldb 19): `tests/debug/variable_twice.cpp` (kiln, clang
  22; `print r` at the `return` gives the first slot's `"equal"`),
  `inlined_import.cpp` (clang 22; `print a` and `print map(a)` inside the
  inlined `f`), `local_static.ll` (`print calls`, `info locals`,
  `frame variable calls`). AArch64: 30 of 30 PASS. x86-64 (qemu's gdb
  stub): 18 of 18 PASS; the IR case is not run there by the harness, so
  its x86-64 build was run by hand under gdb, hod's transcript equal to
  `llc`'s.
- Base check: hod at this package's base (wave 12 and WP-189) refuses
  each reduced seed by the name it names, and compiles every saved
  `template-address` and `die-unsupported` module: those two names were
  already gone.

## Follow-up: a type local to a function without code (§6.26)

`debug:local-type-scope` for a type scoped in a function definition of
this unit with no code here (or only inlined, the type reached first):
`local_type_parent` makes the function's abstract instance as its
static's path does, which is `llc` 22's `getOrCreateContextDIE`. DIE
trees equal to `llc` 22's on both targets for a member template, a free
function and an inlined function (`crates/hod/tests/
debug_real_projects_wp195.rs`); `tests/debug/local_type_no_code.ll`
prints `whatis p` as `T *` under gdb and `(T *) p` under lldb, 12 of 12
PASS on AArch64, and by hand under gdb on x86-64 (hod's transcript
equal to `llc`'s). `llc` 19 writes an empty subprogram instead; hod
follows 22. A type local to a block or to a subprogram that is not a
definition of this unit stays refused.

## Still refused

- `debug:variable-twice`: any repetition other than slot after slot (a
  slot and an indirect slot or a `#dbg_value`, a label twice): `llc`'s
  merge rules for those are not modelled.
- `debug:retained-nodes`: a retained variable or label of an inlined
  subprogram, an import scoped in a block of one, and retained nodes of a
  function also placed out of line.
