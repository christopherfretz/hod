# WP-250 — `selector-split` in the debugger layer's line comparison (L7)

Landed: the `(function, line)` comparison of `cargo xtask debug run`
gets the fuzz layer's evidence-based class `selector-split`
(`spec/harness.md` "debug", "Lines"; `spec/dwarf.md` §5.7): a hod-only
pair left unclassified is set apart only when LLVM's two other `-O0`
selectors of the oracle's `llc` both have a row there. The rule is the
fuzz layer's own function (`fuzz::case::selector_split`); the debugger
layer gathers its evidence per unit, only for a unit with such a pair.

## What was measured

The full tier on AArch64 had one unclassified pair, and exited 1 for it:
`tests/debug/declare_fragment.c` (WP-230), clang 19 and clang 22 at
`-O1`, function `sort`, line 18 (`j--`, the `add nsw i32 %15, -1` of
`!63 = !DILocation(line: 18, column: 8)`).

hod's row is correct: it covers the reload of `%15`, the `sub w9, w9,
#0x1` and the spill of `%22`, the code of that `add`. The oracle
(`llc -O0 -global-isel=0 -fast-isel=0`) selects the `add` with the loop
test's `icmp sgt i32 %15, 1` (line 16) into one `subs w9, w8, #0x1`,
which lies inside the row of line 17 (the copy `a[j] = a[j - 1]`), so
line 18 has no row.

`is_stmt` rows at `sort`, line 18, of the module built by each `-O0`
selector (`llc -O0 <selector> -relocation-model=pic -filetype=obj`;
no `GlobalISel` fallback warning in any build):

| target | front end | hod | SelectionDAG | FastISel | GlobalISel |
|---|---|---|---|---|---|
| aarch64 | clang 19 (`llc-19`) | 1 | 0 | 1 | 1 |
| aarch64 | clang 22 (`llc-22`) | 1 | 0 | 1 | 1 |
| x86_64 | clang 19 (`llc-19`) | 1 | 1 | 1 | 1 |
| x86_64 | clang 22 (`llc-22`) | 1 | 0 | 1 | 1 |

LLVM's own `-O0` selectors disagree at the line and hod agrees with two
of three: the condition of `selector-split`. No IR-only rule was needed.

## Implementation

- `xtask/src/debug/lines.rs`: `Class::SelectorSplit` (named
  `selector-split`, counted in the summary before `unclassified`),
  `has_unclassified_hod_only`, `set_apart_selector_splits` (reclassifies
  only hod-only pairs that are `Unclassified`; never an llc-only pair or
  a pair another class explains).
- `xtask/src/debug/build.rs`: `llc_selector_object` (the reference's
  build with another selector, its standard error kept for the fallback
  warnings).
- `xtask/src/debug/sessions.rs`: `selector_splits` builds each module
  of the unit with `FastISel` and `GlobalISel`, links with the first
  linker as the oracle's program is, counts rows; `LinesResult` keeps
  the evidence and the summary prints one `selector-split:` line per
  pair set apart, verbose or not.
- `xtask/src/fuzz/case.rs`: `fallbacks` made `pub(crate)` (no other
  change).

## Tests

`debug::lines` unit test `selector_splits_set_apart_with_evidence` (set
apart with both rows; unchanged with one selector lacking the row, one
that fell back, one that failed; llc-only and P3 pairs untouched);
`xtask/tests/debug_real.rs` `selector_split_sets_apart_with_evidence`
(the real run on `declare_fragment.c`, lld, gdb, clang 19 and 22:
exit 0, no unclassified pair, every set-apart pair has its evidence,
the clang-22 `sort:18` line printed).
