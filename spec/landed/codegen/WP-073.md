## What is lowered

| model | sequence | relocations |
|---|---|---|
| general dynamic, local dynamic | TLSDESC through `x1`, argument in `x0`, `x0`/`x1`/`NZCV` saved and restored | `TLSDESC_ADR_PAGE21`, `_LD64_LO12`, `_ADD_LO12`, `_CALL` |
| initial exec | `adrp`/`ldr` from the GOT, `+ tpidr_el0` | `TLSIE_ADR_GOTTPREL_PAGE21`, `TLSIE_LD64_GOTTPREL_LO12_NC` |
| local exec | `mrs`, `add` hi12 `lsl #12`, `add` lo12 | `TLSLE_ADD_TPREL_HI12`, `TLSLE_ADD_TPREL_LO12_NC` |

A thread-local address is an operand (call argument, phi and `select`
arm, stored value, with a constant offset of any size);
`llvm.threadlocal.address` and `llvm.thread.pointer` are lowered.
Symbol offsets fold into a relocation only as `llc` folds them (`Direct`,
`0 <= off < 2^20`, `off <=` the value type's allocation size); every
other offset is added in code, without the loop of `add`s the `Got` path
had (5.7e11 instructions for a 2^63 offset).

## What is refused, by name

- `tls:direct-operand`: a thread-local symbol as the callee of a call.
- `tls:address-in-constant`: a thread-local address in an initializer,
  in an aggregate or expression constant, in a symbol difference, in a
  landing-pad clause.
- `a64:thread-local` is no longer returned (the constant stays in
  `target.rs`).

## Evidence

- `tls::every_model_links_runs_and_relaxes`: five builds (non-PIE
  executable, PIE, the library a shared object, descriptors linked into
  a PIE, `-static`) × hod and `llc` × bfd, lld, mold; a C driver checks
  every address against the C compiler's in the main thread and four
  others (each its own copies), 8 thread-local variables of every model
  (one 2 MB, one with ±2^40 offsets), a `select` with a fused compare
  around a descriptor call, six TLS call arguments, `x0` live across an
  access. The TLS relocation kinds of each object are `llc`'s. In the
  linked code: shared object 38 descriptor calls kept (llc 28: SelectionDAG
  reuses one access per block); PIE with descriptors bfd/lld 34 to local
  exec + 7 to initial exec, mold 17 + 21; static bfd/lld 41 to local exec,
  mold 17 + 21 (mold keeps initial exec); executables 10+ to local exec
  under bfd/lld.
- `tls::symbol_offsets_fold_as_llc_folds`: 6 symbols (defined 16 B and
  8 KiB, preemptible, external, `extern_weak`, a function) × 19 offsets
  (0, 1, 15, 16, 17, 8192, 8193, -1, -16, 4095, 4096, 2^20 - 1, 2^20,
  ±2^32, ±3e17, `i64::MAX`, `i64::MIN`), static and PIE, × 3 linkers:
  the `adrp` relocations equal `llc`'s, and every address and load
  agrees with C.
- `tls::each_model_is_the_psabi_sequence`: the disassembled GD, IE and LE
  sequences with their relocations.
- `tls_cxx::thread_local_objects_run_as_clang_builds_them`: `thread_local`
  objects with constructors, destructors, `std::string`, `extern
  thread_local` with dynamic and constant initialization, a `try`, through
  kiln++ and clang++ `-O0` IR, hod, PIE under 3 linkers, 4 threads: the
  output equals clang's own build.
- `back::huge_constant_offset_from_a_global_links` (pr79286) passes;
  `tests/ir/tls.ll` passes `irdiff` under bfd, lld, mold.
- Corpus, `corpus verify --strict` over the 22 modules with
  thread-locals or `llvm.thread.pointer` and `pr79286.c` (LLVM 22 and 19,
  bfd, lld, mold): 18 modules PASS, 54 of 72 results; the other 6 are
  declined for reasons outside this package (`mem:atomic-load` 4,
  `special-global:llvm.global.annotations` 2).

Mutations, each caught and reverted: the descriptor sequence not
restoring `x0` (shared build crashes); `NZCV` clobbered at the restore
(`lib_select` fails); every `Direct` offset folded (the relocation
comparison and pr79286 fail). Not restoring `NZCV` at all is *not*
caught: the static-TLS resolver `_dl_tlsdesc_return` leaves the flags
alone, so only a resolver that clobbers them would show it.
