# WP-139 — the x86-64 corpus

Landed: the corpus for the other architecture, the comparison between the
two corpora, per-test CPU features for cross runs, and a quick gate that
runs every `tests/ir` seed for x86-64. Results are in
`docs/status/corpus-x64.md`.

## What changed

- **`corpus --target <arch>`** (`spec/harness.md` "corpus", "Other
  targets") works for capture, verify, census, reasons and compare.
  - For the other architecture the corpus is its own directory
    (`<build root>/corpus-x64`) with its own tables. The host's corpus
    is not read or written.
  - kiln++ gets `--target=<triple>` in every command, before the
    header's arguments, unless the header pins a target
    (`kiln::plan_for`). clang gets it before the test's flags.
  - Programs are linked by the cross driver and run under the emulated
    runner, with six times the run limit. Admission is irdiff's cross
    run with the witness.
  - The key covers the triple. A missing emulator or system root is a
    missing tool. `capture::Options::sysroot` overrides the system root.
- **`TIMES.tsv`**: a row for each program a capture ran, giving its
  wall time and how it ended. It is not a function of the inputs, and
  snapshots leave it out, as they leave out `CAPTURE.tsv`.
- **`corpus compare`** (`xtask/src/corpus/compare.rs`) sets one corpus
  against another.
  - It reports, per group, the entries of both corpora and how many
    behave the same.
  - It gives each test whose exit or stdout differs, with its class and
    cause from the table of differences
    (`docs/status/corpus-x64-differences.tsv`).
  - It lists the tests captured on one side only, with the other side's
    skip reason, and the emulation-time distribution.
  - It exits 1 on a difference the table does not explain.
- **The `cpu` directive** (`;@ cpu: +cx16`, "Test directives"): CPU
  features added to the emulated runner's model for that test, on both
  sides. It needs exactly one `target`, and native runs ignore it.
  - `hod_testutil::target::cpu_with_features` drops a `-f` and appends
    `+f`, because QEMU applies `-f` after `+f`.
  - `Emulator::args_with` rewrites the `-cpu` value.
  - The baseline stays x86-64-v1 without cx16.
  - `spec/object.md`'s runner paragraph now names that baseline and
    defers to "Cross runs" as the single definition.
- **Gate**: `ci --quick` runs `irdiff --llvm 22 --target <other>` over
  every `tests/ir` test (`QUICK_CROSS_LLVM`). The seed list
  `QUICK_CROSS_SEEDS` is gone. The full tier is unchanged: both majors,
  and `--hybrid`.
- **Oracle batches for x86-64** (`crates/hod_interp/tests/x64_oracle.rs`):
  the interpreter's generated programs, written for the host, are built
  natively and, with only the triple changed, for the other architecture
  (same `llc`, cross driver, QEMU), with each LLVM major. Both programs
  must print what the interpreter says.
  - The quick test runs 4 batches of 120 programs (about 5 s).
  - The ignored test runs the design's 9 batches of 636 programs (18 s).
- **`scripts/x64-packages.py`**: design 7.2's package census over a
  corpus. It imports `packages.py`'s table and counts per module, per
  group and (with `--by-entry`) per entry.

## Tests

- `xtask/tests/corpus_fakes.rs` `other_target_runs_under_the_emulator`
  checks:
  - without the emulator, nothing is captured
  - with it, both producers get the triple and every program runs under
    the fake QEMU (whose CPU model reaches the expectations)
  - `TIMES.tsv` rows exist, and the host corpus is untouched
  - `verify` passes, and `compare` finds the one test that prints where
    it ran
- `xtask/tests/irdiff_fakes.rs` `cross_target_runs_under_the_emulator`
  has a `with_cpu.ll` that sees `+cx16` in its emulator's model, with
  every linker.
- Unit tests:
  - `kiln::tests::cross_command_lines`
  - `directives::tests::cpu_features`
  - `compare::tests::{differences_table, descriptions}`
  - `hod_testutil` `cpu_with_features`
  - `ci`'s quick plan

## Follow-ups

- The `llc` bug found by the cross-check (x86-64 `llvm.eh.sjlj.longjmp`
  through a reloaded `%rbp`) is reduced in
  `.build/target-wp-139/findings/pr64242/`. hod's own lowering of that
  intrinsic must avoid it.
- Emulated time is 6-16× native on the sample, not 6×. No corpus
  program comes near the 60 s limit, but `EMULATION_SLOWDOWN` would
  need about 12-15 for a test that runs for several seconds natively.
- The 6 kiln `target.x86/` tests beyond x86-64-v1 could be admitted
  with a `;@ cpu:` line in their entries if hod ever selects those
  instructions.
