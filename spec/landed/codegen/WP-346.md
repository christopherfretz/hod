# WP-346: i386 integers of 65 to 128 bits

Spec: `spec/codegen-x86.md` §22 ("Integers of 65 to 128 bits"), with
the refusal names in §7 / §8 / §21. Module:
`crates/hod_x86/src/wideint.rs`; dispatch in `int.rs` (entry points),
`agg.rs` (overflow intrinsics, `insertvalue`), `abi.rs`
(`type_refusal`). Tests: `crates/hod/tests/i386_wide_int.rs`; the
wide-index cases left the refusal list of `i386_i64_rest.rs`.

## Where it comes from

clang 19 and 22 (`--target=i686-linux-gnu -O0`) write `i65` for
`__builtin_{add,sub,mul}_overflow` with mixed signedness or widths
(`zext` / `sext` to `i65`, `llvm.{s}{add,sub,mul}.with.overflow.i65`,
`trunc`, `icmp ne`); two modules of the full libc++ run for i686
(`num_get::__do_get_integral<long long>`) stopped at `x86:i64:wide`.
`_BitInt(N)` and coercions reach the other widths.

## What landed

An integer of 65 to 128 bits is of class `Mem`: `ceil(N / 32)` limbs in
a frame slot, the bits above `N` unspecified and extended by every
consumer that reads them. `add` / `sub` (`adc` / `sbb` chains with only
`mov`s between the limbs), `and` / `or` / `xor`, `mul` (an exact
product in a frame area), every `icmp`, `select`, `freeze`, `phi`, the
casts to and from 1..64 bits and the other wide widths, `load` /
`store` of exactly the store size with the bits above `N` zero,
constants, `insertvalue` / `extractvalue`, the six `with.overflow`
intrinsics (no call, no branch: no x87 barrier), a wide
`getelementptr` index (its low limb, as `llc`). An `i128` result is
returned in memory as before (`abi.rs`). Refused:
`x86:i64:wide:{shift,div,intrinsic,switch,abi,width}`; a wide argument
is `x86:abi:wide-arg`. Plain `x86:i64:wide` is no longer reached.

## Measurements

- `llc` 19 and 22 store an `iN` as its store size with the bits above
  `N` zero and load it with a zero-extending byte / word load of the
  last bytes (`movzbl 8(%eax)` for `i65`); hod's disassembly: an `i120`
  load and store touch bytes 0 to 14, an `i65` bytes 0 to 8.
- Overflow at an odd width is `llc`'s rule: the result over `32 L`
  bits compared with its own sign / zero extension from `N` bits.
- Evidence at landing: `i386_wide_int` 6 tests: 36 `.ll` runs and 36 C
  runs equal `llc`'s (LLVM 19 and 22, CPU `generic` / `i686` /
  `pentium4`, static and PIE, plain and `Stress::ALL`); the edge program
  (guard bytes and a `PROT_NONE` page at 65 / 72 / 96 / 100 / 120 / 128
  bits, garbage above the width through every consumer, aliased `add`
  operands and swapping `phi`s, the wide index) 12 runs; the multiply
  program (every pair of the boundary values and 2,048 random pairs per width,
  checked against the exact result) 12 runs. Every `i386*` binary of
  `-p hod` passes (33 binaries, 132 tests). irdiff i686: 171 PASS,
  0 FAIL, 0 ERROR at LLVM 22 and 19. compare-binaries against
  `b9d4aad4`: 14120 comparisons, 0 different, 0 changed outcome (the
  corpora reach no wide integer on i686).

## Review of the first version

A second pass checked the places where a limb-wise lowering is
typically wrong (memory extent, the bits above `N`, carries under
`Stress::ALL`, multiplication and its overflow, compares at the limb
edges) with the tests above; each was already right. Two test bugs were
fixed: the refusal cases called intrinsics without declaring them, and
named an `i128` result as refused although it is returned in memory.

## Not done

Shifts, division, the integer intrinsics, `switch`, wide arguments and
results of 65 to 127 bits stay refused by name.
