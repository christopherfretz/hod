# WP-341: i386 `llvm.frexp`

Spec: `spec/codegen-x86.md` §21 ("Floating-point classes and
`modf`", the `llvm.frexp` paragraph). Module:
`crates/hod_x86/src/fpclass.rs` (`frexp`, and `out_param_call`, the
sequence it shares with `modf`). Barrier: `crates/hod_x86/src/x87.rs`
`barrier` (one arm). Tests: `crates/hod/tests/i386_frexp.rs`.

## Where it comes from

The libc++ `cmath` test built for i686 by clang 22 stopped, after WP-337,
at `x86:intrinsic` for `llvm.frexp.f64.i32` (libc++'s `frexp` is
`__builtin_frexp`). After this package the module compiles completely,
static and PIC, and its program (linked by GNU ld with libm, run under
`qemu-i386 -cpu pentium2,-mmx`) exits 0, as `llc` 22's.

## What landed

`llvm.frexp` of `float`, `double`, `x86_fp80` on i386, x87 and SSE
functions, static and PIC: `frexpf` / `frexp` / `frexpl` through
`pic::emit_call` with the operand at its width in the outgoing area and
the address of the result's `i32` field after it; the fraction popped
from `st0` to the first field. Uses `eax` only; pins no pool register.
The classifier's i386 cell of `intrinsic:llvm.frexp` is `float`,
`double`, `x86_fp80` (and the `i32` / pair classes): `half`, `fp128`
and vectors are `intrinsic:llvm.frexp/<class>` on i386 (before:
`x86:float:half`, `x86:float:fp128`; vectors unchanged).

## Measurements

- `llc` 19 and 22 (`-O0 -fast-isel=0 -global-isel=0`), CPU `generic`,
  `i686`, `+sse2`, static and PIC: the same call as `modf`'s; the
  operand stored by `fstp` (x87) or `movss` / `movsd` (SSE2) at 0, the
  address of a 4-byte stack slot at 4 / 8 / 12, the fraction stored from
  `st0` after the call (SSE2 too), the exponent copied from the slot.
- `llc` 19 and 22 fold `frexp` of a constant (no call; exponent 0 for an
  infinity and a NaN, as glibc). So the barrier holds unless the operand
  is a constant or a folded result; the tests fail if the barrier is
  always or never there.
- clang 19 and 22 write `llvm.frexp` for `__builtin_frexp*` (and not for
  a direct call of `frexpf` / `frexpl`).
- Evidence at landing: `i386_frexp` 36 `.ll` runs and 36 C runs equal
  `llc`'s (LLVM 19 and 22, CPU `generic` / `i686` / `pentium4`, static
  and PIE, plain and `Stress::ALL`); every `i386*` binary of `-p hod`
  passes (28 binaries, 108 tests); irdiff i686 132 PASS, 0 FAIL, 0 ERROR
  at LLVM 22 and 19; compare-binaries against 6984a71d: 14114
  comparisons, 0 different, 0 changed outcome.
