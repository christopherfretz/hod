# WP-208 — AVX-512

Design: `docs/design/0007-avx512.md`. Spec: `spec/codegen.md` §5.6.35,
`spec/mc-x64.md` "EVEX and the opmask instructions".

## Landed

1. **The EVEX encoder and the opmask instructions**
   (`crates/hod_mc_x64/src/evex.rs`): the prefix, compressed `disp8*N`,
   masking, broadcast, `{er}`/`{sae}`, the families the F/VL, BW and DQ
   names need, `kmov`/`k*` logic, tests and shifts. L1
   (`crates/hod_mc_x64/tests/l1/evex.rs`), against `llvm-mc` 19 and 22:
   group `evex` 30,424 encodings (1,397 rejections, 378 of them confirmed
   by `llvm-mc`), `evex-memory-operands` 17,770, `opmask` 2,328.
2. **The masked memory intrinsics** (`llvm.masked.load`, `.store`,
   `.expandload`, `.compressstore`; `crates/hod_x64/src/vector.rs`
   `masked`, reached from `x86::intrinsic`; four `hod_ir` `Intrinsic`
   members after the x86 ones, matrix rows at the end of
   `INTRINSIC_X86`, `todo(LATER)` / `on(MASKED)`), lane by lane on every
   x86-64 function, §5.6.35 (1).

## Census

The second real-project lane's saved modules (WP-200): 27 distinct
modules, 54 distinct masked memory names (18 shapes each of `load`,
`store`, `compressstore`, LLVM 22's signatures); every one of the 18
shapes is a row of the execution test's `SHAPES`, so every census name is
built and executed. Refused names left, by family, in the design's
section 5.1.

## Evidence

**The masked memory intrinsics, by execution** (`masked_memory_intrinsics_agree_with_llc`):
148 functions (each intrinsic on 21 shapes, from `<2 x float>` to
`<64 x i8>`, `<3 x i32>` and `half` lanes among them, with a variable
mask; and with the constant masks none, all, alternating and the top
lane on four shapes), 8 cases each (masks 0, all ones and random; random
memory and pass-through), 1,184 cases. Legs: hod plain (bfd and lld),
hod under every stress option, hod from LLVM 22's spelling of the
signatures, hod in functions with AVX2; `llc` 22 and 19 without features
(scalarized) and with AVX2 (`vmaskmov`), `llc` 22 on LLVM 22's spelling.
All print the same bytes under `qemu-x86_64 -cpu max`. The memory a
call may touch ends at an inaccessible page, so a lane whose bit is
clear and that touched memory would fault (the `llc` AVX2 legs run
without that page: QEMU faults on `vmaskmov` lanes the hardware
suppresses).

Mutations (each run once, then reverted): the lane test inverted (`jb`
for `jae`), and the packed forms addressing lane `i` instead of the
`k`-th set lane: both fault on the inaccessible page in the hod legs.

**Byte identity.** Every 10th entry of the x86-64 corpus
(`.build/corpus-x64`, `scripts/corpus-bytes.py -j 4`), base `b5545a9`
against this branch: 684 modules, 682 objects identical, 2 declines
identical, 0 differ.

**Execution evidence by name.** The four masked memory intrinsics:
executed (above). No `llvm.x86.avx512*` name is built yet.
