# WP-271: libc++ with `-g` at the release candidate cd6ef6bc on both targets

Landed: libc++'s whole test suite (`llvmorg-22.1.8`, `libcxx/test/std`
and `libcxx/test/libcxx`, 9,247 tests) built with `-g` by kiln, once with
`llc` (the control) and once with strict hod (no fallback) as kiln's back
end, natively on AArch64 and for x86-64 with every test binary run under
qemu. Both targets: strict equals the `-g` control. hod built every
module on both targets (7,226 of 7,226), refused nothing, fell back on
nothing and reported no outcome error. No script was changed and nothing
under `crates/` was touched; the runs used the candidate's scripts. The
results are on `docs/status/libcxx-hod-debug.md` and
`docs/status/libcxx-hod-debug-x64.md`, each in a new section "At the
candidate cd6ef6bc" at the top. This closes the release rows 4.6 and 4.7
(`docs/status/release.md`).

## Differences from the control, and what was rerun

- AArch64: `std/atomics/atomics.types.operations/atomics.types.operations.wait/lost_wakeup.pass.cpp`
  is PASS in the control (23.10 s) and TIMEOUT in strict (22.79 s) at the
  20 s limit. It was run alone at `HOD_JOBS=1`, twice per mode, 2026-11-15
  22:28 to 22:32 EST. At 20 s: TIMEOUT in all four (control 21.80 s,
  21.44 s; strict 21.42 s, 21.23 s). At 120 s (`HOD_TIMEOUT=120`): PASS in
  all four (control 25.35 s, 29.90 s; strict 24.97 s, 26.42 s). The test
  takes longer than the 20 s limit in both modes; the difference is not
  hod's.
- AArch64: `ifstream.members/buffered_reads.pass.cpp` is TIMEOUT in the
  control and PASS in strict. Not rerun (no test lost).
- x86-64: 0 changed outcomes (the report and the per-shard joins agree);
  nothing rerun.
- The same in both modes: `offset_range.pass.cpp` times out; the four
  filesystem tests fail (and on x86-64 also
  `fs.op.copy_file/copy_file_procfs.pass.cpp` and
  `syncstream/osyncstream/thread/several_threads.pass.cpp`); the XPASSes
  are `rel_ops.depr_in_cxx20.verify.cpp`, `variant.hash/hash.depr.verify.cpp`
  and, on x86-64, `std.manip/setfill_wchar_max.pass.cpp`.
- The two special modules of WP-210's AArch64 measurement pass in both
  modes: `map/PR28469_undefined_behavior_segfault.sh.cpp` (then refused,
  `debug:dbg-value-expr`) and `func.not_fn/not_fn.nttp.pass.cpp` (then
  kiln's invalid `-g` module, FAIL in the control). No kiln `-g` front-end
  refusal remains.

## Commands

From a hod checkout at `cd6ef6bc` inside the workspace, with the shim
`$S`:

```
export HOD_JOBSERVER_FIFO=<a path that does not exist>
# AArch64 ($D the run directory)
env -u HOD_DEBUG_FLAGS HOD_JOBS=3 scripts/libcxx-hod-debug.sh control $D
env -u HOD_DEBUG_FLAGS HOD_JOBS=3 HOD_SHIM=$S scripts/libcxx-hod-debug.sh strict $D
python3 -I scripts/libcxx-hod-report.py $D/strict $D/strict.tsv $D/control.tsv
# x86-64 ($X the run directory), for K in 1..20, the two modes as two streams side by side
env -u HOD_DEBUG_FLAGS HOD_DEBUG_TARGET=x86_64 HOD_JOBS=4 scripts/libcxx-hod-debug.sh control $X --shard K/20
env -u HOD_DEBUG_FLAGS HOD_DEBUG_TARGET=x86_64 HOD_JOBS=4 HOD_SHIM=$S scripts/libcxx-hod-debug.sh strict $X --shard K/20
scripts/libcxx-hod-debug.sh merge $X control; scripts/libcxx-hod-debug.sh merge $X strict
python3 -I scripts/libcxx-hod-report.py $X/strict $X/strict.tsv $X/control.tsv
# one test alone, twice per mode: its path instead of the selection, HOD_JOBS=1 (and HOD_TIMEOUT=120)
```

## Roots

In the workspace's build directory, `libcxx-5/native-g` and
`libcxx-5/x64-g`: the result files `{control,strict}.tsv` (x86-64 merged,
9,247 rows each, and per shard `{control,strict}-K-of-20.tsv`), the logs,
`report-strict.txt`, the strict coverage logs (`strict/`, on x86-64 merged
from `strict-K-of-20/`), and on AArch64 the reruns of `lost_wakeup`
(`rerun-lost_wakeup*`). The per-test build trees were removed by kiln's
`xtask libcxx` itself.

## Not done

- Hybrid was not run: strict refused nothing, so hybrid adds nothing.
- The debug information quality (`cargo xtask debug trees`) was not
  sampled again at the candidate.
- Only `-O0 -g` as the suite builds it (tests that set their own `-O2`
  included as they come).
- No timing comparison: the runs shared a loaded host and ran in
  parallel.
- The x86-64 tests ran under qemu-user on an AArch64 host, not on x86-64
  hardware.
