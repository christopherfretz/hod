# WP-160 — random programs across compilers, with debug information, in profiles (L10)

Landed: `cargo xtask fuzz --mix`, `--debug`, `--census` and `--profile`
(`xtask/src/fuzz.rs`; `xtask/src/fuzz/split.rs`, `profile.rs`, `abi.rs`,
and `case.rs`, `reduce.rs` extended), their end-to-end tests
(`xtask/tests/fuzz_real.rs`, the planted bug `xtask/tests/fuzz/swap-params.awk`),
layer L10 in `docs/VALIDATION.md` and the numbers of the long runs in
`docs/status/fuzz.md`. The command's contract, WP-154's with these
extensions, is `spec/harness.md` "Random programs"; this file records
what was decided and why.

## Decisions

- **The split is `llvm-extract`'s**, not a text splitter of hod's:
  `--func`/`--glob` for half A and the same list with `--delete` for B.
  `llvm-extract` makes every local definition it keeps an external
  hidden one and every use of the other half an external hidden
  declaration, so internal symbols link across the halves. That is
  sound because a module's names are unique (the renamed symbols
  cannot clash with anything the program links), hidden keeps them out
  of the dynamic symbol table, and nothing in a module at `-O0`
  depends on a symbol's linkage beyond its visibility. It is checked,
  not assumed: every seed links `llc`'s two halves and compares that
  program with the all-`llc` oracle first, and a disagreement is an
  `error` (the harness's side), never a finding.
- **The choice is a hash of the name and the seed** (FNV-1a mixed by
  splitmix64, its low bit), not a stream of random draws: a symbol
  stays on its side as the reducer removes others, so a reduced module
  keeps the split that showed the finding.
- **Both assignments run** (hod A with `llc` B, `llc` A with hod B): a
  disagreement that only one shows names the half hod got wrong.
- **Debug mode reuses `debug::lines::compare`** with the IR's facts, as
  `cargo xtask debug` does, and counts the columns without judging
  them. Two differences of what the compilers fold have no class in
  `debug::permitted` yet: `llc -O0` deletes a store of what was loaded
  from the same address (csmith's `x = x;`, `x ^= 0;`, `a[i] = a[i];`, a
  store of `poison`), leaving hod alone with a row at the line, and hod
  folds a branch on a constant to the next block, leaving `llc` alone.
  The fuzzer takes such pairs apart (`case::self_assignment`,
  `case::constant_branch`) and counts them; the ignored tests
  `self_assignments_are_a_permitted_class` and
  `constant_branches_are_a_permitted_class` pass once the classes exist
  there.
- **The ABI generator is hod's own**: the census of csmith's profiles
  showed no `x86_fp80`/`fp128`, no vectors, no variadic definitions, no
  `__int128` outside bit-fields, and few `byval` arguments. Its programs
  are defined by construction (see the spec), so a disagreement is a
  compiler's.
- **The planted bug** that only `--mix` sees swaps the first two
  parameters of every `callee_*` in definitions, declarations and calls
  of the module hod is given: a module built whole agrees with itself;
  an object of `llc`'s calling it does not.

## Not covered

- Debugger sessions on random programs (`cargo xtask debug` does those
  on its corpus).
- Reducing `debug-lines` findings well: the reducer keeps a line pair
  only by keeping most of the function around it.
- YARPGen; csmith's C++ mode.
