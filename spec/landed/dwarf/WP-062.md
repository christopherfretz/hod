# WP-062 — split DWARF

The contract of what landed is `spec/dwarf.md` §6.14, `spec/cli.md` "The
back half" (the options and the `.dwo` file), `spec/object.md` "`Object`"
(the companion) and `spec/harness.md` "debug" (the L7 test's `.dwo`).
This file records what the work package did, what it measured, and what
it left.

## What landed

**a. The unit's split fields.** `hod_ir`'s `DiCompileUnit` maps
`splitDebugFilename`, `dwoId` and `splitDebugInlining` (LLVM's default
`true`, printed explicitly); `hod_ll` and `hod_bc` read them
(`crates/hod_bc/tests/split_fields.rs`: text and `llvm-as` 19/22 bitcode
agree, the printed module reads back the same). The field table of
`spec/landed/ir/WP-005.md` is regenerated; the survey no longer lists
`debug:DICompileUnit.splitDebugFilename`. The CLI already parsed both
`llc` options; the facade now maps them (`cg_options`): neither is
`Off`, the file alone `Single`, both `Separate`, the output alone stays
`option:split-dwarf-output`.

**b. The writer.** `crates/hod_dwarf/src/split.rs` (new): skeleton and
split unit as `llc` writes them, the `.dwo` sections in the object or in
a companion `hod_obj::Object` (`crates/hod_obj/src/dwo.rs`, new), which
`crates/hod/src/back.rs` (`write_dwo`) writes to the output path. The
children are written by the full writer (`Writer::die`); a block's range
list becomes `DW_FORM_rnglistx` by rewriting four bytes and the `.dwo`
abbreviation table, so no function-DIE code changed. Abbreviation
families 90 to 94 are appended at the end of `abbrev.rs`.

Hooks, one call each:
- `crates/hod_dwarf/src/die.rs` (`UnitPlan::build`): `split::check_unit`;
- `crates/hod_cg/src/emit/lines.rs` (`DebugLines::finish`):
  `write_unit_dies(.., self.split)` in place of `write_debug_info`;
- `crates/hod_cg/src/emit/mod.rs` (`debug_tables`): `debug.split =
  self.options.split_dwarf`;
- `crates/hod/src/back.rs` (`generate_with`): `check_split_dwarf`, then
  `write_dwo`.

**The DWO id** is not `llc`'s (an MD5 of the DIEs that includes frame
offsets hod lays out differently); `hod_dwarf::dwo_id` hashes the `.dwo`
name and the split unit's sections once and writes the value into both
headers, so they agree by construction; every comparison below checks
it, and gdb, lldb and `llvm-dwp` accept the pairs.

**c. Refusals** (stable names, §6.14): `debug:DICompileUnit.dwoId`,
`debug:split-several-units`, `debug:split-dwarf-inlining`,
`debug:split-reduced-unit` (behind `debug:line-tables-inlined` today),
`debug:split-dwarf-name`, `debug:split-dwarf-4` (behind
`debug:dwarf-version` today). Tested in
`crates/hod_a64/tests/dies_split.rs` (`what_split_dwarf_refuses`),
`crates/hod/tests/split_dwarf.rs` and `back.rs`'s unit test.

## Evidence

- **Trees** (`dies_split.rs`, `split_units_are_llcs`): `vars.c`,
  `members.cpp`, `templates.cpp`, `inline.cpp` by clang 19 (`llc` 19 and
  22), clang 22 and kiln++ (`llc` 22): 16 comparisons, 1713 split DIEs.
  Skeleton and split unit equal to `llc`'s in both forms (separate and
  single) after §6.14's masks; every object, `.dwo` and pair `--verify`
  clean; the two DWO ids equal and non-zero. `hand.ll` (a block with two
  ranges: a `.debug_rnglists.dwo` list by `rnglistx`) against `llc` 19
  and 22; a `-gline-tables-only` unit (no split unit, DWO id 0) against
  `llc` 19 and 22.
- **Debuggers** (`dies_split_debugger.rs`): `tests/debug/split.cpp`
  (breakpoint in a member function, backtrace, parameter, local, class
  member, global, static member) by clang++ 19, clang++ 22 and kiln++,
  linked by GNU ld, lld and mold, gdb and lldb: 30 session pairs, hod's
  equal to `llc`'s and every check present; through an `llvm-dwp`
  package with the `.dwo` moved away (3 front ends); and with neither,
  the checks are lost on both sides (the DIEs really come from the
  `.dwo`).
- **L7** (`cargo xtask debug tests/debug/split.cpp`, `tier: quick`):
  12 PASS (clang 19 and 22 × bfd, lld, mold × gdb, lldb-19); the lines
  comparison 28 same, 0 different.
- **Sizes** (sum over the 16 comparisons, hod / `llc`): objects 128,280
  / 122,384 bytes (+4.8%), `.dwo` 47,104 / 45,000 bytes (+4.7%): the
  two-byte abbreviation codes (§11 question 7) and `strx`/`udata`
  forms, as in a full unit. kiln++'s objects differ by more (+16%). For
  `vars` by kiln++: `.text` 1,420 / 1,136, `.eh_frame` 392 / 264,
  `.debug_line` 761 / 646 bytes (code generation, not this package) and
  `.debug_addr` 136 / 24 bytes with its relocations 384 / 48: `llc`
  names each function's code by a range list of offsets from one base
  address (§6.14's first permitted difference), hod by one address per
  function. The `.dwo` files differ by the same +4%.
- **Throughput** (`dies_split.rs`, `split_die_cost`, ignored, release):
  n = 20,000 DIEs 198 ns per DIE full, 211 split; n = 40,000 218 full,
  193 split: the split path costs what the full one does, within noise.
- **Mutations**, each caught and reverted: the skeleton's DWO id `^ 1`
  (`split_units_are_llcs` and `a_line_table_unit_has_no_split_unit`
  fail); a `.debug_str_offsets.dwo` entry `+ 1` (`--verify` fails in
  `split_units_are_llcs` and `a_block_list_goes_to_the_dwo`); `Single`
  and `Separate` swapped in `cg_options` (all four
  `crates/hod/tests/split_dwarf.rs` tests fail).

## Left

  refusals above.
- `DW_AT_GNU_pubnames`/`.debug_gnu_pubnames` (§1.1, no name index).

- The L7 test runs clang front ends only: kiln++ records the absolute

  (`dies_split_debugger.rs` covers kiln++ with a relative name).
