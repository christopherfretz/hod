# WP-259 — `debug kiln` expands kiln's `args:` placeholders

Landed: `cargo xtask debug kiln` expands the placeholders of kiln's test
runner in a test's `args:` before it calls `kiln++` (`spec/harness.md`
"debug", "kiln"). Harness only: nothing under `crates/` changed.

## Why

kiln's `tests/debuginfo/class_decl_two_units.cpp` passes
`-I%{test_dir}/Inputs %{test_dir}/Inputs/class_decl_defs.cpp`. The
harness handed both words to `kiln++` as they were, so `kiln++` stopped
with "no such file or directory: '%{test_dir}/Inputs/class_decl_defs.cpp'"
with both writers: 2 of kiln's 17 debugger sessions (gdb and lldb-19)
measured nothing, and `docs/RELEASE.md` 3.3 (kiln's debugger tests all
pass) was not shown.

## What

kiln's runner (`kiln/xtask/src/test/runner.rs`, `placeholder`) knows
`test_dir` (the test's directory), `repo_root`, `resource_dir`,
`gcc_toolchain` and `libcxx_modules`. `debug kiln` runs `kiln++` from
kiln's root with the test's relative path, so it expands, relative to
that root, as `corpus capture` already does for kiln's tests:
`%{test_dir}` to the test's directory (`tests/debuginfo`), `%{repo_root}`
to `.`, `%{resource_dir}` to `resource`. The two toolchain placeholders
have no value here: a test using one fails its compile with both writers
and the message names the placeholder. Of kiln's debugger tests only
`class_decl_two_units.cpp` uses a placeholder (`%{test_dir}`).

`xtask/src/debug/kiln.rs` `arguments` calls `corpus::kiln::substitute`
(made `pub(crate)`), so the corpus capture and the debugger layer read
kiln's placeholders the same way.
Test: `debug::kiln::tests::expands_kiln_placeholders` (each placeholder,
the attached `-I%{test_dir}` form, a test at the root, a toolchain
placeholder refused by name).
