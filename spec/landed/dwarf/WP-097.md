# WP-097 — line-table columns and the M3 line-table findings

The contract of what landed is `spec/dwarf.md` §5.7 (the permitted
classes) and §5.8 (code emitted out of order), and `spec/harness.md`
"debug" ("Lines", "Columns", "Permitted differences of sessions"). This
file records what the package did, what it measured and what it left.
Its scope was extended with WP-099's line-table findings
(`docs/status/debug.md` "Line tables").

## What landed

- `crates/hod_cg/src/line_rows.rs` (new): rows are recorded per
  *segment*. The driver opens one per instruction with its row location;
  `FnCx::force` (`policy.rs`) switches to the deferred instruction's row
  location for its code and back. `unreachable` and a zero-offset
  `ptradd` have no row location of their own. Nothing changes code.
- `xtask/src/debug/lines.rs`: rows with columns, `compare_function_rows`
  and `ColumnsReport` (functions with the same `(line, column)` set, the
  same set up to P1/P3, the same sequence; positions on one side only).
  The pair classes `load-placement` and `is-constant`, read from the IR.
- `xtask/src/debug/permitted.rs` (new): `IrFacts` (per function, each
  located instruction's opcode, line, column; calls of
  `llvm.is.constant`), `pair_class`, and `only_return_columns`, the
  `return-column` rule for lldb sessions after `finish`.
- `xtask/src/debug/columns.rs` (new): `cargo xtask debug columns`, the
  comparison over a set of `-g` modules, `--dump` for hod's disassembly.
- `scripts/debug-measure.py`: classifies pairs by the same IR rule; two
  new columns.
- Tests: `crates/hod_a64/tests/line_segments.rs` (new: forced code,
  `unreachable`, zero-offset address); `xtask/tests/debug_m3.rs` (the
  seven WP-099 reductions are tests again: four agree with `llc`, three
  are classified as `is-constant` or `load-placement`);
  `tests/debug/gep_column.c` and `finish_column.c` lose their `xfail`.

## Decisions on WP-099's classes

| class | decision |
|---|---|
| `unreachable` | no row of its own; a line-0 row when it is the first code of its block (§5.8) |
| `compare-at-user` | a compare asked for by its user is at its own location (segments) |
| `gep-placement`, hod only | a zero-offset `getelementptr` has no row of its own; not an alias (§5.8 says why) |
| `gep-placement`, llc only | permitted direction; none left after the segments |
| `load-placement` | permitted (§5.7), by IR rule |
| `is-constant` | permitted (§5.7), by IR rule; not free (`mark_reachable` runs before the target folds) |
| `return-column` (sessions) | permitted (§5.7), by IR rule: `llc`'s column is a call's |

Columns (`cargo xtask debug columns`), 70 632 functions:

The corpus (14 `-g` modules, 10 compared): 32 of 38 functions with the
same set, before and after. `tests/debug`: 104 functions, same set 76
before, 81 after.

Code: `llvm-objdump -d -r` of hod's object for all 190 modules is
identical before and after (`debug columns --dump`, `diff -r`).

Sessions (`cargo xtask debug run`, every test, front end, linker and
debugger): before 180 PASS, 6 FAIL (`gep_column.c` under lldb), 19
XFAIL; after 186 PASS, 19 XFAIL. Nothing went from PASS to FAIL; 6 lldb
sessions of `finish_column.c` pass as `permitted: return-column`.

Mutations, each caught and reverted: the switch in `force` removed
(`line_segments::forced_code_has_its_own_row`); `unreachable` keeping
its location (`line_segments::unreachable_has_no_row`); the
`return-column` rule not checking for a call's column
(`permitted::tests::return_columns`).

## Left

- 4 hod-only pairs, one function in 4 modules
  (`std::_Sp_counted_base::_M_release_last_use`, `shared_ptr_base.h:187`):
  hod computes `&this->_M_weak_count` (a `getelementptr` with offset 12)
  on its own line, `llc` combines the add with the earlier load of the
  same base into a post-indexed `ldr` (an optimisation). Not classified:
  the IR's instructions at that line also include a `catch`, a `call`
  and an `unreachable` of the landing pad, so no rule by line fits
  without a file and scope check.
- Columns inside a line both tables have: 8 027 hod-only and 176
  llc-only positions, from `llc`'s instruction-selection folds (§5.7's
  note). Measured, not judged.
- `scripts/debug-pairs-ir.py` still prints WP-099's causes; it reads
  only pairs `debug-measure.py` left unclassified.
