# WP-157 — the line of a fused compare on x86-64

The contract is `spec/dwarf.md` §6.17 "Fused compares" (with the
pointer from §5.8). This file records what the package found and did.

## What `llc` does (19 and 22 agree on every form)

`llc -O0 -fast-isel=0 -mtriple=x86_64-unknown-linux-gnu
-relocation-model=pic`, hand-written IR with one line per instruction:

| construct | `llc`: compare's line | `llc`: consumer's line | hod before | hod after |
|---|---|---|---|---|
| `icmp` + `br` | `sub`/`cmp` (and operand moves) | `jcc`, `jmp` | compare's line (WP-149) | same |
| `fcmp` (`double`, `float`) + `br` | `ucomisd`/`ucomiss` | `jcc` (two for `une`, `oeq`, `ueq`) | branch's line | compare's line |
| `x86_fp80` `fcmp` + `br` | `fucompi`, `fstp` | `jcc` | branch's line | compare's line |
| `icmp` + `select` (`Gpr`) | `sub`/`test`, operand moves | `cmovcc` | select's line | compare's line |
| `icmp` + `zext`/`sext` | `sub`, `setcc` | `movzx` (`neg`) | zext's line | `cmp` at the compare's line, `setcc` at the zext's |
| `x86_fp80` `fcmp` + `x86_fp80` `select` | `fucompi`, `fstp`, `lea`s | `cmov` (22) / `fcmove` (19) | select's line | compare's line |
| `fcmp` + `select` of `Fpr` | none | `minsd`, or `cmpltsd` + mask | select's line | unchanged (as `llc`) |
| a compare with other users | not fused: its own line on both | | | |
| a compare in another block | not fused on either side | | | |
| `switch` | no compare instruction in the IR: everything at the `switch`'s line on both | | | |

## What changed

`crates/hod_x64/src/control.rs` `at_compare` runs a fused compare's
emission at its row location (`FnCx::line_switch`) and switches back;
WP-149's `cond_br` on an `icmp` uses it, and so do `float::cond_br`,
`x87::cond_br`, `x87::select`, `int::select` and `int`'s `zext`/`sext`
(one call each). No byte of code changes; the rows are ordinary
transitions, moved by the shrink pass.

`tests/debug/tls_static.c`: the check of `ticks` is `$2 =` (the harness
has no per-target check), with a comment: AArch64's `llc` prints
`<optimized out>`, x86-64's the value; hod's transcript is compared with
`llc`'s on each target.

## Evidence

- `crates/hod_x64/tests/fused_lines.rs`: a chain of the fused forms whose
  `jcc`s are relaxed to `rel8`; every row starts an instruction, each
  compare's row holds the compare and no consumer, each consumer's row
  its `jcc`/`cmov`/`movzx`; the same holds on `llc` 19's and 22's
  objects, and hod's set of lines is `llc`'s plus the start row (P3).
  Mutations caught: `at_compare` not switching ("no compare at line 11");
  `float::cond_br` wrapping the branches too ("the consumer of line 14
  is at the compare's line 13").
- `xtask/tests/debug_post_index.rs` `fused_compare_keeps_its_line_on_x86_64`:
  not ignored, passes (WP-149's change already made it pass).
- `cargo xtask debug --target x86_64` (520 results, 492 PASS, 6 XFAIL,
  22 SKIP before and after): `lines: same 1322, hod only 0, llc only 4
  (P1 4)` before and after; columns: same (line, column) set 225 → 232
  of 328 functions, positions only `llc` has 100 → 93 (unclassified
  10 → 3). `cargo xtask debug` (AArch64): identical summaries before and
  after (540 results, 528 PASS, 12 XFAIL; lines same 1360, llc only 4 P1).
- Objects: AArch64 byte-identical over the `tests/debug` sources (clang 19
  and 22) and the corpus's `-g` modules; x86-64 `-g` objects differ in
  `.debug_line` (and its relocations) only, in 8 of 86 compiled; x86-64
  objects without debug information byte-identical over the `tests/ir`
  seeds and the x86-64 corpus.

## Left

- `used` shape: `llc` folds a `zext` of a compare into the store that
  follows (`setl (%rdx)`), so the `zext`'s line has no row in its table;
  hod keeps the row. A store fold, not a fused compare; not seen as an
  unclassified pair in `cargo xtask debug`.
