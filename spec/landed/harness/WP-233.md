# WP-233: libc++ re-measured without `-g` on both targets

Landed: libc++'s whole test suite (`llvmorg-22.1.8`, 9,247 tests) was
measured again with hod as kiln's back end and without `-g`, natively on
AArch64 and for x86-64 under qemu. Each time a control (kiln + `llc`) ran
beside strict hod (no fallback) on the same host with the same kiln. In
both targets strict equals the control: the one changed outcome per target
is a timeout under load in the control that passes alone in both modes.
hod built every module on both targets (7,226 of 7,226) and refused
nothing. `scripts/libcxx-hod-debug.sh` (WP-210) gained one option for
this: `HOD_DEBUG_FLAGS` set and empty adds no flag, so the chain runs
without `-g`. Strict was measured again at the 1.0 release candidate
(`02fe2d02`) on both targets, against controls recorded on kiln 1.2.0,
with the same result. The results are on `docs/status/libcxx-hod.md` and
`docs/status/libcxx-hod-x64.md`, each in a new dated section at the top.

## Differences from the control, and what was rerun

- AArch64: `std/input.output/file.streams/fstreams/ifstream.members/buffered_reads.pass.cpp`
  is TIMEOUT in the control and PASS in strict. It was run alone at `-j 1`,
  twice in each mode, and timed out in all four runs at 20 s (26 to 30 s).
  With `HOD_TIMEOUT=120` it passed in both modes (28.0 s with `llc`,
  37.5 s with hod). `lost_wakeup.pass.cpp` (a timeout in both modes) passes
  alone at 120 s in both. `offset_range.pass.cpp` (a timeout in both modes)
  times out alone at 120 s in both.
- x86-64: `std/containers/unord/unord.multimap/local_iterators.pass.cpp`
  is a compile TIMEOUT in the control and PASS in strict. It was run alone
  at `-j 1`, twice in each mode, and passed in all four runs (3.1 to 3.6 s).
- The tests that fail with `llc` too (the four filesystem tests on both
  targets, and `fs.op.copy_file/copy_file_procfs.pass.cpp` under qemu) and
  the XPASSes (`rel_ops.depr_in_cxx20.verify.cpp`,
  `variant.hash/hash.depr.verify.cpp`, and on x86-64
  `std.manip/setfill_wchar_max.pass.cpp`) are the same in both modes.

## Commands

From a hod checkout inside the workspace, with the frozen hod `$H` and
`cargo xtask shim --llvm /usr/lib/llvm-22 --hod $H --out $S --kiln
<workspace>/.build/target-kiln/release/kiln++`:

```
export HOD_DEBUG_FLAGS= HOD_JOBS=4 HOD_JOBSERVER_FIFO=<a path that does not exist>
# AArch64
scripts/libcxx-hod-debug.sh control $D
HOD_SHIM=$S scripts/libcxx-hod-debug.sh strict $D
python3 -I scripts/libcxx-hod-report.py $D/strict $D/strict.tsv $D/control.tsv
# x86-64 census (compile and link only)
HOD_DEBUG_TARGET=x86_64 HOD_X64_QEMU=/bin/true HOD_SHIM=$S scripts/libcxx-hod-debug.sh hybrid $C
python3 -I scripts/libcxx-hod-report.py $C/hybrid $C/hybrid.tsv $C/hybrid.tsv
# x86-64 under qemu, for K in 1..20, control then strict
HOD_DEBUG_TARGET=x86_64 scripts/libcxx-hod-debug.sh control $X --shard K/20
HOD_DEBUG_TARGET=x86_64 HOD_SHIM=$S scripts/libcxx-hod-debug.sh strict $X --shard K/20
scripts/libcxx-hod-debug.sh merge $X control; scripts/libcxx-hod-debug.sh merge $X strict
python3 -I scripts/libcxx-hod-report.py $X/strict $X/strict.tsv $X/control.tsv
# one test alone: its path instead of the selection, HOD_JOBS=1 (and HOD_TIMEOUT=120)
```

The per-test comparison is the join of the two result files:
`join -t$'\t' <(awk -F'\t' 'NR>1{print $2"\t"$1}' control.tsv|sort) <(awk -F'\t' 'NR>1{print $2"\t"$1}' strict.tsv|sort) | awk -F'\t' '$2!=$3'`.
