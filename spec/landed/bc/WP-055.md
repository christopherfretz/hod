# WP-055 — hod_bc: debug information

Landed: `spec/bc.md` §6 (the debug records of the METADATA blocks into
`hod_ir`'s tables, as `hod_ll` reads them from text: `spec/ll.md` §7.4),
§11.6 (`DEBUG_LOC`, `DEBUG_LOC_AGAIN`, debug records 61–66 and the old
`llvm.dbg.*` calls), and the `debug-layout` refusal of §3.4. The
module-level `debug-info` note is gone. `classify` still refuses
`debug:*`.

## What it did

| where | contents |
|---|---|
| `crates/hod_bc/src/debug.rs` (new) | one layout table per record kind (LLVM 19 to 22); two passes (reserve, define) over the module's block and each function's; tuples a field names as one node defined when first named; expressions (version 3), locations, enumerators of any width; `debug-layout` for a length or version LLVM 19 to 22 do not write; the per-function prescan of the METADATA block and the `!dbg` attachment |
| `crates/hod_bc/src/body_debug.rs` (new) | `DEBUG_LOC` (LLVM 22's atom group and rank dropped), `DEBUG_LOC_AGAIN`, records 61–65, record 66 refused as `debug:#dbg_declare_value`, the `llvm.dbg.*` calls, each through `FunctionBuilder` as `hod_ll` does |
| `crates/hod_bc/src/body.rs`, `inst.rs`, `module.rs`, `raw.rs`, `codes.rs` | the dispatch; `llvm.dbg.cu`; a function's `!dbg` as its subprogram; a variable's global-variable expressions; `Body::verify_debug` after each body |
| `crates/hod_bc/tests/common/mod.rs` | the debug dump (`debug_dump`, `loc_text`, `expr_text`) in the body dump; `reassembles` |
| `crates/hod_bc/tests/debug.rs` (new), `src/debug.rs` tests, `tests/robustness.rs` | §6.7, §9.4 |

Outside the listed files: `crates/hod_ir/src/builder.rs`
(`FunctionBuilder::place_records_before`, additive: bitcode writes a
record after the instruction it stands before).

## Evidence

- clang 19 and 22, `-O0` and `-O2`, on `debug_c.c`, `debug_types.cpp`
  and `stl.cpp`, clang 22 `-gkey-instructions` and `-gdwarf-6`, and
  kiln's `kiln_types.ll`: alike. `stl.cpp` 22 `-O2`: 22,529 nodes,
  19,473 located instructions, 22,136 records.
- The 14 corpus modules with `!llvm.dbg.cu`: 12 alike, 2 with no
  oracle (`llvm-dis` writes an undefined `%struct.U`, `spec/bc.md` §10).
- Whole corpus (`differential`, `bodies`, release, 4 workers): LLVM 19
  2,963 alike of 3,107, LLVM 22 2,996 of 3,143, none differ; the rest
  are tool failures.
- Robustness over `tests/data/debug-llvm22.bc`: truncations,
  corruptions and random tails return.

Cost (`examples/bcread`, release, best of 20, peak by `/usr/bin/time`),
clang 22 `stl.cpp` for aarch64:

| input | mode | before | after |
|---|---|---|---|
| no `-g`, 642 KiB | `bc` | 2.59 ms, 4.8–5.2 MB | 2.57 ms, 5.0–5.4 MB |
| no `-g` | `bc-bodies` | 9.70 ms, 5.1 MB | 9.35 ms, 5.1 MB |
| `-g`, 2.31 MiB (text 9.68 MiB) | `bc` | 4.46 ms, 8.2 MB | 17.0 ms, 14.9 MB |
| `-g` | `bc-bodies` | 13.3 ms, 8.4 MB | 28.4 ms, 14.8 MB |

Peaks without `-g` are the spread of five runs each: the same.
With `-g`, module and bodies: 81 MiB/s of bitcode, 341 MiB/s of the
equivalent text (`hod_ll`: 51.3 ms, 189 MiB/s); peak 6.4 MiB above the
module without debug information.

## Open

- The old `llvm.dbg.*` calls have no tool to make them (§6.6).
- Function-local debug metadata with no module-level debug record is
  noted `debug:invalid` where `hod_ll` reads it (§6.6).
- `scan_function` decodes each function block's records a second time.
