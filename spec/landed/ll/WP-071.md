# WP-071 — hod_ll: a numbered block refused after the dense table grew over it

Landed: `spec/ll.md` §11.2 (the numbering rule written as LLVM's, the
one-table invariant of the number tables) and its tests (§11.11).

## The bug

The bench input `huge-function` (clang 22, `-O0`) was refused at its
line 55568, `br label %42022`, "use of undefined value", though block
`42022` is defined eleven lines above. The body reader keeps a
function's numbers in a dense table that may grow up to 4096 past its
length, and a map beyond. The first forward branch of the function
starts the label scan (§11.3), which puts every label of the body in the
tables; the labels after a block of 15,000 values (`27007:` to
`42011:`) were more than 4096 past the dense table, so they went to the
map. At its definition a block the scan had found is not stored again.
The first value of the block, `%42023`, grew the dense table over
`42021` and `42022`, filling them with "not met"; a lookup reads the
dense table first, so the loop's back edge to `%42022` found nothing.
Forward uses still worked (the map was consulted beyond the dense
table), which is why only a backward reference after such a gap failed.
Not a narrowing, not the counter, not parallel reading.

The fix (`crates/hod_ll/src/body.rs`, `Fx::set`): growing the dense table
moves into it what the map held for the numbers it now covers, so a
number is in one table only, and in the map only beyond the dense table.

`hod_bc` has no such table (bitcode refers to blocks by index and to
values relatively): it reads `llvm-as` of `huge-function` to the same
78,028 instructions.

Also, to say what `llvm-as` says: a label out of order is `label
expected to be numbered 'N' or greater` (no `%`), and an argument out of
order is placed at the parameter's type.

## Reduced case

```llvm
define void @f(ptr %p) {
  br label %1                    ; the label scan: 4102 and 4104 go to the map
1:
  %2 = load volatile i8, ptr %p  ; ... through %4101
  br label %4102
4102:
  %4103 = load volatile i1, ptr %p   ; grows the dense table over 4102
  br i1 %4103, label %4102, label %4104
4104:
  ret void
}
```

## Tests

`crates/hod_ll/tests/numbering.rs`:

- `a_block_beyond_the_dense_table_is_found_after_the_table_grows_over_it`:
  the reduced case; `llvm-as` 19 and 22 accept it, the successors are
  the text's.
- `numbered_blocks_and_values_read_as_llvm_reads_them`: four seeds of
  five generated functions (3,000 blocks clang-shaped; numbers skipped,
  some by more than 4096; blocks of more than 4096 instructions; 30% and
  100% of blocks without labels), with forward and backward references
  by `br`, `switch`, `indirectbr` (of a `blockaddress`), `invoke` (to two
  landing pads, one before and one after), `phi` and stored
  `blockaddress`es. Oracles: `llvm-as` 19 and 22 accept each module;
  each block's successors in hod's body are those of `llvm-as |
  llvm-dis`'s text; hod's printing of the module, through `llvm-as |
  llvm-dis`, has the original's block references (targets, `phi`
  incomings, `blockaddress`es); hod's reading of its own printing prints
  the same text. Without the fix the reduced case and this test fail.
- `numbers_out_of_order_are_refused_as_llvm_as_refuses_them`: nine
  refusals (a value or label number twice or going back, a label below
  the unlabelled entry's number, a value with a block's number,
  arguments out of order or twice, an undefined number) at `llvm-as`
  19's and 22's line, column and words; skipped numbers accepted by
  all three.

## Evidence

- `huge-function` (3.39 MB, 78,028 instructions) reads: module and
  bodies 20.5 ms, 263 ns per instruction, 6.0 ns per byte; under the
  same load `tiny-functions` takes 7.2 and `interp` 6.2 ns per byte
  (`hod_bc`'s `bcread ll-bodies`, best of 10; WP-008's figure, bodies
  alone, was 4.7 to 5.4 ns per byte on a quieter host). `hod_bc` on its
  bitcode: 6.8 ms, 87 ns per instruction.
- Linear: the reduced shape repeated (a block of 5,000 values and a
  loop) reads at 311, 306 and 324 ns per instruction for 10,008, 100,062
  and 1,000,602 instructions.
- `hod --strict` on `huge-function` now declines by
  `attr:target-features` (function `helper`), and `huge-function-g` by
  `debug:module-flags`: constructs of other packages, no longer a read
  error. `ll_print 22` prints the whole module.
