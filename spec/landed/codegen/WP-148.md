# WP-148 — x86-64's `musttail` stack-argument rule in the facade

WP-115's follow-up (`spec/landed/codegen/WP-115.md`): the facade gave
x86-64's `classify` no `StackArgs` hook, so every x86-64 `musttail` call
whose areas it must size was `musttail:stack-args-unknown`.

## What it did

| where | change |
|---|---|
| `crates/hod_cg/src/abi.rs` | `TargetStackArgs::per_function(&target, of)`, `PerFunction<T> = fn(&Module, Symbol<'_>) -> Option<T>`: both sides are assigned with `of(module, f)`, `f` being the function that makes the call (`of_function`: the function itself; `of_call`: the function of `call.body()`). `of` answering `None` is no answer. `TargetStackArgs::new` (AArch64) is unchanged |
| `crates/hod_x64/src/call.rs` | `target_of(module, function)`: `X64::for_function`'s answer from the symbol alone (features of `"target-cpu"`/`"target-features"`, the coroutine mark); `None` for a symbol that is not a function |
| `crates/hod/src/session.rs` | `classifier_for` gives x86-64 `X64_STACK_ARGS = TargetStackArgs::per_function(&X64, call::target_of)` |
| `spec/abi-x64.md` §8.5 | "The stack-argument rule (WP-148)": five numbered sentences |

The rule (§8.5): the caller's area is `X64::assign`'s `stack_size` of
its own signature, the call's that of the call (variable arguments
typed by value), both with the caller's target; the call grows when the
second is larger, and when `assign` refuses either side the call stays
`musttail:stack-args-unknown`. As the verifier makes the two signatures
agree, only variable arguments before a forwarded `...` that go to the
stack can grow the area; those that fit reach the code generator, which
still refuses them as `x64:musttail-variable-arguments` (WP-115,
unchanged).

## Evidence

- `crates/hod/tests/musttail_x64.rs`
  `generated_thunks_follow_the_rule_and_run_like_llc`: 180 generated
  thunks (3 seeds), parameters of 14 classes (`i8 signext`,
  `i16 zeroext`, `i32`, `i64`, `ptr`, `i128`, `float`, `double`,
  `x86_fp80`, `fp128`, `<2 x double>`, `<4 x i32>`, `byval` structures
  aligned to 8 and 16; a quarter with an `sret` result), permuted among
  parameters of one type and some computed; two thirds variadic, whose
  callers forward `i64`, `double`, `long double`, `__int128`, a
  24-byte structure and `v2d` in registers and on the stack; a third of
  the thunks first call functions setting every argument register and
  `al = 0`. Each case compiled through the facade alone agrees with a
  SysV model in the test (§3.1, §3.2, §4.2, §6.2): 143 compile (79
  variadic, 114 with named stack arguments), 26 are
  `musttail:stack-args-grow`, 11 `x64:musttail-variable-arguments`.
  The 143 are one object by the facade, one by `hod_x64` with
  `Stress::ALL`, one by `llc` 22 and (53 of them) by `llc` 19, linked
  with `gcc`-built callers and callees under bfd, lld and mold, run
  under `qemu-x86_64` (36 runs). The C callee checks every parameter
  and every forwarded argument byte for byte against the caller's
  value; the caller checks frame canaries and a callee-saved value.
  Every parameter class ran 82 to 113 times.
- `the_calling_functions_features_decide`: five `<4 x double>`
  parameters (some on the stack) compile without AVX, also when the
  callee is declared `+avx`; one under `+avx` or `target-cpu=haswell`,
  and an `x86_fp80` under `-x87`, are `musttail:stack-args-unknown`.
- `the_model_by_hand`: an `i128` after five `i64`s goes to the stack
  and leaves `r9`, so one `i64` extra fits (`x64:musttail-variable-
  arguments`) and two grow.
- `crates/hod/tests/musttail_forward.rs`: x86-64 by text and by bitcode
  19 and 22: the forwarding thunk compiles, `i32 42` is
  `x64:musttail-variable-arguments`, eight `i64`s grow.
- Corpus: the 12 modules of `.build/corpus-x64` with a `musttail` (6
  per LLVM major: `ext.clang.musttail/musttail-deep-run`,
  `coro.generator/libstdcxx-generator-{int,elements-of}-run`,
  `class.virtual/variadic-thunk-run`,
  `expr.await/{symmetric_transfer,awaiter_protocol}`) were all
  `musttail:stack-args-unknown` (first refusal and census,
  `docs/status/reasons-x64.md` on main); all 12 compile now and pass
  `cargo xtask irdiff --target x86_64 --llvm 19|22` under bfd, lld and
  mold (36 PASS). `cargo xtask corpus reasons --target x86_64 -j 4`
  after: compiled 3358 (LLVM 22) and 3318 (LLVM 19), against 3351 and
  3311 in `docs/status/reasons-x64.md`; no `musttail:` reason is left
  in the first refusals or the census. (The seventh module per major is
  not this package's, as it has no `musttail`: the checked-in report
  predates the fourth wave's merge; its `debug:call-sites` and
  `debug:dwarf-version` are gone, and one module is now first
  `debug:dbg-value`.)
- Text: the 143 thunks are 56,353 bytes of hod's `.text` against
  17,323 of `llc` 22's (3.25).
- Mutations, each caught then reverted: the x86-64 rule built with
  `TargetStackArgs::new(&X64)` (the baseline features:
  `the_calling_functions_features_decide` gets `x64:wide-vector-abi`);
  `of_call` assigning the named parameters only (the model disagrees on
  case 0, `the_model_by_hand` too); `before_tail_exit` not reloading
  `al` (a variadic callee reads its forwarded `double`s wrong, the
  program fails).

## Where `llc` 19 differs

The `llc` 19 object leaves out the cases it builds otherwise than the
psABI (`llvm19_differs`):

- an `i128` that goes to the stack with one general register left, then
  a general parameter (`spec/abi-x64.md` §4.2 "LLVM 19");
- any `byval` parameter: `llc` 19 stages the copies of a `musttail`
  call's `byval` arguments at the thunk's own `rsp`
  (`movq %rsp, %r10; movaps %xmm2, (%r10)`), over its return address,
  and the program crashes. `llc` 22 builds the same thunks correctly.
  hod stages them in its frame (`spec/codegen.md` §7.1).

## Follow-ups

- `spec/codegen.md` §7.1 "The `musttail` hook" (about line 3538) still
  says the facade has to hand the hook over; it does for both targets
  now, and `TargetStackArgs::per_function` belongs there (outside this
  package's ownership).
- `crates/hod_x64/src/target.rs` `X64::for_function` could call
  `call::target_of` instead of repeating it.
