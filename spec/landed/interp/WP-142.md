# WP-142 — the reference interpreter's coverage for x86-64 modules

Landed:
- `spec/interp.md` §1, §5 (trap `zero-sign`), §5.6 (`llvm.minnum`,
  `llvm.maxnum`, `llvm.is.fpclass`, `llvm.ptrmask`, the `va_`
  intrinsics), §5.8 (variadic callees), §5.11 (the `x86_fp80`
  intrinsics), new §5.12 (variadic functions on x86-64), §8
  (`call:variadic` narrowed, `call:variadic-type`, `call:variadic-attr`,
  `intrinsic-x86_fp80` narrowed), §11, §12.

## What it did

| where | change |
|---|---|
| `hod_interp` `interp/varargs.rs` (new) | the x86-64 variadic model: the arguments of a call of a variadic body are assigned (G, V, O of `abi-x64.md` §3.1, restated for the subset in §5.12); the callee's frame gets a 176-byte register save area and the call's stack-argument area, the variable arguments are written into them (only the bytes the caller owes: `abi-x64.md` §3.2, §7); `va_start` writes the 24-byte `va_list`, `va_end` unwrites it, `va_copy` copies it |
| `hod_interp` `interp.rs` | `Frame::va`; variadic calls of host functions pass every argument (all targets); variadic bodies elsewhere than x86-64 stay `call:variadic`; `x86_fp80` `sqrt`, rounding family and `fma`; `minnum`/`maxnum` and `is.fpclass` on `float`, `double`, `x86_fp80`; `llvm.ptrmask` (clang aligns the overflow pointer with it) |
| `hod_interp` `x87.rs` | `sqrt` (digit-by-digit root with a sticky remainder), `round_integral` with `Rounding`, `fma` (exact sum in a 250-bit window, one rounding), `min_max`, `fp_class`, `is_signaling` |
| `hod_interp` `error.rs` | `Trap::ZeroSign` (`zero-sign`) |
| tests | `x86_64.rs` (`variadic_layout`, `va_end_and_va_copy`, `variadic_refusals`, `x87_intrinsics`), `x87_oracle.rs` (the intrinsics through glibc), `x64_varargs_oracle.rs` (new), `unsupported.rs` (two expectations moved) |

Decisions:
- **No dependency on `hod_x64::abi`.** It would make the oracle share the
  argument classification with the code generator it checks. The
  interpreter restates the subset it needs (§5.12) and refuses the rest by
  name: aggregates by value, odd vectors, integers wider than 64 bits
  other than `i128`, sub-byte integers without an extension attribute,
  pointers outside address space 0, aggregate or vector returns
  (`call:variadic-type`), `nest` and `byval` alignment over 16
  (`call:variadic-attr`). clang passes C structures as coerced scalars or
  `byval`, never as IR aggregates.
- **LLVM 19 vs 22**: `i128` on the stack leaves the general registers
  (LLVM 22, as `abi-x64.md` §4.2); the oracle runs `__int128` programs
  against LLVM 22 only.
- **AArch64 variadic bodies** stay `call:variadic` (a different
  `va_list`); not needed by the x86-64 code generator.
- **`byval` to host/extern callees**: kept refused (`attr:byval`). The
  sample has no such call that reaches the interpreter (no `attr:byval`
  in the census), and a host function would need C's layout promise.
- **minnum/maxnum**: zeros of opposite signs trap `zero-sign`; a
  signaling NaN operand traps `nan-result` (LLVM 19's and 22's LangRef
  and glibc's `fminl`/`fmaxl` do not agree on either).
- **`is.fpclass` of the x87-only encodings** is `intrinsic-x86_fp80`.
- **Invalid x87 encodings** in `sqrt` and the rounding family give a NaN
  (a trap under the default policy). glibc's `roundl` and `roundevenl`,
  which `llc` calls for `llvm.round.f80`/`llvm.roundeven.f80`, compute on
  the bits instead, so no single answer exists and the trap is right.

## Evidence

- `tests/x64_varargs_oracle.rs`, `variadic_calls_agree_with_llc`: 12 generated C
  programs of 6 variadic functions each (0 to 19 variable arguments of 14
  C types covering INTEGER, SSE, mixed, MEMORY and x87 classes, edge
  values, `va_copy` mid-walk, a `va_list` handed to another function,
  variadic calls from inside a variadic function), compiled by clang 19
  and 22; the interpreter's sink sequence equals that of `llc` 19/22 +
  `qemu-x86_64` (20 runs; the 4 `__int128` programs on LLVM 22 only).
- `x87_intrinsics_agree_with_llc`: 56 operands × (`sqrtl`, 7 roundings,
  `fmal`, `fmaxl`, `fminl`, 10 `__builtin_isfpclass` bits) as clang emits
  them, against `llc` 19 and 22: 1 792 sinks equal.
- `tests/x87_oracle.rs`: 115 055 operations against glibc on the x87
  under qemu, now including about 70 000 intrinsic cases (unnormals,
  pseudo-NaNs and pseudo-infinities for `sqrt`, `floor`, `ceil`, `trunc`,
  `rint`, `nearbyint`; cancelling `fma`s).
- Mutations, each caught: `fp_offset` one register late; `x86_fp80`
  slot aligned to 8; named stack arguments ignored; `i128` split between
  `r9` and the stack (by `x64_varargs_oracle`); `sqrt` without its sticky bit (86
  differences); `round` ties to even; `fma` cancellation without the
  sticky correction (2 differences) (by `x87_oracle`, the last also by
  `x64_varargs_oracle` for `round`).
- `cargo xtask x64census --shipped --interp -j 4` over the WP-138 sample
  (375 modules): interpreter against `llc -O0` + qemu **150 agree, 0
  differ** (was 140, 0). `unsupported:call:variadic` (147) is gone. The
  remaining reasons: `extern:printf` 129, `extern:__cxa_allocate_exception`
  26, `trap:uninitialized-load` 10 (unchanged, §12), `call:inline-asm` 8,
  `extern:sprintf` 5, `type:bfloat` 4, `type:fp128` 4, `extern:_Znwm` 3,
  `extern:malloc` 3, `extern:strcpy` 3, then 2 or 1 each (`memcmp`,
  `stdout`, `strchr`, `strlen`, `global:alias`, `atomicrmw-fmin`,
  `threadlocal.address`, `type:half`, ...).

## Follow-ups

- The census registers only `abort` and `exit`: 136 modules now stop at
  `extern:printf`/`sprintf`/`stdout`. A `printf` host in the census (its
  return value is the number of characters, so it needs the formatting)
  would let them run; xtask is outside this package.
- `llvm.fmuladd` (sample: 6 modules) needs a "fused and unfused agree"
  rule.
- `byval` to host functions when a host needs aggregates.
