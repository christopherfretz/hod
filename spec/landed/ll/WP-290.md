# WP-290 — debug metadata reading, cheaper (`hod_ll`, `hod_ir`)

Landed: item 1 of WP-288's ranked list (`spec/landed/harness/WP-288.md`
§6), the reading of `!DI…` nodes into the debug store. Five commits on
`crates/hod_ll/src/debug.rs` and `crates/hod_ir/src/debug/` (`node.rs`,
`mod.rs`, `unique.rs`), each with its counts in its message, and
`spec/ir.md` §6 (fields by position). No change to emitted bytes,
refusals, error messages or error positions (below). No edit outside the
debug reader, the debug store and the spec. Safe Rust
(`#![forbid(unsafe_code)]` stays), no new dependency.

## Method

As WP-168: Callgrind instruction counts, `HOD_THREADS=1`, the release
profile, attributed by each instruction's own function
(`callgrind_annotate --inclusive=no`); `hod --strict -O0 -filetype=obj
-relocation-model=pic -mtriple=T -o out.o in.ll` on the bench inputs
(`cargo xtask bench --generate`, clang 22). The host is AArch64 Linux, so
the instructions counted are AArch64's for both targets. Hot spots inside
a function were read from `--dump-instr=yes` profiles against `objdump`.
Base is 786e96a, built into its own target directory; head is fc83590.
Totals are what is compared: with fat LTO a function's own count moves by
up to about 2M from one build to the next with no change to it.

## Cuts

Instructions in millions, x86-64 objects.

|---|---:|---:|---:|---:|---:|---:|
| stl-heavy-g | 1311.7 | 1243.6 | 1223.2 | 1217.6 | 1217.4 | 1214.2 |
| templates-g | 915.4 | 876.8 | 866.7 | 863.9 | 863.8 | 862.3 |

- **1** (e3853a0): fields by position. `node_body` looked each field up
  three times by name: `di_field` (a linear scan of the kind's fields,
  then of `DI_FIELD_NOTES`), `static_field` (a scan for the `'static`
  name) and `DiNode::set` (a match on the name, then `field_shape` for
  the value's check). Now `DiKind::field_index(field, hint)` finds the
  position once, looked for from the last position plus one (LLVM writes
  the record's order, so one comparison a field); `field_shape_at` gives
  the shape and `DiNode::set_at` sets it by position. A field found in
  the record is mapped by definition (`map.rs`, `di_field`), so only the
  others still ask `di_field`; the older spellings of a subprogram's
  flags keep going through `set` by name. Duplicates are a bit per
  position, or the list of names for a field with no position.
- **2** (3f6785a): the kind from the metadata index. The index already
  knows each node's `MdKind`; `record_kind` maps it to the `DiKind`
  without reading and matching the kind's name again (`DiKind::named`),
  and the required fields are a match on the kind instead of a scan of
  a `(kind name, field)` table.
- **3** (e71ef80): `DebugInfo::verify` reads a node's references from
  its cells (`DiNode::stored_refs`: the mask, then each present field's
  value and its references) instead of decoding the whole node with
  `DebugInfo::node` and walking `DiNode::refs`.
- **4** (43e314e): `Field::refs` and the `stored_refs` walks take a
  generic visitor instead of `&mut dyn FnMut`.
- **5** (fc83590): `field_value` asked `named_code` twice for a word with
  a code (in the match guard and again in the arm); once now.

Self cost, base to head on stl-heavy-g (millions): `di_field` −31.8,
`static_field` −23.5 (gone), `DiNode::set` −17.4, `bcmp` −15.5,
`node_body` −14.0, `DebugInfo::node` −10.6, `DiKind::named` −9.1,
`define_tuples` −9.0, `field_shape` −6.7; `field_value` +27.7 (it was
inlined into `node_body` and no longer is), `Made::node` +10.0,
`stored_refs` +8.1 (all of `verify`'s walk, locations included, is now
counted there).

the same to the byte. The cuts add no allocation; a scratch field entry
is a `(Key, Val)` of the size the `(&'static str, Val)` was.

## Tried, and did not pay

- Comparing field names without `bcmp`: an inline loop over eight-byte
  chunks, +0.1M (LLVM turned it back into the call); overlapping word
  loads of both names, +3.5M.
- Each kind's decode in `DebugInfo::node` its own `#[inline(never)]`
  function, to shrink the saves of the one large function: +10M.
- `#[inline]` on `field_value`, to put it back into `node_body`: +0.05M.
- A cache of decoded nodes for `DebugInfo::node` (about 60M on
  stl-heavy-g after cut 3, 120 to 210 instructions a call over about
  350,000 calls, most of them from `hod_dwarf` and `hod_cg`): not tried,
  it would raise peak memory. The decode is about 5 instructions a field
  and 45 of entry and dispatch, near the least its interface allows.

## What is left

What remains in reading debug metadata is mostly the lexer's (WP-176):
`field_name` is 42 instructions a field and `field_value` about 65 a
value, most of it the next token. `DebugInfo::node` is the largest debug
cost left; it belongs to its callers (`hod_dwarf`, `hod_cg`) to ask for a
node fewer times, or for one field of it.
