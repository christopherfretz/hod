# WP-187: x86-64 inline assembly with templates

## What is implemented

- **An AT&T assembler for templates**, `hod_asm::x64`
  (`spec/asm.md` §10): comments, statements, `lock`/`rep` prefixes,
  numeric local labels with relaxation, `.byte .word .short .long .quad`,
  and a fixed mnemonic list encoded through `hod_mc_x64` (integer ALU,
  moves and extensions, shifts and rotates, bit scans and tests,
  `setcc`/`cmovcc`/`jcc`, atomics, string instructions, `cpuid`,
  `rdtsc`, `xgetbv`, `syscall`, `pause`, `pushfq`/`popfq`, `int`, `hlt`,
  `std`/`cld`, `fwait`, and the scalar and packed SSE forms listed in
  §10), and symbol fields in memory operands (`sym(%rip)`, `@plt`,
  `@gotpcrel`, `@gottpoff`, `@tpoff`, `@dtpoff`, plain absolute) with
  the relocation llvm-mc 19 and 22 write (§10.2 "Symbols"). A
  template is assembled exactly or refused with an `asm:*` name; nothing
  is guessed.
- **`hod_mc_x64` constructors** `std`, `hlt`, `fwait`, `syscall`,
  `xgetbv`, `int_i` (`spec/mc-x64.md`).
- **The lowering**, `hod_x64::barrier::template` (`spec/asm.md` §11,
  `spec/codegen.md` §5.6.28): the constraints `{reg}`, `r q Q R`, `m`,
  `i n e Z I..O`, `X`, `x`, `rm` and alternatives chosen by llc's
  weights, tied `0..9`, `=`, `=&`, `=*m`, `+`, `%`, flag outputs
  `{@cc*}`; the clobbers `memory cc flags dirflag fpsr` and register
  clobbers (callee-saved ones saved by the prologue); `sideeffect` and
  `alignstack`; the modifiers `b w k q h c n a P`, and the `${:uid}`
  substitution shared with AArch64. Operands are staged in frame
  slots, so a clobbered live register is never relied on.
- Matrix row `call:inline-asm` `ON` on x86-64 (`hod_ir` classify).

## Still refused, by frequency in the census

| form | count | name |
|---|---|---|
| `callbr` with a template (`asm goto`, `jmp ${N:l}`) | 4 | `x64:inline-asm` (WP-181 owns `callbr`) |
| x87 `{st}` operands (`fsqrt`, `fpatan`) | 4 | `asm:constraint/st` |
| the letters `a b c d S D`, `g`, `A` (llc refuses these too) | 0 | `asm:constraint/*` |
| 32-bit addressing, symbol operands, named labels, other directives | 0 | `asm:operand/*`, `asm:directive/*` |
| AVX and unlisted mnemonics, including `ldmxcsr stmxcsr clflush rcp* rsqrt* maskmovdqu` | 0 | `asm:mnemonic/*` |
| `inteldialect`; `unwind` | 0 | `x64:inline-asm-intel`, `x64:inline-asm-unwind` |
| a coroutine body whose template writes `rbx` | 0 | `x64:inline-asm-frame-base` |
| a symbol in an immediate or branch target; `lea` of `@gotpcrel`; other specifiers | 0 | `asm:operand/symbol`, `asm:operand/specifier` |
| a symbol the module does not define or declare | 0 | `asm:symbol` |

The encoders WP-181 is adding are not duplicated here; once they land,
the assembler can name them.

## Evidence

- `crates/hod_asm/tests/llvm_mc_x64.rs`: every accepted body's bytes
  equal llvm-mc 22's and 19's, a pinned core checked without llvm-mc,
  and the refusal table.
- `crates/hod_x64/tests/inline_asm.rs`: about 50 functions
  (`tests/data/inline_asm/`) run under qemu against a C driver, built by
  hod, by hod with the register stress, and by llc 19 and 22, linked
  dynamically and statically; the `forced_*` functions' template bytes
  equal llc's `#APP` blocks through llvm-mc; refusals; `invoke`;
  `callbr` stays refused.
- `crates/hod/tests/x64_inline_asm.rs`: text and llvm-as 19/22 bitcode
  give the same object.
- The census modules (Host.cpp, Valgrind.cpp, blake3_dispatch.c,
  cpuid-min, gtest-all.cc, llvm-rtdyld.cpp) build under `hod --strict
  -O0 -relocation-model=pic -function-sections -data-sections`;
  Host.cpp's `movq %rbx,%rsi; cpuid; xchgq %rbx,%rsi` matches llc 22 in
  both functions; llvm-rtdyld's `allocateTLSSection` carries the
  `R_X86_64_TPOFF32` against `LLVMRTDyldTLSSpace` llc 22 writes.
  llvm-exegesis's Target.cpp stops first at `intrinsic:llvm.x86.fxsave64`
  (WP-190); with `fxsave64`/`fxrstor64`/`flags.read`/`flags.write`
  removed it builds, and a reproducer of `X86SavedState`'s destructor
  writes `9B` as llc does.
- `crates/hod_asm/tests/llvm_mc_x64.rs` `symbol_fields_match_llvm_mc`:
  44 symbol bodies, bytes and relocations (offset, type, symbol, addend)
  equal to llvm-mc 19's and 22's. `crates/hod_x64/tests/inline_asm.rs`:
  TLS, PC32, GOTPCREL and PLT templates run against the driver (dynamic
  and static), and `symbol_fields_are_llcs_relocations` compares the
  relocations with llc 19's and 22's.
- Mutations caught and reverted: a tied input loaded into the wrong
  register (driver FAILs); clobbered registers no longer displaced
  (`clobber_live`, `clobber_xmm` FAIL).
