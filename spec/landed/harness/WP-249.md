# WP-249 — the fuzzing budget meetable at the release candidate (L10)

Landed: the class `llc19-int128-last-register` (`xtask/src/fuzz/int128.rs`,
hooked into the whole mode in `xtask/src/fuzz/case.rs` and into `--mix`
in `xtask/src/fuzz/split.rs`), the verdict `set-apart`
(`case::Verdict::SetApart`), its counting in the summary, the results
file and the budget (`set-apart` and the new `set-apart-seeds` column of
`budget.tsv`, the `set apart` column and the "Set apart (seeds)" list of
`budget.md`), the contract in `spec/harness.md` "Set apart (seeds)",
"Verdicts", "Budget", the verdict in `docs/VALIDATION.md`, and the
csmith working-directory checks. This file records what was decided and
why.

## Decisions

- **An evidence-based class, not a generator that avoids the shape.**
  The 21 findings of the 1.0 budget's x86-64 LLVM 19 `abi` slices are
  `llc` 19's call lowering of an `__int128` that comes with only r9 left
  (`docs/status/fuzz.md`, class 3). Avoiding the shape at LLVM 19 would
  stop exercising it against `llc` 19's run and would set nothing apart
  if hod ever differed there; the class keeps the shape in every
  program and sets a finding apart only when two other compilers agree
  with hod on that finding: gcc on `prog.c` (the psABI's reference, an
  independent front and back end) and `llc` 22 on the same module (the
  same front end, the oracle's flags; "llc's own configurations
  differ"). That is the standing rule's evidence, gathered per finding.
- **Narrow by four gates**: the `abi` profile, x86-64, LLVM 19, a
  `disagree` finding (never a hang, a failure, a link failure or a
  debug finding), and the shape in the module: a call or a definition
  whose arguments, counted in order with the psABI's integer registers,
  reach an `i128` with exactly five of six taken. A type the count does
  not know makes the site unjudged. The shape is rare (one abi program
  of the twelve of seeds 1 to 12, x86-64 LLVM 19), so the builds run
  per finding, not per seed.
- **`--mix`**: the finding's program is hod's half with `llc` 19's
  other half; `llc` 19's half is what the defect is in. The evidence is
  the same assignment with `llc` 22 building that half: it must print
  exactly what gcc's program and `llc` 22's whole module print. That
  shows hod's half agrees with `llc` 22 across the objects, which a
  comparison of hod's whole module alone would not.
- **A verdict of its own** (`set-apart`), not `agree` and not a skip:
  the programs did differ and the seed says something about hod (it
  agrees with two references). It is not saved or reduced (it is no
  finding), its evidence line is in the summary, the results file and
  the budget's log, and the budget lists it with its seed.
- **The site printed is the module's first site of the shape**, which
  is a precondition, not a diagnosis; the evidence is the agreement of
  the three programs.
- **csmith's `platform.info`**: csmith already ran in the seed's
  directory (WP-160), which is under the run's output directory; the
  stray file in the worktree came from csmith run by hand there during
  the budget's triage (`count-float.sh` of that run ran csmith in its
  current directory). The checks of `fuzz_real.rs` failed on a file the
  run had not written; they now fail only on a file newer than the
  test's start (an older one is a note), and a unit test with a csmith
  stand-in shows the run writes it in the seed's directory and not in
  the test's or the workspace's. csmith is spawned through xtask's own
  child runner (`irdiff::process`, with limits and the jobserver), as
  every tool of the harness.

## Tests

- `int128::tests::the_shape`: seed 125392's call (argument 10), a
  definition (parameter 6), and no site with two registers left, none
  left, `byval` and floating point before it, after a definition's
  `...`, behind an unknown type, in a global or a comment.
- `int128::tests::where_it_applies`: not at LLVM 22, AArch64 or another
  profile.
- `int128::tests::the_decision`: set apart when gcc and `llc` 22 both
  match hod; a finding when either differs (stdout or end), gives no
  evidence, the finding is not `disagree`, or hod's program timed out.
- `fuzz_real::llc19_int128_findings_are_set_apart`: seeds 125392
  (whole) and 126005 (`--mix`) with the workspace's hod: `set-apart`, no
  finding, their sites.
- `fuzz_real::a_wrong_convention_with_the_shape_stays_a_finding`: the
  swapping hod (`fuzz/swap-params.awk`) on abi seed 2 `--mix` (the
  shape is there): a finding at LLVM 19 whose detail says
  `not llc19-int128-last-register: gcc -O0's program differs from hod A
  + llc-22 B's`, and a finding at LLVM 22 where the class is not asked.
  On seed 126005 the same swap is set apart, rightly: its finding is
  `llc` 19's alone (hod A + `llc` 22 B prints gcc's output).
- `fuzz_budget::rows_and_the_table`: the columns, a row of 16 fields
  read back, the table's set-apart column, census and list.
- `case::tests::csmith_writes_only_in_the_seed_directory`.

## The release candidate's run

Freeze the candidate's hod and an `xtask` of `64b45de6` or later
(release builds copied out of the build directory, sha256 recorded),
then under `nohup`:

```
cargo xtask fuzz --budget --seed 200001 -j 4 --hod <frozen hod> --out <dir>
```

(or the frozen `xtask` with the same arguments; `llc-22` must be
installed for the x86-64 LLVM 19 `abi` slices). Classes that set a seed
or a pair apart there, each counted and listed: `ub-float-cast` (a skip,
on gcc UBSan's verdict), `selector-split` (`--debug` pairs, on LLVM's
other two selectors), `llc19-int128-last-register` (`abi` seeds at
x86-64 LLVM 19, on gcc and `llc` 22), and `--debug`'s self-assignment
and constant-branch pairs counted apart as before.
