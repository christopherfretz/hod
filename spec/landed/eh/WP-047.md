# WP-047 — `hod_eh`: language-specific data areas (`.gcc_except_table`)

The contract is `spec/eh.md` §9. This file records what the work package
did, what it measured, and what it left.

## What landed

- `crates/hod_eh/src/lsda.rs`: `NO_PAD`, `CallSite`, `Pad`, `Clause`,
  `FuncLsda`, `LsdaOptions`, `write_lsdas`; the call-site, action, type
  and filter tables of `EHStreamer`, sized exactly and written into one
  buffer for the object with scratch buffers reused across functions.
- `crates/hod_eh/src/lib.rs`: the exports and the new `Error` variants
  (`CallSiteOutOfOrder`, `CallSiteBeyondEnd`, `BadPad`, `LandingBeyondEnd`,
  `BadClauses`, `EmptyPad`, `BadTypeId`, `BadFilter`, `BadName`).
- Tests: `tests/common/lsda.rs` (an LSDA decoder, rows rebuilt from llc's
  tables, the round trip), `tests/lsda_oracle.rs` (§9.9 oracle),
  `tests/lsda_unwind.rs` with `tests/data/lsda.{cpp,ll}` (real
  unwinding), `tests/lsda_units.rs` (units), `tests/throughput.rs`
  (`lsda_per_call_site`). `tests/common/mod.rs` gained a multi-section
  splice and the LSDA hook in `round_trip`.
- `spec/eh.md` §9, the `eh.md` row of `spec/README.md`.

## Evidence

- §9.9 oracle, `llc` 19 and 22, AArch64 and x86-64, 9 modules, with and
  without `-function-sections`, each also with the input reversed: all
  72 objects **byte-identical** to `llc` in every `.gcc_except_table*`
  section, its relocations, its group membership and the `DW.stub`
  words in `.data`. The cases are checked to cover catch by type,
  catch-all, cleanup-only, a cleanup with clauses, filters with shared
  tails and `throw()`, shared action chains, COMDAT groups, gap entries,
  two-byte ULEB128 fields and a TType base offset beyond 127. Wrong rows
  (a landing address, a catch type) fail the comparison.
- Real unwinding (AArch64, `llc` 19 and 22): `lsda.ll` gives 12 LSDAs
  and 60 call sites, byte-identical. With hod's LSDAs and `.eh_frame`
  spliced in, linked by `g++` with bfd 2.44, lld 22 and mold 2.37.1 and
  `--eh-frame-hdr`: the normal run prints the 11 expected lines and exits
  0; the `filter` and `noexcept` runs print, write to stderr and end with
  SIGABRT exactly as the original. The wrong table (the first call of
  `two_pads` pointed at the other pad) ends the normal run with SIGABRT
  under all three linkers.
- Throughput (`cargo test -p hod_eh --release --test throughput --
  --ignored --nocapture`): 100,000 AArch64 LSDAs with 16 call sites each
  (1.6 M call sites, about 12 MB): 28.5 ms, **285 ns per function, 17.8 ns
  per call site**. Reusing scratch buffers and writing into an exactly
  sized region took it from 592 ns per function.

## Decisions

1. The input types mirror `hod_cg`'s rows field for field; `hod_eh` keeps
   depending on `hod_obj` only, and WP-049 maps them.
2. A `CallSite::landing` of 0 means the pad's own offset (the reading of
   `spec/codegen.md` §9.4; `record.rs` says "zero without a pad").
3. One stub per type-info symbol per object, ordered by name, in the
   caller's `.data`, as `llc` does; no `GCC_except_tableN` label.
4. No `SHF_LINK_ORDER`, as `llc` with its default binutils version.
5. Everything is validated and encoded before the object is touched, so
   errors leave it unchanged.

## Gaps in the record (for `hod_cg` and WP-049)

- `crates/hod_cg/src/record.rs:72-88`: `CallSiteRow` has no "may throw"
  flag, so hod writes entries for calls to `nounwind` functions that
  `llc` leaves out (§9.3). Same behaviour for every correct program.
- `FuncRecord` has no name or section; the caller supplies them after the
  merge, with the object's `.data`.
- `PadRow::block` (a `hod_ir` `BlockId`) is carried as its index, unused.
- Filter numbering follows `pads` order where `llc` uses reverse
  post-order (§9.5); no case differed.
