# WP-029 — `hod_ir` gaps that `hod_ll` worked around (items 2–4; item 1 parked)

Landed:
- `spec/ir.md`:
  - §2.2: the symbol order;
  - §5.5: `noalias.scope.decl`;
  - §5.7: `sample-profile-suffix-elision-policy`.
- `spec/ll.md`:
  - §3.4: forwarded varargs are no longer unsupported; the unlabelled
    `blockaddress` row is reworded;
  - §5.5: block numbering for `blockaddress`;
  - §5.7: the order;
  - §11.3, §11.6: `...`.
- `spec/bc.md` §5.5: symbol ids.

Item 1 (lookup-only tables for parallel body parsing) is parked. The design
and the remaining steps are in the branch's `PARKED.md`.

## What it did

| item | change |
|---|---|
| addition | `"sample-profile-suffix-elision-policy"` is a dropped string attribute (`attrs.rs`); LLVM 22 bitcode carries it |
| 2 | `Body::empty`, `cast_is_valid`, `sext64` public; the `hod_ll` copies are deleted |
| 2 | `attr_info` on a miss probes only `PREFIXED_STRING_ROWS` (the `no-builtin-` row); a unit test keeps the list equal to the rows with a prefix |
| 2 | `llvm.experimental.noalias.scope.decl` is `NoCode::Drop`; `tests/body_llvm.rs` checks it at `llc -O0` |
| 3 | `musttail … (..., ...)` forwards varargs and parses, with LLVM's three errors for misplaced or missing `...` |
| 3 | a module-level `blockaddress` naming a missing label is `Undefined` ("referenced value is not a basic block"), as in `llvm-as` |
| 3 | `blockaddress(@f, %N)` of an unlabelled block resolves by a lexical numbering of the body; a body the scan cannot settle is noted `blockaddress:unlabelled-block` |
| 4 | `hod_ll` numbers symbols in one pass first: variables, functions, aliases, IFUNCs, each in the text's order; `hod_bc` creates unnamed globals' symbols in place (record order) |

## Evidence

- Captured corpus (`hod_ll --test corpus`):
  - LLVM 19: before, 24,005/24,009 bodies delivered (4 `call:forwarded-varargs`); after, 24,009/24,009.
  - LLVM 22: before, 24,226/24,230 (4 likewise); after, 24,230/24,230.
  - 0 errors before and after.
- `hod_bc` differential with the new order check: 2,864 and 2,896 modules,
  all agree.
- `tests/syntax`: `blockaddress_of_a_block_without_a_label_is_llvms` (8
  cases) and `symbols_are_numbered_in_llvms_module_order`, both against
  `llvm-as | llvm-dis` 19 and 22, plus the new error rows.
- Order experiment:
  - Globals of every kind defined after their first use.
  - `llvm-dis` lists each kind in definition/declaration order.
  - `llc` lays out `.text` and `.data` in that order on both majors.

## Fixes outside `hod_ir`/`hod_ll`

- `crates/hod_bc/src/module.rs` `symbols()`: unnamed symbols are created in
  record order.
- `crates/hod_bc/tests/differential.rs`: `order`, and the `symbol order`
  class.
- `xtask/src/roundtrip/ingest.rs`, `xtask/tests/roundtrip_fakes.rs`: the
  fixtures' unsupported construct is `alloca inalloca`.
