# WP-339: libc++ on i386, the full run (9,247 tests), control and strict

Landed: the full listing of libc++'s suite (`std libcxx`, 9,247 tests)
for `i686-unknown-linux-gnu` in control and strict mode, its per-test
table and refusal census, and the full-run section of
`docs/status/libcxx-hod-i686.md`. It builds on WP-330 (archives and
runner) and WP-336 (the sample). Hybrid was not run here.

## Runner changes

- `scripts/libcxx-i686-clang.sh`, hybrid: the fallback is the script
  itself with `HOD_I686_AS_LLC=1`, which `exec`s `llc -global-isel=0
  -fast-isel=0` with hod's forwarded arguments. A module hod declines is
  then built exactly as the control builds it, so any difference
  between hybrid and control isolates hod. (The flags cannot go on
  hod's own command line: an option hod does not know sends every
  module to the fallback.) Checks: on `full-signbit.pass.ll` (refused
  by hod) the hybrid object is byte-identical to the control `llc`'s and
  differs from plain `llc -O0`'s; on the ten-test set (`ten.txt`),
  control and hybrid give 10 PASS each, one module by the fallback.
- strict: `HOD_CENSUS=1` as well. Per `spec/cli.md` the answer is
  unchanged and the coverage log's field 11 lists every reason, so a
  run without hybrid still has the census.
- `scripts/libcxx-i686-table.py`: hybrid may be missing (column "-",
  census from strict's logs); new `trouble.tsv` lists hod steps with an
  exit other than 0 or 2, or of 60 s or more.

## Reproducing

From the worktree, with the WP-330 build dir `<build>`:

    export CARGO_TARGET_DIR=<build>/kiln-target
    unset HOD_I686_SELECTION                     # the selection is `std libcxx`
    export HOD_I686_HOD=<build>/release/hod      # built from 436a3755
    export HOD_JOBSERVER_FIFO=/run/hod/lanes.fifo HOD_JOBS=4
    for mode in control strict; do
      for k in $(seq 1 20); do nice scripts/libcxx-hod-i686.sh $mode <run> --shard $k/20; done
      scripts/libcxx-hod-i686.sh merge <run> $mode
    done
    python3 -I scripts/libcxx-i686-table.py <run> <run>/tables

(`<build>/run-full.sh` is this loop, resumable: a shard with a `.tsv`
is skipped.) `tables/` gets `table.tsv`, `totals.md`, `census.md`,
`suspects.tsv` and `trouble.tsv`. Back-end time sums: `<run>/<mode>/time.tsv`
(step in field 2, microseconds in field 3, exit in field 4).

The function and intrinsics behind each refusal: for each test of
`table.tsv` with a strict refusal, regenerate the module (`ir-of.sh
<run>/strict/args.tsv <test> <dir>`, which reruns the test's first
compile in control mode with `HOD_I686_KEEP=1`), run `hod -O0
-filetype=obj -mtriple=i686-unknown-linux-gnu [-relocation-model=pic]
--strict <dir>/t.o.ll`, and list the `@llvm.*` calls of the function
its message names (`<build>/intr-full.sh`, run over the 195 tests with
`xargs -P 2`; output `intr-full.tsv`).

The new reduced modules, each refused by hod under its name and built
by `llc -O0 -global-isel=0 -fast-isel=0`, are kept outside the
repository with copies of the tables: `i64-wide-zext-i65.ll`,
`i64-wide-sadd-overflow-i65.ll`, `inline-asm-operand-type-i64-reg-or-mem.ll`.
The latter, whole:

    target triple = "i686-unknown-linux-gnu"
    define void @f(ptr %p) {
      %v = load i64, ptr %p, align 4
      call void asm sideeffect "", "r|m,~{memory},~{dirflag},~{fpsr},~{flags}"(i64 %v)
      ret void
    }
