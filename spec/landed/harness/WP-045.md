The wrapper was removed after checking the engine: `codegen_args` gives
`Build::Reference` `-O0` then `engine::REFERENCE_SELECTOR`
(`-global-isel=0 -fast-isel=0`) on every target; the fake `llc` of
`roundtrip_fakes.rs` still refuses to run without both.

## Decisions, and why

- **The corpus's name is its manifest's digest** (with the entry count
  for the reader). The manifest is a function of the capture's inputs
  and not of the directory, so moving the corpus keeps the name, and any
  recapture that changes an entry changes it. A run against another
  corpus is a note, compares by name and reports no stale lines; it is
  not a failure, so the gate works with whichever corpus is at the
  default location. Updating for another corpus needs a complete run.
- **Quick tier: SHA-256 of the path, first byte below 8** (1 in 32):
  spread over sources, majors and directories, stable as entries come and
  go. 206 entries of 6,250 (kiln 44 + 44, torture 68 + 50; 10 of several
  modules, 6 bitcode); 188 of the old 5,760.
- **Missing corpus**: skipped with a one-line notice, a failure under
  `HOD_REQUIRE_TOOLS=1`, as `irdiff` treats a missing oracle: the gate's
  one rule for tools and build output ("ci").
- **Several modules**: every module is parsed and printed; the worst
  (rank 2 before rank 1, then first) decides, so an earlier honest
  "unsupported" does not hide a later bug. Assembly and verification per
  module; the engine gets the printed modules after their `;@ module:`
  lines and links them itself.
- `Failure::Timeout`/`Crash` are the oracle's tools'; hod's own failures
  are `HodBuild` whatever the way, since the engine reports them as one
  string from the coverage-log reading.

## Outcomes on the new corpus

`cargo xtask roundtrip --corpus .build/corpus-wp023 -j 4`, aarch64,
bfd lld mold (wild not installed), 1072.7 s wall on a loaded host:

| outcome | LLVM 22 | LLVM 19 |
|---|---|---|
| pass | 3100 | 3090 |
| parser-unsupported | 43 | 17 |
| any other | 0 | 0 |

By form: several modules 141 + 138 pass (+5 + 5 with a bitcode module),
all pass; bitcode-delivered single modules 64 + 89 pass, 30 + 5
unsupported; `link: allow-warnings` 5 + 4 pass; the 14 `llc-args`
entries (`-debugger-tune=gdb`) are all `debug-info` unsupported, so the
real-tool test and the fakes cover `llc-args`.

Unsupported constructs (22 / 19): `attr:sample-profile-suffix-elision-policy`
25 / 0 (bitcode modules of LLVM 22, e.g.
`kiln/llvm22/c/expr/gnu-binary-conditional-logical-O2.c.ll`),
`debug-info` 7 / 7, `attr:convergent` 5 / 5,
`special-global:llvm.global.annotations` 2 / 2,
`metadata-arg:llvm.experimental.noalias.scope.decl` 2 / 2,
`metadata-arg:llvm.read_volatile_register.i64` 1 / 1,
`call:forwarded-varargs` 1 / 1, `attr:fmv-features` 1 / 0. 35 of these
are new entries (the old file had 25 lines). **No outcome of rank 2: no
parser or printer bug was found**, so nothing to reduce.

content, which a move keeps. Check with `cargo xtask roundtrip --tier

commit of `tests/roundtrip/expected-aarch64.tsv`.
