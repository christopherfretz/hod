# WP-129 — the lane loop and inline-asm constraints into `hod_cg` (design 0006, R3)

Landed: `crates/hod_cg/src/lanes.rs`, `crates/hod_cg/src/asm_constraints.rs`
(with their unit tests), `spec/codegen.md` §7.3 "The lane loop" and
"Inline-assembly constraints".

A refactor, as WP-117 (R1) was: target-independent decisions move out
of `hod_a64` into `hod_cg` so that x86-64 (WP-132 vectors, its inline
assembly) does not write them again. AArch64 output is unchanged byte
for byte.

## What moved

| from `hod_a64` | to `hod_cg` | the target's part |
|---|---|---|
| `lanes.rs`: `setup` (shape checks, operand images, the result's image), `take`/`load`/`store` per lane, `done` | `lanes::{setup, images, each_lane, load, class_of, finish, Arg, LaneLoop}` | `LaneKernels` (implemented for `A64` in `lanes.rs`), the scalar kernel as a closure |
| `vector.rs`: `Elem`, `MAX_LANES`, the shape decision of `Shape::lanes` | `lanes::{Elem, MAX_LANES, lane_log2, ShapeRefusal, Geometry}` | the refusal names (`a64:vector-*`); `Shape`, `Lanes` and their arrangements stay |
| `mask.rs`: the operand images of `icmp`/`fcmp`/`select` of lanes, `finish_image` | `lanes::{images, finish}` | the per-lane code (`cmp`/`cset`, `csel`) stays |
| `inline_asm.rs`: `Alt`, `Kind`, `Op`, `Ops`, `parse_alt`, `Ops::parse`, `Ops::clobber`, the body of `choose` and `alt_of` | `asm_constraints::{parse, Constraints, Op, Alt, Kind, Constraints::choose, Op::alt, MAX_OPS, MAX_ALTS, SPEC, TIED, FLAG}` | `ConstraintSyntax` (`A64Syntax`: letters, register names, flag conditions, clobbers), the code weights, the refusal names |

`hod_a64::vector` re-exports `Elem` and `MAX_LANES`, so no caller
outside the package changed. `vcall.rs` shares nothing with the loop
(its moves are the AArch64 ABI's lane promotions) and is unchanged.
`barrier.rs` keeps its own copy of a constraint parser (outside this
package's files): it can call `asm_constraints::parse` next.

New in the neutral description, not used by AArch64: `Op::early_clobber`
(`&`), `Op::commutative` (`%`), `Constraints::memory` (`~{memory}`),
`AsmFlags`, and multi-byte letter codes (`ConstraintSyntax::letters`
returns a length: x86-64's `Yz`).

## Equivalence argument

- The driver takes temporaries and loads lanes in exactly the order
  the old per-operation code did; it frees the result register and then
  every taken temporary, where the old code freed a per-case subset.
  `FnCx::free_temp` is a set removal that ignores non-temporaries, and
  nothing is allocated between the store and the frees, so the pool
  state after each lane is the same. After a runtime call (`frem`, a
  libm lane) the taken temporaries are no longer temporaries, so the
  extra frees do nothing.
- The scalar-operand class (`class_of`) of `minmax`/`sat`/`scmp`/`fp`
  calls is computed once before the loop instead of per lane: it reads
  the value's class, which does not change.
- The `scmp`/`ucmp` check of a scalar operand (an internal error) now
  happens before the loop instead of after the first lane's loads.
- The constraint parser reads in the same order and refuses with the
  same names; a digit run is accumulated with wrapping arithmetic (what
  the release build did; a debug build no longer panics on 11 digits).

## Evidence

Base `6357a12` and head built in release; every module compiled by
both, from standard input to standard output
(`scripts/corpus-bytes.py`, the WP-096 script), and the `tests/ir`
seeds with `--mtriple=aarch64-linux-gnu --strict --filetype=obj`, static
and PIC. Corpus: 6451 modules (LLVM 19 and 22), 6441 objects identical,
10 declines identical, 0 differ (2 min 12 s at `-j 4`); 150 of its files
have vectors of lanes, 154 inline assembly. Seeds: 100 compilations, 94
objects identical, 6 refusals identical, 0 differ.

## Tests

`hod_cg`: `lanes::tests::{lane_sizes_and_refusals,
geometry_and_elements}`, `asm_constraints::tests::{operands_and_clobbers,
refusals, choice_by_weight}` (a toy x86-like syntax: two-letter codes,
`{@cc..}`, the `flags`/`dirflag`/`fpsr` clobbers). The `hod_a64` suites
`lanes`, `mask`, `vector`, `vcall`, `neon`, `inline_asm` are unchanged
and pass.
