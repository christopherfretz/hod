# WP-053 — `hod_dwarf` part 2: the DIE writer core

The design is `spec/dwarf.md`. The contract of what landed is §2 (where
the input comes from), §3, §6.1 to §6.3 and §6.5 to §6.7, §7.1 and §8.6.
This file records what the work package did, what it measured, and what
it left.

## What landed

- `crates/hod_dwarf` now also depends on `hod_ir`.
  - `src/abbrev.rs`: the fixed abbreviation table. It has 49 families
    with fixed code blocks (codes 1 to 753); the core's five are
    implemented, and the shapes of WP-057, WP-058 and WP-059 are reserved
    with their owners. The DWARF constants are in `tag`, `at` and `form`,
    and `write_abbrev` writes the used codes.
  - `src/die.rs`:
    - `UnitPlan` (the discovery walk and the scope inversion);
    - `GlobalAddr`, `CodeSpan`, `UnitInput` and `DieSections`;
    - `write_debug_info`, which writes the unit header, the compile-unit
      DIE, global variables, namespaces, base and pointer types,
      `.debug_str_offsets`, `.debug_addr` and `.debug_rnglists`, with
      every relocation.
  - `src/strings.rs`: `DebugStrings`, the pool of §6.3, with its hash.
  - New `Error` variants: `NoUnit`, `NotACompileUnit`, `BadReference`,
    `Unsupported`, `GlobalNotInUnit`, `DuplicateGlobal`, `BadSymbol` and
    `BadSpan`.
- Tests (§8.6):
  - `tests/dies.rs`, `tests/die_oracle.rs`, `tests/die_debugger.rs`, and
    `die_throughput` in `tests/throughput.rs`;
  - `tests/common/meta.rs`, a reader of LLVM debug metadata into
    `hod_ir`'s builder;
  - `tests/common/dies.rs`, with the trees, the normalization, the splice
    and the generator;
  - `tests/common/session.rs`, the linker and masking helpers, moved out
    of `debugger.rs`;
  - `tests/data/dies/{globals,strings,main}.{cpp,ll}`.
- `spec/dwarf.md`:
  - §1.1 corrected: the unit's `DW_AT_low_pc` with ranges has no
    relocation;
  - §1.2: an empty unit;
  - §2: the input decision and what `hod_ir` lacks;
  - §3, §6, §7.1, §7.2 and §8.6;
  - the row of §10 marked landed;
  - open questions 7 and 8.
- The `dwarf.md` row of `spec/README.md`.

## Evidence

- `HOD_REQUIRE_TOOLS=1 cargo test -p hod_dwarf`: 8 lib units, 7 in
  `dies.rs`, 2 in `die_oracle.rs`, 2 in `die_debugger.rs`, and WP-052's
  tests unchanged. There are 2 ignored measurements.
- `--verify` (llvm-dwarfdump 19 and 22, both targets): clean on 8 inputs,
  with WP-052's `.debug_line` written from the plan's file table:
  - no globals, with no code, one code section, or four sections with
    two COMDAT groups;
  - `globals`, with no code and with one section;
  - `strings`, with four sections;
  - `main`;
  - 3,000 generated globals, with four sections.
  It is also clean on one table built by hand with the builder.
- The `llc` comparison (`-O0 -global-isel=0 -fast-isel=0
  -relocation-model=pic`, 19 and 22 × AArch64 and x86-64), on `globals`,
  `strings` and 2,000 generated globals:
  - 6 objects and 4,222 DIEs are equal after §6.7's normalization, and
    are in `llc`'s sibling and attribute order in all 6;
  - the relocation targets of `.debug_info`, `.debug_str_offsets` and
    `.debug_addr` are equal;
  - addresses four bytes off are caught.
- Debuggers (AArch64; `llc` 19 and 22 × bfd, lld, mold; gdb 16.3, lldb
  19), on the program `globals.o` + `main.o` with hod's debug sections in
  `globals.o`:
  - gdb's 104-line session (`info variables -n`, 16 `ptype` and
    `whatis`, 2 `info address`, 34 `print`s in `main`) is identical to
    the original's;
  - lldb's 86-line session (29 `target variable`, 7 `expression`) is
    identical too;
  - addresses four bytes off give a different session every time.
- Determinism: on both targets the bytes are equal over 8 rounds. Each
  round shuffles the globals and the spans, cuts every span at a random
  point, repeats pieces, and deals the rows into 1 to 5 chunks. Plans
  built and written on 3 other threads give the same bytes too.
- Errors: each of the 6 address errors and `NoUnit` leaves the object's
  bytes unchanged. `Unsupported` and `NotACompileUnit` are checked as
  well.
- Throughput was measured with `cargo test --release -p hod_dwarf --test
  throughput die -- --ignored --nocapture`, on the shared host, best of
  five runs. The input was 100,000 globals, which make 100,037 DIEs:
  - the plan takes 37 to 40 ns per DIE;
  - the writer takes 350 to 450 ns per DIE (125 to 165 MB/s of DIE
    sections, 58 bytes per DIE). The run-to-run spread is the host's;
  - the string pool alone takes 80 to 100 ns per string over 217,883
    strings, 46 to 60% of the writer;
  - before the hash fix the writer took 2,883 ns per DIE.
- Bytes against `llc` on the oracle's modules: 1.020×.
  - `.debug_info` is 67,438 bytes against 62,712.
  - `.debug_abbrev` is 884 against 1,422.
  - `.debug_str`, `.debug_str_offsets` and `.debug_addr` are equal.
- `cargo fmt --all --check` and `cargo clippy --workspace --all-targets
  -- -D warnings` are clean. The gate result is in the handback.

## Decisions

1. **The DIE writer reads `hod_ir` directly (§2)**, and addresses come in
   as plain rows. There is no mirror schema.
2. **One function per phase (§7.1)**: plan, record, write. The writer
   sorts and merges its inputs, so its bytes do not depend on order or
   chunking.
3. **Fixed families with option masks (§6.1)**, append-only, with
   reserved blocks for later packages. `.debug_abbrev` holds only the
   used codes.
4. **ULEB forms throughout** (`strx`, `udata`). The cost is two-byte
   codes for families at 128 and above (open question 7).
5. **The unit's range list uses `DW_RLE_startx_length` for every span.**
   It is simpler than `llc`'s `base_addressx` + `offset_pair` and
   independent of which section is `.text`. This is a named difference.
6. **The address table holds the globals in DIE order, then the merged
   spans.**
7. **The string pool's hash mixes before the table indexes it.** The
   plain Fx product put 65,536 names into 43 buckets.

## Left for later

- Per-function DIE runs need their string and address indices fixed
  before the merge (§7.1, open question 8): WP-057.
- An id-keyed string pool needs `hod_ir` to expose the `StrId` of a
  decoded node's strings (`crates/hod_ir/src/debug/node.rs:64`).
- TLS globals (`DW_OP_form_tls_address`): `GlobalAddr` gains a flag
  (WP-059).
- Skipping an empty unit, as `llc` does, is the bridge's job (§1.2, §9).
- Several units append to one `.debug_line` only once the line writer
  can append (§1.2, §4.6). Today a caller gives each unit's
  `line_offset`.
