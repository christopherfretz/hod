# WP-091 — the command line in the facade (design 0004 H2)

Landed: `crates/hod/src/args.rs` (from `crates/hod_cli/src/args.rs`),
`crates/hod/src/env.rs` (new: `Environment` from
`crates/hod_cli/src/driver.rs`), `crates/hod/src/jobserver.rs` (from
`crates/hod_cli/src/jobs.rs`), `crates/hod/src/coverage.rs` (from
`crates/hod_cli/src/coverage.rs`), `InputKind::Module`
(`crates/hod/src/lib.rs`), `spec/cli.md` "The command line in the facade"
and coverage fields 3 and 4. The binary keeps what is its own: the
driver (fallback, conversion, exit statuses, the help text), the
converter and the phase report.

## What landed
- `Options::from_llc_args(&[impl AsRef<str>]) -> Result<Options, ArgError>`:
  the binary's parser (`args::parse`, unchanged) in a mode that knows
  `llc`'s options only and forwards nothing.
- `Environment::{from_process, from_vars, threads, settings}`,
  `Settings::from_env() -> Result<Settings, EnvError>`; every `HOD_*`
  variable and `MAKEFLAGS` is read in `env.rs` and nowhere else.
- `coverage::{Record, Outcome, FallbackStatus, Log, FIELDS}`; field 3
  gains `module` (field 4 `-` with it).

## Choices where design 0004 §4 left one
1. `ArgError` is the shim's `Rejected` renamed, `#[non_exhaustive]`, with
   one variant more, `NoCompile` (`-version`/`-help`, `usage`), which only
   `from_llc_args` returns. hod's own options are unknown options to
   `from_llc_args` (they are not `llc`'s), so it has no `fatal` case.
   `-o` and the input are accepted and dropped.
2. `Settings` gains no field: strict mode and the coverage log are
   `Environment` fields (they change what the caller does with an
   answer). `Settings::from_env` sets `census` and `threads` and reads
   bitcode natively (`HOD_BITCODE_VIA` names a converter process).
3. The coverage line is `Record::line` (the eleven fields as a struct),
   not a free function of eleven arguments, plus the `Log` that appends
   it with one write.
4. `debug_compression` is not set by `from_llc_args` (not `llc`'s); an
   embedding caller that wants the shim's bytes under
   `HOD_COMPRESS_DEBUG_SECTIONS` copies `Environment::compress_debug_sections`.
5. `InputKind::Module` is a variant of the facade's `InputKind`
   (`detect` never returns it), so the record keeps one field type.

## Evidence
- Byte identity, release builds of `6e300f5` (base) and this branch, each
  run with `HOD_STRICT=1 HOD_CENSUS=1` and a coverage log: the 93 seed
  modules of `tests/ir` for both targets (`-mtriple=` aarch64 and x86-64)
  and every fifth corpus entry with its manifest `llc` arguments (1,250):
  1,436 invocations, 1,378 objects byte-identical, 58 declines with the
  same exit status, standard error and coverage fields 1-6 and 11.
  Command-line and environment mistakes (unknown option in strict mode,
  `--threads=0`, `-O4`, two inputs, `zstd`, `HOD_THREADS=x`): same
  status and text.
- Start-up: hod's own time on a declined 4-line module (coverage field
  7), 400 interleaved runs each at load 34: median 12.8 ms new against
  14.0 ms base (p10 10.3 / 11.3): no slower; the time is exec and page
  faults on the shared host. The parse and the environment read do the
  same work as before (one pass, each variable read once).
