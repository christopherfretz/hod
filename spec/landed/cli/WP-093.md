# WP-093 — panic containment and the embedding surface (design 0004 H4, H5)

Landed: `crates/hod/src/contain.rs` (new), `Session::guarded` and
`Session::poison` (`crates/hod/src/session.rs`), `compile_with` moved to
`crates/hod/src/front/read.rs` behind the feature `readers`,
`CompileError::Panic`, `hod::INTERNAL_PANIC`, `hod::EMBED_API`,
`Environment` `#[non_exhaustive]`, `spec/cli.md` "Embedding" and the
reason `internal-panic`. H6 and H7 (kiln's side) are not here.

## What landed
- `CompileError::Panic(String)`: reason `internal-panic`, displayed
  `internal error: hod panicked: <message>`; the shim falls back on it as
  on `internal-error` (status 1 in strict mode).
- Containment boundaries: `contain::contained` (one `catch_unwind`,
  `AssertUnwindSafe` justified at each caller); `Session::with_module`
  and `Session::new` (open), `Session::guarded` around `end_module`,
  `body`, `unsupported_body`, `finish`, `abort`; `compile_with` around
  the whole read-and-compile. Worker threads are spawned in
  `back::compile_bodies`' `std::thread::scope`, so a worker's panic is
  joined, re-raised on the calling thread and contained there.
- Poison by construction: after a contained panic `poison` replaces the
  whole session by `Session::fresh` of the same target with default
  options and settings (dropping the module, bodies, judge and the
  settings' token source) and `stopped` set to the panic; the report is
  kept, with `internal-panic` under census.
- Feature `readers` (default) gates `hod_ll`, `hod_bc`, `compile`,
  `compile_with`, `Session::abort`; the `clippy` step of `cargo xtask ci` also runs
  `clippy -p hod --no-default-features -D warnings`.
- `EMBED_API = 1`; `tests/embed.rs` checks it is the last row of
  `spec/cli.md`'s table and that `Session` is `Send`.

## Choices where design 0004 left one
1. A new variant rather than `Internal`: a harness tells hod's crashes
   from its refusals by reason alone.
2. hod installs no panic hook (the process's hook runs, as for any
   panic); kiln's contained scope decides what its hook does.
3. `HOD_COMPRESS_DEBUG_SECTIONS` stays the caller's to apply (WP-091
   choice 4 made normative); `Environment` is `#[non_exhaustive]` and the
   driver's tests build one with a `with(&base, |e| ...)` helper.
4. `hod_cli` no longer depends on `hod_ll` (it used nothing of it).
5. The test hook (`contain::fault`, six sites: `Reader`, `EndModule`,
   `Feed`, `Worker`, `Codegen`, `Finish`) is `#[cfg(test)]`: absent from
   every other build and from the public API; it is armed per thread and
   handed to the workers a compile starts.

## Evidence
- Tests (`crates/hod/src/contain/tests.rs`): every site through the
  public `Session` and through `compile_with`, with census on and off:
  `Panic` with the forced message, the poisoned session's later calls,
  `out` untouched, no `bodies` phase, every worker started is gone; a
  real fifo jobserver of 3 tokens (`hod_testutil::jobs::PrivatePool`):
  peak held 3, held 0 after the panic, the pool's idle count 3 before and
  after, on both routes; after each site's panic the next compile on the
  same thread writes the bytes of a fresh thread's compile, seed modules
  of both targets (60+ objects).
- Mutations caught: `guarded` without `catch_unwind`, `poison` not
  replacing the state, the lease not giving its token back while
  unwinding.
- Byte identity, release builds of `f1e2502` (base) and this branch,
  `HOD_STRICT=1 HOD_CENSUS=1` with a coverage log: the 58 seed modules of
  `tests/ir` for both targets and every tenth corpus entry of both
  manifests with their `llc` arguments: 1,363 invocations, 1,297 objects
  byte-identical, 66 declines with the same status, standard error and
  coverage fields 1-4, 6 and 11.
- Cost, `valgrind --tool=callgrind`, `HOD_THREADS=1`, instructions:
  synthetic 20,000-function module, aarch64, release (`panic = "abort"`):
  1,103,798,575 base, 1,106,090,651 new (+0.21%, ~115 per function);
  x86-64: 1,300,231,874 / 1,308,952,301 (+0.67%, allocator internals;
  `malloc`/`free` call counts equal to ±15); small corpus modules
  (`strlen-2.c.ll` 14,556,594 / 14,554,054, `ms-struct-run.cpp.ll`
  18,550,787 / 18,552,001): noise. With `panic = "unwind"` (how an
  embedding links hod) aarch64: 1,108,404,368 / 1,112,541,836 (+0.37%).
  The per-function part is one more `memcpy` of the `Body` (20,000
  calls, ~94 instructions each): `body`'s argument moved into the
  contained closure. Passing it through a slot, by reference or with
  `catch_unwind` inlined left the copy in place. Nothing per instruction.

## For H6 and H7 (kiln)
Build hod with `default-features = false` (no readers); assert
`hod::EMBED_API` at build time; keep the bridge's own `catch_unwind`
around the code it runs between hod's calls (the builder, the kit) and
drop the session on any `Err`; the threads hod starts for a call live
inside that call, so kiln's process-wide contained scope (its hook's
test) must be entered around each session call, not only on the
bridge's thread's own code.
